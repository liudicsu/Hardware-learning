## Why desktop-arm lessons are not enough

The SO-101 is screwed to the table; its base never falls over. A humanoid has three things a desktop arm does not:

1. **A floating base.** The torso pose is not set by the joints directly; it can only be pushed through foot–ground contact forces, so the state gains 6 unactuated degrees of freedom.
2. **Contact switching.** Single / double support alternate, so the dynamics can change form every step; landing impacts also heat the motors (see ASAP's limitations below).
3. **Whole-body coordination.** Swinging an arm shifts the centre of mass (CoM), and the legs must compensate at the same time — that is what "whole-body" control means.

The inverted pendulum in [5.2 state-space and LQR](/en/month/month-5/state-space-lqr) is the smallest entry model; this lesson puts it under the constraint "the sole can only push on a finite patch of ground".

## LIPM, ZMP and the capture point

The linear inverted pendulum model (LIPM) shrinks the whole body to one CoM point at a fixed height z_c:

- Lateral dynamics: x'' = ω²·(x − p), ω = √(g / z_c).
- p is the **ZMP** (zero-moment point / centre of pressure), and it **can only sit inside the support foot**, e.g. |p| ≤ 0.10 m.
- **Capture point** ξ = x + x'/ω: while ξ is inside the foot, some in-foot p can bring the CoM to rest; once ξ leaves the foot, the robot falls unless it steps.

To sway the CoM as A·sin(wt), the ZMP amplitude needed is A·(1 + w²/ω²), and the reference's own peak capture point is A·√(1 + (w/ω)²). Raise the frequency and both numbers leave the foot — no controller can save that.

## LIPM tracking toy

`lipm_track_toy.py`: z_c = 0.8 m, foot half-width 0.10 m, 5 cm sway; PD + feed-forward picks the ZMP, which is clipped at the foot edge; CoM measurements carry seeded Gaussian noise. It compares a 0.5 Hz (slow) and a 1.0 Hz (fast) reference; a capture point outside the foot counts as a fall and stops the run.

```python
#!/usr/bin/env python3
"""lipm_track_toy.py: planar linear inverted pendulum (LIPM) CoM tracking (stdlib).

The CoM moves as  x'' = omega^2 * (x - p),  omega = sqrt(g / z_c),
where p is the ZMP (centre of pressure). p can only sit inside the foot,
here |p| <= FOOT_HALF_M. A PD + feed-forward controller picks the p it wants;
if that p is outside the foot it is clipped, and tracking degrades.

Two lateral sway references with the same amplitude:
  - slow (0.5 Hz): the ZMP it needs stays inside the foot
  - fast (1.0 Hz): the *reference* capture point already leaves the foot
    (A·√(1+(w/ω)²) > FOOT_HALF); at the recorded fall (0.045 s) ZMP clipping
    count is 0 — the fall is declared because capture point x + v/ω is outside
    the foot, not because ZMP was clipped. No in-foot ZMP can then stop the CoM;
    the robot must step (here: the run stops and reports a fall)
CoM measurements carry seeded Gaussian noise (SEED) so the run is repeatable.

Also prints ASAP (arXiv 2502.01143) Table V constants used in the lesson prose —
paper numbers, not toy measurements. Take the paper as source of truth.
No humanoid purchase is required; Isaac / MuJoCo training is not run on this page.
"""
import math
import random

SEED = 2
G = 9.81
Z_C = 0.8          # CoM height (m)
FOOT_HALF_M = 0.10  # ZMP limit (m)
AMP_M = 0.05        # sway amplitude (m)
DT = 0.005
T_END = 4.0
KP, KD = 40.0, 12.0
NOISE_M = 0.002

omega = math.sqrt(G / Z_C)


def run(freq_hz, rng):
    w = 2 * math.pi * freq_hz
    x, v = 0.0, AMP_M * w  # start on the reference
    err_sum, n, clipped = 0.0, 0, 0
    t = 0.0
    t_fall = None
    while t < T_END - 1e-9:
        x_des = AMP_M * math.sin(w * t)
        v_des = AMP_M * w * math.cos(w * t)
        a_des = -AMP_M * w * w * math.sin(w * t)
        x_meas = x + rng.gauss(0.0, NOISE_M)
        u = a_des + KP * (x_des - x_meas) + KD * (v_des - v)
        p = x_meas - u / (omega * omega)
        if abs(p) > FOOT_HALF_M:
            p = math.copysign(FOOT_HALF_M, p)
            clipped += 1
        acc = omega * omega * (x - p)
        v += acc * DT
        x += v * DT
        t += DT
        err_sum += abs(x - AMP_M * math.sin(w * t))
        n += 1
        if abs(x + v / omega) > FOOT_HALF_M:  # capture point left the foot
            t_fall = t
            break
    return err_sum / n, clipped / n, t_fall


rng = random.Random(SEED)
need_slow = AMP_M * (1 + (2 * math.pi * 0.5) ** 2 / omega ** 2)
need_fast = AMP_M * (1 + (2 * math.pi * 1.0) ** 2 / omega ** 2)
# peak capture point of the reference itself: A * sqrt(1 + (w/omega)^2)
cp_slow = AMP_M * math.sqrt(1 + (2 * math.pi * 0.5 / omega) ** 2)
cp_fast = AMP_M * math.sqrt(1 + (2 * math.pi * 1.0 / omega) ** 2)
mae_slow, clip_slow, fall_slow = run(0.5, rng)
_, _, fall_fast = run(1.0, rng)

print(f"seed={SEED}")
print(f"z_c={Z_C}")
print(f"omega={omega:.4f}")
print(f"foot_half_m={FOOT_HALF_M:.2f}")
print(f"zmp_needed_slow_m={need_slow:.4f}")
print(f"zmp_needed_fast_m={need_fast:.4f}")
print(f"cp_peak_ref_slow_m={cp_slow:.4f}")
print(f"cp_peak_ref_fast_m={cp_fast:.4f}")
print(f"com_mae_slow_m={mae_slow:.6f}")
print(f"clip_frac_slow={clip_slow:.3f}")
print(f"fell_slow={fall_slow is not None}")
print(f"fell_fast={fall_fast is not None}")
print(f"fall_time_fast_s={fall_fast:.3f}" if fall_fast is not None else "fall_time_fast_s=none")
# ASAP paper constants (arXiv 2502.01143 Table V / Sec. IV-C) for prose binding
print("asap_kick_gmpjpe_vanilla_mm=61.2")
print("asap_kick_gmpjpe_asap_mm=50.2")
print("asap_lebron_gmpjpe_vanilla_mm=159")
print("asap_lebron_gmpjpe_asap_mm=112")
print("asap_real_delta_dof=4")
```

How to read it:

- ω = **3.5018** rad/s (z_c = **0.8** m).
- The slow sway needs a ZMP amplitude of **0.0902** m, inside the **0.10** m foot; the fast sway needs **0.2110** m, far outside.

- Fast: fell_fast=True, a fall declared at **0.045** s. Not a tuning problem but a physical one: lower the frequency or amplitude, or take a step (move the foot to the capture point).

## Floating-base contact kinematics

### Six planar coordinates, not a six-axis floating base

The general robot above has a spatial floating base; this **separate sagittal toy** has `q=(x_b,z_b,θ_b,q1,q2,q3)`: three base coordinates and three revolute joints in one stance leg. It has **no arm** or swing leg. Segment lengths are 0.35, 0.35 and 0.12 m. Angles `a_i=θ_b+Σ(j≤i)q_j` are measured from downward vertical. The foot origin is `p_c=(x_b+Σ L_i sin(a_i), z_b−Σ L_i cos(a_i))`.

Differentiate this forward kinematics to obtain the **2×6** Jacobian. The translation columns are `(1,0)` and `(0,1)`; the pitch column sums all segment derivatives; joint column j sums only downstream segments. The foot can rotate: this is a **two-row point-position constraint**, not a three-row glued sole. A central finite-difference test checks all six analytic columns.

<Formula label="Velocity-level no-slip">r_c = J_c(q) qdot = 0</Formula>

Rank describes independence, not whether the commanded velocity satisfies contact. Even a full-row-rank matrix produces foot motion for an arbitrary qdot. Here the two base-translation columns keep full `J_c` rank **2**, including the straight-leg configuration. Only the **joint-only** 2×3 submatrix loses rank (to **1**) when straight; that warns about leg-only motion authority, not loss of full-Jacobian rank. **Single support need not reduce rank.** Numerical singular values depend on our coordinate scaling (metres and radians), not a universal singularity threshold.

### Contact first, base pitch second

For this full-row-rank matrix, form `J_c⁺=J_cᵀ(J_c J_cᵀ)⁻¹`, then `N=I−J_c⁺J_c`. Project a seeded arbitrary command as `v0=N v_raw`, and add `N eθ α`, where `eθ` selects the existing base-pitch coordinate. Choose `α=(−2 θ_b−v0[2])/N[2,2]` to attain a desired pitch rate without changing the primary contact residual. This is a local **velocity** construction: no mass matrix, actuator torques, joint limits or integration of a walking trajectory. An unactuated base cannot be commanded as an independent motor; dynamic feasibility still needs forces and inverse dynamics.

For source context, [Paredes et al., §II-A Eq. (3) and §III Eq. (20)](https://arxiv.org/html/2408.05308) maintain contact at acceleration level `J_c qddot + Jdot_c qdot=0` and parameterise admissible accelerations with a nullspace. The equations were checked in the opened paper; take the paper as source of truth. Our differentiated position map and velocity projector are explicit toy derivations, **not ASAP's controller** and not the paper's full-body implementation. Holding zero contact velocity initially matters: zero acceleration alone does not remove an existing slip velocity.

### Defined contact screens, not a point-foot polygon

The same synthetic CoM path `x=0.14 sin(2t)` at height 0.8 m gives `F_x=m xddot`, `F_z=m g` and, assuming zero centroidal angular-momentum rate, `CoP=x−h xddot/g`. Both screens receive this same demand. The **point force-only screen** checks positive normal force and `|F_x|≤μ F_z`, with μ=0.6. It has **no support polygon**. The **finite-sole screen** adds `|CoP|≤0.10 m`.

Crucial omission: a point contact cannot support a nonzero moment about itself. The force-only screen deliberately discards the demand's moment `−F_z CoP`; passing it is **not full point-contact wrench feasibility**. The finite sole also needs full dynamics beyond these screens. Thus the difference exposes missing model constraints, not that an ideal point foot can physically realise the same nonzero wrench. The earlier LIPM toy already assumes a finite sole; do not silently transfer that support interval to the point model.

```python
#!/usr/bin/env python3
"""Planar floating-base velocity projection, not a dynamic WBC controller.
q=(xb,zb,theta_b,q1,q2,q3): three base + three leg DOFs, no arm.
Two-row point-position Jc permits foot rotation. Jc*qdot=0 is no-slip;
rank alone never enforces it. Base translation columns keep full Jc rank 2.
Force-only point screen omits moments; it does NOT certify a nonzero wrench
for an ideal point foot. Finite sole adds a CoP test on the SAME demand.
All forces/CoM are synthetic. No humanoid, MoCap or simulator is run.
"""
import math
import random

SEED = 31
LENGTHS = (0.35, 0.35, 0.12)


def kinematics(q):
    angles = [q[2] + sum(q[3:4 + i]) for i in range(3)]
    dx = [l * math.cos(a) for l, a in zip(LENGTHS, angles)]
    dz = [l * math.sin(a) for l, a in zip(LENGTHS, angles)]
    # Segment direction = (sin(a), -cos(a)); angle zero points down.
    point = [q[0] + sum(l * math.sin(a) for l, a in zip(LENGTHS, angles)),
             q[1] - sum(l * math.cos(a) for l, a in zip(LENGTHS, angles))]
    j = [[1.0, 0.0, sum(dx)] + [sum(dx[i:]) for i in range(3)],
         [0.0, 1.0, sum(dz)] + [sum(dz[i:]) for i in range(3)]]
    return point, j


def dot(a, b):
    return sum(x * y for x, y in zip(a, b))


def norm(v):
    return math.sqrt(dot(v, v))


def spectrum(rows):
    a, b, c = dot(rows[0], rows[0]), dot(rows[0], rows[1]), dot(rows[1], rows[1])
    disc = math.hypot(a - c, 2 * b)
    s = [math.sqrt(max(0.0, (a + c + disc) / 2)),
         math.sqrt(max(0.0, (a + c - disc) / 2))]
    return sum(x > 1e-8 for x in s), s


def projector(j):
    # Full-row-rank right inverse: J+ = J^T (J J^T)^-1.
    a, b, c = dot(j[0], j[0]), dot(j[0], j[1]), dot(j[1], j[1])
    det = a * c - b * b
    assert det > 1e-12
    jp = [[(j[0][i] * c - j[1][i] * b) / det,
           (j[1][i] * a - j[0][i] * b) / det] for i in range(6)]
    return [[float(i == k) - sum(jp[i][r] * j[r][k] for r in range(2))
             for k in range(6)] for i in range(6)]


def main():
    rng = random.Random(SEED)
    q = [0.0, 0.8, 0.12, -0.3, 0.6, -0.2]
    _, j = kinematics(q)
    n = projector(j)
    jn = max(abs(sum(j[r][i] * n[i][k] for i in range(6)))
             for r in range(2) for k in range(6))
    # Central finite-difference check of all columns, not only translations.
    fd_err = 0.0
    for k in range(6):
        hi, lo = q[:], q[:]
        hi[k] += 1e-6
        lo[k] -= 1e-6
        ph, _ = kinematics(hi)
        pl, _ = kinematics(lo)
        fd_err = max(fd_err, *(abs((ph[r] - pl[r]) / 2e-6 - j[r][k]) for r in range(2)))
    raw = [rng.uniform(-0.3, 0.3) for _ in range(6)]
    projected = [dot(row, raw) for row in n]
    pitch_target = -2 * q[2]  # secondary base-pitch regulation, rad/s
    gain = (pitch_target - projected[2]) / n[2][2]
    velocity = [projected[i] + n[i][2] * gain for i in range(6)]
    rc = norm([dot(row, velocity) for row in j])
    pitch_err = abs(velocity[2] - pitch_target)
    rank, sigma = spectrum(j)
    straight = kinematics([0.0, 0.82, 0.0, 0.0, 0.0, 0.0])[1]
    straight_rank, _ = spectrum(straight)
    leg_rank, _ = spectrum([row[3:] for row in straight])
    assert jn < 1e-12 and rc < 1e-12 and pitch_err < 1e-12 and fd_err < 1e-8
    assert rank == straight_rank == 2 and leg_rank == 1

    # Shared synthetic CoM/wrench demand; no full inverse-dynamics solution.
    mass, height, mu, sole_half = 20.0, 0.8, 0.6, 0.10
    point_pass, sole_pass, max_cop = 0, 0, 0.0
    for k in range(201):
        t = 2 * math.pi * k / 200
        x = 0.14 * math.sin(2 * t)
        ax = -4 * x
        fx, fz = mass * ax, mass * 9.81
        cop = x - height * ax / 9.81  # zero centroidal angular-momentum rate
        # About the foot origin the demanded moment is -fz*cop.
        force_ok = fz > 0 and abs(fx) <= mu * fz
        sole_ok = force_ok and abs(cop) <= sole_half
        point_pass += int(force_ok)
        sole_pass += int(sole_ok)
        max_cop = max(max_cop, abs(cop))
    assert point_pass == 201 and 0 < sole_pass < point_pass
    print(f"seed={SEED} dofs=6 contact_rows=2 no_arm=True")
    print(f"Jc_rank={rank} sigma_max={sigma[0]:.6f} sigma_min={sigma[1]:.6f}")
    print(f"raw_contact_speed={norm([dot(row, raw) for row in j]):.6f}")
    print(f"contact_residual={rc:.3f} JcN_max={jn:.3f} pitch_rate_error={pitch_err:.3f}")
    print(f"jacobian_fd_ok={fd_err < 1e-8} nullspace_ok={jn < 1e-12}")
    print(f"straight_full_rank={straight_rank} straight_joint_only_rank={leg_rank}")
    print(f"point_force_screen={point_pass}/201 finite_sole_screen={sole_pass}/201")
    print(f"max_abs_cop_m={max_cop:.6f} sole_half_m={sole_half:.2f}")
    print("point_screen_omits_moment=True full_dynamic_feasibility_not_tested=True")


if __name__ == "__main__":
    main()
```

## Reading map

### 1. ASAP (arXiv 2502.01143, RSS 2025) — read closely

<Resource id="asap-paper" />
<Resource id="asap-code" />

ASAP (Aligning Simulation and Real-World Physics) is a two-stage framework, shown in four steps in the paper's Fig. 2:

1. **Pre-train motion tracking**: reconstruct SMPL motions from human video, clean them in simulation, retarget to the Unitree G1, and train a phase-conditioned tracking policy with PPO (asymmetric actor-critic: the critic gets privileged information, the actor only proprioception + phase).
2. **Roll out on the real robot**: deploy the pre-trained policy and record states (motion capture + onboard sensors) and actions.
3. **Learn a delta action model**: Δa_t = π^Δ(s_t, a_t) is added to the replayed real actions so that the simulated s_(t+1) = f_sim(s_t, a_t + Δa_t) matches the recorded real state; trained with PPO.
4. **Freeze the delta model and fine-tune the policy in the "aligned" simulator**, then deploy to the real robot **without** the delta model.

Real-robot part (take the paper as source of truth): with little data, the real-robot delta action model covers only the **4** ankle degrees of freedom (the full 23-DoF model needs many more clips), trained on about 100 motion clips; the paper also reports that two G1 robots were damaged to some extent during data collection — highly dynamic motions overheat the motors. Table V, real closed loop: for the kick (in-distribution), global body-position error g-MPJPE drops from Vanilla **61.2** mm to ASAP **50.2** mm; for LeBron's "Silencer" (out-of-distribution), from **159** to **112** mm.

What to read: §III (definition and training of the delta action), §IV-C real-world and Table V, §VIII limitations (hardware wear, motion-capture dependence, data hunger). What not to run: the real G1, Isaac Gym / Isaac Sim / Genesis training — not run on this page.

## Against 7.4 sim-to-real

| Approach | What it changes | How the ASAP paper rates it (take the paper as source of truth) |
|---|---|---|
| System ID (SysID) | Simulator parameters (CoM shift, mass, PD gain ratios) | Needs a predefined parameter space; long-horizon error builds up |
| Domain randomisation (DR) | Randomised parameters during training | Tends to give over-conservative policies that lose agility |
| Residual dynamics (DeltaDynamics) | A learned residual on s | Overfits and cascades errors over long horizons |
| **Delta action (ASAP)** | A learned residual on the **action**, pulling sim towards real | Better in both open-loop replay and closed-loop fine-tuning |

The key difference: ASAP adds the residual to the **action**, not only to the dynamics, and the fine-tuned policy no longer needs the delta model at deployment.
