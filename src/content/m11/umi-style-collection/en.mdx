## Why collect without a robot body

A desktop arm on a fixed base cannot go into a kitchen, a workshop or a street stall. UMI (Universal Manipulation Interface, Chi et al., RSS 2024; arXiv 2402.10329) pairs a **3D-printed parallel gripper** with a wrist GoPro (fisheye, side mirror, IMU), continuous jaw width and soft fingers, so a human can demonstrate in the wild and a policy can replay the same interface on a robot later. The action interface is a **relative trajectory**: an SE(3) sequence expressed relative to the current end-effector, not absolute world targets and not per-step deltas that accumulate.

## Relative / absolute / delta toy

`relative_traj_toy.py` keeps an SE(2) simplification of the same idea (aligned with UMI §III-B / PD2.1 Fig.6). One action sequence, three reconstructions:

1. **Absolute** — global-frame targets with a fixed calibration bias → end error equals the bias magnitude.
2. **Delta (contrast)** — each step relative to the *previous* pose; the same noise magnitude is added independently to every step-wise delta and the deltas are compounded → noise accumulates along the chunk.
3. **Relative (UMI-style)** — one inference chunk with a fixed anchor T0; the final pose is reconstructed directly as T0 ∘ (T0⁻¹ ∘ TN), **not** by chaining intermediate deltas. Fair noise is added *once* to that final T0⁻¹ ∘ TN action only (intermediate relative targets are not noised), so end error is a single draw (~0.001875 m by default) — not zero, and not a compounded pile-up.

A separate **bias demo** (a different conclusion from error accumulation): during recording the measured EE pose carries a fixed left-multiplied rigid world-frame bias B (say a mis-registered SLAM / camera frame: 3 cm, −2 cm, 0.08 rad) plus ±0.5 mm per-frame noise. Replaying the measured poses as absolute targets carries B straight onto the robot; fixed-anchor relative actions T0⁻¹ ∘ TN cancel B inside the product. Cancelling a fixed left-multiplied world bias is not the same claim as "relative does not accumulate step noise".

```python
#!/usr/bin/env python3
"""relative_traj_toy.py: absolute / delta / relative end-error under SE(2) (stdlib).

UMI PD2.1 / Fig.6 (arXiv 2402.10329 v3): three action representations.
  - absolute: global-frame targets (needs a shared world frame; calib bias sticks)
  - delta (contrast): each step is relative to the *previous* pose → per-step
    action noise compounds along the chunk
  - relative (UMI): one inference chunk with a *fixed anchor* T0; the *final*
    pose is rebuilt directly as T0 ∘ (T0^{-1} ∘ TN) — not a chain of deltas

Fair noise (endpoint-error demo): the same per-component noise magnitude is
added independently to every step-wise delta; for the fixed-anchor arm the
same magnitude is added *once* to the final T0^{-1} ∘ TN action only
(intermediate relative targets are not noised). Relative end error is
therefore a single draw (~0.001875 at default noise), not zero and not a
compounded pile-up.

Bias demo (a *different* conclusion from error accumulation): a fixed left-
multiplied world-frame bias B on measured poses cancels under relative actions
(T0^{-1} Tk), because B drops out of the product. That is not the same claim as
"relative does not accumulate step noise".

Also prints UMI paper constants used in the lesson prose (throughput, ATE)
— paper numbers, not toy measurements. Take the paper as source of truth.
Buying a GoPro is not required.
"""
import math
import random

SEED = 7
random.seed(SEED)


def se2_compose(p, a):
    """Compose pose p=(x,y,yaw) with body-frame action a=(dx,dy,dyaw)."""
    c, s = math.cos(p[2]), math.sin(p[2])
    return (
        p[0] + c * a[0] - s * a[1],
        p[1] + s * a[0] + c * a[1],
        p[2] + a[2],
    )


def se2_inv(p):
    c, s_ = math.cos(p[2]), math.sin(p[2])
    return (-c * p[0] - s_ * p[1], s_ * p[0] - c * p[1], -p[2])


def se2_mul(p, q):
    """p ∘ q for poses (q expressed in p's frame)."""
    return se2_compose(p, q)


def se2_delta(a, b):
    """Body-frame motion taking pose a to pose b: a^{-1} ∘ b."""
    return se2_mul(se2_inv(a), b)


def add_noise(a, noise):
    return (
        a[0] + random.uniform(-noise, noise),
        a[1] + random.uniform(-noise, noise),
        a[2] + random.uniform(-noise, noise),
    )


# True path: 8 relative actions from the origin
pose = (0.0, 0.0, 0.0)
truth = [pose]
for _ in range(8):
    a = (
        0.05 + random.uniform(-0.01, 0.01),
        random.uniform(-0.02, 0.02),
        random.uniform(-0.1, 0.1),
    )
    pose = se2_compose(pose, a)
    truth.append(pose)

# Absolute with a fixed calibration bias in the world frame
calib_err = (0.02, -0.015, 0.05)
abs_end_err = math.hypot(calib_err[0], calib_err[1])  # bias dominates end error

noise = 0.003
T0 = truth[0]

# True step-wise deltas and fixed-anchor relatives from the clean path
deltas = [se2_delta(truth[k], truth[k + 1]) for k in range(len(truth) - 1)]
rels_from_anchor = [se2_delta(T0, truth[k]) for k in range(1, len(truth))]

# Delta (contrast): compound noisy step-wise deltas — noise accumulates
delta_pose = T0
for d in deltas:
    delta_pose = se2_compose(delta_pose, add_noise(d, noise))
delta_end_err = math.hypot(delta_pose[0] - truth[-1][0], delta_pose[1] - truth[-1][1])

# Relative (UMI PD2.1): fixed-anchor reconstruction of the final pose only.
# One noisy (T0^{-1} ∘ TN); intermediate deltas are never chained.
rel_final_action = add_noise(rels_from_anchor[-1], noise)
rel_pose = se2_compose(T0, rel_final_action)
rel_end_err = math.hypot(rel_pose[0] - truth[-1][0], rel_pose[1] - truth[-1][1])

# Bias demo (separate conclusion): fixed left-multiplied world-frame bias B
B = (0.03, -0.02, 0.08)  # world-frame bias (m, m, rad)
meas_noise = 0.0005
meas = []
for T in truth:
    m = se2_mul(B, T)
    meas.append((m[0] + random.uniform(-meas_noise, meas_noise),
                 m[1] + random.uniform(-meas_noise, meas_noise),
                 m[2]))
# absolute replay: robot drives to the measured (biased) final pose
abs_biased_err = math.hypot(meas[-1][0] - truth[-1][0], meas[-1][1] - truth[-1][1])
# relative (fixed-anchor) replay: T0 ∘ (m0^{-1} ∘ m_N); B cancels in the product
rb_pose = se2_mul(T0, se2_mul(se2_inv(meas[0]), meas[-1]))
rel_biased_err = math.hypot(rb_pose[0] - truth[-1][0], rb_pose[1] - truth[-1][1])
# same, with zero noise: bias cancels exactly
meas0 = [se2_mul(B, T) for T in truth]
rb0 = se2_mul(T0, se2_mul(se2_inv(meas0[0]), meas0[-1]))
rel_bias_only_err = math.hypot(rb0[0] - truth[-1][0], rb0[1] - truth[-1][1])

print(f"seed={SEED}")
print(f"steps={len(deltas)}")
print(f"abs_calib_bias_m={abs_end_err:.6f}")
print(f"delta_accum_err_m={delta_end_err:.6f}")
print(f"relative_err_m={rel_end_err:.6f}")
print(f"abs_from_biased_meas_err_m={abs_biased_err:.6f}")
print(f"rel_from_biased_meas_err_m={rel_biased_err:.6f}")
print(f"rel_bias_only_err_m={rel_bias_only_err:.6f}")
# UMI paper constants (arXiv 2402.10329 v3 / project page) for prose binding
print(f"umi_cup_throughput_per_h=111")
print(f"spacemouse_throughput_per_h=35")
print(f"hand_throughput_per_h=231")
print(f"umi_field_success_pct=71.7")
print(f"umi_ate_mm=6.1")
print(f"umi_ate_deg=3.5")
```

How to read it:

- Absolute end error **0.025000** m equals √(0.02² + 0.015²) — the calibration bias, not path length.
- Delta (contrast) accumulates to **0.008287** m over 8 steps of ±0.003 action noise each.
- Relative (fixed anchor) adds the same noise magnitude once to the final T0⁻¹ ∘ TN action → end error **0.001875** m, well below the delta pile-up, because intermediate noise is never chained.
- Bias demo (a different conclusion): replaying the biased measured end pose as an absolute target misses by **0.033248** m; fixed-anchor relative replay misses by **0.000829** m (per-frame measurement noise); with noise removed and only the bias left, **0.000000** m — a fixed left-multiplied world-frame bias cancels. That is not the same claim as "relative does not accumulate step noise".
- Paper constants **111** / **35** / **231**, **71.7**, **6.1** / **3.5** are independent of the toy; they exist so check_diagrams and the prose share one number.

## Teleop latency budget: unilateral positions, not delayed force reflection

UMI's relative trajectories do not remove communication latency. Here a leader sends a shared stream of **500 position commands** to a follower; the follower has a local first-order position servo with **80 ms** time constant and **10 ms** integration step. The coupling is **one-way/unilateral position teleop**: there is no reflected force and no energy-coupled haptic device. Video informs the operator but is not force feedback. Wi-Fi/WebRTC-like numbers below are **illustrative only**, not a measured network, product promise or safety limit.

This is **not 10.2 RTC**, **not 8.3 timestamp sync**, and **not 6.3 async**: those concern chunk continuity, stream alignment and inference scheduling. This section instead separates outgoing commands, returned observations and the operator's delayed decision. The existing relative-pose experiment is unchanged.

### One-way latency, control RTT and video RTT are different measurements

Our nominal low/high command one-way delays are **20/100 ms**; acknowledgement returns are **20/120 ms**. Thus **control RTT = command delay + acknowledgement delay = 40/220 ms**, not automatically twice the outgoing delay. An acknowledgement does not add delay to the command already executing at the follower.

For an explicitly defined **video probe RTT**, send a request along the command path, then return an image through a separate **40/200 ms** video path plus **40 ms** capture/encode/decode/display pipeline. This request-to-image RTT is **100/340 ms**. An unsolicited remote event is seen after only the return+pipeline **display age = 80/240 ms**, not the full probe RTT. Do not double-count its already-travelled request. Continuous streaming glass-to-glass age is a one-way measurement and need not even involve a request; the table's video RTT is this toy's probe definition, not a universal “WebRTC RTT” field.

Both links reuse the same per-command jitter draws of **-10/0/+10 ms**. Delivered packets are ordered by arrival; sequence numbers ensure late old commands cannot overwrite fresher ones. Both links use exactly the same sine command stream and local servo for tracking. Delays, not trajectories or actuator quality, change between arms.

### Explicit operator model and metric definitions

For stop trials, a remote hazard happens at **2.00 s** during a **0.35 m/s** ramp. The operator cannot react until the image is displayed. A lesson-defined reaction time is drawn in **180–280 ms**, identically for both links across **20 trials**. The operator sends a position-hold command at `hazard_time + display_age + reaction_time`; it then travels through the outgoing command path. The same ramp is shared until that arm's delayed stop decision; after it, the commanded position freezes. This is the only event-driven command difference. It is not a human-subject measurement or an e-stop implementation.

- **Tracking MAE**: follower-vs-current-leader mean absolute position error over samples 50–499 of the common sine stream.
- **Best lag**: shift the leader trace by 0–500 ms on the 10 ms grid and choose the minimum absolute error over that same window. It includes transport and servo lag and is a coarse trace-fit metric, not a packet RTT measurement.
- **Stop advance / overshoot**: maximum follower position from the remote hazard onward minus follower position at the hazard, in metres. It is additional travel after the event, **not step-response overshoot** of this monotone servo.
- **Miss rate**: number of the 20 stop trials with additional travel greater than the lesson threshold **0.18 m**. This threshold is not a certified protective distance or a human force limit.

The third row, `one_way_only_estimate`, is an **optimistic accounting ablation of the high link**: it keeps high-link command/ack/video values but pretends display age is zero when scheduling the reaction. It is **not a third physical network** and not the actual performance of the high link. Its equal tracking MAE/lag to high is intentional (same outgoing path); its falsely optimistic stop prediction exposes the missing return path. Do not present that row's 0/20 misses as a real improvement.

The actual toy links yield MAE **0.02348/0.04442 m**, best lag **90/170 ms**, mean stop advance **0.13940/0.22276 m**, and miss counts **0/20 versus 20/20**. Omitting the display age predicts only **0.13876 m** and **0/20** for the high link. These are consequences of the declared model, not evidence that any actual link or operator is safe.

```python
#!/usr/bin/env python3
"""Unilateral POSITION teleop + explicit visual-reaction stop model.
Shared command stream, common packet-jitter draws, shared 20 operator reactions.
Low/high are physical toy links; one_way_only is an optimistic ACCOUNTING
ablation of high, not a third measured network or a proposed safety controller.
All Wi-Fi/WebRTC-like delays are illustrative; no actual network is measured.
"""
from __future__ import annotations
import math
import random
import statistics

SEED = 114
DT = 0.01
TAU = 0.08
N = 500
EVENT = 200
SPEED = 0.35  # m/s, lesson-defined ramp
LIMIT = 0.18  # m additional travel; exercise threshold, NOT a safety standard
# forward command ticks, acknowledgement ticks, video return ticks
LINKS = {"low_RTT": (2, 2, 4), "high_RTT": (10, 12, 20),
         "one_way_only_estimate": (10, 12, 20)}
PIPELINE = 4  # capture/encode/decode/display ticks; no real camera run


def follower(commands, forward_ticks, jitter):
    events = sorted((i + max(0, forward_ticks + jitter[i]), i, value)
                    for i, value in enumerate(commands))
    q, latest, held, cursor = 0.0, -1, 0.0, 0
    result = []
    for step in range(N):
        while cursor < len(events) and events[cursor][0] <= step:
            _, seq, value = events[cursor]
            if seq > latest:  # a late packet never overwrites a fresher command
                latest, held = seq, value
            cursor += 1
        q += (held - q) * DT / TAU
        result.append(q)
    return result


def main():
    rng = random.Random(SEED)
    jitter = tuple(rng.choice((-1, 0, 1)) for _ in range(N))
    reactions = tuple(rng.randint(18, 28) for _ in range(20))
    commands = tuple(0.25 * math.sin(1.8 * i * DT) for i in range(N))
    print(f"seed={SEED} unilateral_position dt_ms={DT*1000:.0f} servo_tau_ms={TAU*1000:.0f}")
    print("shared_stream=500_positions; shared_jitter_draws=yes; shared_reactions=20")
    print("arm command_oneway_ms control_RTT_ms video_probe_RTT_ms display_age_used_ms")
    rows = []
    for name, (forward, ack, video) in LINKS.items():
        display = 0 if name == "one_way_only_estimate" else video + PIPELINE
        # Nominal control probe: command+ack; video probe: request+video+pipeline.
        print(f"{name} {forward*10} {(forward+ack)*10} "
              f"{(forward+video+PIPELINE)*10} {display*10}")
        q = follower(commands, forward, jitter)
        mae = statistics.mean(abs(q[i] - commands[i]) for i in range(50, N))
        lag = min(range(51), key=lambda delay: sum(
            abs(q[i] - commands[i-delay]) for i in range(50, N)))
        advances = []
        for reaction in reactions:
            # Remote hazard at EVENT; seen after display age, then operator reacts.
            stop_sent = EVENT + display + reaction
            stream = tuple(SPEED * DT * min(i, stop_sent) for i in range(N))
            trajectory = follower(stream, forward, jitter)
            advances.append(max(trajectory[EVENT:]) - trajectory[EVENT])
        misses = sum(a > LIMIT for a in advances)
        rows.append((name, mae, lag * 10, statistics.mean(advances), max(advances), misses))
    print("arm tracking_MAE_m best_lag_ms stop_advance_mean_m max_m miss_count/20")
    for name, mae, lag, mean, maximum, misses in rows:
        print(f"{name} {mae:.5f} {lag} {mean:.5f} {maximum:.5f} {misses}/20")
    # Causality and out-of-order behavior: future command cannot act before arrival.
    impulse = (0.0,) * 10 + (1.0,) * (N - 10)
    test = follower(impulse, 5, (0,) * N)
    assert all(x == 0 for x in test[:15]) and test[15] > 0
    assert follower((0.0,) * N, 10, jitter) == [0.0] * N
    assert rows[2][3] < rows[1][3]  # omitted video return makes budget optimistic
    print("reaction_ticks=18..28; stop_sent=hazard+display_age+reaction")
    print("stop_advance=additional_follower_travel_after_hazard; miss=advance_gt_0.18m")
    print("one_way_only_estimate_ignores_display_NOT_actual_high_link_performance")
    print("control_RTT_is_not_video_RTT; no_force_feedback; network_real_robot_not_run")


if __name__ == "__main__":
    main()
```

### Bilateral delay needs a stability argument, not just an RTT table

The opened [Teleoperation of Humanoid Robots: A Survey](https://ar5iv.labs.arxiv.org/html/2301.04317), sections V-A and V-D/E, discusses how delayed force reflection can destabilise bilateral coupling. Passivity-based methods, including **wave variables** and energy-tank designs, provide an energy/stability framework under stated assumptions; adding damping or subtracting a measured delay is not automatically a proof. Classical constant-delay results do not transfer unchanged to arbitrary jitter, loss and sampling. Stability also does not imply high transparency or good tracking. Our unilateral position toy implements **none** of those bilateral guarantees; no force-feedback stability conclusion follows from the stop table.
