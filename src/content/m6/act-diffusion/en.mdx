The [previous lesson](/en/month/month-6/behaviour-cloning) cloned an expert that always did the same thing in the same place. Human operators do not. Asked to move a cup past an obstacle, one operator goes left, another goes right, and the same operator does both on different days. Both are correct. A policy trained to predict "the" action has to cope with data that contains two right answers, and the simplest training loss fails in a systematic way. This lesson shows the failure on a toy task and then looks at the two ideas that today's most used imitation policies are built on: action chunking (ACT) and diffusion (Diffusion Policy).

## Two right answers

Behaviour cloning with a squared-error loss picks, for each observation, the action that minimises the average squared distance to the recorded actions. That is their **mean**. If 7 demos at a spot swerve left by 4.2 cm and 3 swerve right by 4.2 cm, the mean is (−7 + 3) / 10 × 4.2 = −1.7 cm: a gentle drift left that none of the demonstrators made, and one that may be exactly the wrong thing, straight into the obstacle the demonstrators were avoiding.

<Formula label="What a squared-error loss learns">π(o) = mean of the recorded actions at o, which is not one of them when the actions form two groups</Formula>

The fix is to learn a policy that represents the whole distribution of actions and can **sample** one of them, so it picks left or right rather than a blend. ACT does this with a conditional variational autoencoder over chunks of actions; Diffusion Policy does it with a denoising diffusion model over chunks of actions. Both also predict a **chunk** of future actions at once instead of one.

## The block task

The model is a point gripper starting near (0, 0) that must reach (0, 1). A 0.3 m square block sits in between, centred at (0, 0.5). The expert drives straight up to a fork at (0, 0.2), then heads for a waypoint at (−0.3, 0.4) or (+0.3, 0.4), chosen 50/50 per demonstration, and then for the goal. Each step moves at most 5 cm, plus 0.5 cm of actuator noise per axis.

All the policies look at the same thing: the 10 recorded frames nearest the current position. They differ only in what they do with them, which is exactly the difference between the training losses of real policies. `average` takes the mean of their actions (a squared-error network). `sample` replays one of them chosen at random. `chunk N` picks one at random and plays the next N actions of that demonstration before looking again. `diffusion` runs a real DDPM sampler; where a trained network would predict the clean action, it uses the exact answer for these 10 frames.

<CodeSource path="examples/month-6/act-diffusion/multimodal.py" />

```python
"""multimodal.py: why averaging fails on multimodal demonstrations, and what action chunks and diffusion change.

A point gripper starts near (0, 0) and must reach GOAL (0, 1). A square block of side 0.3 m sits in the way,
centred at (0, 0.5). The expert drives straight up to a fork at (0, 0.2) and then passes it on the left or on the right, 50/50, chosen at the start of each
demonstration: both are equally good, so the demonstrations are multimodal. Each step moves at most 0.05 m
plus 0.5 cm of actuator noise per axis. Success: within 0.05 m of GOAL inside 60 steps without touching the block.

Policies (all look at the K = 10 recorded frames nearest the current position):
  average    the mean of their actions; this is what a network trained with a squared-error loss predicts
  sample     the action of one of them, chosen at random, every step
  chunk N    pick one of them at random and play the next N actions of its episode, then look again
             (action chunking, the core idea of ACT; ACT also blends overlapping chunks)
  diffusion  start from Gaussian noise and denoise a chunk of 8 actions in 20 DDPM steps, using the exact
             denoiser for the demonstration set (the function a diffusion policy's network is trained to
             approximate), then play the chunk and look again
Standard library only, fixed seeds.
"""
import math
import random

GOAL, BLOCK_Y, HALF, FORK_Y = (0.0, 1.0), 0.5, 0.15, 0.2
STEP, NOISE, MAX_STEPS, K = 0.05, 0.005, 60, 10


def hits_block(p):
    return abs(p[0]) <= HALF and abs(p[1] - BLOCK_Y) <= HALF


def toward(p, target):
    dx, dy = target[0] - p[0], target[1] - p[1]
    d = math.hypot(dx, dy)
    k = min(1.0, STEP / d) if d > 0 else 0.0
    return dx * k, dy * k


def expert(p, side):
    """Straight up to the fork at (0, 0.2), then to a waypoint beside the block, then to the goal.
    side is -1 (left) or +1 (right); before the fork both kinds of demo look the same."""
    if p[1] < FORK_Y and abs(p[0]) < 0.05:
        return toward(p, (0.0, FORK_Y + 0.05))
    if p[1] < 0.4 and abs(p[0]) < 0.28:
        return toward(p, (0.3 * side, 0.4))
    return toward(p, GOAL)


def run(choose, rng, record=None):
    """choose(p, t) returns a list of actions to play before asking again."""
    p = (rng.uniform(-0.03, 0.03), rng.uniform(-0.03, 0.03))
    plan, t = [], 0
    while t < MAX_STEPS:
        if not plan:
            plan = list(choose(p, t))
        a = plan.pop(0)
        if record is not None:
            record.append((p, a))
        p = (p[0] + a[0] + rng.gauss(0, NOISE), p[1] + a[1] + rng.gauss(0, NOISE))
        t += 1
        if hits_block(p):
            return 'block', t
        if math.hypot(p[0] - GOAL[0], p[1] - GOAL[1]) < 0.05:
            return 'success', t
    return 'timeout', t


def record_demos(n, rng):
    episodes = []
    for _ in range(n):
        side = rng.choice((-1, 1))
        rows = []
        run(lambda p, t: [expert(p, side)], rng, record=rows)
        episodes.append(rows)
    return episodes


class Demos:
    def __init__(self, episodes):
        self.frames = [(e, i, rows[i][0]) for e, rows in enumerate(episodes) for i in range(len(rows))]
        self.episodes = episodes

    def nearest(self, p, k=K):
        return sorted(self.frames, key=lambda f: (f[2][0] - p[0]) ** 2 + (f[2][1] - p[1]) ** 2)[:k]

    def chunk(self, frame, n):
        """The next n actions of that frame's episode, padded with zero moves at the end."""
        e, i, _ = frame
        acts = [a for _, a in self.episodes[e][i:i + n]]
        return acts + [(0.0, 0.0)] * (n - len(acts))


def average_policy(demos):
    def choose(p, t):
        near = demos.nearest(p)
        return [(sum(demos.chunk(f, 1)[0][0] for f in near) / K, sum(demos.chunk(f, 1)[0][1] for f in near) / K)]
    return choose


def chunk_policy(demos, n, rng):
    def choose(p, t):
        return demos.chunk(rng.choice(demos.nearest(p)), n)
    return choose


def diffusion_policy(demos, n, rng, steps=20):
    """DDPM sampling of an n-step action chunk with the exact denoiser of the K nearest demo chunks."""
    betas = [1e-4 + (0.2 - 1e-4) * s / (steps - 1) for s in range(steps)]
    alphas = [1 - b for b in betas]
    abar, prod = [], 1.0
    for a in alphas:
        prod *= a
        abar.append(prod)
    scale = 1 / STEP                     # work in units of one full step so the noise schedule fits

    def choose(p, t):
        data = [[v * scale for a in demos.chunk(f, n) for v in a] for f in demos.nearest(p)]
        dim = len(data[0])
        x = [rng.gauss(0, 1) for _ in range(dim)]
        for s in reversed(range(steps)):
            # exact denoiser: E[x0 | xs] for x0 drawn uniformly from data, xs = sqrt(abar) x0 + sqrt(1 - abar) noise
            logw = [-sum((xi - math.sqrt(abar[s]) * di) ** 2 for xi, di in zip(x, d)) / (2 * (1 - abar[s]))
                    for d in data]
            m = max(logw)
            w = [math.exp(v - m) for v in logw]
            x0 = [sum(wi * d[j] for wi, d in zip(w, data)) / sum(w) for j in range(dim)]
            if s == 0:
                x = x0
                break
            # DDPM posterior mean of x_{s-1} given xs and the predicted x0, plus its noise
            c0 = math.sqrt(abar[s - 1]) * betas[s] / (1 - abar[s])
            cs = math.sqrt(alphas[s]) * (1 - abar[s - 1]) / (1 - abar[s])
            sd = math.sqrt(betas[s] * (1 - abar[s - 1]) / (1 - abar[s]))
            x = [c0 * a0 + cs * xs + sd * rng.gauss(0, 1) for a0, xs in zip(x0, x)]
        return [(x[2 * j] / scale, x[2 * j + 1] / scale) for j in range(n)]
    return choose


def evaluate(label, make, n=100):
    rng = random.Random(2026)
    choose = make(random.Random(11))
    counts = {'success': 0, 'block': 0, 'timeout': 0}
    steps = []
    for _ in range(n):
        result, t = run(choose, rng)
        counts[result] += 1
        if result == 'success':
            steps.append(t)
    mean = f'{sum(steps) / len(steps):.1f}' if steps else '-'
    print(f'{label:<16} success {counts["success"]:>3}/100   hit block {counts["block"]:>3}   '
          f'timeout {counts["timeout"]:>3}   mean steps to goal {mean}')


def main():
    episodes = record_demos(40, random.Random(5))
    lefts = sum(1 for rows in episodes if min(p[0] for p, _ in rows) < -0.1)
    demos = Demos(episodes)
    print(f'40 expert demos: {lefts} pass on the left, {40 - lefts} on the right, {len(demos.frames)} frames')

    print('\nSideways part dx of the first action just past the fork, at (0, 0.23), 200 draws per policy')
    edges = [-0.05, -0.03, -0.01, 0.01, 0.03, 0.05]
    print('  dx bin (cm)  ' + ''.join(f'{100 * lo:+.0f}..{100 * hi:+.0f}'.rjust(9) for lo, hi in zip(edges, edges[1:])))
    rng = random.Random(3)
    near = [demos.chunk(f, 1)[0][0] for f in demos.nearest((0.0, 0.23))]
    rows = [('10 demo frames', near)]
    for label, choose in [('average', average_policy(demos)), ('sample', chunk_policy(demos, 1, rng)),
                          ('diffusion', diffusion_policy(demos, 1, rng))]:
        rows.append((label, [choose((0.0, 0.23), 0)[0][0] for _ in range(200)]))
    for label, dx in rows:
        bins = [sum(1 for v in dx if lo <= v < hi or (hi == edges[-1] and v == hi)) for lo, hi in zip(edges, edges[1:])]
        print(f'  {label:<14}' + ''.join(f'{c:>9}' for c in bins))

    print('\nRollouts: 100 each with 0.5 cm actuator noise, same seed for every policy')
    evaluate('average', lambda r: average_policy(demos))
    evaluate('sample', lambda r: chunk_policy(demos, 1, r))
    for n in (4, 8, 16):
        evaluate(f'chunk {n}', lambda r, n=n: chunk_policy(demos, n, r))
    evaluate('diffusion 1', lambda r: diffusion_policy(demos, 1, r))
    evaluate('diffusion 8', lambda r: diffusion_policy(demos, 8, r))


if __name__ == '__main__':
    main()
```

A third of the averaged runs drive into the block. The remaining runs succeed because noise or a lopsided set of neighbours pushes them far enough to one side that all 10 nearest frames come from the same side; from then on the average and the demonstrations agree. Sampling commits to a side at the fork and succeeds 99 times out of 100. Nothing about the data changed; only the way the policy turns 10 recorded actions into one.

This is the same failure you will see on a real arm as a gripper that stops at an intermediate pose halfway between two grasps, or a mobile robot that drives at the middle of a pillar it was taught to go around. If your demonstrations contain more than one way to do the task, the policy class has to be able to represent more than one answer.

## Action chunks: what ACT adds

ACT (Action Chunking with Transformers, from the ALOHA bimanual robot work; Zhao et al., arXiv:2304.13705) predicts the next k actions at once, k = 100 at 50 Hz in the paper, which is 2 seconds. Chunking helps in three ways. The policy makes k times fewer decisions, so the effective horizon shrinks by k and a one-step prediction error has fewer closed-loop steps in which to push the state off the demonstration distribution (§IV-A). A chunk is internally consistent: it cannot switch from "go left" to "go right" halfway through. And it copes with demonstrations in which the observation does not say what comes next, such as a person pausing before they act, because the chunk carries the timing. To keep motion smooth, ACT queries the policy every step rather than once per chunk. At timestep t every past prediction that covers t is kept in a FIFO; those predictions are combined with exponential weights w_i = exp(−m · i), where i = 0 is the oldest prediction for that same timestep and m (the paper's ensembling weight) sets how fast newer observations take over. The executed action is the normalised weighted sum (Algorithm 2). That is temporal ensembling: it averages several forecasts of one time index, not neighbouring times, so it does not add the lag of ordinary smoothing.

Chunks have a cost, and the toy model shows it clearly. Between decisions the chunk plays **open loop**:

## Diffusion policy

A diffusion model generates a sample by starting from pure Gaussian noise and removing noise in many small steps. Training adds noise to a recorded action chunk, x_s = √ᾱ_s x_0 + √(1 − ᾱ_s) ε, and teaches a network to predict the noise ε (equivalently the clean chunk x_0) from x_s, the step s and the observation. Sampling runs that the other way: from noise, predict x_0, step to a slightly less noisy x, repeat. Because each sample starts from different noise, the result lands in one mode or another; it does not average them. Diffusion Policy (Chi et al.) predicts chunks of 16 actions this way and executes the first 8 before planning again.

<Formula label="Forward noising, step s">x_s = √ᾱ_s · x_0 + √(1 − ᾱ_s) · ε,   ε ~ N(0, I)</Formula>

The model here skips the network. For a fixed set of data points, the best possible prediction of x_0 from x_s has a closed form: a weighted average of the data points, each weighted by how likely it is to have produced x_s. With the forward process x_s = √ᾱ_s x_0 + √(1 − ᾱ_s) ε, that weight is the Gaussian density of the current noisy chunk under each demo chunk d as x_0: w_d ∝ exp(−‖x_s − √ᾱ_s d‖² / (2(1 − ᾱ_s))), which is exactly what `diffusion_policy` computes. Early in denoising the weights are spread across the 10 points; as ᾱ_s → 1 and the residual noise shrinks, one weight dominates, so the sampler converges onto one of those 10 memorised chunks rather than an average of them. That is the function the network is trained towards, so the program runs a real 20-step DDPM sampler with this perfect denoiser for the 10 nearest frames:

A trained network is not perfect, and that is useful: it smooths between demonstrations and produces chunks no single demonstration contained but which still lie in one mode. Its costs are inference time (several denoising passes through a network for each chunk) and a lot of training compute, which is why diffusion and ACT training runs take hours on a GPU while the policies in this lesson take two seconds on a laptop.

## Common mistakes

- **Averaging over modes without noticing.** If a policy moves gradually towards the middle of two options, or stalls between them, check whether your demonstrations contain two ways of doing the task. Either demonstrate one way consistently or use a policy that can sample.
- **Thinking chunking is free.** A chunk runs open loop until the next decision. Tight clearances, a moving object or a slipping grasp need the policy to look again sooner; tune how many actions to execute per decision and measure it.
- **Comparing policies on different data or seeds.** Every line above uses the same 40 demonstrations, the same seed and the same number of runs. Lesson 4 goes one step further and gives every run its own seed, so that each policy meets exactly the same starting conditions; on hardware, that means the same list of start positions for every policy.
- **Calling a memorising policy a good one.** The diffusion policy here can only replay demonstrations. Test on start positions that are not in the dataset before claiming a policy generalises.
- **Mixing up training and inference cost.** A diffusion policy needs several network passes per chunk, so check that inference keeps up with your control rate on the computer that will run it, not only on the training GPU.

## Two hands on one shared task
A policy can represent multimodal actions yet still coordinate two hands poorly. Add a separate **synthetic kinematic shared-strap transport**: two1D fingertip carriages move the endpoints of one compliant strap to a target center while keeping nominal span **0.6 m**. This is not a rigid-body/payload/force simulation; span error is a **kinematic compliance proxy**, not physical strain or force. It is not the ORCA-lite fleet corridor and does not redo ACT chunk mathematics. Units/clearances/controller gains below are synthetic, not robot specifications.

### Equal available information, different coupling

Every tick, **both arms in every mode RECEIVE the full same schema** `(noisy xL,xR,vL,vR,goalL,goalR,span)`. No mode gets clean state, latent actuator gains or future noise. Each seed has the same initial object/endpoints, target, hidden actuator gains and exogenous sensor/disturbance stream for all modes. Realized state trajectories differ because controls differ; common random numbers do not mean the different trajectories have identical observations.

| mode | left arm observes / uses | right arm observes / uses |
|---|---|---|
| independent | observes full snapshot; deliberately uses only own position and goal | observes full snapshot; deliberately uses only own position and goal |
| leader-follower | observes full snapshot; goal feedback, waits when measured span is more than0.06 m short | observes full snapshot; follows measured left position + nominal span, with measured left velocity feedforward |
| joint | observes full snapshot; shared center error + span correction | observes full snapshot; shared center error − span correction |

Thus independent is a **factorized control law**, not a local-sensors-only arm compared against an all-seeing centralized oracle. Coupling/coordination is the changed factor; all available observation fields and physical action budgets are equal. Controllers are fixed analytic laws, not learned TwinVLA heads. Independent uses gain2 on endpoint error; leader uses the same gain2 plus its wait gate/follower feedforward; joint uses center gain2 and span gain5. Position-feedback gains have units s⁻¹. These declared design choices are not universally optimized or tuned on these evaluation seeds.

Use all five seeds **11/23/37/53/71**, initial center±0.05 m and span0.6±0.02 m, transport distance **0.75–0.9 m**. Left response gain0.9–1.0, right0.55–0.8 models an asymmetric plant, shared across methods and not revealed to any controller. Independent Gaussian sensor noise is σ=**0.003 m /0.01 m/s**, velocity disturbance σ=**0.006 m/s**. Plant acceleration and speed are clipped identically to **0.8 m/s² /0.35 m/s**. Every mode executes **400 ticks ×0.02 s =8 s**, including after first arrival: **800 endpoint commands** per run, not early-exit budget savings.

### Define metrics before comparing

The **score-only true-state** observer marks arrival after **20 consecutive** ticks with both endpoint goal errors≤**0.025 m** and span error≤**0.04 m**; controllers/gates only see the noisy snapshot. A collision event is entry into `abs(xR−xL)<0.32 m`, a synthetic fingertip exclusion-distance model; consecutive colliding ticks count once. Success requires arrival by8 s **and zero collision events**. Report collision events, success, minimum signed separation and span RMSE over the **whole horizon**. A timeout receives **8 s capped makespan**, with timeout count explicitly shown: this is not an uncensored mean of arrival times.

| mode | success | collision events mean±sd | capped makespan s mean±sd | timeouts | span RMSE m mean±sd | minimum separation m mean±sd |
|---|---|---|---|---|---|---|
| independent | 5/5 | 0±0 | 4.412000±0.378545 | 0/5 | 0.058698±0.015830 | 0.453802±0.031727 |
| leader-follower | 5/5 | 0±0 | 4.544000±0.442249 | 0/5 | 0.034967±0.003394 | 0.534073±0.001564 |

SD is population sd across all five seeds. Here **all modes succeed without collision**; the experiment does not manufacture an independent-arm failure. Joint has the lowest mean makespan here, leader-follower the smallest mean span RMSE, and independent still reaches every goal. A different load, delay, tolerance, task or gain setting can change these trade-offs. No presumed winner or hardware safety claim follows from five cases. The independent regression includes a separately labelled unreachable-goal unit test to verify timeout accounting, not an extra selected benchmark seed.

### Reading: what TwinVLA actually composes

Im et al., [TwinVLA](https://arxiv.org/abs/2511.05275), describes two arm-specific branches initialized from a pretrained SingleVLA: **duplicate the VLM backbone**, share the **vision encoder and DiT action head**, and retain **per-arm proprioception encoders**. Joint attention concatenates Q/K/V across streams and splits outputs back into arm-specific streams, with a causal cross-arm mask. Shared language/ego-view tokens are processed as a single sequence using **MoE routing between the arm FFN experts**, rather than blindly duplicating shared-input processing. This is a modular learned architecture, not our center/span law. It avoids bimanual **pretraining** in that setup but still uses bimanual demonstrations for fine-tuning; it is not a claim of zero-shot coordination from copying weights alone. #!/usr/bin/env python3
```python
"""Synthetic two-endpoint shared-strap transport, not TwinVLA inference.
All modes/arms RECEIVE (noisy xL,xR,vL,vR,goalL,goalR,span) every tick.
Independent deliberately factorizes local feedback, not local-only sensor access.
Leader-follower uses left velocity/position and a left waiting gate; joint uses
center/span feedback. No controller receives latent actuator gain or future noise.
Each mode runs all400 ticks, including after first arrival, with same plant/noise.
Span error is a kinematic compliance proxy, NOT a force/strain dynamics model.
"""
from math import sqrt
from random import Random
from statistics import mean, pstdev

SEEDS=(11,23,37,53,71)
MODES=('independent','leader_follower','joint')
TICKS, DT, VMAX, AMAX=400,.02,.35,.8
SPAN, COLLISION_DISTANCE=.6,.32


def clip(x,bound):return max(-bound,min(bound,x))


def make_case(seed):
    r=Random(seed);center=r.uniform(-.05,.05);span=SPAN+r.uniform(-.02,.02)
    start=(center-span/2,center+span/2);goal=center+r.uniform(.75,.9)
    gains=(r.uniform(.9,1.),r.uniform(.55,.8))
    # All modes share this exogenous sensor/disturbance stream, not their resulting states.
    stream=tuple((tuple(r.gauss(0,.003) for _ in range(2)),tuple(r.gauss(0,.01) for _ in range(2)),tuple(r.gauss(0,.006) for _ in range(2))) for _ in range(TICKS))
    return start,(goal-SPAN/2,goal+SPAN/2),gains,stream


def commands(observation,mode):
    left,right,vl,vr,gl,gr,span=observation
    if mode=='independent':return (2*(gl-left),2*(gr-right))
    if mode=='leader_follower':
        lead=2*(gl-left)
        if right-left<span-.06:lead=0. # Wait for follower, using the SAME noisy snapshot.
        return lead,2*(left+span-right)+vl
    center_error=(gl+gr-left-right)/2
    span_error=right-left-span
    common=2*center_error
    return common+5*span_error,common-5*span_error


def rollout(case,mode):
    start,goal,gains,stream=case;x=list(start);v=[0.,0.]
    stable=0;arrival=None;collisions=0;was_colliding=False;span_errors=[];min_sep=float('inf')
    for tick,(position_noise,velocity_noise,disturbance) in enumerate(stream):
        obs=(*tuple(a+b for a,b in zip(x,position_noise)),*tuple(a+b for a,b in zip(v,velocity_noise)),*goal,SPAN)
        command=commands(obs,mode)
        for j in range(2):
            desired=gains[j]*clip(command[j],VMAX)+disturbance[j]
            v[j]=clip(v[j]+clip(desired-v[j],AMAX*DT),VMAX)
            x[j]+=v[j]*DT
        separation=x[1]-x[0];min_sep=min(min_sep,separation)
        colliding=abs(separation)<COLLISION_DISTANCE
        collisions+=int(colliding and not was_colliding);was_colliding=colliding
        span_errors.append((separation-SPAN)**2)
        # Truth is a SCORE ONLY observer, not used by commands or its wait gate.
        settled=max(abs(a-b) for a,b in zip(x,goal))<=.025 and abs(separation-SPAN)<=.04
        stable=stable+1 if settled else 0
        if stable>=20 and arrival is None:arrival=(tick+1)*DT
    return {'success':int(arrival is not None and collisions==0),'collisions':collisions,
            'capped_makespan':arrival if arrival is not None else TICKS*DT,'timeout':int(arrival is None),
            'span_rmse':sqrt(mean(span_errors)),'min_separation':min_sep,'ticks':len(stream)}


def main():
    print('Synthetic shared-strap transport; seeds=11/23/37/53/71; no payload/force dynamics')
    print('all arms/modes RECEIVE same noisy xL,xR,vL,vR,goalL,goalR,span; no latent gain/future noise')
    print('independent: each uses own target/state; leader_follower: left gate + right follows measured left; joint: center/span')
    print('equal400 ticks after arrival too; dt=0.02s vmax=0.35m/s amax=0.8m/s2; same gain/noise stream per seed')
    print('arrival=20 consecutive settled ticks; score-only endpoints<=0.025m span_error<=0.04m')
    print('collision event=entry into distance<0.32m; success requires arrival AND zero collision events')
    print('mode success/5 collision_events_mean_sd capped_makespan_s_mean_sd timeouts/5 span_RMSE_m_mean_sd minimum_separation_m_mean_sd')
    cases=tuple(make_case(seed) for seed in SEEDS)
    for mode in MODES:
        rows=[rollout(case,mode) for case in cases]
        def report(key):
            values=[r[key] for r in rows];return f'{mean(values):.6f} {pstdev(values):.6f}'
        print(f'{mode} {sum(r["success"] for r in rows)}/5 {report("collisions")} {report("capped_makespan")} {sum(r["timeout"] for r in rows)}/5 {report("span_rmse")} {report("min_separation")}')
    print('Population sd; censored makespan uses8s at timeout, not an uncensored arrival-time mean')
    print('No presumed mode winner; independent available information equals joint, only coupling differs')
    print('Not ORCA-lite fleet / ACT chunk math; TwinVLA real robots/weights: 本页未运行; figures 以论文为准')


if __name__=='__main__':main()
```

**Sources actually opened (abs + HTML + PDF via pdftotext).** Qixiu Li et al., *CogACT: A Foundational Vision-Language-Action Model for Synergizing Cognition and Action in Robotic Manipulation*, arXiv:2411.19650. Body-verified: componentized VLM → specialized action module; MLP depths vs DiT-style diffusion action heads; paper **Adaptive Action Ensemble (AAE)** for inference-time trajectory ensemble (**以论文为准**). Paper success rates **以论文为准**. Real CogACT weights / GPU training **本页未运行**.

This section is **not** OpenHelix dual-system, **not** VQ-BeT, and **not** RDT2. It deepens the ACT / diffusion lesson with a **synthetic** cognition→action stand-in.

### Model assumptions

- Features are a fixed **VLM-like cognition vector** (stdlib features of the demo state). There is no transformer VLM on this page.
- Arm **A** (`A_mlp_head`): ridge-linear map from features → action (MLP-head stand-in).
- Arm **B** (`B_dit_denoiser`): pairwise feature expansion + a few iterative refine steps (DiT-style **expressivity** stand-in — **not** a real Diffusion Transformer, attention, or noise schedule).
- Arm **C** (`C_quant_tokens`): same linear map after discrete bins (OpenVLA-style quantization floor).
- With **multimodal** actions, plain MSE regression averages the modes (**mode averaging**); a specialized / diffusion-style head can keep modes apart — that is why `multimodal_long` can favor B.
- **Common random numbers:** one seed draws one shared demo/noise tape; A/B/C see identical inputs. Metric: action MSE and a success proxy. Success proxy is **blind** to wall-clock GPU time and to real DiT NFE cost.

### Fair setup

Shared demos, shared feature noise, shared step/budget constants, five seeds. This page does not declare a universal winner: the **unimodal_short** regime is a **near-tie / small gap** (printed |MSE_A−MSE_B|=0.0001; raw ≈5.9e-5) — short-horizon unimodal is easy for both heads; the residual gap comes from ridge regularization and noise, not an exact tie. **multimodal_long** is where specialized expressivity can help. Quantization pays a real floor.

```python
#!/usr/bin/env python3
"""Synthetic CogACT-style cognition→action literacy toy. Stdlib only.

Shared demo features / chunk / noise for every arm (common random numbers per
seed). Every arm faces the **same** noise sources and demos.

Arms (equal demo budget; ≠ OpenHelix / VQ-BeT / RDT2 / ACT-CVAE):
  A_mlp_head       ridge-linear cognition→action (shallow MLP stand-in)
  B_dit_denoiser   ridge on expanded features + iterative refine (DiT-style stand-in)
  C_quant_tokens   ridge-linear on quantized action tokens (OpenVLA-style)

Regimes (≥5 seeds):
  unimodal_short   — |MSE_A−MSE_B| small → **near-tie / small gap** (not exact; ridge+noise)
  multimodal_long  — expanded/DiT-style **wins** on action MSE

Assumptions: CPU stand-in of CogACT componentized VLM→specialized action module
(Qixiu Li et al., arXiv:2411.19650; abs+HTML+PDF read). B's "DiT-style" is an
expressivity stand-in (pairwise feature interactions + iterative refine), not a
real transformer weight stack. Paper SIMPLER/real % 以论文为准; GPU/weights
本页未运行.
"""
from __future__ import annotations

import math
import random

SEEDS = (0, 1, 2, 3, 4)
ARMS = ("A_mlp_head", "B_dit_denoiser", "C_quant_tokens")
FEAT_DIM = 6
ACT_DIM = 3
DIT_ITERS = 4
N_BINS = 10
RIDGE = 1e-2
REGIMES = (
    ("unimodal_short", 40, 2, 1, 0.03),
    ("multimodal_long", 40, 12, 4, 0.03),
)


def shared_demo_pack(seed: int, n_demos: int, chunk: int, n_modes: int, noise_std: float):
    rng = random.Random(30_000 + seed)
    feats, acts, noises = [], [], []
    for i in range(n_demos):
        mode = i % n_modes
        f = [0.0] * FEAT_DIM
        f[mode % FEAT_DIM] = 1.0
        f[-1] = mode / max(1.0, float(n_modes - 1))
        for k in range(FEAT_DIM):
            f[k] += 0.04 * rng.gauss(0.0, 1.0)
        a = []
        for t in range(chunk):
            u = t / max(1, chunk - 1)
            for d in range(ACT_DIM):
                val = (
                    0.5 * f[-1]
                    + 0.55 * math.sin(2.4 * u + 0.8 * d + 1.2 * mode)
                    + 0.4 * (mode + 1) * u * u * math.cos(0.6 * d + mode)
                )
                a.append(val)
        n = [rng.gauss(0.0, noise_std) for _ in range(chunk * ACT_DIM)]
        feats.append(f)
        acts.append(a)
        noises.append(n)
    return feats, acts, noises


def expand_dit(feat: list[float]) -> list[float]:
    """Expressivity stand-in: raw feat + pairwise products (DiT capacity proxy)."""
    out = list(feat)
    for i in range(len(feat)):
        for j in range(i, len(feat)):
            out.append(feat[i] * feat[j])
    return out


def ridge_fit(X: list[list[float]], Y: list[list[float]], lam: float = RIDGE):
    """Return W (out_dim x in_dim), b (out_dim) via normal equations on centered data."""
    n = len(X)
    d = len(X[0])
    o = len(Y[0])
    mean_x = [sum(X[i][k] for i in range(n)) / n for k in range(d)]
    mean_y = [sum(Y[i][j] for i in range(n)) / n for j in range(o)]
    # XtX, XtY
    XtX = [[0.0] * d for _ in range(d)]
    XtY = [[0.0] * o for _ in range(d)]
    for i in range(n):
        xc = [X[i][k] - mean_x[k] for k in range(d)]
        yc = [Y[i][j] - mean_y[j] for j in range(o)]
        for a in range(d):
            for b in range(d):
                XtX[a][b] += xc[a] * xc[b]
            for j in range(o):
                XtY[a][j] += xc[a] * yc[j]
    for a in range(d):
        XtX[a][a] += lam * n
    # Solve XtX W[:,j] = XtY[:,j] via Gauss-Jordan on copy per column is heavy;
    # use Gauss-Jordan once for all RHS.
    M = [XtX[r][:] + XtY[r][:] for r in range(d)]
    for col in range(d):
        piv = max(range(col, d), key=lambda r: abs(M[r][col]))
        M[col], M[piv] = M[piv], M[col]
        div = M[col][col]
        if abs(div) < 1e-12:
            continue
        for j in range(col, d + o):
            M[col][j] /= div
        for r in range(d):
            if r == col:
                continue
            fac = M[r][col]
            for j in range(col, d + o):
                M[r][j] -= fac * M[col][j]
    W = [[M[k][d + j] for k in range(d)] for j in range(o)]  # W[j][k]
    # b = mean_y - W mean_x
    b = []
    for j in range(o):
        b.append(mean_y[j] - sum(W[j][k] * mean_x[k] for k in range(d)))
    return W, b


def predict_linear(feat, W, b):
    return [b[j] + sum(W[j][k] * feat[k] for k in range(len(feat))) for j in range(len(b))]


def quantize(a):
    lo, hi = -1.5, 2.0
    out = []
    for x in a:
        u = (x - lo) / (hi - lo)
        u = 0.0 if u < 0.0 else (1.0 if u > 1.0 else u)
        idx = min(N_BINS - 1, int(u * N_BINS))
        out.append(lo + (idx + 0.5) * (hi - lo) / N_BINS)
    return out


def fit_arm(arm, feats, acts, noises):
    Y = [[acts[i][j] + noises[i][j] for j in range(len(acts[i]))] for i in range(len(acts))]
    if arm == "A_mlp_head":
        X = [f[:] for f in feats]
        W, b = ridge_fit(X, Y)
        return ("lin", W, b)
    if arm == "C_quant_tokens":
        Yq = [quantize(y) for y in Y]
        X = [f[:] for f in feats]
        W, b = ridge_fit(X, Yq)
        return ("quant", W, b)
    # DiT-style: expanded features
    X = [expand_dit(f) for f in feats]
    W, b = ridge_fit(X, Y)
    return ("dit", W, b)


def predict(params, feat):
    kind, W, b = params
    if kind == "dit":
        x0 = predict_linear(expand_dit(feat), W, b)
        # Iterative refine toward the same head (idempotent attractor)
        x = [0.0] * len(x0)
        for s in range(DIT_ITERS):
            alpha = 1.0 / (DIT_ITERS - s)
            x = [x[j] + alpha * (x0[j] - x[j]) for j in range(len(x))]
        return x
    pred = predict_linear(feat, W, b)
    if kind == "quant":
        return quantize(pred)
    return pred


def mse(a, b):
    return sum((x - y) ** 2 for x, y in zip(a, b)) / len(a)


def mean_sd(xs):
    n = len(xs)
    mu = sum(xs) / n
    return mu, math.sqrt(sum((x - mu) ** 2 for x in xs) / (n - 1))


def main():
    print(
        "Synthetic CogACT-style cognition→action toy; shared demos/noise/budget; "
        "not OpenHelix/VQ-BeT/RDT2"
    )
    print(
        f"FEAT_DIM={FEAT_DIM} ACT_DIM={ACT_DIM} DIT_ITERS={DIT_ITERS} "
        f"N_BINS={N_BINS} RIDGE={RIDGE} seeds={len(SEEDS)}"
    )
    print(
        "model: componentized VLM-like features → specialized action module "
        "(Qixiu Li et al. arXiv:2411.19650); A=ridge-linear; "
        "B=pairwise-expanded+iterative DiT-style stand-in; C=quantized tokens; "
        "paper % 以论文为准; GPU/weights 本页未运行"
    )
    print("regime arm action_mse success_proxy (mean+-sd over seeds)")
    summary = {}
    for regime, n_demos, chunk, n_modes, noise_std in REGIMES:
        thresh = 0.02 if regime == "unimodal_short" else 0.08
        packs = {s: shared_demo_pack(s, n_demos, chunk, n_modes, noise_std) for s in SEEDS}
        for arm in ARMS:
            mses, succs = [], []
            for seed in SEEDS:
                feats, acts, noises = packs[seed]
                params = fit_arm(arm, feats, acts, noises)
                ms, ss = [], []
                for i in range(len(feats)):
                    pred = predict(params, feats[i])
                    m = mse(pred, acts[i])
                    ms.append(m)
                    ss.append(1.0 if m < thresh else 0.0)
                mses.append(sum(ms) / len(ms))
                succs.append(sum(ss) / len(ss))
            mm, sm = mean_sd(mses)
            ms_, ss_ = mean_sd(succs)
            summary[(regime, arm)] = (mm, ms_)
            print(f"{regime} {arm} {mm:.4f}+-{sm:.4f} {ms_:.4f}+-{ss_:.4f}")

    ua, ub = summary[("unimodal_short", "A_mlp_head")][0], summary[("unimodal_short", "B_dit_denoiser")][0]
    gap = abs(ua - ub)
    # Means are NOT identical (raw gap ~5.9e-5 → 0.0001 at 4 decimals). Never call this an exact tie.
    lab = (
        "near-tie / small gap; residual from ridge regularization and noise; "
        "short-horizon unimodal is easy for both"
    )
    print(f"unimodal_short: |MSE_A − MSE_B| = {gap:.4f} ({lab})")
    ma, mb = summary[("multimodal_long", "A_mlp_head")][0], summary[("multimodal_long", "B_dit_denoiser")][0]
    mc = summary[("multimodal_long", "C_quant_tokens")][0]
    print(
        f"multimodal_long: MSE_A − MSE_B = {ma - mb:.4f} "
        f"(DiT-style expressivity wins on longer multimodal chunks; C_quant={mc:.4f})"
    )
    print(
        "No winner declared: unimodal short-horizon can make MLP match DiT-style; "
        "multimodal long-chunk is where specialized expressivity helps; "
        "quantization floor is a real OpenVLA-style cost"
    )
    print(
        "Real CogACT / VLA GPU lab: 本页未运行; Qixiu Li et al. arXiv:2411.19650 以论文为准"
    )


if __name__ == "__main__":
    main()
```
