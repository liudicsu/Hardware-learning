Every month so far, you wrote the controller: a PID loop, an LQR gain, a MoveIt goal. Imitation learning (also called learning from demonstration) turns that around. You show the robot the task a few dozen times, usually by moving a leader arm while the follower arm copies it, and a program learns a **policy**, a function from what the robot observes to what it should do next. This lesson builds the simplest version, behaviour cloning, on a toy task where every number can be checked, and shows the failure that every learned policy has to deal with: once the robot drifts into a state the demonstrations never visited, it has no learned action for that state.

## Demonstrations are a table

A demonstration dataset is just a table with one row per control step (a **frame**). Each row stores which episode it belongs to, its position in that episode, what the robot observed and what action the operator took. LeRobot, the library you met in Month 3 with the SO-101, stores exactly these columns (`episode_index`, `frame_index`, `observation.state`, `action`, plus camera images and a task string). On an SO-101 the state is six joint positions and the action is the six joint positions the leader arm asked for, recorded at 30 frames per second.

Behaviour cloning (BC) treats this table as an ordinary supervised learning problem: inputs are the observations, labels are the actions, fit a function, done. Nothing in the training step knows that the rows came from a robot moving through time. That is both why BC is so easy to start with and why it fails in a specific way.

<Formula label="Behaviour cloning">policy = argmin over π of Σ over frames ‖π(observation) − action‖²</Formula>

## The corridor task

The model in this lesson is a point gripper in an L-shaped corridor 0.2 m wide: from (0, 0) along x to the corner at (1, 0), then along y to the goal at (1, 1). Each step the policy commands a move of at most 0.05 m, and the gripper moves by that **plus actuator noise** of 1 cm per axis (servos never land exactly where they were told). An episode succeeds when the gripper is within 5 cm of the goal inside 80 steps without touching a wall.

The expert is a scripted controller that always aims at a point 0.15 m ahead on the centre line; in a real system the corresponding demonstrations would be recorded by you moving the leader arm. In this lesson's model the demonstrations are recorded with no actuator noise, so the frames stay on the centre line and contain no recovery actions. The policy is the simplest possible learner: 1-nearest-neighbour BC, which finds the recorded frame whose observation is closest to the current one and replays its action. A neural network trained with the squared-loss formula above predicts the conditional mean of the actions at each observation. Along the corridor the demonstrations are locally unimodal — one action per place on the centre line — so that mean coincides with the action of the nearest recorded frame, the same decision 1-NN makes. Away from the data both extrapolate without recovery labels, which is the failure this lesson measures.

```python
"""bc_reach.py: behaviour cloning, covariate shift and DAgger on a point gripper in an L-shaped corridor.

The gripper moves in a plane (metres). The corridor runs from START (0, 0) along +x to the corner (1, 0),
then along +y to GOAL (1, 1); it is 0.2 m wide (walls 0.1 m either side of the centre line). Each step the
policy commands a displacement (dx, dy) of at most 0.05 m; the gripper moves by that plus actuator noise
(Gaussian, 0.01 m per axis). Success: within 0.05 m of GOAL inside 80 steps without touching a wall.

The expert is a scripted controller (pure pursuit of a point 0.15 m ahead on the centre line). Demonstrations
are recorded like a teleoperated dataset: one row per frame with episode_index, frame_index, the observation
(x, y) and the action (dx, dy). The learned policy is 1-nearest-neighbour behaviour cloning: look up the
recorded frame whose (x, y) is closest and replay its action. Standard library only, fixed seeds.
usage: python3 bc_reach.py [demos.csv]      (writes the 20-demo dataset to demos.csv if a name is given)
"""
import math
import random
import sys

START, CORNER, GOAL = (0.0, 0.0), (1.0, 0.0), (1.0, 1.0)
HALF_WIDTH, STEP, NOISE, MAX_STEPS = 0.10, 0.05, 0.01, 80


def path_s(p):
    """Distance along the centre line of the point on it nearest p, and p's distance from the line."""
    x, y = p
    cx = min(max(x, 0.0), 1.0)                       # nearest point on the first leg, (cx, 0)
    cy = min(max(y, 0.0), 1.0)                       # nearest point on the second leg, (1, cy)
    d1, d2 = math.hypot(x - cx, y), math.hypot(x - 1.0, y - cy)
    return (cx, d1) if d1 < d2 else (1.0 + cy, d2)


def point_at(s):
    s = min(max(s, 0.0), 2.0)
    return (s, 0.0) if s <= 1.0 else (1.0, s - 1.0)


def in_corridor(p):
    x, y = p
    leg1 = -0.1 <= x <= 1.0 + HALF_WIDTH and abs(y) <= HALF_WIDTH
    leg2 = abs(x - 1.0) <= HALF_WIDTH and -HALF_WIDTH <= y <= 1.0 + HALF_WIDTH
    return leg1 or leg2


def expert(p):
    """Pure pursuit: aim at the centre-line point 0.15 m ahead of where we are, at most STEP per step."""
    s, _ = path_s(p)
    tx, ty = point_at(s + 0.15) if s < 1.85 else GOAL
    dx, dy = tx - p[0], ty - p[1]
    d = math.hypot(dx, dy)
    k = min(1.0, STEP / d) if d > 0 else 0.0
    return dx * k, dy * k


def rollout(policy, rng, noise=NOISE, record=None):
    """Run one episode. Returns (result, steps, worst distance from the centre line, final position)."""
    p = (START[0] + rng.uniform(-0.03, 0.03), START[1] + rng.uniform(-0.03, 0.03))
    worst = 0.0
    for t in range(MAX_STEPS):
        a = policy(p)
        if record is not None:
            record.append((t, p, a))
        p = (p[0] + a[0] + rng.gauss(0, noise), p[1] + a[1] + rng.gauss(0, noise))
        worst = max(worst, path_s(p)[1])
        if not in_corridor(p):
            return 'wall', t + 1, worst, p
        if math.hypot(p[0] - GOAL[0], p[1] - GOAL[1]) < 0.05:
            return 'success', t + 1, worst, p
    return 'timeout', MAX_STEPS, worst, p


def record_demos(n, rng, noise=0.0):
    """Expert demonstrations; by default executed without actuator noise (a careful operator)."""
    frames = []
    for ep in range(n):
        rows = []
        rollout(expert, rng, noise=noise, record=rows)
        frames += [(ep, t, p, a) for t, p, a in rows]
    return frames


def nn_policy(frames):
    """1-nearest-neighbour behaviour cloning: replay the action of the closest recorded observation."""
    obs = [(f[2], f[3]) for f in frames]

    def policy(p):
        best = min(obs, key=lambda o: (o[0][0] - p[0]) ** 2 + (o[0][1] - p[1]) ** 2)
        return best[1]
    return policy


def place(p):
    """Where along the corridor a wall was hit."""
    s, _ = path_s(p)
    return 'leg 1' if s < 0.85 else 'corner' if s < 1.15 else 'leg 2' if s < 1.9 else 'goal end'


def evaluate(policy, seed, n=100):
    rng = random.Random(seed)
    counts = {'success': 0, 'wall': 0, 'timeout': 0}
    walls = {'leg 1': 0, 'corner': 0, 'leg 2': 0, 'goal end': 0}
    worst = []
    for _ in range(n):
        result, _, w, p = rollout(policy, rng)
        counts[result] += 1
        worst.append(w)
        if result == 'wall':
            walls[place(p)] += 1
    worst.sort()
    return counts, worst[n // 2], walls


def report(label, frames, policy):
    c, med, walls = evaluate(policy, seed=2026)
    print(f'{label:<20} {len(frames):>5} frames   success {c["success"]:>3}/100   wall {c["wall"]:>3}   '
          f'timeout {c["timeout"]:>3}   median worst offset {med * 100:.1f} cm')
    if c['wall']:
        print(' ' * 21 + 'wall hits at: ' + ', '.join(f'{k} {v}' for k, v in walls.items()))


def main():
    rng = random.Random(6)
    demos = record_demos(80, rng)
    print('Recorded 80 expert demos (no actuator noise), first frames of episode 0:')
    print('episode_index frame_index  observation.state   action')
    for ep, t, p, a in demos[:3]:
        print(f'{ep:>13} {t:>11}  ({p[0]:+.3f}, {p[1]:+.3f})  ({a[0]:+.3f}, {a[1]:+.3f})')
    lengths = {}
    for ep, *_ in demos:
        lengths[ep] = lengths.get(ep, 0) + 1
    print(f'episode length: {min(lengths.values())} to {max(lengths.values())} frames')
    if len(sys.argv) > 1:
        with open(sys.argv[1], 'w') as f:
            f.write('episode_index,frame_index,x,y,dx,dy\n')
            for ep, t, p, a in demos:
                if ep < 20:
                    f.write(f'{ep},{t},{p[0]:.4f},{p[1]:.4f},{a[0]:.4f},{a[1]:.4f}\n')
        print(f'wrote the first 20 episodes to {sys.argv[1]}')

    print('\nEvaluation: 100 rollouts each, actuator noise 1 cm per step, same seed for every policy')
    report('expert', [], expert)
    for n in (5, 20, 80):
        frames = [f for f in demos if f[0] < n]
        report(f'BC, {n} demos', frames, nn_policy(frames))
    noisy = record_demos(20, random.Random(8), noise=NOISE)      # the expert corrects its own noise
    report('BC, 20 noisy demos', noisy, nn_policy(noisy))

    print('\nDAgger: start from BC on 5 demos; each round runs the current policy 10 times with noise,')
    print('asks the expert what it would have done in every visited state, and adds those frames')
    frames = [f for f in demos if f[0] < 5]
    drng = random.Random(7)
    for k in range(1, 4):
        policy = nn_policy(frames)
        new = []
        for ep in range(10):
            rows = []
            rollout(policy, drng, record=rows)
            new += [(1000 * k + ep, t, p, expert(p)) for t, p, _ in rows]
        frames = frames + new
        report(f'DAgger round {k}', frames, nn_policy(frames))


if __name__ == '__main__':
    main()
```

## Covariate shift

Now run every policy 100 times with the actuator noise switched on. Every policy's evaluation starts from the same random seed. Only the first run of each sees exactly the same start and noise, because policies that take different numbers of steps use up the random numbers at different rates; lesson 4 shows how to seed each run so that every policy meets identical conditions:

</SimOutput>

The expert succeeds every time; it corrects the noise because it computes its action from wherever it really is. The cloned policies fail a third of the time or more, and going from 20 to 80 demonstrations changes nothing: 67 out of 100 both times. "Median worst offset" is the median, over the 100 runs, of how far each run strayed from the centre line; the cloned policy wanders almost twice as far as the expert.

The reason is called **covariate shift**: the states the policy visits at test time are not the states it was trained on. Write one step as a recurrence: actuator noise of about 1 cm per axis moves the gripper to `p_{t+1} = p_t + a_t + ε_t`; a_t is the action of the nearest recorded frame to p_t; those frames lie on the centre line, so a_t has almost no corrective lateral component; the next state is therefore farther from the data, where the next nearest frame is still a centre-line frame. Each step repeats that map, so offset grows instead of being corrected. The noise-free demonstrations all collapse onto the centre line within a few steps, so the dataset contains almost nothing more than 3 cm off it — when noise pushes the gripper 5 cm to the side, the nearest frame still says "go straight", not "come back". Adding more demonstrations of the same kind adds more frames on the centre line, which is why 80 demos are no better than 20.

The "wall hits at" line shows where it goes wrong. Most failures are at the goal end: the demonstrations stop as soon as the expert is within 5 cm of the goal, so there is not a single frame that says what to do near the goal if you arrive a few centimetres off. The policy keeps going in +y and drives into the end wall. Real datasets have the same holes, at the moments right after the operator finished the task, and after a failed grasp, which a good operator never demonstrates.

## Two fixes: noisy demonstrations and DAgger

The cure is to put **recovery** into the data: frames from off the path, labelled with the action that brings the robot back. There are two common ways to get them.

The first is to record the demonstrations with the noise on, so the expert keeps correcting its own drift (the idea behind the DART method). On a real robot that means recording at normal speed with natural disturbances rather than slowly and perfectly, and deliberately demonstrating recoveries. The second is **DAgger** (dataset aggregation): run the current policy, let the expert label every state the policy visited with what the expert would have done there, add those frames to the dataset, retrain and repeat. This collects data exactly where the learner goes wrong. The model starts DAgger from the weakest policy, BC on 5 demos:

## Two ways round an obstacle: MSE, k-means bins and residual VQ

The corridor above had one correct action per place. Real demonstrations often have **several**: one operator goes left round the mug, another goes right. The squared-loss formula at the top of this page then predicts the **mean** of the two, which is straight into the mug. Behavior Transformers (BeT, [arXiv:2206.11251](https://arxiv.org/abs/2206.11251)) handle this by clustering actions with k-means into bins, predicting a categorical distribution over bins, and adding a continuous **offset** to the chosen bin centre. VQ-BeT ([arXiv:2403.03181](https://arxiv.org/abs/2403.03181), [project page](https://sjlee.cc/vq-bet/)) replaces k-means with **residual vector quantisation**: a first codebook quantises the action (the **primary** code, coarse clustering), a second codebook quantises what is left (the **secondary** code, fine detail), and the decoded action is the sum of the chosen vectors, again plus an offset head. The paper uses two residual layers and argues that k-means struggles to scale to high-dimensional actions or long chunks and gives no gradient. Its reports — better mode capture than BeT and Diffusion Policy, and inference about 5× faster than Diffusion Policy in simulation — are **paper claims: 以论文为准**. Nothing here measures speed.

### Fair setup

`vqbet_residual_vq_toy.py` is **synthetic** and stdlib only. A point moves along +x and must pass an obstacle box (0.40 ≤ x ≤ 0.60, |y| < 0.12) on the left or right; each demonstration picks a side with probability 0.5 and a ±20 % speed variation. The observation is a coarse bin of x (10) and of the side the point is already on (3). Every arm gets **the same 60 training demonstrations and 60 held-out ones per seed, the same observation bins, the same count-based head** (empirical frequencies per observation) and **the same rollout noise stream**:

| Arm | Action representation | Stored codebook vectors | Code combinations |
| --- | --- | --- | --- |
| `MSE` | per-observation mean action | — | — |
| `kmeans` (BeT-style) | one codebook, K = 8, + per-(observation, code) offset | 8 | 8 |
| `rvq` (VQ-BeT-style) | primary 4 + secondary 4 on the residual, + offset | 8 | 16 |

Both quantisers get 12 Lloyd iterations (`rvq` spends 6 per stage). Equal codebook size still gives `rvq` twice as many combinations, so its head and offset tables are twice as large; the program prints the parameter counts instead of hiding that. Five seeds, 100 rollouts each, mean±sd. This is not a transformer and not FAST/DCT tokenisation (6.3), diffusion (6.2) or the DAgger loop above.

### Reading the result

- **MSE averages the modes.** At the start the two sides cancel, so the mean action has almost no sideways component and 66 % of rollouts hit the obstacle; none of the five seeds ever sees both sides used.
- **Both discrete arms keep both modes.** `kmeans` and `rvq` never collide and go left about half the time (0.53 and 0.49), because sampling a code picks a side instead of averaging two.
- **Reconstruction is close.** On held-out actions `rvq` quantises slightly better (9.0e-06 vs 1.15e-05 before the offset) but its spread across seeds is larger, and the offset tables, fitted on the training demos, barely change held-out error. On this two-dimensional task with eight vectors each, k-means bins are already enough; the residual codebook's advantage in the paper is claimed for high-dimensional actions and chunks that this toy does not have.

So the lesson is the failure of the mean, not a ranking of the two discrete tokenisers. **GPU training of VQ-BeT and LeRobot runs: 本页未运行.**

```python
#!/usr/bin/env python3
"""vqbet_residual_vq_toy.py: MSE BC vs k-means bins vs residual VQ + offset (stdlib).

Synthetic two-mode demonstrations: a point moves +x through a corridor and must
pass an obstacle box (0.40 <= x <= 0.60, |y| < 0.12) either LEFT or RIGHT; each
demo picks a side with probability 0.5. Action a = (dx, dy) per step.
Observation = (x bin of 10, side bin of 3: y<-0.02 / |y|<=0.02 / y>0.02).
Every arm gets the SAME demos, the SAME observation bins and the SAME
count-based heads; only the action representation differs:
  MSE    : per-observation mean action (least squares with one-hot features)
  kmeans : one codebook of K=8 vectors (Lloyd, 12 iterations), categorical
           over codes per observation + per-(obs, code) mean offset (BeT-style)
  rvq    : residual VQ, 2 stages x 4 vectors (6 + 6 Lloyd iterations; stage 2
           quantizes stage-1 residuals), categorical over the 16 (primary,
           secondary) pairs per observation + per-(obs, pair) mean offset
Both quantizers store 8 codebook vectors and get 12 Lloyd iterations; rvq has
16 code combinations against 8, so its head and offset tables are 2x larger
(printed). Not a transformer, not a trained network, no GPU.
usage: python3 vqbet_residual_vq_toy.py
"""
from __future__ import annotations

import math
import random
import statistics

SEEDS = (0, 1, 2, 3, 4)
N_DEMOS = 60
N_ROLLOUTS = 100
STEPS = 20
DX = 0.05
OBST = (0.40, 0.60, 0.12)
NOISE = 0.004          # per-step actuator noise (demos and rollouts)
K = 8                  # k-means codebook vectors
K1, K2 = 4, 4          # residual VQ: primary and secondary codebook sizes
ITERS = 12             # Lloyd iterations per quantizer (rvq: split 6 + 6)


def obs_of(x, y):
    xb = min(9, max(0, int(x * 10)))
    sb = 0 if y < -0.02 else (2 if y > 0.02 else 1)
    return xb * 3 + sb


def demo(rng):
    side = rng.choice((-1, 1))
    x, y, rows = 0.0, rng.gauss(0, 0.005), []
    gain = 1 + 0.2 * rng.gauss(0, 1)
    for _ in range(STEPS):
        if x < 0.35:
            dy = side * 0.045 * gain
        elif x < 0.65:
            dy = 0.0
        else:
            dy = -side * 0.045 * gain
        a = (DX, dy)
        rows.append((obs_of(x, y), a))
        x += a[0] + rng.gauss(0, NOISE)
        y += a[1] + rng.gauss(0, NOISE)
    return rows


def d2(a, b):
    return (a[0] - b[0]) ** 2 + (a[1] - b[1]) ** 2


def lloyd(points, k, iters, rng):
    cents = [points[i] for i in rng.sample(range(len(points)), k)]
    for _ in range(iters):
        groups = [[] for _ in range(k)]
        for p in points:
            groups[min(range(k), key=lambda j: d2(p, cents[j]))].append(p)
        cents = [(sum(p[0] for p in g) / len(g), sum(p[1] for p in g) / len(g)) if g else cents[j]
                 for j, g in enumerate(groups)]
    return cents


def nearest(p, cents):
    return min(range(len(cents)), key=lambda j: d2(p, cents[j]))


class Quantizer:
    def __init__(self, kind, actions, rng):
        self.kind = kind
        if kind == "kmeans":
            self.books = [lloyd(actions, K, ITERS, rng)]
        else:
            b1 = lloyd(actions, K1, ITERS // 2, rng)
            res = [(a[0] - b1[nearest(a, b1)][0], a[1] - b1[nearest(a, b1)][1]) for a in actions]
            self.books = [b1, lloyd(res, K2, ITERS // 2, rng)]

    def encode(self, a):
        codes, r = [], a
        for b in self.books:
            j = nearest(r, b)
            codes.append(j)
            r = (r[0] - b[j][0], r[1] - b[j][1])
        return tuple(codes)

    def decode(self, codes):
        return (sum(b[j][0] for b, j in zip(self.books, codes)), sum(b[j][1] for b, j in zip(self.books, codes)))

    def combos(self):
        return K if self.kind == "kmeans" else K1 * K2


def fit(kind, rows, rng):
    if kind == "MSE":
        acc = {}
        for o, a in rows:
            s = acc.setdefault(o, [0.0, 0.0, 0])
            s[0] += a[0]; s[1] += a[1]; s[2] += 1
        return {"kind": kind, "mean": {o: (s[0] / s[2], s[1] / s[2]) for o, s in acc.items()}}
    q = Quantizer(kind, [a for _, a in rows], rng)
    counts, off = {}, {}
    for o, a in rows:
        c = q.encode(a)
        counts.setdefault(o, {}).setdefault(c, 0)
        counts[o][c] += 1
        dec = q.decode(c)
        s = off.setdefault((o, c), [0.0, 0.0, 0])
        s[0] += a[0] - dec[0]; s[1] += a[1] - dec[1]; s[2] += 1
    return {"kind": kind, "q": q, "counts": counts,
            "off": {k: (s[0] / s[2], s[1] / s[2]) for k, s in off.items()}}


def act(model, o, rng):
    if model["kind"] == "MSE":
        return model["mean"].get(o, (DX, 0.0))
    cs = model["counts"].get(o)
    if not cs:
        return (DX, 0.0)
    r, acc = rng.random() * sum(cs.values()), 0.0
    for c, n in sorted(cs.items()):
        acc += n
        if r < acc:
            break
    dec, of = model["q"].decode(c), model["off"][(o, c)]
    return (dec[0] + of[0], dec[1] + of[1])


def recon(model, rows):
    """Held-out demo actions: decode-only and decode+offset squared error."""
    if model["kind"] == "MSE":
        e = [d2(a, model["mean"].get(o, (DX, 0.0))) for o, a in rows]
        return statistics.mean(e), statistics.mean(e)
    q, e0, e1 = model["q"], [], []
    for o, a in rows:
        c = q.encode(a)
        dec = q.decode(c)
        of = model["off"].get((o, c), (0.0, 0.0))
        e0.append(d2(a, dec))
        e1.append(d2(a, (dec[0] + of[0], dec[1] + of[1])))
    return statistics.mean(e0), statistics.mean(e1)


def rollout(model, rng):
    x, y, hit, ymin, ymax = 0.0, rng.gauss(0, 0.005), False, 0.0, 0.0
    for _ in range(STEPS):
        a = act(model, obs_of(x, y), rng)
        x += a[0] + rng.gauss(0, NOISE)
        y += a[1] + rng.gauss(0, NOISE)
        if OBST[0] <= x <= OBST[1]:
            hit = hit or abs(y) < OBST[2]
            ymin, ymax = min(ymin, y), max(ymax, y)
    side = "L" if ymin < -OBST[2] else ("R" if ymax > OBST[2] else "-")
    return hit, side, abs(y)


def params(model):
    if model["kind"] == "MSE":
        return f"{2 * len(model['mean'])} (means)"
    q = model["q"]
    book = 2 * sum(len(b) for b in q.books)
    return f"{book} codebook + {q.combos()}x30 head + {2 * q.combos()}x30 offset"


def ms(v, f):
    return f"{statistics.mean(v):{f}}±{statistics.pstdev(v):{f}}"


def main():
    print(f"Synthetic 2-mode demos: {N_DEMOS} train + {N_DEMOS} held-out per seed, {len(SEEDS)} seeds, "
          f"{N_ROLLOUTS} rollouts/seed, obstacle x∈[{OBST[0]},{OBST[1]}] |y|<{OBST[2]}, noise {NOISE}")
    print(f"kmeans K={K}; rvq {K1}x{K2}; {ITERS} Lloyd iterations each; same heads/offset rule")
    rows_out = {}
    for kind in ("MSE", "kmeans", "rvq"):
        res = {"col": [], "left": [], "both": [], "end": [], "q": [], "qo": []}
        for seed in SEEDS:
            drng = random.Random(seed)
            train = [r for _ in range(N_DEMOS) for r in demo(drng)]
            held = [r for _ in range(N_DEMOS) for r in demo(drng)]
            model = fit(kind, train, random.Random(100 + seed))
            q0, q1 = recon(model, held)
            rrng = random.Random(200 + seed)  # same rollout stream for every arm
            outs = [rollout(model, rrng) for _ in range(N_ROLLOUTS)]
            left = sum(s == "L" for _, s, _ in outs)
            right = sum(s == "R" for _, s, _ in outs)
            res["col"].append(sum(h for h, _, _ in outs) / N_ROLLOUTS)
            res["left"].append(left / max(1, left + right))
            res["both"].append(1.0 if left and right else 0.0)
            res["end"].append(statistics.mean(e for _, _, e in outs))
            res["q"].append(q0)
            res["qo"].append(q1)
        rows_out[kind] = (res, params(model))
    print("arm collision left_share both_modes_seen quant_MSE quant+offset_MSE end_|y| params")
    for kind, (r, p) in rows_out.items():
        print(f"{kind} {ms(r['col'], '.2f')} {ms(r['left'], '.2f')} {ms(r['both'], '.1f')} "
              f"{ms(r['q'], '.2e')} {ms(r['qo'], '.2e')} {ms(r['end'], '.3f')} {p}")
    print("MSE regression has no codes: its quant columns are the regression error.")
    print("Paper speed-ups (e.g. 5x vs diffusion) are not measured here: 以论文为准. GPU training: 本页未运行.")


if __name__ == "__main__":
    main()
```

## Common mistakes

- **Recording only perfect demonstrations.** A dataset with no mistakes in it has no recoveries in it, and the policy will meet states the expert never showed it. Demonstrate the recovery from a small slip on purpose.
- **Judging a policy from one run.** One clip proves the policy *can* succeed, not how often. Use a fixed set of starting conditions and count, as the evaluation above does with 100 seeded runs; lesson 4 of this month shows how many trials you need.
- **Changing several things between runs.** The model evaluates every policy with the same seed, number of runs and noise, so that the policy is the main difference. On hardware, keep the objects, lighting and start positions fixed while you compare two policies.
- **Adding more of the same data.** If a policy fails in one place, identify where it fails (the "wall hits at" line), then record or relabel data there. 80 demos of the same thing did not beat 20.
- **Training on what the robot did instead of what was commanded.** The action column must be the command (the leader arm's joint targets), not the follower's measured position one frame later, or the policy learns to lag.
