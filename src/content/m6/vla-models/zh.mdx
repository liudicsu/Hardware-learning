前两课的策略都是针对一台机器人上的一个任务从零训练的。视觉-语言-动作模型（vision-language-action model，VLA）则从一个视觉-语言模型出发——这个网络已经在海量图像和文字上训练过——再在来自许多机器人的示范数据上继续训练，让它把一张相机图像加一句指令（比如“把红色方块放进盒子”）映射成机器人的动作。你很少需要自己从头训练一个；你下载一个，然后用几十条任务示范对它做<strong>微调</strong>（fine-tune）。本课讲动作如何进出这种模型、哪些模型真的能下载，以及它们用什么许可证。

## VLA 是什么

三个部分。<strong>视觉编码器</strong>把每张相机图像变成一串特征向量。<strong>语言模型</strong>把这些特征和分词后的指令一起读入（多数模型还会读入机器人的关节状态，送进语言模型或动作头）。<strong>动作输出</strong>把语言模型的结果变成给电机的数字。前两部分来自预训练好的视觉-语言模型（下面除 Octo 外的模型都是如此）。OpenVLA 报告，在这样的初始化之后，对机器人动作的适应主要发生在动作分词器 / 输出路径以及对机器人轨迹的微调中，而不是从零训练视觉-语言主干（Kim 等人，arXiv:2406.09246；RT-2 类似，Brohan 等人，arXiv:2307.15818）。把“主要在第三部分和微调中”当作带出处的表述，而不是本课测出的结果。

动作输出有两种做法，它们在很大程度上决定了模型的行为：

- <strong>把动作当成词元（token）。</strong>给语言模型的词表加上动作词元，让它以自回归方式逐个生成动作词元。RT-2 和 OpenVLA 是这样做的，每次调用输出一步动作（分别是 8 个和 7 个词元）；π0-FAST 也是，但它的分词器 FAST 会先把一整块动作压缩（见下文）。
- <strong>单独的动作头。</strong>把语言模型的特征送进一个较小的网络，由它通过扩散或流匹配（flow matching，与[上一课](/zh/month/month-6/act-diffusion)的扩散是近亲）生成一整块连续动作。π0、SmolVLA 和 GR00T 是这样做的。π0.5 预训练时只用 FAST 词元，后训练时加上流匹配动作专家，运行时用的就是这个动作专家。Octo 也有扩散动作头，但没有视觉-语言模型：它是一个从零训练的小型 Transformer，文字由冻结的 T5 编码器处理。

第一种做法可以原封不动地复用语言模型，但必须决定怎样把动作写成词元。这正是不用 GPU 也能运行和查看的部分。

## 把动作写成词元：256 个区间

RT-2 和 OpenVLA 给每个动作维度 256 个词元：把每个维度的范围等分成 256 个区间（bin），一个数值就变成它所在区间的编号。256 是词表预算，不是物理常数：OpenVLA 把连续动作的区间叠到 Llama 分词器词表中最少使用的 256 个词元上，从而保住预训练语言模型的文本词元（Kim 等人，arXiv:2406.09246，§3.2）。RT-2 用数据的整个 min/max 范围。OpenVLA 改用数据集的第 1 和第 99 百分位数定范围，超出的值截断到两端区间。百分位数把 256 个区间花在数据主体上；min/max 会把许多区间浪费在罕见极端值上，让普通一步更粗。本课按 OpenVLA 的做法。

<Formula label="单个动作值的区间词元">token = floor(256 × (clip(a, p1, p99) − p1) / (p99 − p1)),   from 0 to 255</Formula>

下面的程序生成一个形状类似 SO-101 遥操作的数据集：50 个回合、6 个关节目标（单位度）、30 Hz。然后用两种方法给一个新回合里 1 秒长的动作块分词：

<CodeSource path="examples/month-6/vla-models/action_tokens.py" />

```python
"""action_tokens.py: how a VLA turns robot actions into tokens, per-step bins versus a DCT of the whole chunk.

A language model outputs tokens, so an autoregressive VLA needs a way to write actions as tokens. Two schemes:
  bins  (OpenVLA): each action dimension at each step becomes one of 256 tokens, bins spread evenly
        between that dimension's 1st and 99th percentile over the dataset (RT-2 spreads them over the full range).
  DCT   (the idea behind FAST, used by pi0-FAST): normalise each dimension to -1..1 with the same percentiles,
        take a discrete cosine transform of each dimension over the chunk, multiply by a scale and round.
        Smooth motion puts almost everything into a few low-frequency coefficients; the rest round to zero.
        (FAST then compresses the integers with byte-pair encoding; this program counts nonzero coefficients.)
The actions are synthetic but shaped like a teleoperated SO-101: 6 joint targets in degrees at 30 Hz, chunks of
1 s (30 steps). Standard library only, fixed seeds.
"""
import math
import random

HZ, CHUNK, JOINTS, BINS = 30, 30, 6, 256


def episode(rng, seconds=10):
    """Smooth joint targets: a few slow sine components per joint, like a person moving a leader arm."""
    comps = [[(rng.uniform(5, 40), rng.uniform(0.1, 0.8), rng.uniform(0, 2 * math.pi)) for _ in range(3)]
             for _ in range(JOINTS)]
    offset = [rng.uniform(-30, 30) for _ in range(JOINTS)]
    return [[offset[j] + sum(a * math.sin(2 * math.pi * f * t / HZ + ph) for a, f, ph in comps[j])
             for j in range(JOINTS)] for t in range(seconds * HZ)]


def percentile(values, q):
    v = sorted(values)
    k = (len(v) - 1) * q
    lo = int(k)
    return v[lo] + (v[min(lo + 1, len(v) - 1)] - v[lo]) * (k - lo)


def to_bins(x, lo, hi):
    u = (min(max(x, lo), hi) - lo) / (hi - lo)
    return min(int(u * BINS), BINS - 1)


def from_bins(token, lo, hi):
    return lo + (token + 0.5) * (hi - lo) / BINS


def dct(x):
    """DCT-II with orthonormal scaling."""
    n = len(x)
    return [math.sqrt((1 if k == 0 else 2) / n) * sum(x[i] * math.cos(math.pi * k * (2 * i + 1) / (2 * n))
                                                      for i in range(n)) for k in range(n)]


def idct(c):
    n = len(c)
    return [sum(math.sqrt((1 if k == 0 else 2) / n) * c[k] * math.cos(math.pi * k * (2 * i + 1) / (2 * n))
                for k in range(n)) for i in range(n)]


def errors(chunk, rebuilt):
    diffs = [abs(a - b) for row, rrow in zip(chunk, rebuilt) for a, b in zip(row, rrow)]
    return math.sqrt(sum(d * d for d in diffs) / len(diffs)), max(diffs)


def main():
    rng = random.Random(6)
    data = [episode(rng) for _ in range(50)]
    lo = [percentile([s[j] for ep in data for s in ep], 0.01) for j in range(JOINTS)]
    hi = [percentile([s[j] for ep in data for s in ep], 0.99) for j in range(JOINTS)]
    print(f'Dataset: 50 episodes of 10 s, {JOINTS} joints at {HZ} Hz; 1st..99th percentile per joint (deg):')
    print('  ' + '  '.join(f'j{j} {lo[j]:+.0f}..{hi[j]:+.0f}' for j in range(JOINTS)))
    print(f'  bin width = range / {BINS}: ' + ', '.join(f'{(hi[j] - lo[j]) / BINS:.2f}' for j in range(JOINTS)) + ' deg')

    chunk = episode(random.Random(99))[:CHUNK]          # a new episode, not in the dataset
    print(f'\nOne {CHUNK}-step chunk (1 s) from a new episode: {CHUNK} x {JOINTS} = {CHUNK * JOINTS} numbers')

    tokens = [[to_bins(chunk[t][j], lo[j], hi[j]) for j in range(JOINTS)] for t in range(CHUNK)]
    rebuilt = [[from_bins(tokens[t][j], lo[j], hi[j]) for j in range(JOINTS)] for t in range(CHUNK)]
    rms, worst = errors(chunk, rebuilt)
    clipped = sum(1 for t in range(CHUNK) for j in range(JOINTS) if not lo[j] <= chunk[t][j] <= hi[j])
    print(f'bins: {CHUNK * JOINTS} tokens, error rms {rms:.3f} deg, max {worst:.3f} deg '
          f'({clipped} values outside the 1st..99th percentile, clipped)')
    print('  joint 0 tokens, first 12 steps: ' + ' '.join(str(tokens[t][0]) for t in range(12)))
    same = sum(1 for t in range(1, CHUNK) for j in range(JOINTS) if tokens[t][j] == tokens[t - 1][j])
    near = sum(1 for t in range(1, CHUNK) for j in range(JOINTS) if abs(tokens[t][j] - tokens[t - 1][j]) <= 2)
    total = (CHUNK - 1) * JOINTS
    print(f'  token equal to the previous step: {same}/{total}; within 2 of it: {near}/{total}')

    print('\nDCT of each joint over the chunk, normalised to -1..1, then scale and round:')
    norm = [[2 * (chunk[t][j] - lo[j]) / (hi[j] - lo[j]) - 1 for j in range(JOINTS)] for t in range(CHUNK)]
    coeffs = [dct([norm[t][j] for t in range(CHUNK)]) for j in range(JOINTS)]
    for scale in (5, 10, 30, 100):
        q = [[round(c * scale) for c in coeffs[j]] for j in range(JOINTS)]
        nonzero = sum(1 for j in range(JOINTS) for v in q[j] if v != 0)
        back = [idct([v / scale for v in q[j]]) for j in range(JOINTS)]
        rebuilt = [[(back[j][t] + 1) / 2 * (hi[j] - lo[j]) + lo[j] for j in range(JOINTS)] for t in range(CHUNK)]
        rms, worst = errors(chunk, rebuilt)
        print(f'  scale {scale:>3}: {nonzero:>3} nonzero coefficients of {CHUNK * JOINTS}, '
              f'error rms {rms:.3f} deg, max {worst:.3f} deg')
    q = [round(c * 10) for c in coeffs[0]]
    print('  joint 0 at scale 10: ' + ' '.join(str(v) for v in q))


if __name__ == '__main__':
    main()
```

## 用 DCT 压缩一个动作块

FAST 是 π0-FAST 背后的分词器（Pertsch 等人，arXiv:2501.09747），它一次给整个动作块分词。它用同样的百分位数把每个维度归一化到 −1..1，对每个维度在整个动作块上做离散余弦变换（discrete cosine transform，DCT），乘上一个缩放系数再取整。为什么低频占主导：遥操作的关节轨迹逐步变化很慢，用少数慢变化的余弦就能逼近；DCT 是到这组余弦上的正交换基，能量集中把大部分 ℓ₂ 质量放进前几个系数。取整会把绝对值低于 1/(2 · scale) 的系数清零——提高 scale 会保留更多小系数、降低重建误差，代价是非零序列更长（见表）。FAST 再用字节对编码（byte-pair encoding）压缩这串整数。程序用非零系数的个数来近似最终的词元数：

## SmolVLA 与异步动作块推理

SmolVLA（Shukor 等，arXiv **2506.01844**）就是上表里那个小模型。即使你不打算微调它，它的论文也有两点值得细读：它怎么做到小，以及它的**异步推理**（asynchronous inference）怎样在计算下一个动作块的同时让机械臂继续动。本节关于 SmolVLA 架构与结果的一切说法都**以论文为准**；本页没有运行权重、GPU 服务器或 SO-100 机械臂。

<Resource id="smolvla-paper" />

### SmolVLA 怎样保持小（以论文为准）

- **总参数约 450M**，其中约 100M 是动作专家（action expert）。骨干是 SmolVLM-2 视觉-语言模型，训练动作专家时 VLM 保持冻结。
- **跳过 VLM 层。** 动作专家读取中间层的特征，而不是最后一层；论文只用语言模型的前一半层（前 16 层），其余丢掉，这部分计算大约减半。
- **视觉词元少：** 只用全局图像，加 pixel shuffle，每帧 64 个视觉词元。
- **交替注意力的动作专家。** 专家的各个块在**交叉注意力**（动作词元看 VLM 特征）和**因果自注意力**（动作词元看更早的动作词元）之间交替，而不是只用一种。
- **流匹配。** 专家用<Term id="flow-matching">流匹配</Term>目标训练，输出 n = 50 个动作的动作块，推理时积分 10 步。
- **社区数据：** 预训练用了不到 30k 个回合，全部来自公开、社区贡献的 LeRobot 数据集。

### 异步推理：什么时候要下一个动作块

按块执行的策略有两种跑法。**同步**（顺序）方式下，机器人执行完整个<Term id="action-chunk">动作块</Term>，再发送观测，队列空着等推理。SmolVLA 的**异步**栈里，**RobotClient** 每个控制周期从队列弹出一个动作；当剩余比例 `|A| / n` 低于阈值 **g** 时，它采一帧新观测发给 **PolicyServer**，自己不停下。新动作块到达后，客户端在重叠的步上把它与旧块剩下的部分合并。g = 0 就是同步；g = 1 每个周期都要新块（每周期一次前向）。设推理延迟为 ℓ_S、控制周期为 Δt，论文推出队列不会被耗空的条件是

<Formula label="异步推理不空闲的条件（SmolVLA §3.3）">g ≥ (E[ℓ_S] / Δt) / n</Formula>

8.3 已经用一个异步阈值对比过同步的空闲帧。它没有讲的是：异步推理是一种**权衡**，下面的玩具测的正是这一点。它还要和两个相邻的概念分开：

| 概念 | 课 | 解决什么 |
| --- | --- | --- |
| 异步动作块推理（本节） | 6.3，以及 8.3 的循环 | 计算下一块时的空闲间隙；何时触发（g） |
| 实时动作块（RTC）软掩码 | 10.2 | 拼接处的跳变：去噪时把新块往旧块引导 |
| 传感器流的因果时间戳对齐 | 8.3 | 哪些相机/关节样本属于同一时刻，且不偷看未来 |

这里的异步**不是** RTC：玩具里的新块不以旧块为条件，也没有软掩码。它也**不是**时间戳对齐：每次请求只有一个观测，没有流匹配。

```python
#!/usr/bin/env python3
"""vla_async_chunk_toy.py: sync vs async action-chunk inference, as a tradeoff (stdlib).

SmolVLA (arXiv 2506.01844, 3.3) runs a RobotClient that pops one action per
control tick from a queue and, when the remaining fraction |A|/n drops below a
threshold g, captures an observation and asks a PolicyServer for a new chunk
without stopping. g = 0 is the sequential limit (drain, then wait), g = 1 the
compute-intensive limit (a request as soon as the last one returns).

Every arm here shares:
  - the same chunk predictor (a function of the observation only),
  - the same chunk size n and control tick dt,
  - the same latency draws l_S: the k-th request of every arm takes LAT[k],
  - the same target path (piecewise-constant velocity, seeded).
The robot tracks a moving target; a chunk is the target extrapolated from the
observation, so old observations give worse actions after a velocity change.

Metrics per arm: idle_s (ticks with an empty queue x dt), infer_calls,
underruns (separate empty-queue episodes), staleness = age of the observation
behind each executed action (mean / max, s), switches = new chunks spliced
into a non-empty queue and their mean |jump| (overlap thrash), track_rmse.
Aggregation f here: actions carry the executed-step index they belong to; on
arrival the new chunk's already-executed steps are dropped and overlapping
steps take the new value (one simple f; the paper only says "aggregate").
This is NOT 10.2 RTC (no soft mask, the new chunk is not conditioned on the
old one) and NOT 8.3 timestamp alignment of sensor streams. Async need not
win every metric. SmolVLA weights, a GPU server and an SO-100 arm are not run
on this page (本页未运行); paper latency / success numbers are 以论文为准.
usage: python3 vla_async_chunk_toy.py
"""
from __future__ import annotations

import math
import random

SEED = 1844
DT = 1 / 30             # 30 Hz control, as in the paper's real-world setting
N_CHUNK = 50            # chunk size n (the paper trains n = 50)
HORIZON = 900           # ticks = 30 s
LAT_MEAN, LAT_SD = 0.30, 0.10   # l_S in seconds (lesson-chosen, not measured)
LAT_MIN = 0.10
ARMS = (("sync", 0.0), ("async_g0.1", 0.1), ("async_g0.3", 0.3), ("async_g0.7", 0.7), ("async_g1.0", 1.0))


def target_path(rng):
    """Target position per tick: velocity changes every 1-3 s."""
    pos, vel, out, t_next = 0.0, 0.0, [], 0
    for t in range(HORIZON + N_CHUNK + 200):
        if t == t_next:
            vel = rng.uniform(-0.3, 0.3)
            t_next = t + rng.randint(30, 90)
        out.append((pos, vel))
        pos += vel * DT
    return out


def latencies(rng, k=2000):
    return [max(LAT_MIN, rng.gauss(LAT_MEAN, LAT_SD)) for _ in range(k)]


def predict_chunk(obs_step, obs_tick, path):
    """Same predictor for all arms: extrapolate the observed target n steps ahead.

    Actions are indexed by executed-step count (not wall time): a chunk from an
    observation taken after step k covers steps k+1 .. k+n.
    """
    p, v = path[obs_tick]
    return {obs_step + 1 + i: p + v * (i + 1) * DT for i in range(N_CHUNK)}


def run(g, path, lat):
    queue = predict_chunk(0, 0, path)   # initial chunk, as in Algorithm 1 line 2
    source = {k: 0 for k in queue}      # step -> wall tick of the observation behind it
    inflight = None                     # (arrival_tick, obs_step, obs_tick)
    step, calls, idle, underruns, was_empty = 0, 1, 0, 0, False
    ages, jumps, errs, held = [], [], [], 0.0
    for t in range(1, HORIZON + 1):
        if inflight and inflight[0] <= t:          # chunk arrives: aggregate f(A, A~)
            _arr, obs_step, obs_tick = inflight
            live = {k: a for k, a in predict_chunk(obs_step, obs_tick, path).items() if k > step}
            overlap = [k for k in live if k in queue]
            if overlap:
                k0 = min(overlap)
                jumps.append(abs(live[k0] - queue[k0]))
            queue.update(live)
            source.update({k: obs_tick for k in live})
            inflight = None
        if step + 1 in queue:                      # pop and execute the next step
            step += 1
            held = queue.pop(step)
            ages.append((t - source[step]) * DT)
            was_empty = False
        else:                                      # empty queue: the arm waits
            idle += 1
            underruns += not was_empty
            was_empty = True
        errs.append(held - path[t][0])
        if inflight is None and (not queue or len(queue) / N_CHUNK < g):
            inflight = (t + max(1, math.ceil(lat[calls] / DT)), step, t)
            calls += 1
    return {
        "idle_s": idle * DT, "calls": calls, "underruns": underruns,
        "age_mean": sum(ages) / len(ages), "age_max": max(ages),
        "switches": len(jumps), "jump_mean": sum(jumps) / len(jumps) if jumps else 0.0,
        "rmse": math.sqrt(sum(e * e for e in errs) / len(errs)),
    }


def main() -> None:
    path = target_path(random.Random(SEED))
    lat = latencies(random.Random(SEED + 1))
    mean_lat = sum(lat[:200]) / 200
    print(f"seed={SEED} dt={DT:.4f}s n={N_CHUNK} horizon={HORIZON * DT:.0f}s "
          f"l_S~N({LAT_MEAN},{LAT_SD}) min {LAT_MIN}s, shared draws (mean of first 200 = {mean_lat:.3f}s)")
    print(f"no-idle rule of thumb (paper 3.3): g >= E[l_S]/(n*dt) = {mean_lat / (N_CHUNK * DT):.3f}")
    print("same predictor, same n, same latency draws, same target path for every arm")
    print(f"{'arm':<11} {'g':>4} {'idle_s':>7} {'infer_calls':>11} {'underruns':>9} "
          f"{'stale_mean_s':>12} {'stale_max_s':>11} {'switches':>8} {'mean_jump':>9} {'track_rmse':>10}")
    rows = {}
    for name, g in ARMS:
        r = run(g, path, lat)
        rows[name] = r
        print(f"{name:<11} {g:4.1f} {r['idle_s']:7.2f} {r['calls']:11d} {r['underruns']:9d} "
              f"{r['age_mean']:12.3f} {r['age_max']:11.3f} {r['switches']:8d} {r['jump_mean']:9.4f} "
              f"{r['rmse']:10.4f}")
    s, a = rows["sync"], rows["async_g0.7"]
    assert a["idle_s"] < s["idle_s"] and a["age_mean"] < s["age_mean"]
    assert a["calls"] > s["calls"] and a["switches"] > s["switches"]
    print(f"ok: async_g0.7 cuts idle {s['idle_s']:.2f}->{a['idle_s']:.2f}s and staleness "
          f"{s['age_mean']:.3f}->{a['age_mean']:.3f}s but costs infer_calls {s['calls']}->{a['calls']} "
          f"and {a['switches']} overlap switches; not RTC (10.2), not stamp sync (8.3); "
          "SmolVLA / GPU / arm 本页未运行")


if __name__ == "__main__":
    main()
```

## VLA 替你做不了的事

VLA 并没有免除前几课的工作，只是把工作转移到另一个环节。你仍然需要一个关于你自己机器人的好数据集，包含你希望它应对的变化和恢复动作。你仍然需要在一组固定条件下评估它。“零样本”（zero-shot）的说法只对与预训练数据相似的机器人和场景成立：OpenVLA 自己的模型卡就写明，不经微调它无法泛化到没见过的机器人形态。你得到的是语言条件（一个模型、多种指令）和一个更好的起点，于是每个任务需要的示范更少。

## 常见错误

- <strong>把“开源”当成“开放权重”，再当成“可以免费商用”。</strong>要看权重的许可证，不只是代码的。GR00T N1.6 的代码是 Apache-2.0，权重却仅限研究用途。
- <strong>忘了归一化统计量。</strong>VLA 输出的是归一化后的动作。把它们还原需要它所微调的数据集的第 1/第 99 百分位数（或均值和标准差）；统计量用错，形状对了，幅度却错了。
- <strong>指望在你的机械臂上零样本运行。</strong>不在你的机器人上微调，VLA 学到的关节或末端约定、相机位置和夹爪都可能和你的不一样。按大约 50 条示范来做计划。
- <strong>忽略推理时间。</strong>一个 7B 模型需要大显存 GPU 才能跑得够快。在真正驱动机器人的那台电脑上测量每秒能出多少个动作；跟不上时，选更小的模型或按动作块执行。
- <strong>以为异步推理「免费」。</strong>只有 g 高于 (E[ℓ_S] / Δt) / n 时它才消除空闲，而且要付出更多推理调用和更多块拼接（玩具里 g = 0.7 时调用从 16 次到 57 次）。按你的延迟和服务器预算选 g。
- <strong>把异步推理、RTC 和时间戳同步混为一谈。</strong>异步决定何时请求下一块（本课）；RTC 用软掩码平滑拼接处（10.2）；流对齐按时间匹配传感器样本（8.3）。
- <strong>把 SmolVLA 论文的数字当成你自己的。</strong>450M 的规模、约 30 % 的提速和 19 对 9 次循环都以论文为准；请在你自己的机械臂上测。
- <strong>不看范围就用区间法。</strong>如果你的任务里有比数据集中任何动作都大的运动，区间分词会把它截断，如上面 6.2 度的误差所示。
