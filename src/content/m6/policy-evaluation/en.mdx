Every lesson this month ended with a line like "success 67/100". On a real arm, 100 trials are not without cost: each one means resetting the scene by hand, and a session of 20 trials can take an hour. This lesson is about getting reliable estimates from few trials: how uncertain a success rate is, how to compare two policies fairly, how many trials a comparison needs, and how to turn failures into the next thing to fix. It is also the part of a portfolio project that reviewers look at first.

## One number is not enough

A success rate from n trials is an estimate. The **Wilson interval** is a good default for its 95 % range: unlike the textbook "p ± 1.96 √(p(1−p)/n)", it stays inside 0..100 % and still works at 0 or n successes. The program uses the corridor and policies from [lesson 1](/en/month/month-6/behaviour-cloning):

<CodeSource path="examples/month-6/policy-evaluation/eval_report.py" />

```python
"""eval_report.py: how to measure a policy, on the behaviour-cloning corridor from lesson 1.

1. Success rates with Wilson 95 % intervals: what "67/100" and "8/10" can and cannot tell you.
2. How much a 10-trial evaluation of the same policy moves around between sessions.
3. A paired comparison: every policy runs from the same list of per-trial seeds (same start, same noise),
   so trials can be compared one by one, with McNemar's exact test on the trials where they disagree.
4. How many trials you need to tell two success rates apart.
5. A failure table: where and when the failures happen.
Standard library only; imports the corridor, expert and policies from ../behaviour-cloning/bc_reach.py.
"""
import math
import os
import random
import sys

sys.path.insert(0, os.path.join(os.path.dirname(os.path.abspath(__file__)), '..', 'behaviour-cloning'))
import bc_reach  # noqa: E402

Z95, Z80 = 1.959964, 0.841621          # two-sided 95 % confidence; 80 % power


def wilson(k, n, z=Z95):
    p = k / n
    centre = (p + z * z / (2 * n)) / (1 + z * z / n)
    half = z * math.sqrt(p * (1 - p) / n + z * z / (4 * n * n)) / (1 + z * z / n)
    return centre - half, centre + half


def trials(policy, seeds):
    """One rollout per seed; each trial gets its own random generator, so its start and noise are fixed."""
    return [bc_reach.rollout(policy, random.Random(s)) for s in seeds]


def mcnemar_p(b, c):
    """Exact two-sided McNemar test: under 'no difference' each disagreement is a fair coin."""
    n = b + c
    if n == 0:
        return 1.0
    tail = sum(math.comb(n, k) for k in range(min(b, c) + 1)) / 2 ** n
    return min(1.0, 2 * tail)


def trials_needed(p1, p2):
    """Trials per policy for a two-sided 5 % test with 80 % power (normal approximation)."""
    pbar = (p1 + p2) / 2
    num = Z95 * math.sqrt(2 * pbar * (1 - pbar)) + Z80 * math.sqrt(p1 * (1 - p1) + p2 * (1 - p2))
    return math.ceil(num * num / (p1 - p2) ** 2)


def main():
    print('1. Success with a Wilson 95 % interval')
    for k, n in ((61, 100), (67, 100), (99, 100), (100, 100), (8, 10), (10, 10)):
        lo, hi = wilson(k, n)
        print(f'  {k:>3}/{n:<3}  {100 * k / n:5.1f} %   95 % interval {100 * lo:5.1f} .. {100 * hi:5.1f} %')

    demos = bc_reach.record_demos(80, random.Random(6))
    bc20 = bc_reach.nn_policy([f for f in demos if f[0] < 20])
    noisy = bc_reach.record_demos(20, random.Random(8), noise=bc_reach.NOISE)
    bc_noisy = bc_reach.nn_policy(noisy)

    print('\n2. BC on 20 demos, ten separate sessions of 10 trials each (different seeds per session)')
    scores = [sum(r[0] == 'success' for r in trials(bc20, range(100 * s, 100 * s + 10))) for s in range(10)]
    print('  successes out of 10: ' + ' '.join(str(v) for v in scores) + f'   (lowest {min(scores)}, highest {max(scores)})')

    print('\n3. Paired comparison over the same 100 trials (seeds 5000..5099)')
    seeds = range(5000, 5100)
    a = trials(bc20, seeds)
    b = trials(bc_noisy, seeds)
    sa, sb = [r[0] == 'success' for r in a], [r[0] == 'success' for r in b]
    both = sum(x and y for x, y in zip(sa, sb))
    only_a = sum(x and not y for x, y in zip(sa, sb))
    only_b = sum(y and not x for x, y in zip(sa, sb))
    neither = sum(not x and not y for x, y in zip(sa, sb))
    for label, s in (('BC, 20 demos', sa), ('BC, 20 noisy demos', sb)):
        lo, hi = wilson(sum(s), len(s))
        print(f'  {label:<20} {sum(s):>3}/100   95 % interval {100 * lo:5.1f} .. {100 * hi:5.1f} %')
    print(f'  both succeed {both}, only the first {only_a}, only the second {only_b}, both fail {neither}')
    print(f'  McNemar exact test on the {only_a + only_b} disagreements: p = {mcnemar_p(only_a, only_b):.2g}')

    print('\n4. Trials per policy to tell two success rates apart (5 % test, 80 % power)')
    for p1, p2 in ((0.67, 0.99), (0.60, 0.80), (0.80, 0.90), (0.90, 0.95)):
        print(f'  {100 * p1:.0f} % vs {100 * p2:.0f} %: {trials_needed(p1, p2):>4} trials each')

    print('\n5. Failures of BC on 20 demos in those 100 trials')
    fails = [r for r in a if r[0] != 'success']
    places = {}
    for result, steps, worst, p in fails:
        key = result if result != 'wall' else 'wall, ' + bc_reach.place(p)
        places.setdefault(key, []).append(steps)
    print(f'  {"failure":<18} {"count":>5} {"share":>7} {"mean step":>10}')
    for key in sorted(places, key=lambda k: -len(places[k])):
        v = places[key]
        print(f'  {key:<18} {len(v):>5} {100 * len(v) / len(fails):>6.0f}% {sum(v) / len(v):>10.1f}')


if __name__ == '__main__':
    main()
```

## The same policy across sessions

Run BC on 20 demos ten times, 10 trials per session, with fresh random conditions each session, i.e. ten independent evaluation sessions:

<SimOutput source="model">

```text
2. BC on 20 demos, ten separate sessions of 10 trials each (different seeds per session)
  successes out of 10: 5 7 5 6 4 7 7 4 4 9   (lowest 4, highest 9)
```

</SimOutput>

The policy did not change, yet one session reports 40 % and another 90 %. That spread is what a single rate predicts: over the paired 100 trials the same policy scores 65/100, so each 10-trial session is a draw from Binomial(10, 0.65) with standard deviation √(10 × 0.65 × 0.35) ≈ 1.51 successes; a ±2 SD band is about 4 to 9 out of 10, which is exactly the range on the board. If you made a change between two sessions, you would attribute the difference to it whichever way the result moved. A single 10-trial session is therefore not enough to decide whether a change helped.

## Compare on the same trials

The fix is to make the conditions identical and compare trial by trial. In the model, each trial gets its own seed (`random.Random(s)` for seed s), so trial 5000 has the same start and the same noise for every policy. That is stricter than the earlier lessons, which started each evaluation from one shared seed: once two policies take different numbers of steps, a shared random stream drifts apart. On hardware the same idea is a fixed list of start positions (and object placements), written down before the session and run in the same order for every policy.

<SimOutput source="model">

```text
3. Paired comparison over the same 100 trials (seeds 5000..5099)
  BC, 20 demos          65/100   95 % interval  55.3 ..  73.6 %
  BC, 20 noisy demos   100/100   95 % interval  96.3 .. 100.0 %
  both succeed 65, only the first 0, only the second 35, both fail 0
  McNemar exact test on the 35 disagreements: p = 5.8e-11
```

</SimOutput>

The trials where both policies succeed or both fail say nothing about which is better. Only the disagreements do. **McNemar's test** asks: if the two policies were equally good, each disagreement would be independent and equally likely to favour either one; how likely is a split this asymmetric? Here all 35 go the same way, p = 2 × 0.5³⁵ = 5.8 × 10⁻¹¹, so the noisy-demo policy is significantly better. Note also that "only the first" is 0: the noisy-demo policy succeeded on every trial where the other one did, a stronger statement than the two success rates alone.

## How many trials

How many trials you need depends on how close the two policies are. The program uses the standard formula for comparing two proportions with a 5 % test and an 80 % chance of detecting a real difference:

<SimOutput source="model">

```text
4. Trials per policy to tell two success rates apart (5 % test, 80 % power)
  67 % vs 99 %:   21 trials each
  60 % vs 80 %:   82 trials each
  80 % vs 90 %:  199 trials each
  90 % vs 95 %:  435 trials each
```

</SimOutput>

Worked through for 80 % vs 90 %: the pooled rate is p̄ = (0.80 + 0.90) / 2 = 0.85. The first term is z95 × √(2 p̄ (1 − p̄)) = 1.959964 × √0.255 = 0.9897; the second is z80 × √(p1(1 − p1) + p2(1 − p2)) = 0.841621 × √(0.16 + 0.09) = 0.4208. Their sum is 1.4105, squared 1.9896, divided by the squared difference 0.10² = 0.01: 198.96, rounded up to 199 trials.

A difference as large as lesson 1's 67 % against 99 % is detectable with about 20 trials. A 10-point improvement on an already good policy, 80 % to 90 %, needs about 200 trials per policy, i.e. several days of manual resets. Two practical consequences: aim your effort at changes big enough to measure, and use paired trials, which need fewer trials than this unpaired formula when the policies agree on most of them.

## Failure analysis

A success rate tells you how often; a failure table tells you what to fix. Sort every failure by where it happened and when:

<SimOutput source="model">

```text
5. Failures of BC on 20 demos in those 100 trials
  failure            count   share  mean step
  wall, goal end        26     74%       41.3
  wall, leg 2            8     23%       30.8
  wall, leg 1            1      3%       15.0
```

</SimOutput>

Three quarters of the failures are at the goal end, mean step 41.3. The expert demos themselves are only 38 to 39 frames long (lesson 1): once the gripper is within the 5 cm success radius of the goal, the episode ends, so the recorded set has almost no frames that say what to do when the gripper is near the goal but still outside that radius. At test time the rollout continues up to 80 steps; after step ~39 the nearest recorded frame is still a late centre-line frame whose action drives straight, so the policy coasts past the 5 cm ball and hits the wall a few steps later — that is the 41.3. That points straight at the fix (record what to do near the goal, or relabel those states with DAgger) and says that the first leg is not worth working on. On a real arm the categories are things like "missed the grasp", "grasped but dropped", "collided", "timed out", "wrong object", each with the trial number and a link to its video.

## An evaluation protocol for your arm

Write this down before the session, not after:

- **The success criterion**, as an operational criterion another person can apply without knowing the implementation ("cube entirely inside the bin, gripper open, within 30 s").
- **The trial list**: start positions and object placements, including some that are not in the training data, run in the same order for every policy.
- **What stays fixed**: lighting, camera positions, objects, the robot's start pose, the code version and checkpoint of each policy.
- **What gets recorded**: one video per trial, the outcome, the failure category, and the time taken.
- **The report**: successes out of trials with the Wilson interval, the paired table if you compare policies, and the failure table.


## Nested eval seeds: synthetic draws, not real training

The K "train seeds" in this section are **synthetic policy draws** — scripted Bernoulli success parameters named `synthetic_policy_draw_k`. They are **not** real neural-network training runs. Treat them as stand-ins for "I trained five times and got five checkpoints," so the nesting of uncertainty stays visible without a GPU.

### Two tables, two uncertainty layers

- **`shared_IC` (paired):** every draw faces the **same** list of evaluation initial conditions. Rates are comparable trial-by-trial in spirit (paired).
- **`independent_IC` (unpaired):** each draw gets its **own** IC list. Print it in a **separate** table — do not merge the rows.

Uncertainty layers stay labeled and separate:

1. **Count interval within one draw:** Wilson 95 % (frequentist) and a uniform-prior Beta(`1+k`, `1+n−k`) central 95 % interval (Bayesian sketch). A pooled Wilson over trials is valid only for **independent evaluation sessions of the same fixed policy**. Do **not** treat multiple `synthetic_policy_draw_k` × shared IC as independent Bernoulli trials and dump them into one pooled Wilson — those draws are different policies.
2. **Across-draw dispersion:** min / median / max of the K point rates. The **best-seed cherry-pick** vs the **median** is printed on purpose: reporting only the best session is the anti-pattern lesson 4 already warned about.

Checklist fields follow arXiv 2409.09491v2 §4 *Analysis and Reporting* (Kress-Gazit et al.): experiment parameters (success criterion, **counts** not just percentages, session timing, ICs and their relation to training), statistical analysis, and failure modes.

```python
#!/usr/bin/env python3
"""eval_seed_layers_toy.py: synthetic policy draws + nested eval seed layers (stdlib).

The K "train seeds" here are SYNTHETIC POLICY DRAWS (scripted Bernoulli success
parameters), NOT real neural-network training runs. Prints use the names
  synthetic_policy_draw_k
  shared_IC          (paired: the same evaluation IC list for every draw)
  independent_IC     (unpaired: each draw gets its own IC list)

Uncertainty layers (NEVER mixed into one unlabeled %):
  1. Count interval on one draw's trials: Wilson 95 % (frequentist) and a
     uniform-prior Beta(1+k, 1+n-k) central 95 % interval (Bayesian sketch).
  2. Across-draw dispersion: min / median / max of the K point rates, plus the
     cherry-picked best-seed rate vs the median (reporting the best alone is
     the anti-pattern).

Checklist fields reference arXiv 2409.09491v2 §4 "Analysis and Reporting"
(Kress-Gazit et al. — Robot Learning as an Empirical Science: Best
Practices for Policy Evaluation):
  §4.1 experiment parameters — semantic success criterion; counts not just %;
       timing of sessions; initial conditions and their relation to training;
  §4.2 statistical analysis — interval / Bayesian layer, separate from
       across-draw spread;
  §4.3 failure modes — categories + frequency (toy: one synthetic category).
usage: python3 eval_seed_layers_toy.py
"""
from __future__ import annotations

import math
import random

SEED = 64
K_DRAWS = 5                 # synthetic_policy_draw_0 .. _4
N_IC = 40                   # evaluation initial conditions per table
# Per-draw true success probabilities (scripted policies, not trained nets).
P_DRAWS = (0.55, 0.62, 0.70, 0.78, 0.66)
Z95 = 1.959964


def wilson(k: int, n: int, z: float = Z95) -> tuple[float, float]:
    p = k / n
    centre = (p + z * z / (2 * n)) / (1 + z * z / n)
    half = z * math.sqrt(p * (1 - p) / n + z * z / (4 * n * n)) / (1 + z * z / n)
    return centre - half, centre + half


def beta_central_interval(k: int, n: int, alpha: float = 0.05) -> tuple[float, float]:
    """Central (1-alpha) interval from Beta(1+k, 1+n-k) via incomplete-beta inverse.

    Uniform prior Beta(1,1) + Bernoulli likelihood → Beta(1+k, 1+n-k).
    Quantiles by bisection on the regularised incomplete beta.
    """
    a = 1.0 + k
    b = 1.0 + (n - k)

    def betacf(x, aa, bb, max_iter=200):
        # Lentz continued fraction for incomplete beta (NR-style).
        tiny = 1e-30
        qab = aa + bb
        qap = aa + 1.0
        qam = aa - 1.0
        c = 1.0
        d = 1.0 - qab * x / qap
        if abs(d) < tiny:
            d = tiny
        d = 1.0 / d
        h = d
        for m in range(1, max_iter + 1):
            m2 = 2 * m
            aa_m = m * (bb - m) * x / ((qam + m2) * (aa + m2))
            d = 1.0 + aa_m * d
            if abs(d) < tiny:
                d = tiny
            c = 1.0 + aa_m / c
            if abs(c) < tiny:
                c = tiny
            d = 1.0 / d
            h *= d * c
            aa_m = -(aa + m) * (qab + m) * x / ((aa + m2) * (qap + m2))
            d = 1.0 + aa_m * d
            if abs(d) < tiny:
                d = tiny
            c = 1.0 + aa_m / c
            if abs(c) < tiny:
                c = tiny
            d = 1.0 / d
            delta = d * c
            h *= delta
            if abs(delta - 1.0) < 1e-10:
                break
        return h

    def betai(x, aa, bb):
        if x <= 0.0:
            return 0.0
        if x >= 1.0:
            return 1.0
        ln_beta = (math.lgamma(aa) + math.lgamma(bb) - math.lgamma(aa + bb))
        front = math.exp(aa * math.log(x) + bb * math.log(1.0 - x) - ln_beta)
        if x < (aa + 1.0) / (aa + bb + 2.0):
            return front * betacf(x, aa, bb) / aa
        return 1.0 - front * betacf(1.0 - x, bb, aa) / bb

    def quantile(p):
        lo, hi = 0.0, 1.0
        for _ in range(80):
            mid = 0.5 * (lo + hi)
            if betai(mid, a, b) < p:
                lo = mid
            else:
                hi = mid
        return 0.5 * (lo + hi)

    return quantile(alpha / 2), quantile(1.0 - alpha / 2)


def median(vals: list[float]) -> float:
    s = sorted(vals)
    n = len(s)
    if n % 2:
        return s[n // 2]
    return 0.5 * (s[n // 2 - 1] + s[n // 2])


def run_table(tag: str, ic_seeds_per_draw: list[list[int]], rng_master: random.Random) -> list[dict]:
    """Evaluate each synthetic draw on its IC list; return per-draw records."""
    rows = []
    print(f"== {tag} ==")
    print(f"{'draw':<26} {'k/n':>7} {'rate%':>7} {'Wilson95%':>18} {'Beta95%':>18}")
    for k, p_true in enumerate(P_DRAWS):
        seeds = ic_seeds_per_draw[k]
        # Independent RNG stream per (draw, IC) from the IC seed alone so a
        # shared IC list is genuinely paired across draws.
        successes = []
        for s in seeds:
            # Paired shared_IC: same IC seed ⇒ same Uniform(0,1); draws differ
            # only through their scripted p_true threshold.
            u = random.Random(s).random()
            successes.append(1 if u < p_true else 0)
        kk = sum(successes)
        n = len(successes)
        rate = kk / n
        wlo, whi = wilson(kk, n)
        blo, bhi = beta_central_interval(kk, n)
        label = f"synthetic_policy_draw_{k}"
        print(f"{label:<26} {kk:>2}/{n:<2} {100 * rate:6.1f}%  "
              f"{100 * wlo:.1f}..{100 * whi:.1f}  {100 * blo:.1f}..{100 * bhi:.1f}")
        rows.append({"k": kk, "n": n, "rate": rate, "p_true": p_true,
                     "wilson": (wlo, whi), "beta": (blo, bhi)})
    rates = [r["rate"] for r in rows]
    best = max(rates)
    med = median(rates)
    print(f"across_draw_dispersion: min={100 * min(rates):.1f}%  "
          f"median={100 * med:.1f}%  max={100 * best:.1f}%  "
          f"best_seed_cherry_pick={100 * best:.1f}%  "
          f"cherry_pick_minus_median={100 * (best - med):.1f} pp")
    print(f"layer_note: Wilson/Beta = count uncertainty WITHIN one draw; "
          f"min/median/max = dispersion ACROSS draws — do not mix into one %")
    print()
    return rows


def main() -> None:
    print(f"seed={SEED} K_draws={K_DRAWS} N_IC={N_IC}")
    print("synthetic_policy_draw_k = scripted Bernoulli policies (NOT real training runs)")
    print(f"true_p per draw: {list(P_DRAWS)}")
    print()
    print("checklist_fields (arXiv 2409.09491v2 §4 Analysis and Reporting):")
    print("  4.1 experiment_parameters: success_criterion | n_evals_counts | "
          "session_timing | ICs_and_relation_to_train")
    print("  4.2 statistical_analysis: Wilson_or_Beta_count_interval "
          "(separate from across-draw dispersion)")
    print("  4.3 failure_modes: categories + frequency + narrative")
    print(f"  toy_success_criterion: Bernoulli trial vs scripted p_k "
          f"(semantic stand-in; real arm criterion 本页未运行)")
    print(f"  toy_IC_relation_to_train: evaluation ICs are held-out synthetic indices; "
          f"not claimed in-distribution to any training set")
    print()

    master = random.Random(SEED)
    # Shared IC list: same N_IC seeds for every draw (paired).
    shared_ics = [master.randrange(10_000_000) for _ in range(N_IC)]
    shared_per_draw = [list(shared_ics) for _ in range(K_DRAWS)]
    rows_shared = run_table("shared_IC (paired)", shared_per_draw, master)

    # Independent IC lists: each draw gets its own N_IC seeds (unpaired).
    indep_per_draw = [[master.randrange(10_000_000) for _ in range(N_IC)]
                      for _ in range(K_DRAWS)]
    rows_indep = run_table("independent_IC (unpaired)", indep_per_draw, master)

    # Synthetic failure table for the median shared draw (illustrates §4.3).
    med_rate = median([r["rate"] for r in rows_shared])
    med_idx = min(range(K_DRAWS),
                  key=lambda i: abs(rows_shared[i]["rate"] - med_rate))
    fails = rows_shared[med_idx]["n"] - rows_shared[med_idx]["k"]
    # Split failures into two toy categories with a fixed ratio.
    cat_a = int(round(0.65 * fails))
    cat_b = fails - cat_a
    print(f"== failure_modes (shared_IC, synthetic_policy_draw_{med_idx} = median) ==")
    print(f"  category              count  share")
```

## Set-of-Mark and Trace-of-Mark (Magma)

The protocol above compares two policies on the same trials. This section applies the same habit to an **output interface** instead of a policy: should a model write a continuous point directly, or choose one of several numbered marks drawn on the image and then predict where that mark goes next? Magma, a foundation model for multimodal agents, uses the second form. The toy below is a **discrete stand-in** for that idea. It is **not** Magma's model, data or benchmarks, **not** a UI agent, and **not** HAMSTER's 2-D path, MolmoAct's traces, TraceVLA or ThinkAct.

<Resource id="magma-paper" />

**Source actually opened (arXiv abstract page, HTML and PDF body read).**

- **Yang et al., Magma: A Foundation Model for Multimodal AI Agents (arXiv 2502.13130 v1, 13 authors, submitted 18 Feb 2025), section 3.2:**
  - **Set-of-Mark.** Candidate regions or points are proposed (for example by segmentation or detection models), numeric marks are overlaid on them, and the model outputs a mark instead of raw coordinates. The paper's reason: the model "faces much less difficulties to predict the numeric marks".
  - Coordinates are normalised by the image size and "quantized into 256 bins" (Figure 3 caption).
  - **Trace-of-Mark.** On video, the model predicts the future traces of the marks. The paper says this forces the model to understand temporal dynamics and to "look ahead of time" before acting, and that "predicting traces uses much fewer tokens" than predicting next frames. Traces are extracted with the CoTracker point tracker, so unlabelled video can supervise them.
  - Benchmark numbers are 以论文为准. GPU, UI or robot runs: **本页未运行**.

### Marks, traces and what is measured

With candidate positions `p_k`, shared relevance scores `s_k` and the target's true trace `p_target(τ)`:

<Formula label="Direct arm A: a regressor's single point averages the candidates by softmax weight">p_A = Σ_k softmax(s)_k · p_k + ε</Formula>

<Formula label="Set-of-Mark arm B: pick the best mark, then read its quantised position">p_B = q(p_k*),  k* = argmax_k s_k,  q(u) = (⌊256 u⌋ + 0.5) / 256</Formula>

<Formula label="Trace-of-Mark: the chosen mark's trace over τ = 1 … L, with a tracked velocity">p_B(τ) = p_B + (v_k* + η) · τ</Formula>

<Formula label="Trace error over the L future steps (printed × 100)">ADE = (1 / L) · Σ_τ ‖p(τ) − p_target(τ)‖</Formula>

**Worked example.** The toy prints the weight a regressor would give the target with no score noise at all. In `cluttered` it is `0.7416` with `K 8`: the remaining weight goes to the other `K − 1` candidates, so the averaged point is pulled away from the target even before noise, and `RADIUS 0.05` is small. The target also moves `0.0800` over `L`, more than `RADIUS`, so a plan that stays where it starts can only succeed at step `L` by luck. In `single_target` the weight is `1.0000`: A's only error is the regression noise `SIG_REG 0.01`, and B's only error is quantisation, at most `0.001953` per axis. In `static_jitter` the weight is `0.9526` and the target moves `0.0000` over `L`, but B's tracked velocity carries an error with `SIG_TRK 0.012` per step, which grows with every step of the trace.

**Correctness criterion.** The quantised point must stay within `0.5 / BINS` of the true coordinate on each axis; the toy prints that bound (`0.001953`) and the test file checks it on several coordinates, and checks A, B and C on a hand-built two-object scene. **No integration step:** every position is the closed form `p + v · τ`, so there is no step size to test.

### Fair setup

`magma_som_tom_toy.py` is **synthetic** and stdlib only. **Model assumptions:**
- Image coordinates in `[0, 1]`, `K` candidates at uniform positions; object 0 is the instructed target; each object moves at a constant velocity of the regime's speed in a random direction.
- One shared belief: the target's score is `SIGNAL` plus Gaussian noise, distractors get noise only, with `SIG_B`. A and B read the same scores; neither is a trained network.
- A has no trace, so its plan for every future step is its one point. B and C use the same trace step; C's numeric labels sit on the wrong objects (a random permutation).
- Grounding means the point is within `RADIUS` of the target now; success means the planned point at step `L` is within `RADIUS` of where the target is then.

| Arm | Output | Trace |
|---|---|---|
| A_direct | one continuous point, softmax-weighted average plus `SIG_REG` noise | none (holds the point) |
| B_somtom | the top-scoring mark, quantised to `BINS` bins | mark velocity plus `SIG_TRK` noise |
| C_shuffle | the same choice, but marks drawn on the wrong objects | same as B |

**Common random numbers:** for each (regime, seed) the positions, velocities, scores, regression noise, tracking noise and permutation of every scene are drawn once and used by all three arms. Five seeds of `SCENES 400` each.

| Regime | Candidates | Target speed | Tracking noise | Expected (written before the first run) |
|---|---|---|---|---|
| cluttered | K 8 | 0.01 per step | 0.002 | B consistent win over A on grounding and success |
| single_target | K 1 | static | 0 | A and B tie on grounding and success |
| static_jitter | K 2 | static | 0.012 | B ties or loses to A on success |

C was expected to lose to B on grounding in every regime with more than one candidate.

**Choices made after seeing results.** None. No constant, arm, metric or regime was changed after the first run, and the table below is that first run. The proposal for this section expected a near-tie for a single obvious target; the toy instead declared a tie on grounding and success for `single_target`, and added `static_jitter` as a regime where B was expected to tie or lose. Alternatives not taken, so no numbers for them appear here: a larger `RADIUS`, which would let A's averaged point count as grounded more often; and a velocity estimate for A, which would turn it into a trace model.

```python
#!/usr/bin/env python3
"""Magma-style Set-of-Mark + Trace-of-Mark vs direct coordinate output vs shuffled marks, on shared scenes.

Synthetic, stdlib only.  Not Magma's model, data or benchmarks: a discrete stand-in for the two
ideas in the paper's section 3.2 (select a numbered mark instead of regressing a coordinate; then
predict the mark's future trace).  Not a UI agent, not HAMSTER's 2-D path, not MolmoAct traces,
not TraceVLA, not ThinkAct.  Magma benchmark numbers are 以论文为准; GPU, UI or robot runs:
本页未运行.

Scene (image coordinates normalised to [0, 1], as in the paper): K candidate objects at uniform
positions; object 0 is the instructed target.  Each object moves with a constant velocity per
step (speed set by the regime, random direction); its true trace is p + v * tau, tau = 1..L.
Shared belief: the same noisy relevance score per candidate, target SIGNAL + N(0, SIG_B),
distractors N(0, SIG_B); softmax weights w_k.
Arms (same scene, same scores):
  A_direct  outputs one continuous point: sum_k w_k p_k plus N(0, SIG_REG) per axis (a regressor
            averages its candidates); no trace, so its plan for every future step is that point
  B_somtom  selects the mark with the highest score; the point is that mark's position quantised
            to BINS bins per axis (the paper quantises coordinates into 256 bins); then predicts
            the mark's trace with a tracked velocity v + N(0, SIG_TRK) per axis
  C_shuffle same selection and trace step as B, but the numeric labels are drawn on the wrong
            objects (a uniform random permutation; with K = 1 it can only be the identity)
Metrics per seed (SCENES scenes): grounding % (point within RADIUS of the target now), trace ADE
(mean distance to the target's true trace over L steps, x 100), success % (planned point at step
L within RADIUS of the target then).  No integration step: positions are closed form per step.
Common random numbers: per (regime, seed), the positions, velocities, scores, regression noise,
tracking noise and permutations are drawn once per scene and used by all three arms.
Regimes and expectations, written before the first run:
  cluttered      K 8, speed 0.01 per step, SIG_TRK 0.002   B consistent win over A on grounding
                                                            and success
  single_target  K 1, static, SIG_TRK 0                      A and B tie on grounding and success
  static_jitter  K 2, static, SIG_TRK 0.012                 B ties or loses to A on success (the
                                                            trace adds error to a static target)
  C loses to B on grounding in every regime with K > 1.
"""
import math
import random

SEEDS = (0, 1, 2, 3, 4)
SCENES = 400
L = 8              # trace length (steps)
RADIUS = 0.05
BINS = 256
SIGNAL, SIG_B = 3.0, 1.0
SIG_REG = 0.01
NUM_ZERO = 1e-9
ARMS = ("A_direct", "B_somtom", "C_shuffle")
# name: (K, speed per step, SIG_TRK); written before the first run
REGIMES = {
    "cluttered": (8, 0.01, 0.002),
    "single_target": (1, 0.0, 0.0),
    "static_jitter": (2, 0.0, 0.012),
}
STREAM = {"cluttered": 0, "single_target": 1, "static_jitter": 2}


def quantise(u):
    k = min(BINS - 1, max(0, int(u * BINS)))
    return (k + 0.5) / BINS


def shared_draws(regime, seed):
    rng = random.Random(1000 * STREAM[regime] + seed)
    k, speed, sig_trk = REGIMES[regime]
    scenes = []
    for _ in range(SCENES):
        pos = [(rng.uniform(0.05, 0.95), rng.uniform(0.05, 0.95)) for _ in range(k)]
        vel = []
        for _ in range(k):
            th = rng.uniform(0.0, 2.0 * math.pi)
            vel.append((speed * math.cos(th), speed * math.sin(th)))
        score = [(SIGNAL if i == 0 else 0.0) + rng.gauss(0.0, SIG_B) for i in range(k)]
        reg = (rng.gauss(0.0, SIG_REG), rng.gauss(0.0, SIG_REG))
        trk = (rng.gauss(0.0, sig_trk), rng.gauss(0.0, sig_trk)) if sig_trk > 0 else (0.0, 0.0)
        perm = list(range(k))
        rng.shuffle(perm)
        scenes.append((pos, vel, score, reg, trk, perm))
    return scenes


def plan(arm, scene):
    pos, vel, score, reg, trk, perm = scene
    if arm == "A_direct":
        mx = max(score)
        w = [math.exp(s - mx) for s in score]
        tot = sum(w)
        px = sum(wi * p[0] for wi, p in zip(w, pos)) / tot + reg[0]
        py = sum(wi * p[1] for wi, p in zip(w, pos)) / tot + reg[1]
        return [(px, py)] * (L + 1)
    sel = max(range(len(score)), key=lambda i: score[i])
    obj = perm[sel] if arm == "C_shuffle" else sel
    p = (quantise(pos[obj][0]), quantise(pos[obj][1]))
    v = (vel[obj][0] + trk[0], vel[obj][1] + trk[1])
    return [(p[0] + v[0] * t, p[1] + v[1] * t) for t in range(L + 1)]


def evaluate(arm, scenes):
    g = s = ade = 0.0
    for sc in scenes:
        pos, vel = sc[0], sc[1]
        tr = [(pos[0][0] + vel[0][0] * t, pos[0][1] + vel[0][1] * t) for t in range(L + 1)]
        pl = plan(arm, sc)
        g += math.dist(pl[0], tr[0]) <= RADIUS
        s += math.dist(pl[L], tr[L]) <= RADIUS
        ade += sum(math.dist(pl[t], tr[t]) for t in range(1, L + 1)) / L
    n = len(scenes)
    return {"ground": 100.0 * g / n, "ade": 100.0 * ade / n, "success": 100.0 * s / n}


def mean_sd(xs):
    mu = sum(xs) / len(xs)
    return mu, math.sqrt(sum((x - mu) ** 2 for x in xs) / (len(xs) - 1))


def num(x):
    if x != 0.0 and abs(x) < 5e-5:
        return f"{x:.3e}"
    return f"{x:.4f}"


def sign_note(diffs, m):
    n, opp, zero = len(diffs), sum(1 for d in diffs if d * m < 0), sum(1 for d in diffs if d == 0)
    if opp == 0 and zero == 0:
        return f"same sign on all {n} seeds"
    if opp == 0:
        return f"no seed has the opposite sign, {zero} of {n} equal"
    note = f"{opp} of {n} seeds {'has' if opp == 1 else 'have'} the opposite sign"
    return note + (f", {zero} of {n} equal" if zero else "")


def verdict(xa, xb):
    diffs = [a - b for a, b in zip(xa, xb)]
    if all(d == 0.0 for d in diffs):
        return "0.0000+-0.0000: tie: identical on every seed"
    m, s = mean_sd(diffs)
    if abs(m) < NUM_ZERO and s < NUM_ZERO:
        return f"{num(m)}+-{num(s)}: numerically zero (floating-point residue), effectively a tie"
    if abs(m) <= s:
        label = "near-tie / small gap, within seed noise (|m| <= sd)"
    elif abs(m) < 0.2 * min(abs(mean_sd(xa)[0]), abs(mean_sd(xb)[0])):
        label = "small but consistent gap, not a tie (|m| > sd)"
    else:
        label = "clear gap, not a tie (|m| > sd)"
    return f"{num(m)}+-{num(s)}: {label}; {sign_note(diffs, m)}"


def main():
    print("Synthetic Magma-style probe: direct point vs Set-of-Mark + Trace-of-Mark vs shuffled marks; discrete stand-in, not Magma")
    print(f"SCENES={SCENES} L={L} RADIUS={RADIUS} BINS={BINS} SIGNAL={SIGNAL} SIG_B={SIG_B} SIG_REG={SIG_REG} seeds={len(SEEDS)}")
    print(f"quantisation error at most {0.5 / BINS:.6f} per axis; no integration step (closed-form positions per step)")
    print("regime arm grounding_% trace_ADE_x100 success_%  (mean+-sd over seeds)")
    for regime, (k, speed, sig_trk) in REGIMES.items():
        w0 = math.exp(SIGNAL) / (math.exp(SIGNAL) + (k - 1))
        print(f"{regime} (K {k}; speed {speed} per step, target moves {speed * L:.4f} over L; SIG_TRK {sig_trk}; noise-free target weight {w0:.4f})")
        draws = [shared_draws(regime, s) for s in SEEDS]
        res = {arm: [evaluate(arm, d) for d in draws] for arm in ARMS}
        for arm in ARMS:
            cols = ["{}+-{}".format(*map(num, mean_sd([r[key] for r in res[arm]]))) for key in ("ground", "ade", "success")]
            print(f"  {arm} " + " ".join(cols))
        for x, y in (("B_somtom", "A_direct"), ("C_shuffle", "B_somtom")):
            for key in ("ground", "ade", "success"):
                print(f"  paired {x[0]}-{y[0]} {key}: {verdict([r[key] for r in res[x]], [r[key] for r in res[y]])}")
    print("No winner declared: marks help where a regressor averages many candidates, change nothing with one target, and a noisy trace hurts a static target; wrong marks hurt")
    print("Magma benchmark numbers 以论文为准; GPU / UI / robot: 本页未运行")


if __name__ == "__main__":
    main()
```

### Read the regimes

How the labels are used on this page, in this order: **tie: identical on every seed** only when the paired per-seed difference is exactly zero on every seed; **numerically zero (floating-point residue), effectively a tie** when `|paired mean|` and its sd are both below 1e-9 (no sign count is printed on such a line); **near-tie / small gap, within seed noise** when `|paired mean| ≤ sd`; otherwise a **consistent** gap (`|paired mean| > sd`), called **small** if `|m|` is under 20 % of the smaller arm mean and **clear** otherwise; the 20 % rule only chooses between those two words. Every consistent line carries a same-sign count over the 5 seeds, and any seed with the opposite sign is reported; a sign count alone never makes a gap consistent. Gaps are computed from unrounded values. Paired differences are B−A and C−B. Grounding and success are in percent; trace ADE is printed × 100.

- **cluttered:**
  - **Marks win with a clear gap:** B−A grounding +70.6000±1.9653 and B−A success +82.1000±0.6982, same sign on all 5 seeds. A grounds 21.1500 % of scenes and B 91.7500 %. B−A trace ADE is −9.9207±0.7258, also clear on all 5 seeds.

## Common mistakes

- **Reporting the best session.** If you ran three **independent evaluation sessions of the same fixed policy**, report all three or their total (a pooled Wilson is then meaningful). Picking the best one is how 40 % becomes 90 %. Do **not** pool multiple synthetic draws × shared IC as if they were i.i.d. Bernoulli trials of one policy.
- **Deciding the criterion afterwards.** If the same near-miss counts as success in one session and failure in the next, the numbers are meaningless.
- **Only testing where you trained.** Include start positions that are not in the dataset and report them separately; that is where policies differ most.
- **Treating overlapping intervals as a tie or separate intervals as proof.** Intervals are a quick check; for two policies on the same trials, use the paired comparison.
- **Changing the scene between policies.** Moving the camera or the bin between two policies' sessions turns your comparison into a comparison of scenes.
- **Calling synthetic draws "trained policies."** They are scripted Bernoulli stands-ins. Say so in the report.
- **Merging shared_IC and independent_IC into one table.** Paired and unpaired designs answer different questions; keep separate tables.
- **Mixing Wilson/Beta with across-draw min/max into one unlabeled %.** Count uncertainty and seed dispersion are different layers.
- **Pooling draws × shared IC into one Wilson.** Different `synthetic_policy_draw_k` are different policies; a pooled count interval is reserved for repeated evals of one fixed policy.
- **Reporting only the best synthetic seed.** Print the median (and the full set). Cherry-picking is how 70 % becomes 85 %.
