## Why this matters in robotics

A ROS 2 robot is not one program but a crowd of small programs called nodes: one reads the camera, one turns wheel commands into motor voltages, one publishes the battery state. You start them from a terminal, watch their log output, and stop the one that misbehaves. Test scripts and data loggers are ordinary Python files run with `python3`. The robot computer — a Raspberry Pi, a Jetson or a mini PC — usually runs Linux with no monitor attached, so you reach it over `ssh` and read text.

The terminal is the interface available when the robot is deployed and no graphical interface is connected. You need a small vocabulary, not a hundred commands. By the end of this lesson you will have three working scripts — an Ohm's-law calculator, a resistor class and a <Term id="json">JSON</Term> logger — installed without breaking the rest of your machine.

## Setting up: one terminal, one Python

On macOS, open **Terminal** from Applications → Utilities. On Linux, open your distribution's terminal; Bash and Zsh both work. On Windows you have two options:

- **WSL2 with Ubuntu (recommended).** WSL2 runs a real Linux kernel inside Windows. ROS 2 targets Ubuntu, and most robotics tutorials assume Linux paths. Install it from an Administrator PowerShell with `wsl --install`, reboot if asked, then open **Ubuntu** from the Start menu.
- **Git Bash.** A lighter Bash-like shell with common Unix commands. Fine for this lesson, but it is not a real Linux environment for ROS 2 later.

Check your interpreter:

```bash
python3 --version
```

You want **3.10 or newer**. On native Windows the launcher is usually `py`:

```bash
py --version
```

On macOS, `python3` may come from the Xcode Command Line Tools; if it is missing, install Python from python.org. Remember that `python` and `python3` are not always the same program. On many Linux systems `python` does not exist, and on some it is an old Python 2. Use `python3` on macOS/Linux and `python` or `py` on Windows, consistently.

## Virtual environments and pip

A Python installation comes with a shared set of packages. If every project installed into that shared set, two projects needing different versions would conflict, and one careless upgrade could break a working tool. A **virtual environment** is a private folder with its own Python link and package directory. Activate it, and `python` and `pip` in that shell resolve to the private copy.

```bash
cd ~/robotics/month1
python3 -m venv .venv
source .venv/bin/activate
```

On native Windows (PowerShell or cmd) the activation command is:

```text
.venv\Scripts\activate
```

Your prompt should now start with `(.venv)`. That marker tells you which environment the next `pip install` will modify. Upgrade <Term id="pip">pip</Term> and install one package:

```bash
python -m pip install --upgrade pip
pip install rich
```

`python -m pip` guarantees that pip belongs to the Python you just invoked, avoiding the classic "I installed it but Python cannot find it" confusion. `rich` is a small library for terminal output; `numpy` is the numerical library you will meet later. Record what you installed so it is reproducible:

```bash
pip freeze > requirements.txt
pip install -r requirements.txt
deactivate
```

The first command writes package names and versions to a text file; the second recreates that set on another machine or in a fresh <Term id="venv">venv</Term>. `deactivate` removes the `(.venv)` marker.

Two rules. **Never commit `.venv` to Git**: it contains binaries and absolute paths, is large, and can be rebuilt from `requirements.txt`. Add `.venv/` to `.gitignore`. **Do not install project packages globally** just because activation was inconvenient; that is how an unrelated upgrade breaks a robot script.

## A command-line tool in Python: ohm.py

This script computes current from voltage and resistance, and the output of a two-resistor divider. It uses <Term id="argparse">`argparse`</Term> with two subcommands. Create `ohm.py`:

<CodeSource path="examples/month-1/python-terminal/ohm.py" />

```python
"""ohm.py — command-line Ohm's law and voltage divider calculator."""

import argparse
import sys


def current(volts: float, ohms: float) -> float:
    """Return the current, in amps, through a resistance at a given voltage."""
    if ohms <= 0:
        raise ValueError("ohms must be positive")
    return volts / ohms


def divider(vin: float, r1: float, r2: float) -> float:
    """Return the output voltage of a two-resistor divider, in volts."""
    if r1 <= 0 or r2 <= 0:
        raise ValueError("resistances must be positive")
    return vin * r2 / (r1 + r2)


def main() -> None:
    parser = argparse.ArgumentParser(
        description="Ohm's law and voltage divider calculator"
    )
    sub = parser.add_subparsers(dest="command", required=True)

    p_current = sub.add_parser("current", help="I = V / R, printed in mA")
    p_current.add_argument("--volts", type=float, required=True)
    p_current.add_argument("--ohms", type=float, required=True)

    p_divider = sub.add_parser("divider", help="Vout = Vin * R2 / (R1 + R2)")
    p_divider.add_argument("--vin", type=float, required=True)
    p_divider.add_argument("--r1", type=float, required=True)
    p_divider.add_argument("--r2", type=float, required=True)

    args = parser.parse_args()

    if args.command == "current":
        ma = current(args.volts, args.ohms) * 1000
        print(f"{ma:.1f} mA")
    elif args.command == "divider":
        v = divider(args.vin, args.r1, args.r2)
        print(f"{v:.3f} V")


if __name__ == "__main__":
    try:
        main()
    except ValueError as e:
        print(f"error: {e}", file=sys.stderr)
        sys.exit(1)
```

Run both examples:

```bash
python ohm.py current --volts 5 --ohms 220
```

```text
22.7 mA
```

```bash
python ohm.py divider --vin 5 --r1 10000 --r2 4700
```

```text
1.599 V
```

Check the arithmetic by hand:

```text
I = V / R = 5 V / 220 Ω = 0.022727... A
0.022727... A × 1000 = 22.727... mA
```

`{ma:.1f}` rounds to one decimal, so the output is `22.7 mA`. For the divider:

```text
Vout = Vin × R2 / (R1 + R2)
     = 5 V × 4700 Ω / (10 000 Ω + 4700 Ω)
     = 5 × 4700 / 14 700 V
     = 23 500 / 14 700 V
     = 1.598639... V
```

`{v:.3f}` prints three decimals, giving `1.599 V`.

How the pieces fit:

- **A function is a named calculation.** `current(volts, ohms)` takes two floats and returns a float. Type hints document intent; Python does not enforce them at runtime. The docstring is what `help(current)` shows.
- **Return inside, print at the edge.** Returning a number lets a test, a GUI or another script reuse the <Term id="function">function</Term>. Printing once in `main()` keeps the calculation reusable.
- **Validate at the boundary.** Zero or negative resistance is meaningless here, so `raise ValueError` stops with a clear message instead of returning infinity.
- **`argparse` builds the interface.** `add_subparsers(..., required=True)` makes `current` or `divider` mandatory; `type=float, required=True` converts text and errors helpfully when a flag is missing. Try `python ohm.py --help` and `python ohm.py divider --help`.
- **The `if __name__ == "__main__":` guard** runs only when the file is executed directly. If another script does `from ohm import divider`, the functions are available and `main()` does not run.
- **The `try`/`except` at the bottom** turns our deliberate error into a short message and exit code 1:

```text
$ python ohm.py current --volts 5 --ohms 0
error: ohms must be positive
```

The `$` is a shell prompt, not part of the command. Exit code 1 tells a shell script or CI job that the command failed. Use `python ohm.py` rather than `./ohm.py` until you add a shebang and executable permission; naming the interpreter removes the "wrong Python" problem.

## Classes: a Resistor with a tolerance

A class bundles data with its operations. A resistor has a nominal value and a tolerance, and can report its plausible range. Python's `@dataclass` removes most of the boilerplate:

<CodeSource path="examples/month-1/python-terminal/resistors.py" />

```python
"""resistors.py — dataclass Resistor, series/parallel helpers."""

from dataclasses import dataclass


@dataclass
class Resistor:
    """A resistor with a nominal value and a tolerance (0.05 = 5 %)."""

    ohms: float
    tolerance: float = 0.05

    def min(self) -> float:
        """Lowest value within tolerance."""
        return self.ohms * (1 - self.tolerance)

    def max(self) -> float:
        """Highest value within tolerance."""
        return self.ohms * (1 + self.tolerance)


def series(*rs: Resistor) -> Resistor:
    """Resistors in series: values add up, absolute deviations (ohms x tolerance) add too."""
    if not rs:
        raise ValueError("series() needs at least one resistor")
    ohms = sum(r.ohms for r in rs)
    tolerance = sum(r.ohms * r.tolerance for r in rs) / ohms
    return Resistor(ohms=ohms, tolerance=tolerance)


def parallel(*rs: Resistor) -> Resistor:
    """Resistors in parallel: conductances add up."""
    if not rs:
        raise ValueError("parallel() needs at least one resistor")
    conductance = sum(1 / r.ohms for r in rs)
    return Resistor(ohms=1 / conductance)


if __name__ == "__main__":
    r2k2 = Resistor(2_200)
    print(r2k2)
    print(f"range: {r2k2.min():.0f}–{r2k2.max():.0f} Ω")

    result = parallel(Resistor(10_000), Resistor(10_000))
    print(f"parallel: {result.ohms:.0f} Ω")

    chain = series(Resistor(1_000), Resistor(4_700))
    print(f"series: {chain.ohms:.0f} Ω, range {chain.min():.0f}–{chain.max():.0f} Ω")
```

`python resistors.py` prints:

```text
Resistor(ohms=2200, tolerance=0.05)
range: 2090–2310 Ω
parallel: 5000 Ω
series: 5700 Ω, range 5415–5985 Ω
```

The first line is the `__repr__` generated by `@dataclass`. `Resistor(2_200)` calls the generated initialiser, so `ohms` is 2200 and `tolerance` defaults to 0.05. The range follows from the meaning of a ±5 % part:

```text
min = 2200 Ω × (1 − 0.05) = 2200 Ω × 0.95 = 2090 Ω
max = 2200 Ω × (1 + 0.05) = 2200 Ω × 1.05 = 2310 Ω
```

A gold-band resistor is a ±5 % part; a multimeter reading should land in that window. The methods return numbers, so they are useful in tests, not just in printed text.

`*rs` collects any number of arguments into a tuple. `series` adds the values; tolerances do not add as percentages. The absolute deviations (value × tolerance) add instead, so two −5 % parts in series are still only 5 % low in total. For 1 kΩ ±5 % and 4.7 kΩ ±5 %:

```text
1 kΩ ±5 %   → 950–1050 Ω
4.7 kΩ ±5 % → 4465–4935 Ω
series      → 5415–5985 Ω
(50 + 235) / 5700 = 0.05 = ±5 %
```

Adding the percentages (10 %, 5130–6270 Ω) is wrong: summing relative errors applies to products and quotients, not to sums. `parallel` adds conductances:

```text
1 / Rtotal = 1 / R1 + 1 / R2
```

For two equal 10 kΩ resistors:

```text
1 / Rtotal = 1 / 10 000 Ω + 1 / 10 000 Ω
           = 0.0001 + 0.0001 S
           = 0.0002 S
Rtotal = 1 / 0.0002 Ω = 5000 Ω
```

Two equal resistors in parallel give half the value — 5 kΩ, not 20 kΩ. Note that `parallel` returns the default 5 % tolerance rather than combining the inputs; a worst-case design would evaluate the extremes.

## Files and JSON: a measurement log

The multimeter lesson asks you to measure five resistors and compare them with their colour bands. A script makes that record timestamped and reusable. JSON is a text format for nested data — objects with string keys, arrays, numbers, strings, booleans and null — and it maps almost directly onto Python lists and dictionaries. A measurement is naturally a dict; the log is a list of them.

<CodeSource path="examples/month-1/python-terminal/log.py" />

```python
"""log.py — append a measurement to measurements.json and check tolerance."""

import json
from datetime import datetime, timezone
from pathlib import Path

LOG_FILE = Path("measurements.json")


def load_measurements() -> list[dict]:
    """Read the log if it exists, else start with an empty list."""
    if LOG_FILE.exists():
        text = LOG_FILE.read_text(encoding="utf-8")
        return json.loads(text)
    return []


def save_measurements(measurements: list[dict]) -> None:
    """Write the whole list back, pretty-printed."""
    LOG_FILE.write_text(
        json.dumps(measurements, indent=2), encoding="utf-8"
    )


def record(part: str, expected_ohms: float, measured_ohms: float) -> dict:
    """Append one measurement and return that entry."""
    entry = {
        "part": part,
        "expected_ohms": expected_ohms,
        "measured_ohms": measured_ohms,
        "time": datetime.now(timezone.utc).isoformat(timespec="seconds"),
    }
    measurements = load_measurements()
    measurements.append(entry)
    save_measurements(measurements)
    return entry


def report_out_of_tolerance(measurements: list[dict], limit: float = 0.05) -> None:
    """Print every measurement that misses its nominal value by more than limit."""
    bad = 0
    for m in measurements:
        expected = m["expected_ohms"]
        measured = m["measured_ohms"]
        if expected == 0:
            continue
        error = abs(measured - expected) / expected
        if error > limit:
            bad += 1
            print(
                f"{m['part']}: expected {expected:.0f} Ω, "
                f"measured {measured:.0f} Ω → off by {error * 100:.1f} %"
            )
    print(f"{bad} of {len(measurements)} measurements out of {limit * 100:.0f} % tolerance")


if __name__ == "__main__":
    record("R1", 4700, 4688)
    print("Logged 1 measurement.")
    report_out_of_tolerance(load_measurements())
```

On a fresh folder, `python log.py` gives:

```text
Logged 1 measurement.
0 of 1 measurements out of 5 % tolerance
```

`measurements.json` now holds one object in a list:

```json
[
  {
    "part": "R1",
    "expected_ohms": 4700,
    "measured_ohms": 4688,
    "time": "2026-05-04T09:14:07+00:00"
  }
]
```

Your timestamp will differ; `datetime.now(timezone.utc)` reads the clock and `isoformat(timespec="seconds")` writes a sortable UTC timestamp. The reading 4688 Ω is only 12 Ω below nominal:

```text
error = |4688 − 4700| / 4700 = 12 / 4700 = 0.002553...
0.002553... × 100 = 0.255... %
```

About 0.3 %, comfortably inside ±5 %. If you change the call to `record("R1", 4700, 4400)` and run again, the file keeps both entries and the report lists the out-of-tolerance entry:

```text
Logged 1 measurement.
R1: expected 4700 Ω, measured 4400 Ω → off by 6.4 %
1 of 2 measurements out of 5 % tolerance
```

The check uses the expected value as the denominator, because a 5 % part may miss nominal by 5 % in either direction.

Why the code is shaped this way:

- **`Path("measurements.json")`** is a path object with `.exists()`, `.read_text()` and `.write_text()`, so there is no manual string concatenation and it behaves on Windows and Linux.
- **Encoding is explicit.** `encoding="utf-8"` keeps the file readable everywhere; relying on the platform default is how unexpected Unicode errors appear.
- **Read, modify, write.** JSON has no append operation. The script loads the list, appends one dict, and writes it back with `indent=2` so a human can still read it in Git.
- **`with open(...)` is the classic form.** `Path.read_text()` and `write_text()` open and close the file for you. When you need more control (reading line by line, appending to a text log), use a `with` block, which closes the file automatically even if an exception is raised inside it:

```python
with open("notes.txt", "a", encoding="utf-8") as f:
    f.write("R1 measured 4688 ohms\n")
```
- **Timestamps make the record useful** when you compare drift over months or match a log line to a photo of the bench.

For the five-resistor task, call `record` once per part, using the colour-band value and the meter reading:

```python
if __name__ == "__main__":
    record("R1", 4700, 4688)
    record("R2", 1000, 996)
    record("R3", 220, 221)
    record("R4", 10_000, 10_120)
    record("R5", 47, 46)
    report_out_of_tolerance(load_measurements())
```

Use your own measurements, not these. The habit is measure, log, compare, then ask why an outlier is outside its band. A resistor reading 0 Ω is a short or the wrong meter range, and a display showing `1` often means open circuit, not 1 Ω.

## Errors and debugging

A traceback lists the call sequence and the point of failure. Read it **bottom-up**:

```text
Traceback (most recent call last):
  File "divide.py", line 4, in <module>
    print(10 / 0)
ZeroDivisionError: division by zero
```

Start with the last line: the error type and message. Then walk up to find your line. The bottom tells you *what* failed; the frames tell you *where*. Skip frames from code you did not write.

Common beginner errors:

- `ModuleNotFoundError` — you installed into a different Python, or forgot to activate the venv. Check the `(.venv)` marker, then `which python3` and `python -m pip --version`.
- `FileNotFoundError` — wrong directory or a typo in the name. Run `pwd` and `ls`.
- `IndentationError` / `TabError` — tabs and spaces are mixed. Set your editor to four spaces and re-indent.
- `SyntaxError` — usually a missing colon, quote or closing parenthesis on the line *before* the one reported.

Catch expected bad input specifically:

```python
from ohm import current

try:
    print(current(5, 0))
except ValueError as error:
    print(f"bad input: {error}")
```

```text
bad input: ohms must be positive
```

`except Exception` would also hide programming mistakes such as a misspelled variable. Catch what you expect; let other exceptions propagate during development. For inspection, `python -i` runs the script and leaves you at a prompt with the module loaded:

```bash
python -i ohm.py current --volts 5 --ohms 220
```

```text
22.7 mA
>>> current(12, 1000)
0.012
```

You can now call functions and try fixes without editing the file. `print()` is also a valid debugging method; print the value and its type where behaviour differs from expectation, and use `print(f"{r=}")` to see a name and value together. Remove the prints once the bug is understood.

## Sampling and aliasing: when a fast tone reads as a slow one

Every script so far in this lesson computes with numbers you typed. Robot code mostly computes with numbers a sensor **sampled**: an ADC, an IMU or an encoder reads a continuous signal at a fixed rate `fs`. This section uses the Python you just learned (`math`, `cmath`, `random`, dicts and list comprehensions) to run one small numerical experiment on what sampling keeps and what it scrambles. It is a **synthetic** model with ideal samples, not an ADC measurement.

<Resource id="wiki-nyquist-shannon" />

<Resource id="wiki-aliasing" />

**Sources actually opened (HTML body read).**

- **Wikipedia — Nyquist–Shannon sampling theorem:** if a function `x(t)` contains no frequencies higher than `B` hertz, it is completely determined by samples spaced less than `1/(2B)` seconds apart, so a sufficient sample rate is anything larger than `2B` samples per second; equivalently, for a given `fs` perfect reconstruction is possible for a bandlimit `B < fs/2`. The threshold `2B` is the **Nyquist rate**, an attribute of the input; `fs/2` is the **Nyquist frequency**, an attribute of the sampling equipment. When the bandlimit is too high, the reconstruction shows imperfections called aliasing. 以原文为准.
- **Wikipedia — Aliasing:** a reconstructed signal contains low-frequency components that were not in the original when the original has components above the Nyquist frequency `fs/2`; the alias frequencies of a real sinusoid are `|f + N·fs|`, and the point `f = fs/2` where the reconstruction folds is the folding frequency. Aliasing is generally avoided by applying low-pass anti-aliasing filters before sampling; the attenuated high-frequency components still produce aliases, but typically at amplitudes low enough not to matter. 以原文为准.

### Nyquist rate and folding

<Formula label="Sufficient sample rate">fs > 2 × B</Formula>

A real tone at `f` sampled at `fs` is read at the folded frequency, the distance from `f` to the nearest multiple of `fs`:

<Formula label="Folding">f_seen = min(f mod fs, fs − (f mod fs))</Formula>

**Worked example.** With `fs = 50 Hz` the Nyquist frequency is 25 Hz. A 40 Hz tone gives `40 mod 50 = 40`, and `50 − 40 = 10`, so the samples look exactly like a 10 Hz tone. With `fs = 200 Hz` the same 40 Hz tone is below `fs/2 = 100 Hz` and is read at 40 Hz, but a 150 Hz vibration on the same wire folds to `200 − 150 = 50 Hz` and appears as a peak that was never in the band you wanted. At the boundary: with `fs = 100 Hz`, a 49 Hz tone (0.98 × fs/2) is read at 49 Hz and a 51 Hz tone (1.02 × fs/2) is also read at 49 Hz.

**Why about two samples per period.** To tell a sinusoid apart from slower ones, the samples must catch it going both up and down, so you need more than two samples per period, at least one in every half-cycle; with fewer, a slower sinusoid passes through exactly the same sample points and the two cannot be told apart.

An anti-alias prefilter is a low-pass placed **before** the sampler. This toy uses a 4th-order Butterworth magnitude with its corner at a quarter of the sample rate:

<Formula label="Prefilter magnitude">|H(f)| = 1 / √(1 + (f / FC)^8), FC = 0.25 × fs</Formula>

At `fs = 200 Hz` (`FC = 50 Hz`) the toy prints the gain as 0.9917 at 30 Hz, 0.8361 at 45 Hz, 0.1508 at 80 Hz and 0.0301 at 120 Hz. The filter that removes the 150 Hz vibration also shrinks a 45 Hz tone you wanted by 16 %. **Safe sampling** in this toy means `fs > 2B` for the wanted tone **and** no tone above `fs/2` left above the 0.05 peak threshold after the declared prefilter.

**No integration step here.** Each sample is evaluated in closed form at `t = n / fs`; nothing is stepped in time, so no step-size stability criterion applies (the independent tests check that the script has no time step). The boundary that matters is the Nyquist frequency itself, and the tests check it at 0.98× and 1.02× of `fs/2`.

### Fair setup

`nyquist_aliasing_toy.py` is **synthetic** and stdlib only. **Model assumptions:** ideal impulse sampling (no aperture, no jitter, no quantisation; this is **not** a claim about any real ADC); a 1 s record, so the plain DFT has 1 Hz bins; every tone sits on an integer number of hertz, so a tone below `fs/2` lands on one bin with no leakage; the prefilter acts on each tone's amplitude in steady state (its phase delay is not modelled, because every metric here is a spectral magnitude); ADC noise with sd 0.01 is added after the prefilter.

| Arm | Sample rate | Prefilter |
|---|---|---|
| A_low | 50 Hz | none |
| B_aaf | 200 Hz | 4th-order Butterworth, FC = 0.25 × fs |
| C_raw | 200 Hz | none |

**Common random numbers:** for each (regime, seed, trial) the wanted tone's frequency, amplitude and phase, the interferer's frequency and phase, and the noise record are drawn once and shared by all three arms (the 50 Hz arm uses the first 50 noise samples). Five seeds × 8 trials; each metric is the per-seed mean over trials, reported as mean±sd over seeds. `freq_err_Hz` is the distance from the strongest DFT peak to the wanted tone; `false_peaks` counts bins above 0.05 that are not within ±1 bin of the wanted tone; `amp_err_%` is the amplitude error at the strongest peak, so in A it is measured **at the alias** when the tone has folded.

| Regime | Wanted tone | Interferer |
|---|---|---|
| slow_tone | 2–8 Hz | none |
| single_tone | 35–45 Hz | none |
| interferer | 10–30 Hz | 120–180 Hz, amplitude 0.5 |
| near_edge | 70–90 Hz | none |

**Choice made after seeing results.** The first run had three regimes; `slow_tone` was added afterwards to show a case where the 50 Hz rate is enough. Every other regime and every parameter (`FC = 0.25 × fs`, order 4, threshold 0.05, noise 0.01) is unchanged from that first run, so the three-regime run is the same three blocks printed below. The arm called `A_low` was named `A_under` in the first run; it was renamed because in `slow_tone` it is not under-sampled.

```python
#!/usr/bin/env python3
"""Synthetic Nyquist / aliasing toy: sample shared tones, read the spectrum. Stdlib only.

Ideal impulse sampling of a sum of sinusoids over a 1 s window, then a plain DFT
(1 Hz bins). Tones sit on integer Hz, so a tone below fs/2 lands on one bin with
no leakage; a tone above fs/2 lands on its alias bin |f - k fs|.

Arms (one shared signal per trial):
  A_low     fs = FS_LOW = 50 Hz, no prefilter (below 2B in every regime except slow_tone)
  B_aaf     fs = FS_HIGH (above 2B) with an analog anti-alias prefilter before sampling:
            4th-order Butterworth magnitude |H(f)| = 1 / sqrt(1 + (f / FC)^8), FC = 0.25 fs,
            applied to each tone's amplitude (steady state; phase delay not modelled,
            the metrics are spectral magnitudes)
  C_raw     fs = FS_HIGH, no prefilter

slow_tone was added after the first run (the other regimes and every parameter are unchanged).

Common random numbers: per seed and trial the tone frequencies, amplitudes, phases
and the ADC noise sequence (sd 0.01, added after the prefilter, drawn once at the
longest record and truncated) are shared by every arm. No integration step: the
signal is evaluated in closed form at each sample instant.

Metrics per trial, averaged over TRIALS per seed: freq_err = |strongest DFT peak -
wanted tone| in Hz; false_peaks = bins above THRESH that are not the wanted tone
(+-1 bin); amp_err = |amplitude at the strongest peak - wanted amplitude| in %.
Safe sampling: fs > 2B and no tone above fs/2 left above THRESH after the declared
prefilter. Labels: tie = identical on every seed; numerically zero = |paired mean|
and sd both < 1e-9 (effectively a tie, no sign count); |m| <= sd = near-tie;
|m| > sd = consistent gap (small if |m| < 20 % of the smaller arm mean, else clear),
with a sign count. Real scope / ADC: 本页未运行. Wikipedia definitions: 以原文为准.
"""
import cmath
import math
import random

SEEDS = (0, 1, 2, 3, 4)
TRIALS = 8
FS_LOW, FS_HIGH = 50, 200  # Hz, 1 s records -> 1 Hz DFT bins
FC_RATIO = 0.25  # prefilter corner FC = FC_RATIO * fs
ORDER = 4
THRESH = 0.05  # peak threshold (amplitude units; full-scale tone = 1)
NOISE = 0.01
NUM_ZERO = 1e-9
ARMS = ("A_low", "B_aaf", "C_raw")
# name: wanted tone range (Hz), wanted amplitude range, interferer range (Hz) or None, interferer amplitude
REGIMES = {
    "slow_tone": ((2, 8), (0.5, 1.0), None, 0.0),
    "single_tone": ((35, 45), (0.5, 1.0), None, 0.0),
    "interferer": ((10, 30), (0.5, 1.0), (120, 180), 0.5),
    "near_edge": ((70, 90), (0.5, 1.0), None, 0.0),
}
ARM_FS = {"A_low": FS_LOW, "B_aaf": FS_HIGH, "C_raw": FS_HIGH}


def prefilter(f, fs):
    return 1.0 / math.sqrt(1.0 + (f / (FC_RATIO * fs)) ** (2 * ORDER))


def alias(f, fs):
    """Apparent frequency of a real tone f after sampling at fs (folding about fs/2)."""
    r = f % fs
    return min(r, fs - r)


def shared_trial(regime, seed, trial):
    """Common random numbers: one signal + one noise record per (regime, seed, trial)."""
    (lo, hi), (alo, ahi), intr, iamp = REGIMES[regime]
    rng = random.Random(f"{regime}-{seed}-{trial}")
    tones = [(rng.randint(lo, hi), rng.uniform(alo, ahi), rng.uniform(0.0, 2 * math.pi))]
    if intr:
        tones.append((rng.randint(*intr), iamp, rng.uniform(0.0, 2 * math.pi)))
    noise = [rng.gauss(0.0, NOISE) for _ in range(FS_HIGH)]
    return tones, noise


def sample(arm, tones, noise):
    fs = ARM_FS[arm]
    gains = [prefilter(f, fs) if arm == "B_aaf" else 1.0 for f, _, _ in tones]
    return [sum(g * a * math.sin(2 * math.pi * f * n / fs + p) for g, (f, a, p) in zip(gains, tones)) + noise[n]
            for n in range(fs)]


def spectrum(x):
    """One-sided amplitude spectrum, bins 1..N/2-1 (1 Hz apart for a 1 s record)."""
    n = len(x)
    return {k: 2.0 / n * abs(sum(v * cmath.exp(-2j * math.pi * k * i / n) for i, v in enumerate(x)))
            for k in range(1, n // 2)}


def trial_metrics(arm, tones, noise):
    spec = spectrum(sample(arm, tones, noise))
    f0, a0, _ = tones[0]
    peak = max(spec, key=lambda k: (spec[k], -k))
    false = sum(1 for k, v in spec.items() if v > THRESH and abs(k - f0) > 1)
    return {"freq": float(abs(peak - f0)), "false": float(false), "amp": 100.0 * abs(spec[peak] - a0) / a0}


def safe(arm, tones):
    fs = ARM_FS[arm]
    g = (lambda f: prefilter(f, fs)) if arm == "B_aaf" else (lambda f: 1.0)
    left = [f for f, a, _ in tones if f >= fs / 2 and g(f) * a > THRESH]
    return fs > 2 * tones[0][0] and not left


def mean_sd(xs):
    mu = sum(xs) / len(xs)
    return mu, math.sqrt(sum((x - mu) ** 2 for x in xs) / (len(xs) - 1))


def num(x):
    if x != 0.0 and abs(x) < 5e-5:
        return f"{x:.3e}"
    return f"{x:.4f}"


def sign_note(diffs, m):
    n, opp, zero = len(diffs), sum(1 for d in diffs if d * m < 0), sum(1 for d in diffs if d == 0)
    if opp == 0 and zero == 0:
        return f"same sign on all {n} seeds"
    if opp == 0:
        return f"no seed has the opposite sign, {zero} of {n} equal"
    note = f"{opp} of {n} seeds {'has' if opp == 1 else 'have'} the opposite sign"
    return note + (f", {zero} of {n} equal" if zero else "")


def verdict(xa, xb):
    diffs = [a - b for a, b in zip(xa, xb)]
    if all(d == 0.0 for d in diffs):
        return "0.0000+-0.0000: tie: identical on every seed"
    m, s = mean_sd(diffs)
    if abs(m) < NUM_ZERO and s < NUM_ZERO:
        return f"{num(m)}+-{num(s)}: numerically zero (floating-point residue), effectively a tie"
    if abs(m) <= s:
        label = "near-tie / small gap, within seed noise (|m| <= sd)"
    elif abs(m) < 0.2 * min(abs(mean_sd(xa)[0]), abs(mean_sd(xb)[0])):
        label = "small but consistent gap, not a tie (|m| > sd)"
    else:
        label = "clear gap, not a tie (|m| > sd)"
    return f"{num(m)}+-{num(s)}: {label}; {sign_note(diffs, m)}"


def main():
    print("Synthetic sampling toy; ideal impulse sampling + plain DFT; shared tones / phases / ADC noise; not a real ADC")
    print(f"seeds={len(SEEDS)} trials={TRIALS} record=1 s fs_low={FS_LOW} Hz fs_high={FS_HIGH} Hz "
          f"prefilter Butterworth order {ORDER} FC={FC_RATIO} fs threshold={THRESH} noise sd={NOISE}; no time step (closed-form samples)")
    print(f"folding check: fs=100 Hz, tone 49 Hz -> {alias(49, 100)} Hz, tone 51 Hz -> {alias(51, 100)} Hz, "
          f"tone 150 Hz -> {alias(150, 100)} Hz; fs=200 Hz, tone 150 Hz -> {alias(150, 200)} Hz")
    print(f"prefilter gain at fs=200 Hz: 30 Hz {prefilter(30, 200):.4f}, 45 Hz {prefilter(45, 200):.4f}, "
          f"80 Hz {prefilter(80, 200):.4f}, 120 Hz {prefilter(120, 200):.4f}, 180 Hz {prefilter(180, 200):.4f}")
    print("regime arm freq_err_Hz false_peaks amp_err_%  safe_trials  (mean+-sd over seeds of per-seed trial means)")
    for regime in REGIMES:
        (lo, hi), _, intr, iamp = REGIMES[regime]
        print(f"{regime} (wanted {lo}..{hi} Hz" + (f", interferer {intr[0]}..{intr[1]} Hz amp {iamp}" if intr else "") + ")")
        res = {a: [] for a in ARMS}
        nsafe = {a: 0 for a in ARMS}
        for seed in SEEDS:
            per = {a: [] for a in ARMS}
            for trial in range(TRIALS):
                tones, noise = shared_trial(regime, seed, trial)
                for a in ARMS:
                    per[a].append(trial_metrics(a, tones, noise))
                    nsafe[a] += safe(a, tones)
            for a in ARMS:
                res[a].append({k: sum(t[k] for t in per[a]) / TRIALS for k in ("freq", "false", "amp")})
        for a in ARMS:
            cells = " ".join("{}+-{}".format(*map(num, mean_sd([r[k] for r in res[a]]))) for k in ("freq", "false", "amp"))
            print(f"  {a} fs={ARM_FS[a]} {cells}  safe {nsafe[a]}/{len(SEEDS) * TRIALS}")
        for x, y in (("A_low", "B_aaf"), ("C_raw", "B_aaf")):
            for k in ("freq", "false", "amp"):
                print(f"  paired {x[0]}-{y[0]} {k}: {verdict([r[k] for r in res[x]], [r[k] for r in res[y]])}")
    print("slow_tone: 50 Hz is already above 2B, so the low rate reads the tone as well as the high one")
    print("single_tone: below 2B the tone folds to fs - f; above 2B the prefilter costs passband droop at 35..45 Hz")
    print("interferer: without a prefilter the 120..180 Hz tone folds into 20..80 Hz and reads as a real peak")
    print("near_edge: a corner at 0.25 fs eats a 70..90 Hz wanted tone; fs > 2B is not enough with a real filter")
    print("No winner declared: an anti-alias filter needs fs well above 2B so its corner clears the band you want")
    print("Real scope / ADC: 本页未运行; Wikipedia definitions 以原文为准")


if __name__ == "__main__":
    main()
```

### Read the regimes

How the labels are used on this page, in this order: **tie: identical on every seed** only when the paired per-seed difference is exactly zero on every seed; **numerically zero (floating-point residue), effectively a tie** when `|paired mean|` and its sd are both below 1e-9 (no sign count is printed on such a line); **near-tie / small gap, within seed noise** when `|paired mean| ≤ sd`; otherwise a **consistent** gap (`|paired mean| > sd`), called **small** if `|m|` is under 20 % of the smaller arm mean and **clear** otherwise; the 20 % rule only chooses between those two words. Every consistent line carries a same-sign count over the 5 seeds, and any seed with the opposite sign is reported; a sign count alone never makes a gap consistent. Gaps are computed from unrounded values.

- **slow_tone:** 50 Hz is already above `2B` for a 2–8 Hz tone, so A finds the right frequency: paired A−B frequency error and false peaks are a **tie: identical on every seed**. A's amplitude error is larger with a clear gap (paired A−B 0.1110±0.0533, same sign on all 5 seeds) because 50 samples average the noise less than 200. The prefilter costs B nothing here: C−B amplitude is −1.322e-06±2.423e-06, a **near-tie / small gap, within seed noise** with 1 of 5 seeds of the opposite sign. It is not numerically zero: the droop at 8 Hz is tiny but larger than 1e-9.
- **single_tone:** A samples a 35–45 Hz tone at 50 Hz and reads it 29.8500±0.3791 Hz away, as the fold predicts. **A loses with a clear gap:** paired A−B frequency error 29.8500±0.3791 and false peaks 1.0000±0.0000, both same sign on all 5 seeds. A's amplitude error looks better than B's (paired −7.9810±0.5252, clear, 5/5) only because it is measured on the alias. B and C find the same frequency (**tie** on frequency error and on false peaks), but **B loses amplitude with a clear gap:** 8.2123±0.5281 % against 0.1059±0.0248 % (paired C−B −8.1064±0.5337, same sign on all 5 seeds). That is the passband droop of a corner at 50 Hz on a 35–45 Hz tone.
- **interferer:** without a prefilter the 120–180 Hz tone folds into 20–80 Hz. **C loses with a clear gap** on false peaks: 0.9750±0.0559 per trial against B's 0 (paired C−B 0.9750±0.0559, same sign on all 5 seeds), and C counts as unsafe on 0 of 40 trials. It is not exactly 1 because a fold that lands within ±1 bin of the wanted tone is not counted as a separate peak. Both arms still find the wanted tone (**tie** on frequency error), and their amplitude errors are a **near-tie / small gap, within seed noise** (C−B −0.1308±0.1390; all 5 seeds have the same sign, but `|m| ≤ sd`). A loses frequency and false peaks with clear gaps (2.2000±1.8804 Hz and 1.1500±0.2236, 5/5); its amplitude error against B is a near-tie (3.0909±4.6715, 1 of 5 seeds of the opposite sign).
- **near_edge:** a 70–90 Hz wanted tone at `fs = 200 Hz` meets `fs > 2B`, and B even counts as safe on 40 of 40 trials, but the prefilter corner at 50 Hz eats it. **B loses with a clear gap:** amplitude error 84.6084±1.3317 % against C's 0.1260±0.0244 % (paired C−B −84.4824±1.3352, same sign on all 5 seeds). The rule `fs > 2B` is necessary but not enough: a real filter needs room between the band you want and `fs/2`. A loses frequency with a clear gap (paired A−B 63.2750±4.1102, 5/5).

The page **does not declare a universal winner**: a low rate is fine when the band is low, a prefilter is the only arm that rejects an out-of-band tone, and the same prefilter distorts a wanted tone that sits close to its corner. Real scope or ADC: **本页未运行**.
