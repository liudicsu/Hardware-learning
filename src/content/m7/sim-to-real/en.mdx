Policies that look perfect in lesson 7.1 or 7.3 often fall apart on a real SO-101. The <Term id="sim-to-real-gap">reality gap</Term> comes from mass, friction, damping, actuator bandwidth, appearance, sensor noise and **latency**. Two complementary answers: <Term id="system-identification">system identification</Term> fits the sim to a measured plant; <Term id="domain-randomization">domain randomisation</Term> trains across a distribution so the policy does not overfit one sim. This lesson runs a 1st-order sysid toy, a friction×delay×bias DR scan with Wilson intervals, and a hardware checklist. Safety here uses general engineering practice (torque / speed limits, a reachable e-stop, never bypass joint limits) — we do not hard-bind ISO clause numbers in this page.

## Reality gap, sysid, DR

Classic references (re-checked this batch):

- Tobin et al., 2017, arXiv 1703.06907 — **visual** domain randomisation for transferring deep networks from sim to the real world.
- Peng et al., 2017, arXiv 1710.06537 — **dynamics** randomisation for sim-to-real robotic control.

Sysid asks: "what τ, mass, friction does **my** arm actually have?" DR asks: "can the policy still succeed when those parameters wander?" You usually want both: identify a nominal plant, then randomise around it.

MuJoCo can model observation delay as a multiple of the simulation timestep (proposal reminder: `nsample × timestep`). The DR toy below uses an explicit command-delay queue instead of a full MJCF.

## Fit a lag, then scramble it

```python
#!/usr/bin/env python3
"""Fit a 1st-order lag model to a synthetic joint step response (stdlib).

System identification (sysid) estimates real dynamics so the sim can be
calibrated before domain randomization. We synthesize:

    y[k+1] = y[k] + dt/tau * (u[k] - y[k]) + noise

then recover ``tau_hat`` by least-squares on the discrete update. Relative
error must stay under 5 % for the CI gate (proposal §2.4).
"""
from __future__ import annotations

import math
import random

SEED = 11
DT = 0.01
TRUE_TAU = 0.08  # seconds
NOISE_STD = 0.002
N_STEPS = 400
STEP_AMPLITUDE = 1.0


def simulate(tau: float, rng: random.Random) -> list[tuple[float, float, float]]:
    """Return list of (t, u, y)."""
    y = 0.0
    rows = []
    for k in range(N_STEPS):
        t = k * DT
        u = 0.0 if t < 0.2 else STEP_AMPLITUDE
        y = y + (DT / tau) * (u - y) + rng.gauss(0.0, NOISE_STD)
        rows.append((t, u, y))
    return rows


def fit_tau(rows: list[tuple[float, float, float]]) -> float:
    """LS fit of y_{k+1}-y_k = (dt/tau)(u_k - y_k) → beta=dt/tau."""
    # beta * x = dy  with x = (u - y)
    num = 0.0
    den = 0.0
    for i in range(len(rows) - 1):
        _, u, y = rows[i]
        _, _, y2 = rows[i + 1]
        x = u - y
        dy = y2 - y
        num += x * dy
        den += x * x
    beta = num / den
    if beta <= 1e-9:
        raise RuntimeError("degenerate fit")
    return DT / beta


def main() -> None:
    rng = random.Random(SEED)
    rows = simulate(TRUE_TAU, rng)
    tau_hat = fit_tau(rows)
    rel_err = abs(tau_hat - TRUE_TAU) / TRUE_TAU
    print("sysid_fit — 1st-order lag step response (seed=%d)" % SEED)
    print("dt=%.3f  true_tau=%.4f  noise_std=%.4f  n=%d" % (DT, TRUE_TAU, NOISE_STD, N_STEPS))
    print("tau_hat=%.6f  rel_err=%.4f (%.2f%%)" % (tau_hat, rel_err, 100 * rel_err))
    assert rel_err < 0.05, "sysid relative error %.4f exceeds 5%%" % rel_err
    print("ok: |tau_hat - true_tau|/true_tau < 5%")


if __name__ == "__main__":
    main()
```

```python
#!/usr/bin/env python3
"""Domain-randomization scan: friction / latency / sensor bias vs grasp success.

A short open-loop close-then-lift schedule that succeeds under nominal
parameters is replayed under friction×{1.0,0.7,0.4}, command delay {0,2,5}
steps, and vertical sensor bias {0, ±1.5 cm}. Per-cell rates use a Wilson
score interval (same idea as month-6 ``eval_report.py``).

Takeaway for lesson 7.4: latency and friction misspecification open the
reality gap even when the policy schedule is unchanged — motivate sysid + DR
before any SO-101 deployment.
"""
from __future__ import annotations

import math
import random
from dataclasses import dataclass

SEED = 13
N_TRIALS = 40
DT = 0.02
HORIZON = 60
LIFT_TARGET = 0.10  # metres
PALM_SPEED = 0.35   # m/s commanded when "lifting"


def wilson(successes: int, n: int, z: float = 1.96) -> tuple[float, float, float]:
    if n <= 0:
        return 0.0, 0.0, 0.0
    p = successes / n
    den = 1.0 + z * z / n
    centre = (p + z * z / (2 * n)) / den
    half = (z / den) * math.sqrt(p * (1 - p) / n + z * z / (4 * n * n))
    return p, max(0.0, centre - half), min(1.0, centre + half)


@dataclass
class TrialResult:
    success: bool
    final_z: float
    slipped: bool


def simulate(friction_scale: float, delay: int, z_bias: float, rng: random.Random) -> TrialResult:
    """Kinematic lift with a single slip draw when the lift starts.

    Slip probability rises when friction is low **or** the close command is
    delayed relative to the lift (gripper still open when the palm rises).
    ``z_bias`` affects only the measured height used for the success check.
    """
    true_z = 0.0
    # delayed commands
    close_q = [False] * delay
    lift_q = [0.0] * delay
    closed = False
    lift_started = False
    slipped = False
    for t in range(HORIZON):
        intend_close = t >= 5
        intend_lift = PALM_SPEED if t >= 12 else 0.0
        close_q.append(intend_close)
        lift_q.append(intend_lift)
        do_close = close_q.pop(0)
        lift_cmd = lift_q.pop(0)
        if do_close:
            closed = True
        if lift_cmd > 0.0 and not lift_started:
            lift_started = True
            # one-shot slip draw at lift onset
            # base fail ~ 0.05 at fric=1, delay=0; grows with (1-fric) and delay
            fail_p = 0.05 + 0.55 * (1.0 - friction_scale) + 0.08 * delay
            # if close has not yet arrived when lift starts, almost certain slip
            if not closed:
                fail_p = max(fail_p, 0.9)
            fail_p = max(0.0, min(0.95, fail_p))
            if rng.random() < fail_p:
                slipped = True
        if lift_cmd > 0.0 and closed and not slipped:
            true_z += lift_cmd * DT
        elif slipped:
            true_z = max(0.0, true_z - 0.4 * DT)
    measured = true_z + z_bias
    success = (not slipped) and closed and measured >= LIFT_TARGET
    return TrialResult(success=success, final_z=true_z, slipped=slipped)


def scan_cell(friction_scale: float, delay: int, z_bias: float, seed: int):
    rng = random.Random(seed)
    ok = 0
    for _ in range(N_TRIALS):
        r = random.Random(rng.randint(0, 10**9))
        if simulate(friction_scale, delay, z_bias, r).success:
            ok += 1
    p, lo, hi = wilson(ok, N_TRIALS)
    return ok, p, lo, hi


def main() -> None:
    cells = [
        # fric, delay, bias
        (1.0, 0, 0.0),
        (0.7, 0, 0.0),
        (0.4, 0, 0.0),
        (1.0, 2, 0.0),
        (1.0, 5, 0.0),
        (1.0, 0, -0.015),
        (0.4, 5, -0.015),
    ]
    print("randomize_eval — DR scan friction×delay×z_bias (seed=%d, trials/cell=%d)"
          % (SEED, N_TRIALS))
    print("lift_target=%.2f m  palm_speed=%.2f m/s" % (LIFT_TARGET, PALM_SPEED))
    print("fric  delay  z_bias  ok/%d  rate   wilson95" % N_TRIALS)
    rates = {}
    for i, (fs, dly, zb) in enumerate(cells):
        ok, p, lo, hi = scan_cell(fs, dly, zb, seed=SEED + 19 * i)
        rates[(fs, dly, zb)] = p
        print(" %.1f  %5d  %+6.3f  %3d    %.3f  [%.3f, %.3f]" % (fs, dly, zb, ok, p, lo, hi))
    nom = rates[(1.0, 0, 0.0)]
    assert nom >= 0.85, "nominal success too low: %.3f" % nom
    assert rates[(1.0, 5, 0.0)] < nom - 0.2, "delay=5 should clearly hurt vs nominal"
    assert rates[(0.4, 0, 0.0)] < nom - 0.2, "low friction should clearly hurt"
    assert rates[(0.4, 5, -0.015)] <= 0.15, "worst cell should be near floor"
    print("ok: DR scan shows friction/delay/bias sensitivity (Wilson intervals)")


if __name__ == "__main__":
    main()
```

## Checklist: moving 7.1 / 7.3 policies to hardware

Mark every hardware step **needs hardware**. Before enabling a learned policy on an SO-101 / Feetech stack:

1. **Zero / home.** Record the encoder reading at a mechanical hard-stop or marked jig; write it down; confirm the URDF / MJCF zero matches.
2. **Limits.** Software joint limits inside the manufacturer range; torque and speed caps below stall; a physically reachable e-stop that cuts motor power.
3. **Latency budget.** Measure command-to-motion delay (scope or timestamped log). If it exceeds what the DR scan survived, fix the stack before blaming the policy.
4. **Sensor path.** Depth / proprio offsets: re-run a small zero-check after every camera remount (ties to lesson 7.6 hand-eye).
5. **Failure log.** For each real trial record: slip, timeout, collision, e-stop, tracking divergence — same discipline as Month 6's failure table.

Isaac Lab (README: GPU-accelerated; Isaac Sim workflows target Isaac Sim 6.2) can host large DR campaigns; it is optional and **not required on this page**. Prefer the CPU toys above until the checklist is green.

## Common mistakes

- **Randomising appearance only.** Tobin-style visual DR does not fix a wrong τ; Peng-style dynamics DR does not fix a wrong camera extrinsics.
- **Skipping sysid because "DR will cover it".** A nominal plant that is 2× too soft wastes the whole DR budget on an empty region.
- **No e-stop rehearsal.** A policy that closes the jaws on a finger is not an "interesting failure mode" — it is a lab incident.
- **Reporting a single success rate without an interval.** The Wilson column exists so 21/40 and 37/40 are not treated as equally precise.
