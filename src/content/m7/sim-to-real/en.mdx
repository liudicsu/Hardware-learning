Policies that look perfect in lesson 7.1 or 7.3 often fall apart on a real SO-101. The <Term id="sim-to-real-gap">reality gap</Term> comes from mass, friction, damping, actuator bandwidth, appearance, sensor noise and **latency**. Two complementary answers: <Term id="system-identification">system identification</Term> fits the sim to a measured plant; <Term id="domain-randomization">domain randomisation</Term> trains across a distribution so the policy does not overfit one sim. This lesson runs a 1st-order sysid toy, a friction×delay×bias DR scan with Wilson intervals, and a hardware checklist. Safety here uses general engineering practice (torque / speed limits, a reachable e-stop, never bypass joint limits) — we do not hard-bind ISO clause numbers in this page.

## Reality gap, sysid, DR

Classic references (re-checked this batch):

- Tobin et al., 2017, arXiv 1703.06907 — **visual** domain randomisation for transferring deep networks from sim to the real world.
- Peng et al., 2017, arXiv 1710.06537 — **dynamics** randomisation for sim-to-real robotic control.

Sysid asks: "what τ, mass, friction does **my** arm actually have?" DR asks: "can the policy still succeed when those parameters wander?" You usually want both: identify a nominal plant, then randomise around it.

MuJoCo can model observation delay as a multiple of the simulation timestep (proposal reminder: `nsample × timestep`). The DR toy below uses an explicit command-delay queue instead of a full MJCF.

```python
#!/usr/bin/env python3
"""Fit a 1st-order lag model to a synthetic joint step response (stdlib).

System identification (sysid) estimates real dynamics so the sim can be
calibrated before domain randomization. We synthesize:

    y[k+1] = y[k] + dt/tau * (u[k] - y[k]) + noise

then recover ``tau_hat`` by least-squares on the discrete update. Relative
error must stay under 5 % for the CI gate (proposal §2.4).
"""
from __future__ import annotations

import math
import random

SEED = 11
DT = 0.01
TRUE_TAU = 0.08  # seconds
NOISE_STD = 0.002
N_STEPS = 400
STEP_AMPLITUDE = 1.0


def simulate(tau: float, rng: random.Random) -> list[tuple[float, float, float]]:
    """Return list of (t, u, y)."""
    y = 0.0
    rows = []
    for k in range(N_STEPS):
        t = k * DT
        u = 0.0 if t < 0.2 else STEP_AMPLITUDE
        y = y + (DT / tau) * (u - y) + rng.gauss(0.0, NOISE_STD)
        rows.append((t, u, y))
    return rows


def fit_tau(rows: list[tuple[float, float, float]]) -> float:
    """LS fit of y_{k+1}-y_k = (dt/tau)(u_k - y_k) → beta=dt/tau."""
    # beta * x = dy  with x = (u - y)
    num = 0.0
    den = 0.0
    for i in range(len(rows) - 1):
        _, u, y = rows[i]
        _, _, y2 = rows[i + 1]
        x = u - y
        dy = y2 - y
        num += x * dy
        den += x * x
    beta = num / den
    if beta <= 1e-9:
        raise RuntimeError("degenerate fit")
    return DT / beta


def main() -> None:
    rng = random.Random(SEED)
    rows = simulate(TRUE_TAU, rng)
    tau_hat = fit_tau(rows)
    rel_err = abs(tau_hat - TRUE_TAU) / TRUE_TAU
    print("sysid_fit — 1st-order lag step response (seed=%d)" % SEED)
    print("dt=%.3f  true_tau=%.4f  noise_std=%.4f  n=%d" % (DT, TRUE_TAU, NOISE_STD, N_STEPS))
    print("tau_hat=%.6f  rel_err=%.4f (%.2f%%)" % (tau_hat, rel_err, 100 * rel_err))
    assert rel_err < 0.05, "sysid relative error %.4f exceeds 5%%" % rel_err
    print("ok: |tau_hat - true_tau|/true_tau < 5%")


if __name__ == "__main__":
    main()
```

```python
#!/usr/bin/env python3
"""Domain-randomization scan: friction / latency / sensor bias vs grasp success.

A short open-loop close-then-lift schedule that succeeds under nominal
parameters is replayed under friction×{1.0,0.7,0.4}, command delay {0,2,5}
steps, and vertical sensor bias {0, ±1.5 cm}. Per-cell rates use a Wilson
score interval (same idea as month-6 ``eval_report.py``).

Takeaway for lesson 7.4: latency and friction misspecification open the
reality gap even when the policy schedule is unchanged — motivate sysid + DR
before any SO-101 deployment.
"""
from __future__ import annotations

import math
import random
from dataclasses import dataclass

SEED = 13
N_TRIALS = 40
DT = 0.02
HORIZON = 60
LIFT_TARGET = 0.10  # metres
PALM_SPEED = 0.35   # m/s commanded when "lifting"


def wilson(successes: int, n: int, z: float = 1.96) -> tuple[float, float, float]:
    if n <= 0:
        return 0.0, 0.0, 0.0
    p = successes / n
    den = 1.0 + z * z / n
    centre = (p + z * z / (2 * n)) / den
    half = (z / den) * math.sqrt(p * (1 - p) / n + z * z / (4 * n * n))
    return p, max(0.0, centre - half), min(1.0, centre + half)


@dataclass
class TrialResult:
    success: bool
    final_z: float
    slipped: bool


def simulate(friction_scale: float, delay: int, z_bias: float, rng: random.Random) -> TrialResult:
    """Kinematic lift with a single slip draw when the lift starts.

    Slip probability rises when friction is low **or** the close command is
    delayed relative to the lift (gripper still open when the palm rises).
    ``z_bias`` affects only the measured height used for the success check.
    """
    true_z = 0.0
    # delayed commands
    close_q = [False] * delay
    lift_q = [0.0] * delay
    closed = False
    lift_started = False
    slipped = False
    for t in range(HORIZON):
        intend_close = t >= 5
        intend_lift = PALM_SPEED if t >= 12 else 0.0
        close_q.append(intend_close)
        lift_q.append(intend_lift)
        do_close = close_q.pop(0)
        lift_cmd = lift_q.pop(0)
        if do_close:
            closed = True
        if lift_cmd > 0.0 and not lift_started:
            lift_started = True
            # one-shot slip draw at lift onset
            # base fail ~ 0.05 at fric=1, delay=0; grows with (1-fric) and delay
            fail_p = 0.05 + 0.55 * (1.0 - friction_scale) + 0.08 * delay
            # if close has not yet arrived when lift starts, almost certain slip
            if not closed:
                fail_p = max(fail_p, 0.9)
            fail_p = max(0.0, min(0.95, fail_p))
            if rng.random() < fail_p:
                slipped = True
        if lift_cmd > 0.0 and closed and not slipped:
            true_z += lift_cmd * DT
        elif slipped:
            true_z = max(0.0, true_z - 0.4 * DT)
    measured = true_z + z_bias
    success = (not slipped) and closed and measured >= LIFT_TARGET
    return TrialResult(success=success, final_z=true_z, slipped=slipped)


def scan_cell(friction_scale: float, delay: int, z_bias: float, seed: int):
    rng = random.Random(seed)
    ok = 0
    for _ in range(N_TRIALS):
        r = random.Random(rng.randint(0, 10**9))
        if simulate(friction_scale, delay, z_bias, r).success:
            ok += 1
    p, lo, hi = wilson(ok, N_TRIALS)
    return ok, p, lo, hi


def main() -> None:
    cells = [
        # fric, delay, bias
        (1.0, 0, 0.0),
        (0.7, 0, 0.0),
        (0.4, 0, 0.0),
        (1.0, 2, 0.0),
        (1.0, 5, 0.0),
        (1.0, 0, -0.015),
        (0.4, 5, -0.015),
    ]
    print("randomize_eval — DR scan friction×delay×z_bias (seed=%d, trials/cell=%d)"
          % (SEED, N_TRIALS))
    print("lift_target=%.2f m  palm_speed=%.2f m/s" % (LIFT_TARGET, PALM_SPEED))
    print("fric  delay  z_bias  ok/%d  rate   wilson95" % N_TRIALS)
    rates = {}
    for i, (fs, dly, zb) in enumerate(cells):
        ok, p, lo, hi = scan_cell(fs, dly, zb, seed=SEED + 19 * i)
        rates[(fs, dly, zb)] = p
        print(" %.1f  %5d  %+6.3f  %3d    %.3f  [%.3f, %.3f]" % (fs, dly, zb, ok, p, lo, hi))
    nom = rates[(1.0, 0, 0.0)]
    assert nom >= 0.85, "nominal success too low: %.3f" % nom
    assert rates[(1.0, 5, 0.0)] < nom - 0.2, "delay=5 should clearly hurt vs nominal"
    assert rates[(0.4, 0, 0.0)] < nom - 0.2, "low friction should clearly hurt"
    assert rates[(0.4, 5, -0.015)] <= 0.15, "worst cell should be near floor"
    print("ok: DR scan shows friction/delay/bias sensitivity (Wilson intervals)")


if __name__ == "__main__":
    main()
```

## Contact DR versus latency-only

The scan above only *measures* how a frozen schedule breaks. The next question is whether randomising **while you tune** helps, and what it costs. `randomize_eval.py` put friction and delay in the same table; here they are separated. One arm randomises **latency only** and keeps contact parameters at their nominal values. The other randomises the **contact parameters**, friction coefficient µ and block mass, on top of the same latency.

The toy task: a force-limited pusher drives a block along a line at a commanded speed `v_cmd`. It plans its release mark from the **nominal** model: the block should slide `v_cmd² / (2 µ₀ g)` after release, plus the mean latency travel. The stop command lands L seconds late, then the block slides with a Coulomb friction proxy (deceleration µ·g) until it rests. Success means stopping within ±15 mm of 0.30 m, and at rest within 1.5 s. A heavier block accelerates more slowly under the same 5 N force limit.

What makes the comparison fair:

- **One controller parameter**, `v_cmd`, tuned by both arms over the same 41-value grid (0.20–1.00 m/s).
- **Same budget:** 200 training episodes per candidate in both arms.
- **Same noise seed stream:** episode k of every arm and every candidate uses the same latency draw, the same ±3 % friction jitter and the same uniforms. The DR arm maps those uniforms onto µ ∈ [0.25, 0.60] and m ∈ [0.30, 0.90] kg.
- **Same score:** most successes first, then the shorter mean cycle time.
- **Shared evaluation episodes** (a separate seed), scored at nominal µ = 0.40 / m = 0.50 kg and at shifted µ and mass.

Nothing is fitted. No τ is refitted and no parameter is estimated: that is `sysid_fit.py` above, and persistent excitation belongs to 5.1. This is tuning a controller across a distribution. The friction is a one-line Coulomb proxy, **not** MuJoCo's soft-contact solver (7.1); real MuJoCo contact DR typically perturbs `solref` / `solimp` / `friction` on geoms (see the [MuJoCo XML reference](https://mujoco.readthedocs.io/en/stable/XMLreference.html)), and no real push on an SO-101 was run on this page (本页未运行).

```python
#!/usr/bin/env python3
"""contact_dr_toy.py: contact-parameter domain randomisation vs latency-only (stdlib).

A force-limited pusher drives a block along a line at a commanded speed v_cmd
(the ONE controller parameter tuned here). The release mark is planned from
the NOMINAL model (slide v^2 / (2 mu0 g) plus the mean latency travel); the
stop command lands L seconds late. The block then slides with a Coulomb
friction proxy (deceleration mu * g) until it rests. Success: final position
within TOL of X_TARGET and at rest by T_MAX. A heavier block accelerates more
slowly under the same force limit; lower friction slides further.

Two arms tune v_cmd on the SAME budget: the same candidate grid, the same
number of training episodes and the SAME noise seed stream (episode k of every
arm and every candidate uses the same latency draw, friction jitter and
uniforms). Score = successes, ties broken by the shorter mean cycle time.
  latency_only  randomises latency only; mu and mass stay nominal
  contact_dr    randomises the same latency AND mu, mass (contact parameters)
Both are evaluated on shared eval episodes: nominal mu / mass (in-distribution
for latency_only), shifted mu, shifted mass, and a mu outside the DR range.
No universal "DR wins": here it pays in nominal cycle time.
Not system identification: nothing is fitted (7.4's sysid_fit owns tau; 5.1
owns PE). The friction model is a toy proxy, not the MuJoCo contact solver.
Real pushing on an SO-101 is not run on this page (本页未运行).
usage: python3 contact_dr_toy.py
"""
from __future__ import annotations

import math
import random

SEED = 74
G = 9.81
DT = 0.001
X_TARGET = 0.30     # m
TOL = 0.015         # m
T_MAX = 1.5         # s, cycle-time limit (push + slide)
K_V, F_MAX = 40.0, 5.0          # N per m/s, N (force-limited pusher)
MU0, M0 = 0.40, 0.50            # nominal friction coefficient, kg
MU_RANGE, M_RANGE = (0.25, 0.60), (0.30, 0.90)   # contact DR ranges
LAT_RANGE = (0.0, 0.03)         # s, randomised in both arms
JITTER = 0.03                   # +-3 % per-episode friction jitter (both arms)
GRID = [round(0.20 + 0.02 * i, 2) for i in range(41)]   # v_cmd candidates 0.20..1.00
N_TRAIN, N_EVAL = 200, 200


def release_mark(v_cmd):
    """Release planned from the NOMINAL model: slide v^2/(2 mu0 g) plus mean latency travel."""
    return X_TARGET - v_cmd ** 2 / (2 * MU0 * G) - v_cmd * sum(LAT_RANGE) / 2


def episode(v_cmd, mu, m, lat):
    """(final position, time to rest) for one push-release-slide episode."""
    x_rel = release_mark(v_cmd)
    x, v, t_rel = 0.0, 0.0, None
    t = 0.0
    while True:
        pushing = t_rel is None or t < t_rel
        if pushing:
            f = max(0.0, min(F_MAX, K_V * (v_cmd - v)))
            a = (f - mu * m * G) / m
            if v <= 0.0 and a < 0.0:
                a = 0.0
        else:
            a = -mu * G
        v = max(0.0, v + a * DT)
        x += v * DT
        t += DT
        if t_rel is None and x >= x_rel:
            t_rel = t + lat
        if t_rel is not None and t >= t_rel and v <= 0.0:
            return x, t
        if t > 10.0:
            return x, t


def draws(seed, n):
    """Shared noise stream: (latency, jitter, u_mu, u_m) per episode."""
    rng = random.Random(seed)
    return [(rng.uniform(*LAT_RANGE), rng.uniform(-JITTER, JITTER), rng.random(), rng.random())
            for _ in range(n)]


def params(arm, d, mu=None, m=None):
    lat, jit, u_mu, u_m = d
    if arm == "contact_dr":
        mu = MU_RANGE[0] + u_mu * (MU_RANGE[1] - MU_RANGE[0])
        m = M_RANGE[0] + u_m * (M_RANGE[1] - M_RANGE[0])
    return mu * (1.0 + jit), m, lat


def score(v_cmd, eps):
    """(successes, mean |err| m, mean cycle time s); success = within TOL and by T_MAX."""
    runs = [episode(v_cmd, mu, m, lat) for mu, m, lat in eps]
    errs = [abs(x - X_TARGET) for x, _ in runs]
    ok = sum(e <= TOL and t <= T_MAX for e, (_, t) in zip(errs, runs))
    return ok, sum(errs) / len(errs), sum(t for _, t in runs) / len(runs)


def tune(arm, train):
    eps = [params(arm, d, MU0, M0) for d in train]
    best = None
    for v in GRID:
        ok, mae, cyc = score(v, eps)
        if best is None or (ok, -cyc) > (best[1], -best[3]):   # success first, then faster cycle
            best = (v, ok, mae, cyc)
    return best


def main() -> None:
    train = draws(SEED, N_TRAIN)
    evals = draws(SEED + 1, N_EVAL)
    print(f"seed={SEED} target={X_TARGET} m tol=+-{TOL} m t_max={T_MAX} s "
          f"latency~U{LAT_RANGE} s jitter=+-{JITTER:.0%} F_max={F_MAX} N")
    print(f"budget per arm: {len(GRID)} v_cmd candidates x {N_TRAIN} train episodes, same seed stream")
    print(f"nominal mu={MU0} m={M0} kg; contact DR mu~U{MU_RANGE} m~U{M_RANGE} kg")
    tuned = {}
    for arm in ("latency_only", "contact_dr"):
        v, ok, mae, cyc = tune(arm, train)
        tuned[arm] = v
        print(f"tuned {arm:<12} v_cmd={v:.2f} m/s release_mark={release_mark(v):.3f} m  "
              f"train success={ok}/{N_TRAIN} mean|err|={mae * 1000:.1f} mm cycle={cyc:.2f} s")
    conds = (("nominal", MU0, M0), ("mu_low_0.28", 0.28, M0), ("mu_high_0.55", 0.55, M0),
             ("mass_0.85", MU0, 0.85), ("mu_out_0.15", 0.15, M0))
    print(f"{'eval (shared episodes)':<22} {'latency_only':>23} {'contact_dr':>23}")
    res = {}
    for name, mu, m in conds:
        cells = []
        eps = [params("eval", d, mu, m) for d in evals]
        for arm in ("latency_only", "contact_dr"):
            ok, mae, cyc = score(tuned[arm], eps)
            res[(name, arm)] = (ok, cyc)
            cells.append(f"{ok:3d}/{N_EVAL} {mae * 1000:5.1f}mm {cyc:4.2f}s")
        print(f"{name:<22} {cells[0]:>23} {cells[1]:>23}")
    lo, dr = "latency_only", "contact_dr"
    assert res[("nominal", lo)][0] >= res[("nominal", dr)][0], "latency_only should not lose in-distribution"
    assert res[("nominal", lo)][1] < res[("nominal", dr)][1], "DR pays cycle time at nominal"
    assert res[("mu_high_0.55", dr)][0] > res[("mu_high_0.55", lo)][0], "DR should help at shifted mu"
    assert res[("mass_0.85", dr)][0] > res[("mass_0.85", lo)][0], "DR should help at shifted mass"
    assert res[("mu_out_0.15", dr)][0] <= N_EVAL // 20, "outside the DR range DR is not a cure"
    print("ok: same budget / seed stream; DR trades nominal cycle time for shifted mu/mass; "
          "mu outside the DR range still fails; toy friction != MuJoCo; SO-101 本页未运行")


if __name__ == "__main__":
    main()
```

How to read it:

- **The two arms choose differently.** Latency-only picks 0.52 m/s (release mark 0.258 m). Contact DR picks 0.34 m/s (release mark 0.280 m), a slower push that leaves less to slide.
- **In distribution, DR does not win.** At nominal µ and mass both arms score 200/200. DR's mean error is smaller (4.6 vs 6.8 mm), but each push takes 1.08 s instead of 0.72 s, 50 % longer. That cycle time is what DR costs on the conditions latency-only was tuned for. Its own training score is also lower: 196/200 against 200/200.
- **Under shift, DR holds.** At µ = 0.55 latency-only drops to 81/200 while DR keeps 200/200. With a 0.85 kg block it is 156/200 against 200/200, and at µ = 0.28 it is 191/200 against 200/200.
- **Outside the randomised range, DR fails too.** At µ = 0.15 the scores are 0/200 and 2/200. DR covers the range you randomised, not beyond it.

Why slowing down helps: the slide is v² / (2µg), so the error from a wrong µ grows with v². At 0.52 m/s the block slides 34.5 mm at µ = 0.40 but 25.1 mm at µ = 0.55, a 9.4 mm shortfall before any latency jitter. At 0.34 m/s the slides are 14.7 mm and 10.7 mm, a 4.0 mm shortfall.

2. **Limits.** Software joint limits inside the manufacturer range; torque and speed caps below stall; a physically reachable e-stop that cuts motor power.
3. **Latency budget.** Measure command-to-motion delay (scope or timestamped log). If it exceeds what the DR scan survived, fix the stack before blaming the policy.
4. **Sensor path.** Depth / proprio offsets: re-run a small zero-check after every camera remount (ties to lesson 7.6 hand-eye).
5. **Failure log.** For each real trial record: slip, timeout, collision, e-stop, tracking divergence — same discipline as Month 6's failure table.

## Common mistakes

- **Randomising appearance only.** Tobin-style visual DR does not fix a wrong τ; Peng-style dynamics DR does not fix a wrong camera extrinsics.
- **Skipping sysid because "DR will cover it".** A nominal plant that is 2× too soft wastes the whole DR budget on an empty region.
- **No e-stop rehearsal.** A policy that closes the jaws on a finger is not an "interesting failure mode" — it is a lab incident.
- **Declaring DR the winner from shifted conditions only.** Report the nominal row and the cost too: in the toy DR ties at nominal (200/200) but every push takes 1.08 s instead of 0.72 s.
- **Testing outside the range you randomised.** At µ = 0.15, below the DR range [0.25, 0.60], DR scores 2/200. Widen the range only if the wider range is physically plausible for your arm.
- **Calling DR tuning system identification.** `contact_dr_toy.py` estimates nothing; it picks one controller parameter across a distribution. Sysid (above) and persistent excitation (5.1) are separate jobs.
- **Reporting a single success rate without an interval.** The Wilson column exists so 21/40 and 37/40 are not treated as equally precise.

## Visual domain randomisation after Tobin et al.

<Resource id="tobin-dr" />

The opening of this page cites Tobin et al. and *Common mistakes* warns that Tobin-style visual DR does not fix a wrong τ. This section reads the paper and adds the missing toy. The arXiv abstract page gives the title **Domain Randomization for Transferring Deep Neural Networks from Simulation to the Real World** and six authors: Josh Tobin, Rachel Fong, Alex Ray, Jonas Schneider, Wojciech Zaremba and Pieter Abbeel. From the PDF body (以论文为准): domain randomisation trains models on simulated images that transfer to real images **by randomising rendering in the simulator**; with enough variability the real world may appear to the model **as just another variation**. For each training sample the authors randomise the number and shape of distractor objects, the position and **texture** of every object, the textures of the table, floor, skybox and robot, the camera's position, orientation and field of view, the number of lights and their position, orientation and specular characteristics, and the type and amount of image noise. Textures are **non-realistic**: a random RGB value, a gradient between two random RGB values, or a checker between two random RGB values. The detector **does not have access to the colour** of the object of interest, only its size and shape, and the MuJoCo renderer they use is not intended to be photo-realistic.

Their reported results, 以论文为准 and **not** reproduced here: a real-world object detector trained only on simulated images is accurate to about 1.5 cm on average, robust to distractors and partial occlusions; a Fetch robot using it picked the target in 38 of 40 trials; and in the ablation, performance **degrades significantly when fewer than 1,000 textures** are used, while adding noise had a negligible effect on accuracy. The toy below is a **k-NN stand-in**, not their CNN, and its pixel errors are not centimetres.

This section is **not** the contact-DR toy above (that randomises µ and mass for a push controller), **not** the lag sysid fit and **not** Peng-style dynamics randomisation. It randomises **appearance only**, and then shows what appearance cannot buy.

**Worked example — a labelled hand calculation, also printed by the toy.** The object rides a conveyor at 30.0 px/s and the gripper arrives 0.10 s after the frame, so the object moves 3.0000 px in that time. A controller that assumes the simulator's τ = 0.05 s aims 30.0 × (0.10 − 0.05) = 1.5000 px short, which is not below the 1.0 px tolerance **even with a perfect detector**. No texture changes that number.

**No integration step here.** The toy evaluates closed-form positions; there is no ODE and no step-size criterion.

### Fair setup

`tobin_visual_domain_randomization_toy.py` is **synthetic** and stdlib only. **Model assumptions:** a 24-pixel grey-scale camera row shows one object 4.0 px wide at a continuous position on a background; each surface has a flat, gradient or checker texture, a lighting gain multiplies the row and Gaussian pixel noise is added. The detector is 3-nearest-neighbour regression on raw pixels from 600 training rows. All sizes, colours, gains, the conveyor speed and both τ values are **declared toy parameters**.

| Arm | Training appearance | τ used by the grasp controller |
|---|---|---|
| A_canonical | one canonical texture: bright flat object on a dark flat background, gain 1 | TAU_REAL (dynamics-aware) |
| B_random | 200 random textures from a palette, random gain in 0.6–1.4 (Tobin-style) | TAU_REAL (dynamics-aware) |
| C_rand_tau | B's detector, unchanged | TAU_SIM, the wrong τ |

**Common random numbers:** for each seed one set of training positions and pixel noise is drawn once and shared by A and B, so they differ **only** in textures and gains; for each (regime, seed) one test set of positions, textures, gains and noise is shared by every arm. C reuses B's detector exactly. B **never sees** the held-out test textures: the printed peek check confirms that neither the held-out textures nor the canonical one are in B's palette on any seed. Five seeds, 40 test rows each. Metrics are `loc_err` (px), `grasp_err` (px) and the success fraction, where a grasp succeeds only when `grasp_err` is **strictly** below TOL.

| Regime | Test appearance and motion | What was pre-declared |
|---|---|---|
| heldout | four held-out textures, static object | B **consistent** better transfer than A; C equals B because nothing moves |
| canonical | A's own training texture, static | A and B may **near-tie**, or B may **lose** (over-randomisation); **keep** |
| moving | held-out textures, 30.0 px/s | C **consistent** loses against B even with visual DR; **keep** |

```python
#!/usr/bin/env python3
"""Tobin-style visual domain randomisation: canonical texture vs random textures vs random textures + wrong tau.

Synthetic 1-D "camera row" and a k-nearest-neighbour detector, stdlib only.
Not a deep network, not MuJoCo rendering, not a real camera and not the
contact-DR or lag-sysid toys on this page.  GPU training / real camera /
robot: 本页未运行.  Tobin et al. (arXiv 1703.06907) statements and numbers
(for example their 1.5 cm) 以论文为准; nothing here reproduces them.

What the paper body says (and what this toy keeps): train a detector only on
simulated images whose rendering is randomised (non-realistic random
textures: a random RGB value, a gradient between two random values or a
checker between two random values; lights; noise), so that with enough
variability the real world may look like just another variation.  The
detector never sees the colour of the object, only its size and shape.  The
paper's ablation reports that fewer unique textures hurt transfer.

Toy: a W-pixel grey-scale row shows one object of width OBJ_W at a
continuous position x (anti-aliased coverage) on a background.  Each surface
has a texture: flat, gradient or checker between grey values.  A lighting
gain multiplies the row and Gaussian pixel noise is added.  The detector is
k-NN regression (K_NN neighbours, squared pixel distance) from the row to x.
Arms:
  A_canonical : trained on ONE canonical texture (bright flat object on a
                dark flat background, gain 1)
  B_random    : trained on PALETTE random textures (Tobin-style) and random
                gains; the held-out test textures are never in the palette
  C_rand_tau  : B's detector unchanged, but the grasp controller uses a wrong
                latency tau (TAU_SIM) instead of the real TAU_REAL
Grasp proxy: the object moves at U px/s on a conveyor; the gripper arrives
TAU_REAL after the frame and aims at x_hat + U * tau_model.  grasp_err =
|aim - true position at arrival|; success iff grasp_err < TOL (strict).
A and B use tau_model = TAU_REAL (dynamics-aware); C uses TAU_SIM.

Common random numbers: for each seed one training set of positions and
pixel noise is drawn once and shared by A and B (they differ only in
textures and gains); for each (regime, seed) one test set (positions,
textures, gains, noise) is shared by every arm.
No integration step: closed-form positions, no ODE, no time-step criterion.

Regimes and parameters were written before the first run:
  heldout   : held-out "real" textures, static object (U = 0)
              - B consistent better transfer than A; keep
              - C equals B (tau does not matter when nothing moves)
  canonical : test texture identical to A's training texture, U = 0
              - A and B may near-tie, or B may lose (over-randomisation); keep
  moving    : held-out textures, U = U_MOVE px/s
              - C consistent lose vs B even with visual DR (appearance does
                not fix a wrong tau); keep
Alternatives, also written before the first run, on the same seeds:
  PALETTE = 10 random textures instead of 200 (heldout);
  TOL = 2.0 px instead of 1.0 px (moving).
All sizes, colours, gains, U and tau values are declared toy parameters.
"""
from __future__ import annotations

import math
import random

SEEDS = (0, 1, 2, 3, 4)
NUM_ZERO = 1e-9
W = 24                  # pixels in the camera row (toy)
OBJ_W = 4.0             # object width, px (toy)
X_LO, X_HI = 2.0, 18.0  # object left edge range, px
N_TRAIN = 600
N_TEST = 40
K_NN = 3
PIX_SIGMA = 0.02        # pixel noise (toy)
PALETTE = 200           # unique random texturizations for B (toy)
GAIN_LO, GAIN_HI = 0.6, 1.4
U_MOVE = 30.0           # conveyor speed, px/s (toy)
TAU_REAL = 0.10         # s, real camera-to-gripper latency (toy)
TAU_SIM = 0.05          # s, the wrong latency C's controller uses (toy)
TOL = 1.0               # px, grasp succeeds iff grasp_err < TOL
ARMS = ("A_canonical", "B_random", "C_rand_tau")
CANON = (("flat", 0.80, 0.80), ("flat", 0.20, 0.20))   # (object, background)
# Held-out "real" textures: fixed, never drawn into B's palette.
REAL = (
    (("flat", 0.35, 0.35), ("checker", 0.60, 0.75)),
    (("gradient", 0.90, 0.70), ("flat", 0.50, 0.50)),
    (("checker", 0.10, 0.30), ("gradient", 0.30, 0.60)),
    (("flat", 0.60, 0.60), ("flat", 0.85, 0.85)),
)
REGIMES = {"heldout": ("real", 0.0), "canonical": ("canon", 0.0), "moving": ("real", U_MOVE)}
KINDS = ("flat", "gradient", "checker")


def texture_value(tex, i):
    kind, a, b = tex
    if kind == "flat":
        return a
    if kind == "gradient":
        return a + (b - a) * i / (W - 1)
    return a if i % 2 == 0 else b


def render(x, obj, bg, gain, noise):
    row = []
    for i in range(W):
        cover = max(0.0, min(i + 1.0, x + OBJ_W) - max(float(i), x))
        v = cover * texture_value(obj, i) + (1.0 - cover) * texture_value(bg, i)
        row.append(gain * v + noise[i])
    return row


def random_texture(rng):
    kind = KINDS[rng.randrange(3)]
    a = rng.random()
    b = a if kind == "flat" else rng.random()
    return (kind, a, b)


def palette(seed, size):
    rng = random.Random(f"tobin-palette|{seed}|{size}")
    return [(random_texture(rng), random_texture(rng)) for _ in range(size)]


def train_draws(seed):
    """Shared by A and B: positions, pixel noise, palette picks, gains."""
    rng = random.Random(f"tobin-train|{seed}")
    xs = [rng.uniform(X_LO, X_HI) for _ in range(N_TRAIN)]
    noise = [[rng.gauss(0.0, PIX_SIGMA) for _ in range(W)] for _ in range(N_TRAIN)]
    picks = [rng.random() for _ in range(N_TRAIN)]
    gains = [rng.uniform(GAIN_LO, GAIN_HI) for _ in range(N_TRAIN)]
    return xs, noise, picks, gains


def train_set(arm, seed, size=PALETTE):
    xs, noise, picks, gains = train_draws(seed)
    if arm == "A_canonical":
        return [(render(x, CANON[0], CANON[1], 1.0, n), x) for x, n in zip(xs, noise)]
    pal = palette(seed, size)
    return [(render(x, *pal[int(p * size)], g, n), x) for x, n, p, g in zip(xs, noise, picks, gains)]


def test_draws(regime, seed):
    rng = random.Random(f"tobin-test|{regime}|{seed}")
    which = REGIMES[regime][0]
    out = []
    for _ in range(N_TEST):
        x = rng.uniform(X_LO, X_HI)
        if which == "canon":
            obj, bg, gain = CANON[0], CANON[1], 1.0
        else:
            obj, bg = REAL[rng.randrange(len(REAL))]
            gain = rng.uniform(0.8, 1.2)
        noise = [rng.gauss(0.0, PIX_SIGMA) for _ in range(W)]
        out.append((render(x, obj, bg, gain, noise), x))
    return out


def knn(train, row):
    best = sorted((sum((a - b) ** 2 for a, b in zip(img, row)), x) for img, x in train)[:K_NN]
    return sum(x for _, x in best) / K_NN


def evaluate(arm, regime, seed, train, tol=TOL):
    u = REGIMES[regime][1]
    tau_model = TAU_SIM if arm == "C_rand_tau" else TAU_REAL
    loc, grasp, ok = [], [], 0
    for row, x in test_draws(regime, seed):
        xh = knn(train, row)
        aim = xh + u * tau_model
        err = abs(aim - (x + u * TAU_REAL))
        loc.append(abs(xh - x))
        grasp.append(err)
        ok += 1 if err < tol else 0
    return {"loc_err": sum(loc) / len(loc), "grasp_err": sum(grasp) / len(grasp), "success": ok / N_TEST}


def mean_sd(xs):
    mu = sum(xs) / len(xs)
    return mu, math.sqrt(sum((x - mu) ** 2 for x in xs) / (len(xs) - 1))


def num(x):
    if x != 0.0 and abs(x) < 5e-4:
        return f"{x:.3e}"
    return f"{x:.4f}"


def sign_note(diffs, m):
    n, opp, zero = len(diffs), sum(1 for d in diffs if d * m < 0), sum(1 for d in diffs if d == 0)
    if opp == 0 and zero == 0:
        return f"same sign on all {n} seeds"
    if opp == 0:
        return f"no seed has the opposite sign, {zero} of {n} equal"
    note = f"{opp} of {n} seeds {'has' if opp == 1 else 'have'} the opposite sign"
    return note + (f", {zero} of {n} equal" if zero else "")


def fmt_pair(m, s):
    return f"{num(m)}+-{num(s)}"


def verdict(xa, xb):
    diffs = [a - b for a, b in zip(xa, xb)]
    if all(d == 0.0 for d in diffs):
        return "0.0000+-0.0000: tie: identical on every seed"
    m, s = mean_sd(diffs)
    if abs(m) < NUM_ZERO and s < NUM_ZERO:
        return f"{fmt_pair(m, s)}: numerically zero (floating-point residue), effectively a tie"
    if abs(m) <= s:
        label = "near-tie / small gap, within seed noise (|m| <= sd)"
    elif abs(m) < 0.2 * min(abs(mean_sd(xa)[0]), abs(mean_sd(xb)[0])):
        label = "small but consistent gap, not a tie (|m| > sd)"
    else:
        label = "clear gap, not a tie (|m| > sd)"
    return f"{fmt_pair(m, s)}: {label}; {sign_note(diffs, m)}"


METRICS = ("loc_err", "grasp_err", "success")
_TRAIN = {}


def trained(arm, seed, size=PALETTE):
    key = ("A_canonical" if arm == "A_canonical" else "B_random", seed, size)
    if key not in _TRAIN:
        _TRAIN[key] = train_set(key[0], seed, size)
    return _TRAIN[key]


def collect(regime, size=PALETTE, tol=TOL):
    return {arm: [evaluate(arm, regime, s, trained(arm, s, size), tol) for s in SEEDS] for arm in ARMS}


def col(rows, key):
    return [r[key] for r in rows]


def report(regime):
    res = collect(regime)
    which, u = REGIMES[regime]
    print(f"{regime} (test textures={which}, U={u:.1f} px/s):")
    for arm in ARMS:
        parts = [f"{key} {fmt_pair(*mean_sd(col(res[arm], key)))}" for key in METRICS]
        print(f"  {arm} " + " ".join(parts))
    for key in METRICS:
        print(f"  paired B-A {key}: {verdict(col(res['B_random'], key), col(res['A_canonical'], key))}")
    for key in METRICS:
        print(f"  paired C-B {key}: {verdict(col(res['C_rand_tau'], key), col(res['B_random'], key))}")
    return res


def main():
    print("Synthetic 1-D camera-row toy with a k-NN detector; canonical vs random textures vs random textures + wrong tau; not a DNN")
    print(f"seeds={len(SEEDS)} W={W} px OBJ_W={OBJ_W:.1f} px N_TRAIN={N_TRAIN} N_TEST={N_TEST} K_NN={K_NN} "
          f"PIX_SIGMA={PIX_SIGMA:.2f} PALETTE={PALETTE} GAIN=[{GAIN_LO:.1f}, {GAIN_HI:.1f}] (declared toy parameters)")
    print(f"U_MOVE={U_MOVE:.1f} px/s TAU_REAL={TAU_REAL:.2f} s TAU_SIM={TAU_SIM:.2f} s TOL={TOL:.1f} px "
          f"(success iff grasp_err < TOL, strict; declared toy parameters)")
    print("No integration step: closed-form positions, no time-step criterion")
    print("Regimes and parameters were written before the first run")
    leaked = any(p in REAL or p == CANON for s in SEEDS for p in palette(s, PALETTE))
    print(f"peek_check: any held-out real texture or the canonical texture inside B's palette on any seed: {leaked}")
    bias = U_MOVE * (TAU_REAL - TAU_SIM)
    print(f"hand_calc wrong tau: aim error = U*(TAU_REAL - TAU_SIM) = {U_MOVE:.1f}*({TAU_REAL:.2f} - {TAU_SIM:.2f}) "
          f"= {bias:.4f} px, which is not < TOL={TOL:.1f} px even with a perfect detector")
    print(f"hand_calc object travel during TAU_REAL: U*TAU_REAL = {U_MOVE * TAU_REAL:.4f} px")
    for regime in REGIMES:
        report(regime)
    print("alternative PALETTE=10 on heldout (same seeds, same training positions and noise):")
    alt = collect("heldout", size=10)
    base = collect("heldout")
    print(f"  B_random@alt loc_err {fmt_pair(*mean_sd(col(alt['B_random'], 'loc_err')))} "
          f"(PALETTE={PALETTE}: {fmt_pair(*mean_sd(col(base['B_random'], 'loc_err')))})")
    print(f"  paired B-A loc_err@alt: {verdict(col(alt['B_random'], 'loc_err'), col(alt['A_canonical'], 'loc_err'))}")
    print(f"  paired B200-B10 loc_err: {verdict(col(base['B_random'], 'loc_err'), col(alt['B_random'], 'loc_err'))}")
    print("alternative TOL=2.0 px on moving (same seeds):")
    alt = collect("moving", tol=2.0)
    for arm in ARMS:
        print(f"  {arm}@alt success {fmt_pair(*mean_sd(col(alt[arm], 'success')))}")
    print(f"  paired C-B success@alt: {verdict(col(alt['C_rand_tau'], 'success'), col(alt['B_random'], 'success'))}")
    print("No winner declared: random textures buy transfer to unseen appearance, cost accuracy on the one texture A was trained on, and do nothing for a wrong tau")
    print("GPU training / real camera / robot: 本页未运行; Tobin et al. arXiv 1703.06907 statements and numbers 以论文为准")


if __name__ == "__main__":
    main()
```

### Read the regimes

How the labels are used here, in this order: **tie** only when the paired per-seed difference is exactly zero on every seed; **numerically zero (floating-point residue), effectively a tie** when both the paired mean and its sd are below 1e-9 (no sign count is attached); **near-tie / small gap, within seed noise** when the absolute paired mean is at most the sd; otherwise a **consistent** gap, called **small but consistent** under 20 % of the smaller arm mean and **clear** above it. Every consistent line carries a same-sign count over the 5 seeds. Paired differences are B−A and C−B; a negative `loc_err` or `grasp_err` difference, or a positive success difference, favours B (or C).

- **heldout.** Random textures transfer better: paired B−A loc_err -3.4207±0.8743 px and paired B−A success 0.1950±0.0758 are both **clear gap, not a tie**, same sign on all 5 seeds. The pre-declared DR win held. B is still far from good: its loc_err is 2.2700±0.6663 px and it succeeds on 0.4700±0.1137 of the rows, against A's 5.6907±0.3947 px and 0.2750±0.0685. C−B is **tie: identical on every seed** on every metric, because with a static object τ does not enter the grasp.
- **canonical.** On the one texture A was trained on, B **loses** a little: paired B−A loc_err 0.1828±0.0448 px, **clear**, 5/5, the over-randomisation cost that was pre-declared as possible and is **kept**. On success it is a **near-tie** (paired B−A success -0.0050±0.0112, 4 of 5 seeds equal), because both errors sit far inside the tolerance.
- **moving.** Appearance DR does **not** fix a wrong τ. The detector is identical, so paired C−B loc_err is a **tie**, but paired C−B grasp_err 0.3734±0.2150 px is **small but consistent** and paired C−B success -0.3300±0.1110 is **clear**, both 5/5: C succeeds on 0.1750±0.0433 of the rows against B's 0.5050±0.0798. The pre-declared loss held and is **kept**. B still beats A on appearance here (paired B−A loc_err -3.4064±0.8660 px, 5/5; paired B−A success 0.2100±0.1616, 1 of 5 seeds has the opposite sign).

**Choices made after seeing results.** None. The image model, the detector, both palettes, U, both τ values, both tolerances and both alternatives were written before the first run. Alternatives on the same seeds:

- **Palette size.** With **10** random textures instead of 200, B's held-out loc_err is 1.5310±0.8132 px against 2.2700±0.6663 px (paired B200−B10 loc_err 0.7390±0.3862, **clear**, 5/5), and B still beats A (paired B−A loc_err@alt -4.1596±0.9999). **This goes the opposite way from the paper's ablation**, where fewer than 1,000 textures hurt (以论文为准). It is printed as it came out and was not retuned. A likely reason, not tested here: with 600 training rows a 200-texture palette leaves 3 rows per texture (手算: 600 / 200 = 3), so k-NN rarely finds a neighbour that matches both colours and position, whereas the paper trains a CNN on far more images. The toy shows the mechanism of visual DR, not its scaling law.
- **Tolerance.** With TOL = 2.0 px on the moving regime, the τ error no longer crosses the tolerance on most rows: paired C−B success@alt -0.0450±0.0818 is a **near-tie** (1 of 5 seeds opposite, 2 of 5 equal). A loose success threshold can hide a wrong τ; the grasp_err line above does not.

Neither alternative was adopted; the defaults stand.
