A robot that knows where it is and has a map of where it is going can do something genuinely useful: you click a point on the floor plan and it drives there by itself, around the furniture, without you steering. That needs two things at once. To build a map, the robot has to know where it was when it saw each wall. To know where it is, it has to compare what it sees with a map. **SLAM** (simultaneous localization and mapping) solves both together, and **Nav2** turns "where I am" plus "where I want to be" into wheel commands.

This is the sixth and last lesson of Month 4. Everything it needs is already in place: m4bot from Lesson 3, the obstacles world and the lidar from Lesson 4, and `diff_drive_controller` from Lesson 5, which publishes odometry and accepts `TwistStamped` commands. Today we add three packages that every ROS 2 mobile robot uses — SLAM Toolbox for the map, Nav2 for the driving and `nav2_map_server` for saving the map — and one habit that saves hours: checking odometry before trusting any map built on it.

The practice task follows the order you would use on a real robot: calibrate odometry against the lidar, map the room and save the map, navigate in the saved map, then break navigation on purpose and find out why. The month's milestone is **map a room with SLAM Toolbox and navigate it autonomously with Nav2**.

## <Term id="slam">SLAM</Term> in one picture

Odometry alone is not enough. `diff_drive_controller` integrates wheel rotations into a pose, and every small error — a wheel that slips, a radius that is half a millimetre off, a turn that comes out one degree long — is added up forever. After a few minutes of driving, odometry can be tens of centimetres and several degrees away from the truth, and it never notices. The lidar, on the other hand, sees the walls directly, but a single scan does not say where the robot is unless you already have a map to compare it with.

SLAM Toolbox combines the two. It keeps a **pose graph**: whenever the robot has moved far enough, it stores the current scan together with the pose where it was taken. With this lesson's settings, a scan is only considered once the robot is about 0.18 m in a straight line from the last scan considered (√0.8 × `minimum_travel_distance`), and it is stored if it is at least 0.2 m or 0.2 rad from the last stored scan. Turning on the spot adds nothing: `minimum_travel_heading` only counts on its own with `check_min_dist_and_heading_precisely: true`. Each new scan is matched against the recent ones (scan matching), which corrects the small odometry errors as they happen. When the robot comes back to a place it has seen before, SLAM Toolbox recognises the scan (a **loop closure**) and adjusts the whole graph so that the old and new views agree. The map is then drawn from all the scans at their corrected poses.

SLAM Toolbox does not overwrite odometry. It publishes `map → odom`, the correction that makes the whole chain land in the right place. Odometry stays smooth for the controllers that need a continuous signal, and the map frame stays right for planning. When SLAM Toolbox corrects drift, only `map → odom` moves.

## Check odometry first

SLAM Toolbox uses odometry as its first guess for every scan match. If odometry is only a little off, scan matching fixes it. If it is badly off — say every turn comes out ten per cent too short — the first guess lands far from the truth, matching may lock onto the wrong wall, and the map comes out smeared or doubled. So before mapping, measure how good odometry is.

The cleanest test for a differential-drive robot is a full turn on the spot. Turning is where odometry is weakest, because the turn angle depends on the wheel separation, and the real separation is where the tyres touch the ground, not where the CAD drawing says. A full turn also has a built-in reference: after exactly 360°, the room looks exactly as it did before. `spin_check.py` turns the robot until odometry says 360°, then compares the lidar scan before and after. If the robot really turned 365°, every wall appears 5° further round, and the script finds the rotation that lines the two scans up.

<CodeSource path="examples/month-4/slam-nav/spin_check.py" />

```python
#!/usr/bin/env python3
"""Check odometry's heading against the lidar: spin m4bot one full turn by odometry, then ask the
lidar how far it really turned.

usage: python3 spin_check.py        (with control.launch.py or slam.launch.py running)
If odometry is right, the room looks the same to the lidar before and after one turn. If not, the
two scans are rotated against each other, and the rotation is the odometry's heading error."""
import math

import rclpy
from geometry_msgs.msg import TwistStamped
from nav_msgs.msg import Odometry
from rclpy.node import Node
from rclpy.parameter import Parameter
from rclpy.qos import qos_profile_sensor_data
from sensor_msgs.msg import LaserScan


class SpinCheck(Node):
    def __init__(self):
        super().__init__('spin_check', parameter_overrides=[Parameter('use_sim_time', value=True)])
        self.cmd = self.create_publisher(TwistStamped, 'diff_drive_controller/cmd_vel', 10)
        self.create_subscription(Odometry, 'diff_drive_controller/odom', self.on_odom, 1)
        self.scans = []
        self.create_subscription(LaserScan, 'scan', self.scans.append, qos_profile_sensor_data)
        self.yaw = None

    def on_odom(self, msg):
        q = msg.pose.pose.orientation
        self.yaw = math.atan2(2 * (q.w * q.z + q.x * q.y), 1 - 2 * (q.y * q.y + q.z * q.z))

    def send(self, w):
        msg = TwistStamped()
        msg.header.stamp = self.get_clock().now().to_msg()
        msg.twist.angular.z = w
        self.cmd.publish(msg)

    def average_scan(self, count=5):
        """Mean of the next `count` scans; beams without a hit count as the lidar's maximum range."""
        self.scans.clear()
        while len(self.scans) < count:
            rclpy.spin_once(self, timeout_sec=0.1)
        top = self.scans[0].range_max
        return [sum(min(s.ranges[i], top) for s in self.scans) / count
                for i in range(len(self.scans[0].ranges))]

    def settle(self, seconds):
        end = self.get_clock().now().nanoseconds + seconds * 1e9
        while self.get_clock().now().nanoseconds < end:
            self.send(0.0)
            rclpy.spin_once(self, timeout_sec=0.05)

    def run(self):
        while self.yaw is None:
            rclpy.spin_once(self, timeout_sec=0.1)
        before = self.average_scan()
        turned, last = 0.0, self.yaw
        while turned < 2 * math.pi - 0.002:              # one full turn, counted by odometry
            remaining = 2 * math.pi - turned
            self.send(max(0.05, min(0.5, 2.0 * remaining)))
            rclpy.spin_once(self, timeout_sec=0.05)
            step = math.atan2(math.sin(self.yaw - last), math.cos(self.yaw - last))
            turned, last = turned + step, self.yaw
        self.settle(1.0)
        after = self.average_scan()
        turned += math.atan2(math.sin(self.yaw - last), math.cos(self.yaw - last))
        error = best_shift(before, after)
        odom_deg, real_deg = math.degrees(turned), math.degrees(turned) + error
        print(f'odometry says: {odom_deg:.1f} deg')
        print(f'lidar says:    {real_deg:.1f} deg  (scans rotated by {error:+.1f} deg)')
        print(f'odometry / real = {odom_deg / real_deg:.3f}')


def best_shift(before, after, step=0.1, limit=60.0):
    """The angle (deg) that turns the `before` scan into the `after` one, to `step` degrees.

    A robot that turned d degrees too far sees every wall d degrees further clockwise, so
    after(theta) = before(theta + d). Beams are 1 degree apart; in between we interpolate."""
    n = len(before)

    def at(scan, deg):
        i = math.floor(deg) % n
        f = deg - math.floor(deg)
        return scan[i] * (1 - f) + scan[(i + 1) % n] * f

    def cost(d):
        return sum(abs(after[i] - at(before, i + d)) for i in range(n))

    shifts = [k * step - limit for k in range(int(2 * limit / step) + 1)]
    return min(shifts, key=cost)


def main():
    rclpy.init()
    node = SpinCheck()
    node.run()
    node.destroy_node()
    rclpy.shutdown()


if __name__ == '__main__':
    main()
```

That is a large error. Odometry thought it had turned 360°, but the robot really turned about 403°, 12 % more. Straight lines were fine in Lesson 5 (the drive-distance action stopped within 3 mm), so the wheel radius is right and the separation is wrong. In this simulation the wheel–ground contact makes the 0.28 m wheel base behave like a narrower one; on a real robot the cause is usually tyres that are wider or softer than the drawing. Either way the fix is the same, because `diff_drive_controller` has a parameter for it:

<Formula label="Separation calibration">new multiplier = old multiplier × odometry angle ÷ real angle</Formula>

Here that is 1.0 × 360 ÷ 403.1 = 0.893. The editor's first calibration run gave 0.896, which is what `odom_calibration.yaml` uses; the 0.003 difference is run-to-run variation of the contact model and well inside what you can measure this way.

## Map the room

SLAM Toolbox's defaults are good; `slam.yaml` sets only the frames, the topic and the few values that depend on our robot.

<CodeSource path="examples/month-4/slam-nav/m4_nav/config/slam.yaml" />

```yaml

slam_toolbox:
  ros__parameters:
    mode: mapping                 # mapping: build a new map; localization: use a saved one
    odom_frame: odom              # published by diff_drive_controller (Lesson 5)
    map_frame: map                # SLAM Toolbox publishes map -> odom
    base_frame: base_footprint
    scan_topic: /scan
    resolution: 0.05              # m per map cell
    max_laser_range: 8.0          # the lidar's range in Lesson 4's xacro
```

### Drive the tour

Now drive the robot around until every wall and obstacle has been seen from more than one side. With a keyboard you would run `ros2 run teleop_twist_keyboard teleop_twist_keyboard --ros-args -p stamped:=true -p use_sim_time:=true -r cmd_vel:=/diff_drive_controller/cmd_vel`, as in Lesson 5. For a repeatable result the editor used a script that does the same thing: spin on the spot, then drive to two opposite corners and back.

<CodeSource path="examples/month-4/slam-nav/tour.py" />

```python
#!/usr/bin/env python3
"""Drive m4bot along a fixed tour of the obstacles room, so SLAM Toolbox sees every corner.

usage: python3 tour.py        (with slam.launch.py running)
The same thing you would do with teleop_twist_keyboard, but repeatable: it turns on the spot and
drives between waypoints, steering by odometry. It prints the odometry pose at each waypoint."""
import math

import rclpy
from geometry_msgs.msg import TwistStamped
from nav_msgs.msg import Odometry
from rclpy.node import Node
from rclpy.parameter import Parameter

# (x, y) in the odom frame, which starts where the robot was spawned: the room's centre
WAYPOINTS = [(1.4, 1.4), (-1.2, -1.2), (0.0, 0.0)]


class Tour(Node):
    def __init__(self):
        # stamp commands with the simulator's clock, like every node in a simulation
        super().__init__('tour', parameter_overrides=[Parameter('use_sim_time', value=True)])
        self.cmd = self.create_publisher(TwistStamped, 'diff_drive_controller/cmd_vel', 10)
        self.create_subscription(Odometry, 'diff_drive_controller/odom', self.on_odom, 1)
        self.pose = None

    def on_odom(self, msg):
        p, q = msg.pose.pose.position, msg.pose.pose.orientation
        yaw = math.atan2(2 * (q.w * q.z + q.x * q.y), 1 - 2 * (q.y * q.y + q.z * q.z))
        self.pose = (p.x, p.y, yaw)

    def send(self, v, w):
        msg = TwistStamped()
        msg.header.stamp = self.get_clock().now().to_msg()
        msg.twist.linear.x, msg.twist.angular.z = v, w
        self.cmd.publish(msg)

    def step(self):
        rclpy.spin_once(self, timeout_sec=0.05)

    def turn_to(self, target):
        while True:
            self.step()
            err = math.atan2(math.sin(target - self.pose[2]), math.cos(target - self.pose[2]))
            if abs(err) < 0.02:
                break
            self.send(0.0, max(-0.6, min(0.6, 2.0 * err)))   # slow turns keep the scans sharp
        self.send(0.0, 0.0)

    def drive_to(self, x, y):
        while True:
            self.step()
            dx, dy = x - self.pose[0], y - self.pose[1]
            if math.hypot(dx, dy) < 0.05:
                break
            err = math.atan2(dy, dx) - self.pose[2]
            err = math.atan2(math.sin(err), math.cos(err))
            self.send(min(0.25, math.hypot(dx, dy)), 2.0 * err)
        self.send(0.0, 0.0)

    def run(self):
        while self.pose is None:
            self.step()
        print('spin once on the spot')
        for target in (math.pi / 2, math.pi, -math.pi / 2, 0.0):
            self.turn_to(target)
        for x, y in WAYPOINTS:
            self.turn_to(math.atan2(y - self.pose[1], x - self.pose[0]))
            self.drive_to(x, y)
            print(f'at waypoint ({x:.1f}, {y:.1f}): odom x {self.pose[0]:.2f} y {self.pose[1]:.2f}')
        self.turn_to(0.0)
        print(f'done, facing +x again: yaw {math.degrees(self.pose[2]):.0f} deg')


def main():
    rclpy.init()
    node = Tour()
    node.run()
    node.destroy_node()
    rclpy.shutdown()


if __name__ == '__main__':
    main()
```

### Save the map

There are two formats, for two different consumers. SLAM Toolbox's **pose graph** (`.posegraph` plus `.data`) contains every scan and pose, so SLAM Toolbox can load it later, localize in it and even keep extending it. The **occupancy grid** (`.pgm` image plus `.yaml`) is just the picture, which Nav2's map server, other tools and people can read. Save both while `slam.launch.py` is still running. Neither service creates folders — map_saver's `map_io.cpp` only opens the two files, with `image.write` and `std::ofstream`, and stops with `Failed to write map` if `~/maps` is missing — so make it first:

```bash
mkdir -p ~/maps
```

In nav2_map_server (version 1.3.13, the Jazzy release used here), saving and loading use two different sets of thresholds, so the 0.25/0.65 in the log and the 0.196 in room.yaml are not in conflict. When saving (map_saver → map_io::saveMapToFile), 0.25 and 0.65 classify the occupancy grid cell values (0–100 %): `cell <= rint(0.25*100)=25` becomes white pixel 254 (free); `cell >= rint(0.65*100)=65` becomes black pixel 0 (occupied); everything else, along with unknown (-1), becomes grey 205. These two defaults are used when the thresholds are unspecified, as shown in [map_saver.cpp L165–178](https://github.com/ros-navigation/navigation2/blob/1.3.13/nav2_map_server/src/map_saver/map_saver.cpp#L165-L178) and [map_io.cpp L529–549](https://github.com/ros-navigation/navigation2/blob/1.3.13/nav2_map_server/src/map_io.cpp#L529-L549).

The thresholds in the yaml serve a different purpose: they tell map_server how to read the PGM back. With `negate: 0`, the loader computes `p = 1 − pixel/255` and marks cells with `p >= occupied_thresh` as occupied, `p <= free_thresh` as free, and the rest as unknown in trinary mode, as shown in [map_io.cpp L256–275](https://github.com/ros-navigation/navigation2/blob/1.3.13/nav2_map_server/src/map_io.cpp#L256-L275). Because the trinary pixels are fixed at 254/205/0, saveMapToFile always writes occupied_thresh 0.65 and free_thresh 0.196 in trinary mode, regardless of the thresholds used for saving, as noted in [map_io.cpp L608–613](https://github.com/ros-navigation/navigation2/blob/1.3.13/nav2_map_server/src/map_io.cpp#L608-L613).

```text
pixel 254 → p = 1 − 254/255 = 0.0039 ≤ 0.196 → free
pixel 205 → p = 1 − 205/255 = 0.1961 > 0.196 → unknown
pixel   0 → p = 1 − 0/255   = 1.0    ≥ 0.65  → occupied
```

0.196 sits just below 50/255 = 0.19608, so grey stays unknown; if the yaml said 0.25, every grey unknown pixel (0.1961 ≤ 0.25) would be loaded as free space and the planner could route through unexplored areas. So do not "correct" free_thresh in a saved trinary map to 0.25.

A map that looks right in RViz can still be wrong by a few cells, so check it against the world it came from. `map_check.py` reads the saved files with nothing but Python's standard library and looks for occupied cells where Lesson 4's world file put the walls and obstacles:

<CodeSource path="examples/month-4/slam-nav/map_check.py" />

```python
#!/usr/bin/env python3
"""Check a saved map against the world it came from: are the walls and obstacles where the
obstacles world (Lesson 4) put them?

usage: python3 map_check.py ~/maps/room.yaml      (exit code 1 if an object is missing or the map is too empty)
Reads the .yaml and .pgm written by nav2_map_server's map_saver_cli. Only the Python standard
library is needed. The map frame starts where the robot was spawned, the centre of the room."""
import os
import sys

# what is really in the obstacles world, in the map frame (centre x, centre y, half x, half y)
OBJECTS = {
    'north wall': (3.0, 0.0, 0.05, 3.0),
    'south wall': (-3.0, 0.0, 0.05, 3.0),
    'west wall': (0.0, 3.0, 3.05, 0.05),
    'east wall': (0.0, -3.0, 3.05, 0.05),
    'red box': (2.0, 0.0, 0.2, 0.2),
    'blue pillar': (1.0, -1.2, 0.15, 0.15),
    'green block': (-1.5, 1.5, 0.6, 0.6),   # 1.2 x 0.3 m turned 0.6 rad: check its bounding square
}
# The fewest occupied cells that still count as "found", and the fewest occupied and free cells
# in the whole map: about half the smaller count seen in two real runs of tools/sim/ros/run.sh
# (2026-10-20), so the normal run-to-run spread passes but a blank map or a missing object fails.
MIN_CELLS = {                    # seen in run 1 / run 2
    'north wall':    40,       # 190 /  81
    'south wall':   125,       # 250 / 275
    'west wall':     66,       # 133 / 152
    'east wall':     97,       # 195 / 242
    'red box':       12,       #  24 /  26
    'blue pillar':    6,       #  12 /  12
    'green block':   24,       #  48 /  48
}
MIN_OCCUPIED = 347               # 747 / 694
MIN_FREE = 6329                  # 12659 / 12730


def read_yaml(path):
    """The few keys map_saver writes, without needing PyYAML."""
    meta = {}
    for line in open(path):
        key, _, value = line.partition(':')
        meta[key.strip()] = value.strip()
    origin = [float(v) for v in meta['origin'].strip('[]').split(',')]
    return meta['image'], float(meta['resolution']), origin


def read_pgm(path):
    """A binary (P5) PGM: returns width, height and the rows, top row first."""
    data = open(path, 'rb').read()
    fields, pos = [], 0
    while len(fields) < 4:                    # magic, width, height, maxval
        while data[pos:pos + 1].isspace():
            pos += 1
        if data[pos:pos + 1] == b'#':         # comment line
            pos = data.index(b'\n', pos)
            continue
        end = pos
        while not data[end:end + 1].isspace():
            end += 1
        fields.append(data[pos:end])
        pos = end
    width, height = int(fields[1]), int(fields[2])
    pixels = data[pos + 1:]
    return width, height, [pixels[r * width:(r + 1) * width] for r in range(height)]


def main():
    yaml_path = sys.argv[1]
    image, res, origin = read_yaml(yaml_path)
    width, height, rows = read_pgm(os.path.join(os.path.dirname(yaml_path), image))
    print(f'map: {width} x {height} cells of {res:.2f} m = {width * res:.1f} m x {height * res:.1f} m')
    counts = {0: 0, 254: 0, 205: 0}           # occupied, free, unknown in a trinary map
    for row in rows:
        for v in row:
            counts[v] = counts.get(v, 0) + 1
    total = width * height
    print(f'occupied {counts[0]} ({100 * counts[0] / total:.0f} %), free {counts[254]} '
          f'({100 * counts[254] / total:.0f} %), unknown {counts[205]} ({100 * counts[205] / total:.0f} %)')
    failed = []
    if counts[0] < MIN_OCCUPIED:
        failed.append(f'only {counts[0]} occupied cells in the map, need {MIN_OCCUPIED}')
    if counts[254] < MIN_FREE:
        failed.append(f'only {counts[254]} free cells in the map, need {MIN_FREE}')

    def cell(x, y):                           # map coordinates -> pixel value (row 0 = top = max y)
        col = int((x - origin[0]) / res)
        row = height - 1 - int((y - origin[1]) / res)
        return rows[row][col] if 0 <= col < width and 0 <= row < height else None

    for name, (cx, cy, hx, hy) in OBJECTS.items():
        # look for occupied cells in the object's footprint plus one cell all round
        found = 0
        steps_x, steps_y = int(2 * (hx + res) / res) + 1, int(2 * (hy + res) / res) + 1
        for i in range(steps_x):
            for j in range(steps_y):
                if cell(cx - hx - res + i * res, cy - hy - res + j * res) == 0:
                    found += 1
        verdict = 'found' if found >= MIN_CELLS[name] else 'TOO FEW' if found else 'MISSING'
        print(f'{name:12s} at ({cx:+.1f}, {cy:+.1f}): {verdict} ({found} occupied cells)')
        if verdict != 'found':
            failed.append(f'{name}: {found} occupied cells, need {MIN_CELLS[name]}')
    for reason in failed:
        print('FAIL: ' + reason)
    return 1 if failed else 0              # exit code 1: the map does not match the world


if __name__ == '__main__':
    sys.exit(main())
```

### What Nav2 runs

Nav2 is a set of servers coordinated by a behaviour tree. The parameter file [`m4_nav/config/nav2.yaml`](https://github.com/liudicsu/Hardware-learning/blob/main/examples/month-4/slam-nav/m4_nav/config/nav2.yaml) is based on the one shipped with `nav2_bringup`, and the lines changed for m4bot are marked `# m4bot`. Follow one goal through it:

<Diagram id="nav2-pipeline" />

1. **`bt_navigator`** receives the `NavigateToPose` goal and runs a behaviour tree: plan, follow, and on failure try recoveries (clear the costmaps, spin, wait, back up) before giving up.
2. **`planner_server`** plans a path on the **global <Term id="costmap">costmap</Term>**, which is the saved map (the static layer) plus obstacles currently seen by the lidar, plus inflation. The planner is NavFn, a grid search.
3. **`controller_server`** follows the path with Regulated Pure Pursuit at up to 0.25 m/s, steering on the **local costmap**, a 3 m × 3 m window around the robot built from the lidar alone. It turns on the spot first when the path points more than 0.785 rad (45°) away from the robot's heading.
4. **`velocity_smoother`** limits acceleration, and **`collision_monitor`** slows or stops the robot if the lidar sees something about to be hit. Its output, `cmd_vel_out_topic: "/diff_drive_controller/cmd_vel"`, is the only line that connects Nav2 to Lesson 5's controller. Because that controller expects `TwistStamped`, every server that publishes velocities has `enable_stamped_cmd_vel: true`.

The robot's shape enters through `footprint`, a rectangle around `base_footprint` from 0.11 m behind to 0.21 m in front and 0.16 m to each side. Those numbers come from the URDF: the chassis faces sit at `chassis_offset_x ± chassis_x/2 = 0.05 ± 0.15` → +0.20 m / −0.10 m, and the tyres' outer face is at `wheel_separation/2 + wheel_width/2 = 0.14 + 0.015 = 0.155` m; with a 1 cm clearance margin that is +0.21 / −0.11, and ±0.16 after flooring the tyre side (0.155 + 0.01 = 0.165) down to the centimetre. **Inflation** adds a cost that falls off with distance around every obstacle, out to `inflation_radius: 0.45` m. Nav2's formula ([`inflation_layer.hpp`](https://github.com/ros-navigation/navigation2/blob/main/nav2_costmap_2d/include/nav2_costmap_2d/inflation_layer.hpp) in Navigation2) is `cost = (254 − 1) · exp(−cost_scaling_factor · (d − inscribed_radius))` for distance `d` beyond the inscribed radius, with this lesson's `cost_scaling_factor: 3.0`; cells on the obstacle are lethal (255) and cells inside the inscribed radius are inscribed (254). The 0.45 m radius is a clearance choice for m4bot, not the output of a tuning run shown in this lesson. Cells the footprint would hit are forbidden; inflated cells are allowed but expensive, so the planner keeps a margin where it can and squeezes through narrow gaps only when it must. Goals count as reached within `xy_goal_tolerance` 0.10 m and `yaw_goal_tolerance` 0.15 rad (about 9°).

## When navigation fails

Nav2 failures look alike from the outside: the robot does not move, or it spins and gives up. The cause is almost always one of a few things, and each leaves a trace you can find.

| Symptom | Likely cause | Where to look |
| --- | --- | --- |
| "Lookup would require extrapolation" or "frame does not exist" in the logs | one node runs on wall time while the rest use the simulator's clock (`use_sim_time`) | `ros2 param get <node> use_sim_time` on each node |
| The goal is accepted, nothing moves | velocities go to a topic nobody listens to, or plain `Twist` reaches a controller that wants `TwistStamped` | `ros2 topic info -v /diff_drive_controller/cmd_vel` |
| Planning fails at once | the goal or the robot is inside an obstacle or its forbidden zone; or the map frame is missing because localization did not start | the global costmap in RViz; `ros2 run tf2_tools view_frames` |
| A goal inside an obstacle still returns SUCCEEDED | possibly the planner's `tolerance` (NavFn plans to the nearest free cell within that distance of the goal), possibly the goal checker's `xy_goal_tolerance` (it accepts any stop within that radius); the status alone does not tell you which | compare the final pose with the goal yourself: `tf2_echo map base_footprint` and the distance to the goal you sent |
| The robot stops for no visible reason | the lidar stopped publishing, so the costmaps time out the sensor and the collision monitor sees no data | `ros2 topic hz /scan` |
| The map is smeared or the robot jumps in RViz | odometry badly calibrated, or `map_start_pose` far from the real starting pose | `spin_check.py`; the starting pose |
| The robot will not pass through a doorway that is clearly wide enough | the footprint or `inflation_radius` too large for the gap | the costmaps in RViz |

The new row deserves a word: SUCCEEDED means "stopped within tolerance of where the planner and goal checker decided to go", not "reached the point you asked for". With this lesson's `nav2.yaml`, NavFn's `tolerance: 0.5` lets the planner end its path at a free cell up to 0.5 m from an unreachable goal, and `xy_goal_tolerance: 0.10` then accepts a stop within 0.10 m of that path's end. One of them, or both together, may be what turns a goal inside a pillar into a success. Do not guess which; after every goal, read the final pose (`tf2_echo map base_footprint` with `use_sim_time:=true`), work out its distance to the goal you sent, and treat a distance larger than `xy_goal_tolerance` as a failure your own code must catch.

Start with TF, because every server needs `map → odom → base_footprint` to be complete and current. `ros2 run tf2_tools view_frames` draws the tree (Lesson 3's broken-tree diagnosis works here unchanged); `ros2 run tf2_ros tf2_echo map base_footprint --ros-args -p use_sim_time:=true` shows whether the robot has a pose in the map at all. Note the `use_sim_time:=true`: without it, `tf2_echo` asks for transforms at the computer's time while everything else lives on Gazebo's clock, and it will only ever report extrapolation errors, which is the first row of the table in miniature.

Then look at the costmaps. In RViz, add a Map display on `/global_costmap/costmap` and one on `/local_costmap/costmap`. A goal that sits in the bright forbidden band around an obstacle cannot be reached however good the rest of the setup is, and a doorway whose two inflated edges touch is closed as far as the planner is concerned. Lowering `inflation_radius` opens it; making the footprint smaller than the real robot also opens it, and that is how robots end up scraping door frames. Fix the footprint first, then tune inflation.

<Callout type="tip" title="Read the log from the top">Nav2 prints its recoveries in order ("Running spin", "Running backup", ...) before it finally reports a failure. The first warning before them usually names the real problem, for example a costmap sensor timeout or a failed transform. Scrolling straight to the last line only tells you that it gave up.</Callout>

## ICP: two local registration updates, one shared scan pair (+210 min)

The [Open3D ICP tutorial](https://www.open3d.org/docs/release/tutorial/pipelines/icp_registration.html) distinguishes point-to-point `Σ||Rp_i+t−q_i||²` from point-to-plane `Σ[n_iᵀ(Rp_i+t−q_i)]²`, with target normals. Both need a reasonable initial pose; neither guarantees the correct alignment. This section adds registration mathematics rather than redoing the odometry turn check or 3DGS. <Resource id="open3d-icp-objectives" />

### Declared 2D surface reconstruction and equal information

`icp_point_plane_toy.py` is a **nearest-segment surface surrogate**, not Open3D's discrete nearest-point backend. Seven ordered target scan vertices reconstruct a closed piecewise-linear room; 42 source returns sample the underlying seven walls. All dimensions/poses/noise are **synthetic**, coordinates in metres and angles in radians. The source-to-target generating pose is `(θ,tx,ty)=(0.15,0.12,−0.07)`. Each seed **11/23/37/53/71** adds independent σ=**0.004 m** Gaussian noise to target vertices and source returns; the exact same noisy scans, adjacency reconstruction and initial pose are passed to both arms.

For every transformed source point x, **both arms brute-force the same nearest-segment projection** to obtain q and the unit normal of that noisy target segment. No generating wall IDs, clean target normals or true correspondences are supplied. Target adjacency/surface reconstruction is a declared input available to both, not an oracle privileged to point-to-plane. Point-to-point ignores normals and freezes these projected q values for a 2D rigid centroid/atan2 update. Point-to-plane uses their normals in a local least-squares update. When a projection is in a segment's interior, Euclidean and normal distances agree, but the **frozen-pair update models differ**. At later iterations the estimates and therefore associations may diverge; the matcher and input geometry, not all resulting q pairs, remain shared.

### Point-to-plane is a small-angle linearization

With current transformed point `x=(x,y)` and residual `r=nᵀ(x−q)`, a left increment has `x'≈x+(dtx,dty)+dθ(−y,x)`. Its row is **`a=[nx,ny,−nx*y+ny*x]`**, so solve `min Σ(r+a·δ)²`, `δ=(dtx,dty,dθ)`, using `AᵀA δ=−Aᵀr`. This educational 3×3 pivoted elimination rejects rank loss; production QR/SVD can diagnose conditioning more robustly. Reassociate and relinearize each iteration, then apply the actual finite rotation, not the first-order point approximation. Large increments invalidate the local approximation: both arms use the **same** synthetic trust bounds **0.35 rad / 0.5 m** per update and cap **40 iterations**. This does not establish global convergence.

Both stop at a shared **geometric RMSE≤0.012 m**, or the cap/rank failure. RMSE is Euclidean distance to freshly matched noisy target segments, even when the plane arm optimizes normal residuals. A separate **SCORE-ONLY** pose hit requires angular error≤**0.03 rad** and translation error≤**0.03 m** relative to the generating pose; it never guides fitting. Initial translation is truth plus `(0.10,−0.08)` m and shared seed jitter±0.01 m; rotation is truth plus a swept offset and shared jitter±0.005 rad. Translation/jitter are held identical across rotation offsets for each seed.

### A corridor can fool a frozen-matching rank test

The degenerate case has parallel horizontal walls and a source patch with x from−1.5 to1.5 m, y=±1 m. Target segments extend to±100 m as an **idealized no-visible-ends model in the overlap**, not a sensor-range claim. A fresh projection after translating along x keeps the same geometric cost: shifting1 m still gives RMSE=0. Both arms' **re-associated objective Hessian has rank2/3, condition=∞, null direction along-wall dx**. It is finite-differenced from the mean squared Euclidean cost using `(dx m,dy m,dθ rad)` and h=1e−4; numeric condition values depend on parameter scaling, but this exact null direction does not.

In contrast, freezing projected q values gives point-point a **rank3/3, condition2.000** normal matrix: it artificially pins tangential point identities. Do **not** call that scene observability. Point-to-plane's normal system is singular and rejected; both physical registration objectives lack along-wall information. Keep the distinction between a solver's frozen-pair curvature and the re-associated scene geometry; visible ends/corners or another sensor are needed to constrain that direction.

```python
#!/usr/bin/env python3
"""2D ICP surface surrogate, not Open3D/KITTI/SLAM Toolbox measurements.
Target scan vertices are connected polylines; BOTH arms use the same nearest
segment projection, not hidden true point indices. Normals come from those
same noisy segments. Point-point freezes projected q for a rigid increment;
point-plane linearizes normal residuals. This is not Open3D's discrete NN backend.
Corridor diagnostics REASSOCIATE projections: frozen point-point matches can
appear full rank while physical wall sliding is unobservable for BOTH arms.
"""
from math import atan2, cos, sin, sqrt, hypot, pi, radians, degrees
from random import Random
from statistics import mean, pstdev

SEEDS=(11,23,37,53,71)
OFFSETS=(-120,-60,-30,0,30,60,120)
CAP, STOP_RMSE=40,.012
TRUE=(.15,.12,-.07)  # source->target theta(rad), tx(m), ty(m); SCORE ONLY.
VERTICES=((-1.4,-.8),(1.1,-.8),(1.1,.45),(.25,.45),(.25,1.2),(-.9,1.2),(-1.4,.2))


def transform(point, pose):
    a,tx,ty=pose;c,s=cos(a),sin(a);x,y=point
    return c*x-s*y+tx,s*x+c*y+ty


def compose(pose, delta):
    dx,dy,da=delta
    tx,ty=transform((pose[1],pose[2]),(da,dx,dy))
    return pose[0]+da,tx,ty


def segments(vertices):
    return tuple(zip(vertices,vertices[1:]+vertices[:1]))


def nearest(point, target):
    best=None
    for a,b in target:
        vx,vy=b[0]-a[0],b[1]-a[1];den=vx*vx+vy*vy
        u=max(0.,min(1.,((point[0]-a[0])*vx+(point[1]-a[1])*vy)/den))
        q=(a[0]+u*vx,a[1]+u*vy)
        d=(point[0]-q[0])**2+(point[1]-q[1])**2
        if best is None or d<best[0]:best=(d,q,(-vy/sqrt(den),vx/sqrt(den)))
    return best


def correspondences(source, target, pose):
    return tuple((x,*nearest(x,target)[1:]) for x in (transform(p,pose) for p in source))


def rmse(source, target, pose):
    return sqrt(mean(nearest(transform(p,pose),target)[0] for p in source))


def solve3(a,b):
    scale=max(abs(x) for row in a for x in row)
    rows=[list(row)+[v] for row,v in zip(a,b)]
    for j in range(3):
        pivot=max(range(j,3),key=lambda i:abs(rows[i][j]))
        if abs(rows[pivot][j])<=1e-10*max(scale,1e-30):return None
        rows[j],rows[pivot]=rows[pivot],rows[j]
        factor=rows[j][j];rows[j]=[v/factor for v in rows[j]]
        for i in range(3):
            if i!=j:
                factor=rows[i][j];rows[i]=[x-factor*y for x,y in zip(rows[i],rows[j])]
    return tuple(row[3] for row in rows)


def normal_matrix(rows):
    return [[sum(row[i]*row[j] for row in rows) for j in range(3)] for i in range(3)]


def increment(matches,arm):
    if arm=='point_point':
        xc=tuple(mean(x[j] for x,_,_ in matches) for j in range(2))
        qc=tuple(mean(q[j] for _,q,_ in matches) for j in range(2))
        cross=sum((x[0]-xc[0])*(q[1]-qc[1])-(x[1]-xc[1])*(q[0]-qc[0]) for x,q,_ in matches)
        dot=sum((x[0]-xc[0])*(q[0]-qc[0])+(x[1]-xc[1])*(q[1]-qc[1]) for x,q,_ in matches)
        angle=atan2(cross,dot);rx,ry=transform(xc,(angle,0.,0.))
        return qc[0]-rx,qc[1]-ry,angle
    rows=[(n[0],n[1],-n[0]*x[1]+n[1]*x[0]) for x,_,n in matches]
    residual=[n[0]*(x[0]-q[0])+n[1]*(x[1]-q[1]) for x,q,n in matches]
    return solve3(normal_matrix(rows),[-sum(row[j]*v for row,v in zip(rows,residual)) for j in range(3)])


def fit(source,target,initial,arm):
    pose=initial
    for step in range(CAP+1):
        error=rmse(source,target,pose)
        if error<=STOP_RMSE or step==CAP:return pose,error,step
        delta=increment(correspondences(source,target,pose),arm)
        if delta is None:return pose,error,step
        # Same synthetic trust bounds for BOTH update rules: .35rad / .5m per step.
        factor=min(1.,.35/max(abs(delta[2]),1e-30),.5/max(hypot(*delta[:2]),1e-30))
        pose=compose(pose,tuple(factor*x for x in delta))
    raise AssertionError('unreachable')


def make_case(seed, offset):
    rng=Random(seed)
    target=segments(tuple((x+rng.gauss(0,.004),y+rng.gauss(0,.004)) for x,y in VERTICES))
    source=[]
    for a,b in segments(VERTICES):
        for j in range(6):
            u=(j+.5)/6;x=a[0]+u*(b[0]-a[0]);y=a[1]+u*(b[1]-a[1])
            px,py=transform((x-TRUE[1],y-TRUE[2]),(-TRUE[0],0.,0.))
            source.append((px+rng.gauss(0,.004),py+rng.gauss(0,.004)))
    initial=(TRUE[0]+radians(offset)+rng.uniform(-.005,.005),TRUE[1]+.10+rng.uniform(-.01,.01),TRUE[2]-.08+rng.uniform(-.01,.01))
    return tuple(source),target,initial


def hit(pose):
    angle=abs((pose[0]-TRUE[0]+pi)%(2*pi)-pi)
    return angle<=.03 and hypot(pose[1]-TRUE[1],pose[2]-TRUE[2])<=.03


def eigenvalues(a):
    a=[list(row) for row in a]
    for _ in range(40):
        p,q=max(((0,1),(0,2),(1,2)),key=lambda ij:abs(a[ij[0]][ij[1]]))
        if abs(a[p][q])<1e-13:break
        tau=(a[q][q]-a[p][p])/(2*a[p][q]);t=(1 if tau>=0 else -1)/(abs(tau)+sqrt(1+tau*tau))
        c=1/sqrt(1+t*t);s=t*c;apq=a[p][q]
        a[p][p]-=t*apq;a[q][q]+=t*apq;a[p][q]=a[q][p]=0.
        for k in range(3):
            if k not in (p,q):
                x,y=a[k][p],a[k][q];a[k][p]=a[p][k]=c*x-s*y;a[k][q]=a[q][k]=s*x+c*y
    return tuple(sorted(a[i][i] for i in range(3)))


def conditioning(matrix):
    ev=eigenvalues(matrix);threshold=max(abs(x) for x in ev)*1e-7
    rank=sum(x>threshold for x in ev)
    return rank,('inf' if rank<3 else f'{ev[-1]/ev[0]:.3f}')


def corridor():
    source=tuple((x,y) for x in (-1.5,-1.,-.5,0.,.5,1.,1.5) for y in (-1.,1.))
    target=(((-100.,-1.),(100.,-1.)),((-100.,1.),(100.,1.)))
    # Hessian of freshly REASSOCIATED mean squared Euclidean distance.
    h=1e-4
    def cost(v):return rmse(source,target,(v[2],v[0],v[1]))**2
    zero=(0.,0.,0.);base=cost(zero);H=[[0.]*3 for _ in range(3)]
    for i in range(3):
        plus=[0.]*3;plus[i]=h;minus=[-x for x in plus]
        H[i][i]=(cost(plus)-2*base+cost(minus))/(h*h)
        for j in range(i):
            vals=[]
            for si,sj in ((1,1),(1,-1),(-1,1),(-1,-1)):
                v=[0.]*3;v[i]=si*h;v[j]=sj*h;vals.append(cost(v))
            H[i][j]=H[j][i]=(vals[0]-vals[1]-vals[2]+vals[3])/(4*h*h)
    return source,target,H


def main():
    print('ICP 2D nearest-segment surface surrogate; no true correspondence IDs supplied')
    print('seeds=11/23/37/53/71 shared scans/noise/init per offset; sigma=0.004m cap=40 stop_RMSE=0.012m')
    print('same trust bounds .35rad/.5m; hit uses SCORE-ONLY true pose <=0.03rad and <=0.03m')
    print('offset_deg arm pose_hit/5 geometric_RMSE_mean_sd_m iterations_mean_sd')
    for offset in OFFSETS:
        cases=tuple(make_case(seed,offset) for seed in SEEDS)
        for arm in ('point_point','point_plane'):
            results=[fit(*case,arm) for case in cases]
            errors=[row[1] for row in results];steps=[row[2] for row in results]
            print(f'{offset} {arm} {sum(hit(row[0]) for row in results)}/5 {mean(errors):.6f} {pstdev(errors):.6f} {mean(steps):.2f} {pstdev(steps):.2f}')
    source,target,H=corridor()
    print('corridor: two parallel walls, no visible ends; dx(m),dy(m),dtheta(rad) parameter scaling')
    for arm in ('point_point','point_plane'):
        rank,cond=conditioning(H)
        print(f'{arm} reassociated_H_rank={rank}/3 condition={cond} null=along_wall_dx shifted_1m_RMSE={rmse(source,target,(0.,1.,0.)):.6f}')
    matches=correspondences(source,target,(0.,0.,0.))
    frozen=normal_matrix([row for (x,y),_,_ in matches for row in ((1,0,-y),(0,1,x))])
    rank,cond=conditioning(frozen)
    print(f'point_point FROZEN-match normal rank={rank}/3 condition={cond}; artificial tangent anchoring != scene observability')
    print('No presumed winner; basin means sampled offsets only; population sd, not wall-clock speed')
    print('Open3D / real lidar / SLAM Toolbox registration: 本页未运行')


if __name__=='__main__':main()
```
