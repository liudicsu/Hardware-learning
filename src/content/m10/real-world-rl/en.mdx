## Why a real arm is a hard RL environment

7.3 trained in simulation, where a reset is free and a million steps is a coffee break. On a real arm:

- **The reward is sparse.** "The part is in the slot" is easy to judge and hard to shape; dense shaped rewards invite reward hacking (7.2).
- **Every failure costs a reset.** Somebody re-stages the scene. A learner that needs thousands of failures before its first success is not usable.
- **Exploration must stay safe.** Random actions hit things; limits from 8.5 bound the action space.
- **Hours, not days.** The budget is a few hours of robot time, so every transition should be reused many times: off-policy RL with a replay buffer, not on-policy PPO.

## RLPD: offline data in every batch

RLPD (Ball et al., 2023) asks how to use a small offline dataset (demos) inside an ordinary off-policy learner such as SAC, without pre-training. Its recipe has three parts:

- <Term id="symmetric-sampling">Symmetric sampling</Term>: every training batch is 50 % from the offline buffer and 50 % from the online replay buffer. The paper finds this works better than simply putting the offline data into the replay buffer at the start, and that the exact ratio is not critical.
- **LayerNorm in the critic**, which bounds how far Q-values can extrapolate to actions the data never covered.
- **Sample efficiency tricks**: a large critic ensemble and many gradient updates per environment step (a high update-to-data ratio).

The abstract reports up to 2.5× improvement over prior approaches across a range of benchmarks; that is the paper's measurement, not run here.

## HIL-SERL: RLPD plus a human on a real arm

HIL-SERL (Luo et al., 2024) builds on RLPD and adds what a real robot needs:

- **A few demos** (20–30 in the paper) in their own buffer; the learner samples the demo buffer and the RL buffer equally.
- **A <Term id="reward-classifier">reward classifier</Term>** instead of a hand-written reward: a small image classifier trained on success / failure frames (the paper uses about 200 positive and 1000 negative frames, collected in about 5 minutes, and reports over 95 % accuracy). It turns "did it work?" into a binary reward and an end-of-episode signal.
- **Human interventions** with a SpaceMouse during training. Intervention transitions go into both buffers; the policy's own transitions only into the RL buffer. The paper warns that long, sparse interventions that carry the task to success make the critic overestimate values: correct briefly and hand back.
- **Engineering**: actions in the end-effector frame with bounds, an impedance controller, a pretrained vision backbone, and an actor–learner split so the robot keeps acting while the learner updates.

Reported results (paper's measurements, not run here): training takes 1 to 2.5 hours for nearly all tasks; against imitation baselines trained on comparable data, success improves on average by about 2× and cycle time is about 1.8× faster. Training from scratch with neither demos nor interventions reached 0 % in their ablation.

## Run the chain toy

`rlpd_chain_toy.py` shrinks this to a 10-state "combination lock": in every state one of two actions moves forward, the other sends you back to the start (a reset), and only the goal pays reward 1. A uniformly random run of nine moves opens it once in 512 tries. Three tabular Q-learners use the same replay update (8 sampled transitions per step): online replay only, 3 demos dumped into the same buffer, and 3 demos in their own buffer with 50/50 symmetric sampling.
```python
"""rlpd_chain_toy.py: why a few demos plus 50/50 sampling make sparse-reward RL possible (stdlib).

A 10-state "combination lock" chain stands in for a real-robot task:
- states 0..9, start at 0, goal is state 9;
- in every state one of two actions is right (fixed per state); the right one
  moves forward, the wrong one sends you back to 0 (think: the part slipped,
  someone resets the scene);
- reward is 1 only on reaching the goal, 0 everywhere else; at most 30 steps
  per episode, 40 episodes per run.

Three tabular Q-learning learners share the same replay update (8 sampled
transitions per environment step, epsilon-greedy with epsilon 0.1):
  online    online replay only, no demos
  one_buf   3 demos dumped into the same buffer as online data (uniform
            sampling, so the demos get diluted as online data piles up)
  rlpd_5050 3 demos in their own buffer, every sample is a coin flip between
            the demo buffer and the online buffer (RLPD's symmetric sampling)

20 seeds each. Reported: how many seeds ever reached the goal while
training, mean episode of the first success, how many resets the learner
caused (each one is a human walking over on a real robot), greedy success at
the end, and what share of the last episode's samples came from demos.
No neural nets, no ensembles, no LayerNorm: only the data-mixing idea.
"""

import random

N = 10            # states 0..9, goal = N - 1
H = 30            # steps per episode
EPISODES = 40
SEEDS = 20
ALPHA = 0.5
GAMMA = 0.9
EPS = 0.1
UPDATES = 8       # sampled Q updates per environment step
DEMOS = 3
LOCK_SEED = 7     # the "right" action per state is the same for every run


def make_lock():
    r = random.Random(LOCK_SEED)
    return [r.randrange(2) for _ in range(N - 1)]


LOCK = make_lock()


def step(s, a):
    """Return (next_state, reward, done)."""
    if a != LOCK[s]:
        return 0, 0.0, False          # wrong action: back to the start
    s2 = s + 1
    if s2 == N - 1:
        return s2, 1.0, True
    return s2, 0.0, False


def demo_transitions():
    out = []
    for _ in range(DEMOS):
        s = 0
        while True:
            a = LOCK[s]
            s2, r, done = step(s, a)
            out.append((s, a, r, s2, done))
            if done:
                break
            s = s2
    return out


def act(q, s, rng, eps):
    if rng.random() < eps or q[s][0] == q[s][1]:
        return rng.randrange(2)
    return 0 if q[s][0] > q[s][1] else 1


def update(q, t):
    s, a, r, s2, done = t
    target = r if done else r + GAMMA * max(q[s2])
    q[s][a] += ALPHA * (target - q[s][a])


def greedy_success(q):
    s = 0
    for _ in range(H):
        a = 0 if q[s][0] >= q[s][1] else 1   # fixed tie-break, no luck
        s, _, done = step(s, a)
        if done:
            return True
    return False


def run(mode, seed):
    rng = random.Random(1000 + seed)
    q = [[0.0, 0.0] for _ in range(N)]
    demos = demo_transitions()
    online = []
    first = None
    resets = 0
    from_demo = drawn = 0
    for ep in range(1, EPISODES + 1):
        s = 0
        ep_demo = ep_drawn = 0
        for _ in range(H):
            a = act(q, s, rng, EPS)
            s2, r, done = step(s, a)
            t = (s, a, r, s2, done)
            online.append(t)
            if a != LOCK[s]:
                resets += 1
            for _ in range(UPDATES):
                if mode == "online":
                    x = online[rng.randrange(len(online))]
                    d = False
                elif mode == "one_buf":
                    i = rng.randrange(len(demos) + len(online))
                    d = i < len(demos)
                    x = demos[i] if d else online[i - len(demos)]
                else:  # rlpd_5050
                    d = rng.random() < 0.5
                    x = demos[rng.randrange(len(demos))] if d else online[rng.randrange(len(online))]
                update(q, x)
                ep_demo += d
                ep_drawn += 1
            if done:
                if first is None:
                    first = ep
                break
            s = s2
        from_demo, drawn = ep_demo, ep_drawn
    return {
        "first": first,
        "resets": resets,
        "greedy": greedy_success(q),
        "demo_share": from_demo / drawn,
        "steps": len(online),
    }


def summarize(mode):
    rs = [run(mode, k) for k in range(SEEDS)]
    hit = [r["first"] for r in rs if r["first"] is not None]
    never = SEEDS - len(hit)
    mean_first = sum(hit) / len(hit) if hit else float("nan")
    resets = sum(r["resets"] for r in rs) / SEEDS
    greedy = sum(r["greedy"] for r in rs)
    share = sum(r["demo_share"] for r in rs) / SEEDS
    steps = sum(r["steps"] for r in rs) / SEEDS
    return len(hit), never, mean_first, resets, greedy, share, steps


def main():
    print("10-state lock chain: wrong action -> back to 0, reward only at the goal")
    print(f"right actions per state: {LOCK}")
    print(f"chance a uniformly random run of 9 moves opens the lock: 1/{2 ** (N - 1)}")
    print(f"{EPISODES} episodes x <= {H} steps, {UPDATES} sampled updates per step, epsilon {EPS}, {SEEDS} seeds")
    print(f"demos: {DEMOS} x {N - 1} transitions = {DEMOS * (N - 1)} transitions")
    print()
    print("mode       reached  never  first_ep  resets/run  greedy_end  demo_share_last  env_steps/run")
    rows = {}
    for mode in ("online", "one_buf", "rlpd_5050"):
        rows[mode] = summarize(mode)
        hit, never, mf, rs, g, sh, st = rows[mode]
        print(f"{mode:<10} {hit:>4}/{SEEDS}  {never:>5}  {mf:>8.1f}  {rs:>10.1f}  {g:>7}/{SEEDS}  {100 * sh:>13.1f} %  {st:>13.1f}")
    print()
    o, b, p = rows["online"], rows["one_buf"], rows["rlpd_5050"]
    print(f"resets per run: online {o[3]:.1f} vs rlpd_5050 {p[3]:.1f} (each reset = a person re-staging the scene)")
    print(f"demo share of the last episode's samples: one_buf {100 * b[5]:.1f} %, rlpd_5050 {100 * p[5]:.1f} %")
    print("note: tabular Q never forgets, so one_buf still works here; with a neural critic the")
    print("diluted demos are what RLPD found weaker than keeping a fixed 50/50 split.")


if __name__ == "__main__":
    main()
```

## Common mistakes

- **No demos, no interventions.** With a sparse reward the learner may never see a success; the paper's from-scratch ablation stayed at 0 %, and the toy's online-only learner misses in some seeds.
- **Long takeovers that finish the task.** They inflate the critic's values; correct and hand back.
- **A reward classifier that is fooled.** If it fires on near-misses, the policy learns the near-miss. Add the false positives as negatives and retrain.
- **Unbounded exploration.** Set joint / end-effector limits (8.5) before the first online episode.

## Preferences: DPO-style loss versus a learned reward (+210 min)

A preference pair says which candidate is better at the **same context**, not how far along a video the robot has progressed. This is distinct from [10.7 SARM / RA-BC](/en/month/month-10/vla-rl-finetune), Cal-ConRFT calibration, RPD teacher guidance and OneDP distillation; the RLPD/HIL-SERL chain above remains a different experiment. Rafailov et al. (2023), [Direct Preference Optimization](https://arxiv.org/abs/2305.18290), derives the pairwise objective from a KL-regularized reward objective and a Bradley–Terry preference model. It is originally a language-model paper, not evidence that this toy runs VLA preference training. Paper figures: **以论文为准**. Full VLA/GPU and online robot RL: **本页未运行**.

### The loss and its reference

For preferred winner `y_w` and loser `y_l`, condition every probability on x:

<Formula label="DPO-style preference loss">−logσ(β[(logπ−logπref)(y_w)−(logπ−logπref)(y_l)])</Formula>

Here `σ(z)=1/(1+exp(−z))`. **πref is frozen**, with positive support, not another policy updated alongside π. The log-ratios measure changes relative to that reference; the pairwise normalization terms cancel. **β** scales the preference logit and corresponds to the KL strength in the paper's reward-to-policy derivation. With finite steps and fixed learning rate, changing β also changes gradient magnitude/saturation; it is not a promise that larger β always gives better success or monotonically smaller measured KL. At π=πref this pair loss is log2, not zero. In the toy the ascent update is `β σ(−z)(f_w−f_l)` for linear logits; the executable tests check it against finite differences of the log-probability loss.

### One corpus, an explicit total-update budget

All values are **synthetic**. Context x is uniform on [−1,1], actions `a∈{−1,0,1}`; the generator's utility is `u(x,a)=−[a−(0.85x+0.2sin4x)]²`. The policy uses shared four-feature logits `f=(ax,a sin4x,a,a²)` and frozen reference weights **(−0.3,0,0.2,−0.5)**; all policy arms start there. Every seed **11/23/37/53/71** generates the same **64** candidate-action pairs for all arms. Clean labels rank the two training candidates; the **25 % label-flip probability case** reverses a fixed random subset, without changing candidates, contexts or evaluation starts. Training binary-success labels use a utility gap≤0.12; those are separate supervision, not the preference label itself.

Each arm gets **240 total gradient-update slots**, full batch64, learning rate **0.12**, β=**0.5**, and for RM+RL KL coefficient τ=**0.5**. Every slot consumes the same context/pair batch; data are reused, not240 new pair collections. Budget counts a gradient update to one four-parameter block, **not FLOPs or total parameter count**:

| arm | objective / supervision actually used | policy / reward updates |
|---|---|---|
| BC on preferred only | cross-entropy on the labelled winner; ignores loser likelihood | 240 / 0 |
| DPO | pairwise reference-relative loss; no explicit reward fit | 240 / 0 |
| reward-model + RL | first Bradley–Terry reward fit, then maximize `Eπ[r_hat]−τ KL(π,πref)` | 120 / 120 |
| BC-all | cross-entropy averaging both candidate actions | 240 / 0 |
| success-filter | BC on the pair's binary-success candidates, zero contribution if neither succeeds | 240 / 0 |

**Do not give RM+RL240 reward updates plus240 policy updates and call it equal.** Its120+120 allocation is declared before evaluation; fewer policy steps and a separate reward block are part of this fixed-budget comparison. The RL phase exactly enumerates the three actions to compute its expected learned reward / KL gradient: no PPO, sampled environment interaction or ground-truth reward oracle. The three core preference-only arms never consume binary labels. Records expose the same fields to all arms, but **success-filter consumes extra binary training supervision**; it is an auxiliary baseline, not evidence that success filtering beats preference learning under preference-only information. BC-all and success-filter are included to distinguish throwing data away from learning pairwise ordering.

### Held-out performance and label corruption

Evaluation has **256 disjoint contexts per seed**, generated by a separate RNG, never passed to training. Success is the exact policy probability of choosing an action within0.12 of the best utility, averaged over held-out contexts; regret is `max_a u−Eπu`. These are finite-action expected metrics, not robot rollout success. Truth utility is used only in data generation and evaluation.
```python
#!/usr/bin/env python3
"""Synthetic contextual bandit, not robot/VLA DPO or an online RL reproduction.
Five arms reconcile BC-all/success-filter literacy with the three core baselines.
Every arm receives SAME 64 training preference pairs and 240 total gradient slots.
RM+RL spends 120 slots fitting reward, then 120 on exact expected reward-minus-KL.
Binary success labels are extra TRAINING supervision for success_filter only;
all records include them but core DPO/RM/BC_preferred do not consume them.
Truth utility is used only by data generation and held-out scoring, never training.
"""
from math import exp, log, log1p, sin
from random import Random
from statistics import mean, pstdev

SEEDS=(11,23,37,53,71)
ACTIONS=(-1.,0.,1.)
REF=(-.3,0.,.2,-.5)
PAIRS, UPDATES, BETA, LR=64,240,.5,.12
ARMS=('BC_all','success_filter','BC_preferred','DPO','RM_RL')


def features(x,a):return (a*x,a*sin(4*x),a,a*a)


def dot(a,b):return sum(x*y for x,y in zip(a,b))


def probabilities(theta,x):
    scores=[dot(theta,features(x,a)) for a in ACTIONS];mx=max(scores)
    values=[exp(v-mx) for v in scores];total=sum(values)
    return tuple(v/total for v in values)


def utility(x,a):return -(a-(.85*x+.2*sin(4*x)))**2


def successful(x,a):return max(utility(x,b) for b in ACTIONS)-utility(x,a)<=.12


def make_data(seed,noise):
    rng=Random(seed);flip=Random(seed+9000);records=[]
    for _ in range(PAIRS):
        x=rng.uniform(-1,1);a,b=rng.sample(range(3),2)
        w,l=(a,b) if utility(x,ACTIONS[a])>=utility(x,ACTIONS[b]) else (b,a)
        if flip.random()<noise:w,l=l,w
        records.append((x,w,l,tuple(int(successful(x,a)) for a in ACTIONS)))
    erng=Random(seed+1000);evaluation=tuple(erng.uniform(-1,1) for _ in range(256))
    assert not set(evaluation)&{x for x,_,_,_ in records}
    return tuple(records),evaluation


def sigmoid_minus(z):
    if z>=0:
        e=exp(-z);return e/(1+e)
    return 1/(1+exp(z))


def dpo_loss(theta,x,w,l):
    p,ref=probabilities(theta,x),probabilities(REF,x)
    z=BETA*((log(p[w])-log(ref[w]))-(log(p[l])-log(ref[l])))
    return max(0.,-z)+log1p(exp(-abs(z)))


def gradient(theta,reward,records,arm,slot):
    grad=[0.]*4
    for x,w,l,success in records:
        fs=tuple(features(x,a) for a in ACTIONS)
        if arm=='DPO' or (arm=='RM_RL' and slot<UPDATES//2):
            delta=tuple(a-b for a,b in zip(fs[w],fs[l]))
            if arm=='DPO':
                z=BETA*dot(tuple(a-b for a,b in zip(theta,REF)),delta)
                g=tuple(BETA*sigmoid_minus(z)*v for v in delta)
            else:g=tuple(sigmoid_minus(dot(reward,delta))*v for v in delta)
        else:
            p=probabilities(theta,x)
            if arm=='RM_RL':
                ref=probabilities(REF,x)
                adjusted=tuple(dot(reward,f)-BETA*log(pa/pr) for f,pa,pr in zip(fs,p,ref))
                baseline=dot(p,adjusted)
                g=tuple(sum(pa*(v-baseline)*f[j] for pa,v,f in zip(p,adjusted,fs)) for j in range(4))
            else:
                candidates=(w,l) if arm=='BC_all' else ((w,) if arm=='BC_preferred' else tuple(a for a in (w,l) if success[a]))
                # Empty binary-success pairs contribute zero, but still use the same slot/batch denominator.
                g=tuple((mean(fs[a][j] for a in candidates)-sum(pa*f[j] for pa,f in zip(p,fs))) if candidates else 0. for j in range(4))
        grad=[a+b/len(records) for a,b in zip(grad,g)]
    return tuple(grad)


def train(records,arm):
    theta=REF;reward=(0.,)*4;policy_updates=reward_updates=0
    for slot in range(UPDATES):
        g=gradient(theta,reward,records,arm,slot)
        if arm=='RM_RL' and slot<UPDATES//2:
            reward=tuple(a+LR*b for a,b in zip(reward,g));reward_updates+=1
        else:
            theta=tuple(a+LR*b for a,b in zip(theta,g));policy_updates+=1
    return theta,(policy_updates,reward_updates)


def evaluate(theta,contexts):
    successes=[];regrets=[]
    for x in contexts:
        p=probabilities(theta,x);u=tuple(utility(x,a) for a in ACTIONS)
        successes.append(sum(pa*int(successful(x,a)) for pa,a in zip(p,ACTIONS)))
```
