## Why a real arm is a hard RL environment

7.3 trained in simulation, where a reset is free and a million steps is a coffee break. On a real arm:

- **The reward is sparse.** "The part is in the slot" is easy to judge and hard to shape; dense shaped rewards invite reward hacking (7.2).
- **Every failure costs a reset.** Somebody re-stages the scene. A learner that needs thousands of failures before its first success is not usable.
- **Exploration must stay safe.** Random actions hit things; limits from 8.5 bound the action space.
- **Hours, not days.** The budget is a few hours of robot time, so every transition should be reused many times: off-policy RL with a replay buffer, not on-policy PPO.

## RLPD: offline data in every batch

RLPD (Ball et al., 2023) asks how to use a small offline dataset (demos) inside an ordinary off-policy learner such as SAC, without pre-training. Its recipe has three parts:

- <Term id="symmetric-sampling">Symmetric sampling</Term>: every training batch is 50 % from the offline buffer and 50 % from the online replay buffer. The paper finds this works better than simply putting the offline data into the replay buffer at the start, and that the exact ratio is not critical.
- **LayerNorm in the critic**, which bounds how far Q-values can extrapolate to actions the data never covered.
- **Sample efficiency tricks**: a large critic ensemble and many gradient updates per environment step (a high update-to-data ratio).

The abstract reports up to 2.5× improvement over prior approaches across a range of benchmarks; that is the paper's measurement, not run here.

## HIL-SERL: RLPD plus a human on a real arm

HIL-SERL (Luo et al., 2024) builds on RLPD and adds what a real robot needs:

- **A few demos** (20–30 in the paper) in their own buffer; the learner samples the demo buffer and the RL buffer equally.
- **A <Term id="reward-classifier">reward classifier</Term>** instead of a hand-written reward: a small image classifier trained on success / failure frames (the paper uses about 200 positive and 1000 negative frames, collected in about 5 minutes, and reports over 95 % accuracy). It turns "did it work?" into a binary reward and an end-of-episode signal.
- **Human interventions** with a SpaceMouse during training. Intervention transitions go into both buffers; the policy's own transitions only into the RL buffer. The paper warns that long, sparse interventions that carry the task to success make the critic overestimate values: correct briefly and hand back.
- **Engineering**: actions in the end-effector frame with bounds, an impedance controller, a pretrained vision backbone, and an actor–learner split so the robot keeps acting while the learner updates.

Reported results (paper's measurements, not run here): training takes 1 to 2.5 hours for nearly all tasks; against imitation baselines trained on comparable data, success improves on average by about 2× and cycle time is about 1.8× faster. Training from scratch with neither demos nor interventions reached 0 % in their ablation.

## Run the chain toy

`rlpd_chain_toy.py` shrinks this to a 10-state "combination lock": in every state one of two actions moves forward, the other sends you back to the start (a reset), and only the goal pays reward 1. Three tabular Q-learners use the same replay update (8 sampled transitions per step): online replay only, 3 demos dumped into the same buffer, and 3 demos in their own buffer with 50/50 symmetric sampling.
```python
"""rlpd_chain_toy.py: why a few demos plus 50/50 sampling make sparse-reward RL possible (stdlib).

A 10-state "combination lock" chain stands in for a real-robot task:
- states 0..9, start at 0, goal is state 9;
- in every state one of two actions is right (fixed per state); the right one
  moves forward, the wrong one sends you back to 0 (think: the part slipped,
  someone resets the scene);
- reward is 1 only on reaching the goal, 0 everywhere else; at most 30 steps
  per episode, 40 episodes per run.

Three tabular Q-learning learners share the same replay update (8 sampled
transitions per environment step, epsilon-greedy with epsilon 0.1):
  online    online replay only, no demos
  one_buf   3 demos dumped into the same buffer as online data (uniform
            sampling, so the demos get diluted as online data piles up)
  rlpd_5050 3 demos in their own buffer, every sample is a coin flip between
            the demo buffer and the online buffer (RLPD's symmetric sampling)

20 seeds each. Reported: how many seeds ever reached the goal while
training, mean episode of the first success, how many resets the learner
caused (each one is a human walking over on a real robot), greedy success at
the end, and what share of the last episode's samples came from demos.
No neural nets, no ensembles, no LayerNorm: only the data-mixing idea.
"""

import random

N = 10            # states 0..9, goal = N - 1
H = 30            # steps per episode
EPISODES = 40
SEEDS = 20
ALPHA = 0.5
GAMMA = 0.9
EPS = 0.1
UPDATES = 8       # sampled Q updates per environment step
DEMOS = 3
LOCK_SEED = 7     # the "right" action per state is the same for every run


def make_lock():
    r = random.Random(LOCK_SEED)
    return [r.randrange(2) for _ in range(N - 1)]


LOCK = make_lock()


def step(s, a):
    """Return (next_state, reward, done)."""
    if a != LOCK[s]:
        return 0, 0.0, False          # wrong action: back to the start
    s2 = s + 1
    if s2 == N - 1:
        return s2, 1.0, True
    return s2, 0.0, False


def demo_transitions():
    out = []
    for _ in range(DEMOS):
        s = 0
        while True:
            a = LOCK[s]
            s2, r, done = step(s, a)
            out.append((s, a, r, s2, done))
            if done:
                break
            s = s2
    return out


def act(q, s, rng, eps):
    if rng.random() < eps or q[s][0] == q[s][1]:
        return rng.randrange(2)
    return 0 if q[s][0] > q[s][1] else 1


def update(q, t):
    s, a, r, s2, done = t
    target = r if done else r + GAMMA * max(q[s2])
    q[s][a] += ALPHA * (target - q[s][a])


def greedy_success(q):
    s = 0
    for _ in range(H):
        a = 0 if q[s][0] >= q[s][1] else 1   # fixed tie-break, no luck
        s, _, done = step(s, a)
        if done:
            return True
    return False


def run(mode, seed):
    rng = random.Random(1000 + seed)
    q = [[0.0, 0.0] for _ in range(N)]
    demos = demo_transitions()
    online = []
    first = None
    resets = 0
    from_demo = drawn = 0
    for ep in range(1, EPISODES + 1):
        s = 0
        ep_demo = ep_drawn = 0
        for _ in range(H):
            a = act(q, s, rng, EPS)
            s2, r, done = step(s, a)
            t = (s, a, r, s2, done)
            online.append(t)
            if a != LOCK[s]:
                resets += 1
            for _ in range(UPDATES):
                if mode == "online":
                    x = online[rng.randrange(len(online))]
                    d = False
                elif mode == "one_buf":
                    i = rng.randrange(len(demos) + len(online))
                    d = i < len(demos)
                    x = demos[i] if d else online[i - len(demos)]
                else:  # rlpd_5050
                    d = rng.random() < 0.5
                    x = demos[rng.randrange(len(demos))] if d else online[rng.randrange(len(online))]
                update(q, x)
                ep_demo += d
                ep_drawn += 1
            if done:
                if first is None:
                    first = ep
                break
            s = s2
        from_demo, drawn = ep_demo, ep_drawn
    return {
        "first": first,
        "resets": resets,
        "greedy": greedy_success(q),
        "demo_share": from_demo / drawn,
        "steps": len(online),
    }


def summarize(mode):
    rs = [run(mode, k) for k in range(SEEDS)]
    hit = [r["first"] for r in rs if r["first"] is not None]
    never = SEEDS - len(hit)
    mean_first = sum(hit) / len(hit) if hit else float("nan")
    resets = sum(r["resets"] for r in rs) / SEEDS
    greedy = sum(r["greedy"] for r in rs)
    share = sum(r["demo_share"] for r in rs) / SEEDS
    steps = sum(r["steps"] for r in rs) / SEEDS
    return len(hit), never, mean_first, resets, greedy, share, steps


def main():
    print("10-state lock chain: wrong action -> back to 0, reward only at the goal")
    print(f"right actions per state: {LOCK}")
    print(f"chance a uniformly random run of 9 moves opens the lock: 1/{2 ** (N - 1)}")
    print(f"{EPISODES} episodes x <= {H} steps, {UPDATES} sampled updates per step, epsilon {EPS}, {SEEDS} seeds")
    print(f"demos: {DEMOS} x {N - 1} transitions = {DEMOS * (N - 1)} transitions")
    print()
    print("mode       reached  never  first_ep  resets/run  greedy_end  demo_share_last  env_steps/run")
    rows = {}
    for mode in ("online", "one_buf", "rlpd_5050"):
        rows[mode] = summarize(mode)
        hit, never, mf, rs, g, sh, st = rows[mode]
        print(f"{mode:<10} {hit:>4}/{SEEDS}  {never:>5}  {mf:>8.1f}  {rs:>10.1f}  {g:>7}/{SEEDS}  {100 * sh:>13.1f} %  {st:>13.1f}")
    print()
    o, b, p = rows["online"], rows["one_buf"], rows["rlpd_5050"]
    print(f"resets per run: online {o[3]:.1f} vs rlpd_5050 {p[3]:.1f} (each reset = a person re-staging the scene)")
    print(f"demo share of the last episode's samples: one_buf {100 * b[5]:.1f} %, rlpd_5050 {100 * p[5]:.1f} %")
    print("note: tabular Q never forgets, so one_buf still works here; with a neural critic the")
    print("diluted demos are what RLPD found weaker than keeping a fixed 50/50 split.")


if __name__ == "__main__":
    main()
```

## Common mistakes

- **No demos, no interventions.** With a sparse reward the learner may never see a success; the paper's from-scratch ablation stayed at 0 %, and the toy's online-only learner misses in some seeds.
- **Long takeovers that finish the task.** They inflate the critic's values; correct and hand back.
- **A reward classifier that is fooled.** If it fires on near-misses, the policy learns the near-miss. Add the false positives as negatives and retrain.
- **Unbounded exploration.** Set joint / end-effector limits (8.5) before the first online episode.

## Preferences: DPO-style loss versus a learned reward
A preference pair says which candidate is better at the **same context**, not how far along a video the robot has progressed. This is distinct from [10.7 SARM / RA-BC](/en/month/month-10/vla-rl-finetune), Cal-ConRFT calibration, RPD teacher guidance and OneDP distillation; the RLPD/HIL-SERL chain above remains a different experiment. Rafailov et al. (2023), [Direct Preference Optimization](https://arxiv.org/abs/2305.18290), derives the pairwise objective from a KL-regularized reward objective and a Bradley–Terry preference model. It is originally a language-model paper, not evidence that this toy runs VLA preference training. Paper figures: **以论文为准**. Full VLA/GPU and online robot RL: **本页未运行**.

### The loss and its reference

For preferred winner `y_w` and loser `y_l`, condition every probability on x:

<Formula label="DPO-style preference loss">−logσ(β[(logπ−logπref)(y_w)−(logπ−logπref)(y_l)])</Formula>

Here `σ(z)=1/(1+exp(−z))`. **πref is frozen**, with positive support, not another policy updated alongside π. The log-ratios measure changes relative to that reference; the pairwise normalization terms cancel. **β** scales the preference logit and corresponds to the KL strength in the paper's reward-to-policy derivation. With finite steps and fixed learning rate, changing β also changes gradient magnitude/saturation; it is not a promise that larger β always gives better success or monotonically smaller measured KL. At π=πref this pair loss is log2, not zero. In the toy the ascent update is `β σ(−z)(f_w−f_l)` for linear logits; the executable tests check it against finite differences of the log-probability loss.

### One corpus, an explicit total-update budget

All values are **synthetic**. Context x is uniform on [−1,1], actions `a∈{−1,0,1}`; the generator's utility is `u(x,a)=−[a−(0.85x+0.2sin4x)]²`. The policy uses shared four-feature logits `f=(ax,a sin4x,a,a²)` and frozen reference weights **(−0.3,0,0.2,−0.5)**; all policy arms start there. Every seed **11/23/37/53/71** generates the same **64** candidate-action pairs for all arms. Clean labels rank the two training candidates; the **25 % label-flip probability case** reverses a fixed random subset, without changing candidates, contexts or evaluation starts. Training binary-success labels use a utility gap≤0.12; those are separate supervision, not the preference label itself.

Each arm gets **240 total gradient-update slots**, full batch64, learning rate **0.12**, β=**0.5**, and for RM+RL KL coefficient τ=**0.5**. Every slot consumes the same context/pair batch; data are reused, not240 new pair collections. Budget counts a gradient update to one four-parameter block, **not FLOPs or total parameter count**:

| arm | objective / supervision actually used | policy / reward updates |
|---|---|---|
| BC on preferred only | cross-entropy on the labelled winner; ignores loser likelihood | 240 / 0 |
| DPO | pairwise reference-relative loss; no explicit reward fit | 240 / 0 |
| reward-model + RL | first Bradley–Terry reward fit, then maximize `Eπ[r_hat]−τ KL(π,πref)` | 120 / 120 |
| BC-all | cross-entropy averaging both candidate actions | 240 / 0 |
| success-filter | BC on the pair's binary-success candidates, zero contribution if neither succeeds | 240 / 0 |

**Do not give RM+RL240 reward updates plus240 policy updates and call it equal.** Its120+120 allocation is declared before evaluation; fewer policy steps and a separate reward block are part of this fixed-budget comparison. The RL phase exactly enumerates the three actions to compute its expected learned reward / KL gradient: no PPO, sampled environment interaction or ground-truth reward oracle. The three core preference-only arms never consume binary labels. Records expose the same fields to all arms, but **success-filter consumes extra binary training supervision**; it is an auxiliary baseline, not evidence that success filtering beats preference learning under preference-only information. BC-all and success-filter are included to distinguish throwing data away from learning pairwise ordering.

### Held-out performance and label corruption

Evaluation has **256 disjoint contexts per seed**, generated by a separate RNG, never passed to training. Success is the exact policy probability of choosing an action within0.12 of the best utility, averaged over held-out contexts; regret is `max_a u−Eπu`. These are finite-action expected metrics, not robot rollout success. Truth utility is used only in data generation and evaluation.
```python
#!/usr/bin/env python3
"""Synthetic contextual bandit, not robot/VLA DPO or an online RL reproduction.
Five arms reconcile BC-all/success-filter literacy with the three core baselines.
Every arm receives SAME 64 training preference pairs and 240 total gradient slots.
RM+RL spends 120 slots fitting reward, then 120 on exact expected reward-minus-KL.
Binary success labels are extra TRAINING supervision for success_filter only;
all records include them but core DPO/RM/BC_preferred do not consume them.
Truth utility is used only by data generation and held-out scoring, never training.
"""
from math import exp, log, log1p, sin
from random import Random
from statistics import mean, pstdev

SEEDS=(11,23,37,53,71)
ACTIONS=(-1.,0.,1.)
REF=(-.3,0.,.2,-.5)
PAIRS, UPDATES, BETA, LR=64,240,.5,.12
ARMS=('BC_all','success_filter','BC_preferred','DPO','RM_RL')


def features(x,a):return (a*x,a*sin(4*x),a,a*a)


def dot(a,b):return sum(x*y for x,y in zip(a,b))


def probabilities(theta,x):
    scores=[dot(theta,features(x,a)) for a in ACTIONS];mx=max(scores)
    values=[exp(v-mx) for v in scores];total=sum(values)
    return tuple(v/total for v in values)


def utility(x,a):return -(a-(.85*x+.2*sin(4*x)))**2


def successful(x,a):return max(utility(x,b) for b in ACTIONS)-utility(x,a)<=.12


def make_data(seed,noise):
    rng=Random(seed);flip=Random(seed+9000);records=[]
    for _ in range(PAIRS):
        x=rng.uniform(-1,1);a,b=rng.sample(range(3),2)
        w,l=(a,b) if utility(x,ACTIONS[a])>=utility(x,ACTIONS[b]) else (b,a)
        if flip.random()<noise:w,l=l,w
        records.append((x,w,l,tuple(int(successful(x,a)) for a in ACTIONS)))
    erng=Random(seed+1000);evaluation=tuple(erng.uniform(-1,1) for _ in range(256))
    assert not set(evaluation)&{x for x,_,_,_ in records}
    return tuple(records),evaluation


def sigmoid_minus(z):
    if z>=0:
        e=exp(-z);return e/(1+e)
    return 1/(1+exp(z))


def dpo_loss(theta,x,w,l):
    p,ref=probabilities(theta,x),probabilities(REF,x)
    z=BETA*((log(p[w])-log(ref[w]))-(log(p[l])-log(ref[l])))
    return max(0.,-z)+log1p(exp(-abs(z)))


def gradient(theta,reward,records,arm,slot):
    grad=[0.]*4
    for x,w,l,success in records:
        fs=tuple(features(x,a) for a in ACTIONS)
        if arm=='DPO' or (arm=='RM_RL' and slot<UPDATES//2):
            delta=tuple(a-b for a,b in zip(fs[w],fs[l]))
            if arm=='DPO':
                z=BETA*dot(tuple(a-b for a,b in zip(theta,REF)),delta)
                g=tuple(BETA*sigmoid_minus(z)*v for v in delta)
            else:g=tuple(sigmoid_minus(dot(reward,delta))*v for v in delta)
        else:
            p=probabilities(theta,x)
            if arm=='RM_RL':
                ref=probabilities(REF,x)
                adjusted=tuple(dot(reward,f)-BETA*log(pa/pr) for f,pa,pr in zip(fs,p,ref))
                baseline=dot(p,adjusted)
                g=tuple(sum(pa*(v-baseline)*f[j] for pa,v,f in zip(p,adjusted,fs)) for j in range(4))
            else:
                candidates=(w,l) if arm=='BC_all' else ((w,) if arm=='BC_preferred' else tuple(a for a in (w,l) if success[a]))
                # Empty binary-success pairs contribute zero, but still use the same slot/batch denominator.
                g=tuple((mean(fs[a][j] for a in candidates)-sum(pa*f[j] for pa,f in zip(p,fs))) if candidates else 0. for j in range(4))
        grad=[a+b/len(records) for a,b in zip(grad,g)]
    return tuple(grad)


def train(records,arm):
    theta=REF;reward=(0.,)*4;policy_updates=reward_updates=0
    for slot in range(UPDATES):
        g=gradient(theta,reward,records,arm,slot)
        if arm=='RM_RL' and slot<UPDATES//2:
            reward=tuple(a+LR*b for a,b in zip(reward,g));reward_updates+=1
        else:
            theta=tuple(a+LR*b for a,b in zip(theta,g));policy_updates+=1
    return theta,(policy_updates,reward_updates)


def evaluate(theta,contexts):
    successes=[];regrets=[]
    for x in contexts:
        p=probabilities(theta,x);u=tuple(utility(x,a) for a in ACTIONS)
        successes.append(sum(pa*int(successful(x,a)) for pa,a in zip(p,ACTIONS)))
```

## Reason, then act: a visual plan latent (ThinkAct)

RLPD and HIL-SERL above improve one policy from rewards. A pretrained VLA can also fail for a different reason. It maps the current observation straight to an action, so when two stages of a task look the same in the camera it does not know which stage it is in. **ThinkAct** splits the work in two. A multimodal LLM reasons over the instruction and the image and writes a **visual plan latent**, a short 2-D trajectory, and it is trained with reinforcement learning on rewards computed from that plan. A separate action model then acts conditioned on the latent. This section builds a **synthetic** stand-in for the plan-latent idea. It is not Qwen2.5-VL, not GRPO training and not a DiT policy, and it does not redo CoT-VLA, MAP-VLA (10.5) or TraceVLA.

<Resource id="thinkact-paper" />

**Source actually opened (PDF body read via pdftotext, arXiv 2507.16815 v2, cs.CV).**

- **Huang, Wu, Chen, Wang and Yang, "ThinkAct: Vision-Language-Action Reasoning via Reinforced Visual Latent Planning" (NVIDIA, National Taiwan University):**
  - A reasoning MLLM `F_θ` (Qwen2.5-VL 7B) produces reasoning text and a visual plan latent `c_t`. The latent decodes to K = 8 gripper points in [0, 1]².
  - The **goal reward** (eq. 1) is `r_goal = ½ (f(p_1, p̂_1) + f(p_K, p̂_K))` with `f(p, p′) = max(0, 1 − ‖p − p′‖²)`. The **trajectory reward** (eq. 2) is `r_traj = max(0, 1 − d(τ, τ̂))` with dynamic time warping as the distance. Eq. 3 combines them as `r = 0.9 · r_visual + 0.1 · r_format`, with `r_visual = 0.5 · r_goal + 0.5 · r_traj`.
  - Training is GRPO (eq. 4) with group-normalised advantages, β = 1e-2, a rollout size of 5 and 6K iterations.
  - The action model `π_φ` is a 432M DiT policy conditioned on `c_t` through a Q-Former (32 queries) and trained by imitation (eq. 5) with `F_θ` frozen. It runs **asynchronously**: one latent serves N actions (N = 15 on SimplerEnv, 75 on LIBERO). Appendix B.6 reports N = 25 / 50 / 75 / 100 → 84.0 / 84.6 / 84.4 / 83.7 % on LIBERO.
  - **Reported results (以论文为准):** Table 1 gives LIBERO overall 84.4 (OpenVLA 76.5, DiT-Policy 76.8, CoT-VLA 83.9), LIBERO-Long 70.9, and SimplerEnv Google-VM 71.5, Google-VA 65.1, Bridge-VM 43.8. Table 3 (SimplerEnv) ablates the rewards: full 60.1, without `r_traj` 59.2, without `r_goal` 59.1, without both 56.9, SFT only 56.4. Appendix B.7 reports ThinkAct about 17 % slower than OpenVLA, and its per-suite deltas there do not all match the differences in Table 1; this page does not resolve that.
  - The paper also reports few-shot adaptation (10 demos per task) and self-correction from a short video, and it names MLLM hallucination as a limitation. Training used 16 A100 GPUs (本页未运行).

### Plan rewards and what the latent carries

<Formula label="Goal reward (ThinkAct eq. 1)">r_goal = ½ · (f(p_1, q_1) + f(p_K, q_K)),  f(p, q) = max(0, 1 − ‖p − q‖²)</Formula>

<Formula label="Trajectory reward (ThinkAct eq. 2)">r_traj = max(0, 1 − DTW(p, q))</Formula>

<Formula label="Visual reward (ThinkAct eq. 3, without the format term)">r_visual = 0.5 · r_goal + 0.5 · r_traj</Formula>

In the toy the latent is the list of remaining **stage targets**, scaled to [0, 1]² on a 9 × 9 grid. It is not ThinkAct's 8 gripper points.

**Worked example.** Take the task P → Q → P with P = (2, 6) and Q = (6, 2) on the grid, so each cell is 1/8 after scaling. A correct latent scores `r_visual = 1`. The **rotated** latent Q → P → P has the right endpoint, so its endpoint error is 0 cells, but its first point is off by (0.5, 0.5): `f = 1 − 0.5 = 0.5`, `r_goal = 0.75`, DTW = 0.7071, `r_traj = 0.2929`, `r_visual = 0.5214`. A latent whose first point is jittered by one cell scores 0.9336. **Endpoint error alone cannot see a wrong order; the trajectory term can.**

**No integration step.** The robot moves one grid cell per step and nothing is stepped in continuous time, so no step-size stability criterion applies. The quantity that plays that role is the **latent refresh** interval, the toy's version of ThinkAct's N actions per latent.

### Fair setup

`thinkact_visual_latent_toy.py` is **synthetic** and stdlib only. **Model assumptions:**
- A task is an ordered list of target cells, and some cells are visited twice (PQP, PQPQ). The stage advances when the robot stands on the next target.
- The camera shows the stage indicator with probability `1 − q_hide`. When it is hidden, a revisited cell looks the same in different stages.
- **Shared demos:** 20 expert episodes per trial (x first, then y; a 0.1 chance per step of slipping to a random move) give the labels for every learned table.
- The reasoner stand-in writes the remaining targets. Each target is moved to a neighbouring cell with probability `p_plan` (a hallucination stand-in), and the latent is rewritten every `refresh` steps if the stage is visible.
- An unseen key falls back to the "stage hidden" majority, and then to "stay".

| Arm | Input to the action table |
|---|---|
| A_direct | (cell, visible stage or "hidden") |
| B_latent | (cell, current plan point); it moves to the next point on reaching one |
| C_scrambled | B's table with the same targets in rotated order (t_2, …, t_K, t_1); with one stage this is the identity |

**Common random numbers:** for each (regime, seed, trial) the scene, the tasks, the demos, the plan jitter, the slip draws and the hide draws are drawn once and shared by all three arms. There are 5 seeds × 40 trials.

The metrics are:
- `stage`: the share of stages completed.
- `full`: all stages completed.
- `endpoint`: the latent's endpoint error in cells.
- `r_visual`: the eq. 3 visual reward of the first latent; A has no latent and prints 0.

| Regime | Stages | q_hide | hide block | p_plan | refresh | drop |
|---|---|---|---|---|---|---|
| single_step | P | 0.5 | 1 | 0.1 | start only | no |
| multi_stage | PQP | 0.5 | 1 | 0.1 | start only | no |
| ambiguous | PQPQ | 0.8 | 1 | 0.1 | start only | no |
| multi_stage_block | PQP | 0.5 | 8 | 0.1 | start only | no |
| ambiguous_block | PQPQ | 0.8 | 8 | 0.1 | start only | no |
| noisy_plan | PQP | 0.5 | 1 | 0.5 | start only | no |
| drop_dense | PQP | 0.5 | 1 | 0.1 | every 5 steps | yes |
| drop_sparse | PQP | 0.5 | 1 | 0.1 | start only | yes |

In the `drop` regimes, once in the middle third of the episode the stage counter falls back by one (the object slips). The latent then has to be rewritten, or it will point past a stage that is no longer done.

**Choices made after seeing results.** Three changes came after the first full run; the toy prints the first version of each.
- **The fallback.** At first an unseen (cell, plan point) key made B stay where it was, while A kept its (cell, hidden) fallback. That asymmetry, not the latent, decided the result: B lost to A in every regime, for example multi_stage B−A full −0.2000±0.0901 and noisy_plan −0.6850±0.0576. Now every arm uses the same fallback. The old line is printed for each regime.
- **What C is.** C first used the latent of a different task in the same scene. Its keys never occur in the demos, so it fell back to A's hidden-stage table and in effect ignored the latent (single_step C−B is a tie on every seed). C now rotates the true targets, so its keys are seen in the demos but in the wrong order. The first C is printed (C−B full).
- **The `_block` regimes.** With a fresh hide draw every step, the multi_stage gap was only a near-tie. A camera that loses the indicator for stretches of 8 steps is the case the latent is for, so two block regimes were added. The per-step regimes remain in the table and in the output.

```python
#!/usr/bin/env python3
"""Synthetic ThinkAct-style toy: direct policy vs plan-latent policy vs a scrambled latent. Stdlib only.

A 9 x 9 grid; a task is an ordered list of target cells (stages), possibly revisiting a cell.
The stage counter advances when the robot stands on the next target. A camera shows the stage
indicator with probability 1 - Q_HIDE per step; otherwise the observation is the cell only, so
a revisited cell looks the same in different stages (perceptual aliasing).
Shared demos: N_DEMO expert episodes per trial (x first, then y; each step slips to a random
move with probability SLIP) give the labels for every learned table.

Arms (same task, same demos, same slip draws, same hide draws):
  A_direct   obs -> action: majority demo action for (cell, visible stage or "hidden")
  B_latent   a reasoner stand-in writes a plan latent = the remaining targets (each cell jittered
             to a neighbour with probability P_PLAN, a hallucination stand-in); the action model is
             the majority demo action for (cell, current plan point) and moves to the next point when
             it stands on one; the latent is rewritten every REFRESH steps when the stage is visible
             (REFRESH = 0: written once at the start)
  C_scrambled  B's action model with the same targets in a rotated order (t_2, ..., t_K, t_1);
             with one stage the rotation is the identity, so C equals B there by construction
  The first version's C used the targets of a different task in the same scene; its (cell, point)
  keys never occur in the demos, so it fell back to A's hidden-stage table; it is printed as an
  alternative.
An unseen key falls back to the (cell, hidden) majority for every arm, then to "stay"; the first
version let B stay at once and is printed as the fallback alternative.
Plan metrics for a latent (points scaled to [0, 1]^2 as in ThinkAct eq. 1-3):
  r_goal = (f(p_1, q_1) + f(p_K, q_K)) / 2 with f = max(0, 1 - |p - q|^2)
  r_traj = max(0, 1 - DTW(p, q)) (DTW: sum of Euclidean distances along the best alignment)
  r_visual = 0.5 r_goal + 0.5 r_traj; endpoint error = |p_K - q_K| in cells
The latent is a list of stage targets, not ThinkAct's 8 gripper points; no MLLM, no GRPO, no DiT.
No integration step: the grid moves one cell per step, nothing is stepped in continuous time.
Common random numbers: per (regime, seed, trial) the scene, the tasks, the demos, the plan jitter,
the slip draws and the hide draws are drawn once and shared by every arm.
Metrics per trial, averaged over TRIALS per seed: stage (share of stages completed), full
(all stages completed), endpoint, r_visual (latent arms only).
Labels: tie = identical on every seed; numerically zero = |paired mean| and sd both < 1e-9
(effectively a tie, no sign count); |m| <= sd = near-tie; |m| > sd = consistent gap (small if
|m| < 20 % of the smaller arm mean, else clear), with a sign count.
Qwen2.5-VL / LIBERO / SimplerEnv / a GPU: 本页未运行. Paper numbers: 以论文为准.
"""
import math
import random

SEEDS = (0, 1, 2, 3, 4)
TRIALS = 40
SIZE = 9
N_DEMO = 20
SLIP = 0.1
MOVES = ((0, 0), (1, 0), (-1, 0), (0, 1), (0, -1))
NUM_ZERO = 1e-9
ARMS = ("A_direct", "B_latent", "C_scrambled")
# name: (stage pattern, Q_HIDE, P_PLAN, REFRESH, drop, HIDE_BLOCK)
# HIDE_BLOCK = steps per hide draw (1 = a fresh draw every step); the two *_block regimes were
# added after the per-step regimes had run (see the en / zh prose); every regime is printed.
REGIMES = {
    "single_step": ("P", 0.5, 0.1, 0, False, 1),
    "multi_stage": ("PQP", 0.5, 0.1, 0, False, 1),
    "ambiguous": ("PQPQ", 0.8, 0.1, 0, False, 1),
    "multi_stage_block": ("PQP", 0.5, 0.1, 0, False, 8),
    "ambiguous_block": ("PQPQ", 0.8, 0.1, 0, False, 8),
    "noisy_plan": ("PQP", 0.5, 0.5, 0, False, 1),
    "drop_dense": ("PQP", 0.5, 0.1, 5, True, 1),
    "drop_sparse": ("PQP", 0.5, 0.1, 0, True, 1),
}


def cell(rng):
    return (rng.randrange(SIZE), rng.randrange(SIZE))


def expert(c, t):
    if c[0] != t[0]:
        return 1 if t[0] > c[0] else 2
    if c[1] != t[1]:
        return 3 if t[1] > c[1] else 4
    return 0


def step(c, a):
    return (min(SIZE - 1, max(0, c[0] + MOVES[a][0])), min(SIZE - 1, max(0, c[1] + MOVES[a][1])))


def world(regime, seed, trial):
    pattern, q_hide, p_plan, refresh, drop, block = REGIMES[regime]
    rng = random.Random(f"{regime}-{seed}-{trial}")
    start = cell(rng)
    names = sorted(set(pattern))
    while True:
        spots = {n: cell(rng) for n in names}
        other = {n: cell(rng) for n in names}
        allc = list(spots.values()) + list(other.values()) + [start]
        if len(set(allc)) == len(allc):
            break
    task = [spots[n] for n in pattern]
    wrong = [other[n] for n in pattern]
    horizon = 2 * sum(abs(a[0] - b[0]) + abs(a[1] - b[1]) for a, b in zip([start] + task, task)) + 6
    demos = []
    for _ in range(N_DEMO):
        c, s, rec = start, 0, []
        for _ in range(horizon):
            if s == len(task):
                break
            a = expert(c, task[s])
            rec.append((c, s, rng.random() < q_hide, task[s], a))
            c = step(c, rng.randrange(5) if rng.random() < SLIP else a)
            if c == task[s]:
                s += 1
        demos.append(rec)
    jit = [[(rng.random(), rng.randrange(4)) for _ in range(len(task))] for _ in range(horizon + 1)]
    slips = [(rng.random(), rng.randrange(5)) for _ in range(horizon)]
    draws = [rng.random() < q_hide for _ in range(horizon)]
    hides = [draws[t // block] for t in range(horizon)]
    t_drop = rng.randrange(horizon // 3, 2 * horizon // 3) if drop else -1
    return start, task, wrong, horizon, demos, jit, slips, hides, t_drop, p_plan, refresh


def majority(table, key):
    votes = table.get(key)
    if not votes:
        return None
    return max(range(5), key=lambda a: (votes[a], -a))


def tables(demos):
    ta, tb = {}, {}
    for rec in demos:
        for c, s, hid, tgt, a in rec:
            for key in ((c, s if not hid else -1), (c, -1)):
                ta.setdefault(key, [0] * 5)[a] += 1
            tb.setdefault((c, tgt), [0] * 5)[a] += 1
    return ta, tb


def jitter(points, draws, p_plan):
    out = []
    for p, (u, d) in zip(points, draws):
        if u < p_plan:
            m = MOVES[1 + d]
            p = (min(SIZE - 1, max(0, p[0] + m[0])), min(SIZE - 1, max(0, p[1] + m[1])))
        out.append(p)
    return out


def dtw(p, q):
    inf = float("inf")
    d = [[inf] * (len(q) + 1) for _ in range(len(p) + 1)]
    d[0][0] = 0.0
    for i in range(1, len(p) + 1):
        for j in range(1, len(q) + 1):
            c = math.dist(p[i - 1], q[j - 1])
            d[i][j] = c + min(d[i - 1][j], d[i][j - 1], d[i - 1][j - 1])
    return d[len(p)][len(q)]


def plan_scores(plan, task):
    p = [(x / (SIZE - 1), y / (SIZE - 1)) for x, y in plan]
    q = [(x / (SIZE - 1), y / (SIZE - 1)) for x, y in task]
    f = lambda a, b: max(0.0, 1.0 - math.dist(a, b) ** 2)
    r_goal = 0.5 * (f(p[0], q[0]) + f(p[-1], q[-1]))
    r_traj = max(0.0, 1.0 - dtw(p, q))
    return math.dist(plan[-1], task[-1]), 0.5 * r_goal + 0.5 * r_traj


def rotate(points):
    return points[1:] + points[:1]


def latent_source(arm, task, wrong):
    if arm == "B_latent":
        return task
    if arm == "C_scrambled":
        return rotate(task)
    return wrong


def run(arm, regime, seed, trial, fallback="table"):
    start, task, wrong, horizon, demos, jit, slips, hides, t_drop, p_plan, refresh = world(regime, seed, trial)
    ta, tb = tables(demos)
    c, s = start, 0
    source = latent_source(arm, task, wrong)
    plan = jitter(source, jit[0], p_plan)
    endpoint, r_vis = plan_scores(plan, task)
    ptr = 0
    for t in range(horizon):
        if s == len(task):
            break
        if t == t_drop and s > 0:
            s -= 1
        if arm == "A_direct":
            a = majority(ta, (c, -1 if hides[t] else s))
            a = majority(ta, (c, -1)) if a is None and fallback == "table" else a
        else:
            if refresh and t > 0 and t % refresh == 0 and not hides[t]:
                remaining = latent_source(arm, task[s:], wrong[s:]) or source[-1:]
                plan, ptr = jitter(remaining, jit[t], p_plan), 0
            a = majority(tb, (c, plan[ptr])) if ptr < len(plan) else None
            a = majority(ta, (c, -1)) if a is None and fallback == "table" else a
        a = 0 if a is None else a
        u, r = slips[t]
        c = step(c, r if u < SLIP else a)
        if c == task[s]:
            s += 1
        if arm != "A_direct" and ptr < len(plan) and c == plan[ptr]:
            ptr += 1
    out = {"stage": s / len(task), "full": 1.0 if s == len(task) else 0.0}
    out["endpoint"] = endpoint if arm != "A_direct" else 0.0
    out["r_visual"] = r_vis if arm != "A_direct" else 0.0
    return out


def mean_sd(xs):
    mu = sum(xs) / len(xs)
    return mu, math.sqrt(sum((x - mu) ** 2 for x in xs) / (len(xs) - 1))


def num(x):
    if x != 0.0 and abs(x) < 5e-5:
        return f"{x:.3e}"
    return f"{x:.4f}"


def sign_note(diffs, m):
    n, opp, zero = len(diffs), sum(1 for d in diffs if d * m < 0), sum(1 for d in diffs if d == 0)
    if opp == 0 and zero == 0:
        return f"same sign on all {n} seeds"
    if opp == 0:
        return f"no seed has the opposite sign, {zero} of {n} equal"
    note = f"{opp} of {n} seeds {'has' if opp == 1 else 'have'} the opposite sign"
    return note + (f", {zero} of {n} equal" if zero else "")


def verdict(xa, xb):
    diffs = [a - b for a, b in zip(xa, xb)]
    if all(d == 0.0 for d in diffs):
        return "0.0000+-0.0000: tie: identical on every seed"
    m, s = mean_sd(diffs)
    if abs(m) < NUM_ZERO and s < NUM_ZERO:
        return f"{num(m)}+-{num(s)}: numerically zero (floating-point residue), effectively a tie"
    if abs(m) <= s:
        label = "near-tie / small gap, within seed noise (|m| <= sd)"
    elif abs(m) < 0.2 * min(abs(mean_sd(xa)[0]), abs(mean_sd(xb)[0])):
        label = "small but consistent gap, not a tie (|m| > sd)"
    else:
        label = "clear gap, not a tie (|m| > sd)"
    return f"{num(m)}+-{num(s)}: {label}; {sign_note(diffs, m)}"


KEYS = ("stage", "full", "endpoint", "r_visual")


def main():
    print("Synthetic ThinkAct-style toy; grid stages, plan latent = remaining targets; not Qwen2.5-VL / LIBERO / SimplerEnv")
    print(f"seeds={len(SEEDS)} trials={TRIALS} grid={SIZE} demos={N_DEMO} slip={SLIP}; no integration step (one cell per step); A has no latent, so its endpoint and r_visual print 0")
    print("regime arm stage full endpoint r_visual  (mean+-sd over seeds of per-seed trial means)")
    for regime, (pattern, q_hide, p_plan, refresh, drop, block) in REGIMES.items():
        print(f"{regime} (stages={len(pattern)} pattern={pattern}, q_hide={q_hide}, hide_block={block}, p_plan={p_plan}, refresh={refresh or 'start only'}, drop={drop})")
        res = {}
        for arm in ARMS:
            res[arm] = []
            for seed in SEEDS:
                rs = [run(arm, regime, seed, t) for t in range(TRIALS)]
                res[arm].append({k: sum(r[k] for r in rs) / TRIALS for k in KEYS})
            cells = " ".join("{}+-{}".format(*map(num, mean_sd([r[k] for r in res[arm]]))) for k in KEYS)
            print(f"  {arm} {cells}")
        for x, y in (("B_latent", "A_direct"), ("C_scrambled", "B_latent"), ("C_scrambled", "A_direct")):
            for k in ("stage", "full"):
                print(f"  paired {x[0]}-{y[0]} {k}: {verdict([r[k] for r in res[x]], [r[k] for r in res[y]])}")
```

### Read the regimes

How the labels are used on this page, in this order: **tie: identical on every seed** only when the paired per-seed difference is exactly zero on every seed; **numerically zero (floating-point residue), effectively a tie** when `|paired mean|` and its sd are both below 1e-9 (no sign count is printed on such a line); **near-tie / small gap, within seed noise** when `|paired mean| ≤ sd`; otherwise a **consistent** gap (`|paired mean| > sd`), called **small** if `|m|` is under 20 % of the smaller arm mean and **clear** otherwise; the 20 % rule only chooses between those two words. Every consistent line carries a same-sign count over the 5 seeds, and any seed with the opposite sign is reported; a sign count alone never makes a gap consistent. Gaps are computed from unrounded values. Paired differences are B−A, C−B and C−A.

- **single_step:** B−A is a **tie: identical on every seed** on both metrics, and C−B is also a tie because rotating one target changes nothing. With one stage there is no hidden context for the latent to carry.
- **multi_stage (hide drawn every step):** a **near-tie**: B−A full −0.0250±0.0306, no seed of the opposite sign, 2 of 5 equal. Half the steps show the stage, which is enough for A.
- **ambiguous:** the latent **wins**, by a small but consistent margin: B−A full 0.0800±0.0597, no seed of the opposite sign, 1 of 5 equal.
- **multi_stage_block and ambiguous_block:** small but consistent wins for the latent, B−A full 0.0300±0.0209 (1 of 5 equal) and 0.0950±0.0371 (same sign on all 5 seeds).
- **Scrambled latent:** C−B full is clear in multi_stage (−0.1500±0.0661) and multi_stage_block (−0.1700±0.0274), 5/5. It is small but consistent in ambiguous (−0.0700±0.0326) and a **near-tie** in ambiguous_block (−0.0300±0.0326, 2 of 5 equal). There the rotated PQPQ order is QPQP, which still passes many of the right cells on the way.
- **noisy_plan:** **the latent loses.** With `p_plan = 0.5`, B−A full is −0.0950±0.0622, small but consistent, no seed of the opposite sign (1 of 5 equal). A hallucinated plan is worse than no plan here.
- **drop_dense and drop_sparse:** after the drop, a latent rewritten every 5 steps gives a small but consistent win (B−A full 0.0450±0.0447, 1 of 5 seeds of the opposite sign). Written only at the start, it is a **near-tie** (−0.0200±0.0622). A stale latent loses the advantage, much as ThinkAct needs to re-reason in order to self-correct.

The page **does not declare a universal winner**. In this toy a plan latent helps when it carries stage context the camera hides, and only by a small margin. It ties when nothing is hidden and loses when the plan is hallucinated. A wrong order costs most when the order matters.
