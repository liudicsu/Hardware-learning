## Three ways to output an action

[6.2](/en/month/month-6/act-diffusion) showed the core problem with demonstrations: when experts sometimes go left of an obstacle and sometimes go right, a policy trained with mean-squared error outputs the **average**, which drives straight into the obstacle.

| Head | What the network learns | How an action comes out | Cost at inference |
| --- | --- | --- | --- |
| MSE regression | one action per observation | one forward pass | lowest; averages modes |
| Diffusion (6.2) | the noise added at each step | many denoising steps | many forward passes |
| <Term id="flow-matching">Flow matching</Term> | a <Term id="velocity-field">velocity field</Term> v(x, τ) | integrate from noise along the field | a few to tens of steps |

Flow matching (Lipman et al., arXiv **2210.02747**) trains a continuous normalising flow without simulating it: the network regresses a target velocity along a fixed path from noise to data. Because the path is a straight line, a handful of integration steps already gives good samples.

## π0's conventions

π0 (arXiv **2410.24164**) attaches a 300M-parameter action expert to a PaliGemma 3B vision-language model (about 3.3B parameters in total) and predicts chunks of **H=50** actions. Its flow-matching conventions, in the notation of the paper:

- Path: `A^τ = τ·A + (1−τ)·ε`, with `ε ~ N(0, I)` and τ from 0 (pure noise) to 1 (the action chunk).
- Target velocity: `u = A − ε`. The network learns `v_θ(A^τ, o) ≈ u`.
- Training samples τ from a Beta distribution that puts more weight on noisy (low τ) times, with s = 0.999 as the cut-off.
- Inference: start from noise and apply forward Euler, `A^{τ+δ} = A^τ + δ·v_θ`, with **10** steps (`δ = 0.1`).

Every one of those 10 steps runs the action expert again. On an RTX 4090 the paper reports **27 ms** for the 10 action steps, out of **73 ms** on board (14 ms image encoders, 32 ms observation forward pass). The step count is part of inference latency; [10.2](/en/month/month-10/real-time-chunking) deals with what that latency does to the seams between chunks. These are published figures from the paper; they were not run on this page (本页未运行).

## Run the closed-form toy

`flow_match_toy.py` uses a 1-D target with two modes, ±1 with standard deviation 0.1 (think "left of the obstacle" and "right of it"). For a Gaussian mixture the marginal velocity has a closed form, so there is **no network**: we integrate the exact field with 1, 2, 3, 5, 10 and 50 Euler steps and count how many of 2000 samples land near a mode (within 0.3 of ±1) or near the invalid mean 0.

```python
"""flow_match_toy.py: 1-D flow matching with a closed-form velocity (stdlib).

Target: a bimodal mixture 0.5*N(-1, 0.1^2) + 0.5*N(+1, 0.1^2) — think of it as
"go left of the obstacle" vs "go right". Path (pi0 convention):

    x_tau = tau * x1 + (1 - tau) * eps,   eps ~ N(0, 1),   tau in [0, 1]
    target velocity u = x1 - eps

Because the target is a Gaussian mixture, the *marginal* velocity
E[x1 - eps | x_tau = x] has a closed form, so no network is trained here.
We integrate it with forward Euler from tau=0 (noise) to tau=1 and count how
many samples land near a mode vs near the (invalid) mean 0.

This is a toy: a real policy learns v_theta(A_tau, obs) with a network.
"""

import math
import random

SEED = 7
N = 2000
MODES = (-1.0, 1.0)
SIGMA = 0.1
STEPS = (1, 2, 3, 5, 10, 50)
NEAR = 0.3  # "near" radius for both mode and mean


def gauss(rng: random.Random) -> float:
    """Box-Muller from rng.random() so the stream is stable across versions."""
    u1 = rng.random()
    u2 = rng.random()
    return math.sqrt(-2.0 * math.log(1.0 - u1)) * math.cos(2.0 * math.pi * u2)


def velocity(x: float, tau: float) -> float:
    """Closed-form marginal velocity E[x1 - eps | x_tau = x] for the mixture."""
    var = tau * tau * SIGMA * SIGMA + (1.0 - tau) ** 2
    cov = tau * SIGMA * SIGMA - (1.0 - tau)  # Cov(x1 - eps, x_tau | mode)
    logw = [-(x - tau * m) ** 2 / (2.0 * var) for m in MODES]
    top = max(logw)
    w = [math.exp(v - top) for v in logw]
    z = sum(w)
    return sum(
        (wk / z) * (m + cov / var * (x - tau * m)) for wk, m in zip(w, MODES)
    )


def sample(x0: float, steps: int) -> float:
    x = x0
    dt = 1.0 / steps
    for k in range(steps):
        x = x + dt * velocity(x, k * dt)
    return x


def main() -> None:
    rng = random.Random(SEED)
    noise = [gauss(rng) for _ in range(N)]
    print(f"target: 0.5*N(-1,{SIGMA}^2) + 0.5*N(+1,{SIGMA}^2)  samples={N}  seed={SEED}")
    print(f"v(x=0.50, tau=0.0) = {velocity(0.5, 0.0):+.3f}   (= mean(x1) - x)")
    print(f"v(x=0.50, tau=0.9) = {velocity(0.5, 0.9):+.3f}   (points to the +1 mode)")
    print(f"{'steps':>5} {'near_mode':>9} {'near_mean':>9} {'mean_abs':>8}")
    for steps in STEPS:
        xs = [sample(x0, steps) for x0 in noise]
        near_mode = sum(1 for x in xs if abs(abs(x) - 1.0) < NEAR) / N
        near_mean = sum(1 for x in xs if abs(x) < NEAR) / N
        mean_abs = sum(abs(x) for x in xs) / N
        print(f"{steps:>5} {near_mode:>9.3f} {near_mean:>9.3f} {mean_abs:>8.3f}")
    print("1 Euler step lands every sample on the mean (an action between the modes);")
    print("more steps recover both modes. pi0 uses 10 steps (delta = 0.1).")


if __name__ == "__main__":
    main()
```

How to read it:

- At τ=0 the field is `mean(x1) − x`: the noise has not yet "seen" any mode, so every sample is pulled towards the average 0. With **1** step that is the whole trajectory: near_mean = **1.000**, exactly the MSE failure.
- Late in the path (τ=0.9) the field near x=0.5 is **+3.011**, pointing hard at the +1 mode. More steps give samples time to commit to a side: near_mode rises to **0.780** at 3 steps, **0.987** at 10 and **0.996** at 50.
- 10 steps already gets most of the quality; going from 10 to 50 buys little and costs 5× the action-expert passes. That is why π0 uses 10.

This is a toy: a real policy learns `v_θ` from data with a network and conditions on the observation.

## Fewer steps: rectified flow and consistency

Because every step costs latency, several lines of work try to need fewer steps. Rectified flow (arXiv 2209.03003) straightens the learned paths so that a coarse Euler step stays on track. Consistency Policy (arXiv 2405.07503) distils a diffusion policy so that one or two steps suffice; its abstract reports an order-of-magnitude inference speed-up over the fastest alternative it compares with. This lesson covers only the motivation; we do not derive or run either.

## Absolute, relative and delta actions

What a chunk *contains* matters as much as how it is sampled. The LeRobot action-representations page distinguishes three choices:

| Representation | Each action is | Notes |
| --- | --- | --- |
| absolute | the target joint (or end-effector) position | LeRobot default |
| relative | target minus the current state at chunk start | used by OpenPI / π0; errors do not accumulate across chunks |
| delta | change from the previous action | errors accumulate along the chunk; UMI argues against it |

Relative actions are compatible with RTC (10.2). Flags such as `--policy.use_relative_actions=true` follow the LeRobot v0.6.x docs; commands may change between versions. Not run on this page (本页未运行).

## Common mistakes

- **Using 1 or 2 steps to save time without checking samples.** The toy shows 1 step collapses to the mean, the same failure as MSE.
- **Calling flow matching "faster than diffusion" by default.** It is cheaper per good sample because paths are straight, but each step is still a full action-expert pass.
- **Mixing action representations.** Training on relative actions and executing them as absolute targets sends the arm to the wrong place.
- **Reading the 73 ms as your robot's latency.** It is an RTX 4090 figure from the paper, not measured here.

## OneDP-style one-step regression surrogate (+210 min)

The original [OneDP paper](https://arxiv.org/abs/2410.21257) distils a pretrained diffusion policy by matching **diffused action distributions along the chain with reverse KL**. Its gradient uses a difference of scores; OneDP-S introduces an auxiliary score estimator and OneDP-D uses an analytic simplification. That KL-along-chain objective is **reading only**, not ordinary pointwise teacher MSE. [Consistency Policy](https://arxiv.org/abs/2405.07503) uses consistency trajectory modelling/self-consistency along a probability-flow ODE (with a denoising objective); neither paper is implemented here. OneDP's 2 %–10 % additional cost and 1.5→62 Hz, and any Consistency Policy figures, are **以论文为准**. Real diffusion/GPU/robot work: **本页未运行**.

The papers' Hz and success-rate numbers are for reading comparison only, not measurements or reproduced results on this page.

This additive experiment is a **regression surrogate**: an analytic teacher, not a learned diffusion model. It does not reproduce multimodal action distributions or the score objective, and does not contradict the earlier closed-form mixture toy: one-step generation needs learned information, not merely removing integration steps. We do not redo RTC (10.2), Cal-ConRFT/advantage filtering (10.7), or VLA RL (8.2).

### Declared data, fit budget and independent success

Synthetic plant displacement is `D(a)=a+0.22*a³`. A start has position `x0=−e`, goal 0. Teacher starts `a=0` and makes eight updates `a←a+0.5*(e−D(a))`: **N=8 actual field calls**, no training. Each seed in **11/23/37/53/71** creates 64 stratified demo errors `e∈[−1.2,1.2]` with within-bin fraction 0.25…0.75, labels `teacher(e)+Normal(0,0.008²)`, and one shared random initialization. Both students get identical demo pairs, features and initialization. The four fixed Legendre features are `[1,x,(5x³−3x)/2,(63x⁵−70x³+15x)/8]`, `x=e/1.2`. Full-batch MSE GD uses lr=0.25; the full student has **240 updates**, the deliberately underfit student **2**. This unequal optimization budget is an underfit control, **not a convergence or training-efficiency comparison**.

All three arms are evaluated on the same 64 **held-out eval starts** (within-bin fraction 0.9, disjoint from every seed's demos). No student fitting receives eval starts or teacher eval labels. Action MSE is relative to held-out teacher actions; the teacher's own MSE is zero **by definition**, not ground truth. Independent task success is `abs(−e+D(a))≤0.004`, evaluated by the nonlinear plant, not by agreement with the teacher. One student feature-dot-product forward counts as NFE=1; each teacher field call counts as one. Scorer-only reference queries are excluded from policy inference NFE. These are different call types/FLOPs: **NFE is not measured latency or Hz**, and 8→1 is not an 8× wall-clock claim.

```python
#!/usr/bin/env python3
"""OneDP-style REGRESSION SURROGATE, not KL-along-chain/score distillation.
Synthetic analytic eight-field-call teacher solves a nonlinear inverse plant.
Both students see the SAME 64 noisy teacher demos and copy the SAME init;
240 vs 2 updates is a deliberately unequal underfit control, not convergence proof.
Every scored state/start is held out; fit() never receives eval states/labels.
NFE counts actual field/forward calls, not FLOPs, Hz or wall-clock speed.
Original Consistency Policy and GPU OneDP/Franka are not run: 本页未运行.
"""
from random import Random
from statistics import mean, pstdev

SEEDS = (11, 23, 37, 53, 71)
N_STEPS = 8
N_DEMOS = N_EVAL = 64
FULL_UPDATES, UNDER_UPDATES = 240, 2
LR, DEMO_SIGMA, TOLERANCE = .25, .008, .004
EVAL_STARTS = tuple(-1.2 + 2.4*(j+.9)/N_EVAL for j in range(N_EVAL))


def displacement(action):
    """Independent nonlinear one-step plant: x_next=-error+D(action), goal=0."""
    return action + .22*action**3


def field(error, action):
    return error - displacement(action)


def teacher(error):
    action, nfe = 0., 0
    for _ in range(N_STEPS):
        action += .5*field(error, action)
        nfe += 1
    return action, nfe


def features(error):
    """Fixed Legendre basis on normalized error; not evaluated teacher labels."""
    x = error/1.2
    return (1., x, (5*x**3-3*x)/2, (63*x**5-70*x**3+15*x)/8)


def student(weights, error):
    return sum(w*x for w,x in zip(weights, features(error))), 1


def demonstrations(seed):
    rng = Random(seed)
    # Training fractional bins .25..75 never overlap held-out fractional bin .9.
    starts = tuple(-1.2 + 2.4*(j+.25+.5*rng.random())/N_DEMOS for j in range(N_DEMOS))
    demos = tuple((s, teacher(s)[0]+rng.gauss(0,DEMO_SIGMA)) for s in starts)
    initial = tuple(rng.gauss(0,.02) for _ in range(4))
    return demos, initial


def fit(demos, initial, updates):
    """Only training pairs and initial weights; no teacher query or held-out input."""
    weights = list(initial)
    design = tuple((features(state), label) for state,label in demos)
    for _ in range(updates):
        gradient = [0.]*len(weights)
        for basis, label in design:
            residual = sum(w*x for w,x in zip(weights,basis))-label
            for j,x in enumerate(basis):
                gradient[j] += 2*residual*x/len(design)
        weights = [w-LR*g for w,g in zip(weights,gradient)]
    return tuple(weights)


def evaluate(policy, starts, references, training_states):
    if set(starts) & set(training_states):
        raise ValueError("training/evaluation state overlap")
    mse, successes, calls = 0., 0, 0
    for state, reference in zip(starts,references):
        action, nfe = policy(state)
        mse += (action-reference)**2
        successes += int(abs(-state+displacement(action)) <= TOLERANCE)
        calls += nfe
    return mse/len(starts), calls/len(starts), successes/len(starts)


def run(seed):
    demos, initial = demonstrations(seed)
    full, under = fit(demos, initial,FULL_UPDATES), fit(demos, initial,UNDER_UPDATES)
    # References are SCORER-ONLY; no student inference/fitting receives them.
    references = tuple(teacher(s)[0] for s in EVAL_STARTS)
    states = tuple(s for s,_ in demos)
    policies = (("teacher_N8",teacher,0),
                ("student_1",lambda s: student(full,s),FULL_UPDATES),
                ("underfit_1",lambda s: student(under,s),UNDER_UPDATES))
    return [(name,updates,evaluate(policy,EVAL_STARTS,references,states)) for name,policy,updates in policies]


def main():
    print("OneDP-style regression surrogate ONLY; KL-along-chain is reading, not implemented")
    print("shared demos=64 held-out eval starts=64 overlap=0; N-step teacher=8 actual field calls")
    print("student updates=240 underfit updates=2 (unequal on purpose); same data/features/init")
    print("demo_sigma=0.008 success_abs_plant_error<=0.004; NFE is calls, not Hz or wall time")
    print("seed arm fit_updates action_MSE NFE_per_query success")
    all_rows = {name: [] for name in ("teacher_N8","student_1","underfit_1")}
    for seed in SEEDS:
        for name,updates,metrics in run(seed):
            all_rows[name].append(metrics)
            mse,nfe,success=metrics
            print(f"{seed} {name} {updates} {mse:.8f} {nfe:.1f} {success:.6f}")
    print("five-seed spread: arm metric mean population_sd min max")
    for name,rows in all_rows.items():
        for j,metric in enumerate(("action_MSE","NFE","success")):
            values=[row[j] for row in rows]
            print(f"{name} {metric} {mean(values):.8f} {pstdev(values):.8f} {min(values):.8f} {max(values):.8f}")
    print("Teacher self-reference MSE=0 by definition; success independently uses nonlinear plant")
    print("Scorer reference queries excluded from policy NFE; different call types are not equal FLOPs")
    print("No diffusion distribution/score/consistency training; GPU and robot: 本页未运行; paper 以论文为准")


if __name__ == "__main__":
    main()
```
