## Train and deploy are different jobs

The LeRobot compute guide is blunt: on CPU only, don't train; use Colab or rent a GPU. Its peak-VRAM envelopes at batch size 8 make the point:

| Policy group | Training VRAM (batch 8) |
| --- | --- |
| light behaviour cloning (e.g. ACT) | about 2–6 GB |
| diffusion | about 8–14 GB |
| SmolVLA | about 10–16 GB |
| π0 / π0.5 | about 24–40 GB |

Deployment runs one observation at a time and needs far less, but it has its own limits: memory, power, heat and, above all, latency. [8.2](/en/month/month-8/vla-finetune) has a bytes-per-parameter table; this lesson asks how small and how fast a policy can get on the device that will actually run it. In LeRobot, `--policy.device` picks cpu / cuda / mps / xpu, and `--accelerator.mixed_precision` takes no, bf16 or fp16 (fp16 is rejected on CPU). Follow the LeRobot v0.6.x docs; options may change between versions.

## int8 by hand

<Term id="quantization">Quantisation</Term> stores a float as a small integer q plus two numbers shared by many values. The ONNX Runtime docs use:

- `val_fp32 = scale × (val_q − zero_point)`
- asymmetric: `scale = (max − min) / (qmax − qmin)`
- symmetric: `scale = max(|max|, |min|) × 2 / (qmax − qmin)`, zero_point = 0

The range is widened if needed so that **0 is exactly representable**: zero padding and ReLU outputs are everywhere, and an offset on 0 would bias every layer. A single scale for a whole tensor is *per-tensor*; one scale per output channel is *per-channel*.

`int8_quant_toy.py` quantises a fixed 4 × 16 weight matrix three ways, then repeats with one outlier (4.0) placed in channel 1. `ch0_max_err` is the worst error in channel 0, which contains no outlier.

```python
"""int8_quant_toy.py: 8-bit linear quantisation by hand (stdlib).

Formulas follow the ONNX Runtime quantisation docs:
    val_fp32 = scale * (val_quantized - zero_point)
    asymmetric: scale = (max - min) / (qmax - qmin)
    symmetric:  scale = max(|max|, |min|) * 2 / (qmax - qmin)

Symmetric int8 here uses the range -127..127 (zero_point = 0); asymmetric
uint8 uses 0..255. The range is widened to include 0 so that 0.0 is exactly
representable. A 4 x 16 weight matrix (4 output channels) is quantised
per-tensor (one scale) and per-channel (one scale per row). One outlier in
channel 1 shows why a single large value hurts every weight that shares its
scale.
"""

import random

SEED = 3
ROWS, COLS = 4, 16


def weights(with_outlier: bool) -> list[list[float]]:
    rng = random.Random(SEED)
    w = [[round(rng.uniform(-0.5, 0.5), 4) for _ in range(COLS)] for _ in range(ROWS)]
    if with_outlier:
        w[1][5] = 4.0
    return w


def sym_params(xs: list[float]) -> tuple[float, int, int, int]:
    qmin, qmax = -127, 127
    scale = max(abs(max(xs)), abs(min(xs))) * 2 / (qmax - qmin)
    return scale, 0, qmin, qmax


def asym_params(xs: list[float]) -> tuple[float, int, int, int]:
    qmin, qmax = 0, 255
    lo, hi = min(min(xs), 0.0), max(max(xs), 0.0)
    scale = (hi - lo) / (qmax - qmin)
    zp = max(qmin, min(qmax, round(qmin - lo / scale)))
    return scale, zp, qmin, qmax


def roundtrip(xs: list[float], params: tuple[float, int, int, int]) -> list[float]:
    scale, zp, qmin, qmax = params
    q = [max(qmin, min(qmax, round(x / scale) + zp)) for x in xs]
    return [scale * (v - zp) for v in q]


def run(w: list[list[float]], scheme: str) -> tuple[float, float, float, bool]:
    flat = [x for row in w for x in row]
    back: list[float] = []
    scales: list[float] = []
    if scheme == "per-channel":
        for row in w:
            p = sym_params(row)
            scales.append(p[0])
            back += roundtrip(row, p)
    else:
        p = sym_params(flat) if scheme == "sym tensor" else asym_params(flat)
        scales = [p[0]] * ROWS
        back = roundtrip(flat, p)
    errs = [abs(a - b) for a, b in zip(flat, back)]
    ch0 = errs[:COLS]
    bound = all(
        e <= scales[i // COLS] / 2 + 1e-12 for i, e in enumerate(errs)
    )
    mse = sum(e * e for e in errs) / len(errs)
    return scales[0], max(ch0), mse, bound


def main() -> None:
    print(f"{ROWS}x{COLS} weights, seed={SEED}, uniform(-0.5, 0.5); outlier case sets w[1][5]=4.0")
    print(f"{'case':<8} {'scheme':<12} {'scale_ch0':>9} {'ch0_max_err':>11} {'mse':>10} {'<=scale/2':>9}")
    for case, flag in (("plain", False), ("outlier", True)):
        w = weights(flag)
        for scheme in ("sym tensor", "asym tensor", "per-channel"):
            s0, e0, mse, bound = run(w, scheme)
            print(f"{case:<8} {scheme:<12} {s0:>9.5f} {e0:>11.5f} {mse:>10.2e} {str(bound):>9}")
    params = 100_000_000
    print(f"weight bytes for {params // 1_000_000}M params (weights only, no activations):")
    for name, nbytes in (("fp32", 4), ("bf16", 2), ("int8", 1)):
        print(f"  {name:<5} {params * nbytes / 1e6:>6.0f} MB")


if __name__ == "__main__":
    main()
```

How to read it:

- Without the outlier all three schemes give a scale near **0.00390** and errors well under one scale step.
- With the outlier, the per-tensor symmetric scale grows to **0.03150** and channel 0's worst error to **0.01436**, even though channel 0 never changed. Per-channel keeps channel 0's scale at **0.00390** and its error at **0.00190**.
- `<=scale/2` is True everywhere: rounding error is at most half a step, so the scale *is* the error budget.
- int8 weights take a quarter of fp32: **400 MB** vs **100 MB** for 100M parameters (weights only).

## Smaller is not always faster

The ONNX Runtime docs list three ways to quantise: dynamic (activation ranges computed at run time, recommended for RNNs and transformers), static (ranges calibrated on sample data, recommended for CNNs) and quantisation-aware training if neither keeps accuracy. A speed-up also needs hardware with fast int8 paths, such as x86 VNNI, NVIDIA Tensor Core int8 or Arm dot-product instructions; on older hardware a quantised model can be slower than fp32. ## A latency budget

A <Term id="latency-budget">latency budget</Term> adds up every stage between "the camera saw it" and "the action is ready", then converts the sum into control steps: that is d in 10.2. `latency_budget.py` uses published component times only: π0 on an RTX 4090 (14 ms image encoders, 32 ms observation forward, 27 ms for 10 action steps; **73 ms** on board, **86 ms** with 13 ms of network when off board) and the RTC paper's π0.5 breakdown (97.43 ms model, 6.89 ms network, 1.44 ms resize, 3.00 ms other). Each scenario is repeated with up to 33.3 ms of camera frame age at 30 fps.

```bash
$ python3 latency_budget.py
```

<CodeSource path="examples/month-10/edge-deploy-checklist/latency_budget.py" />

```python
"""latency_budget.py: end-to-end latency -> inference delay d (stdlib).

d = floor(delta / dt) as defined in the RTC paper (arXiv 2506.07339), where
delta is the time from observation to a usable action chunk and dt is the
control period. We also print ceil(delta / dt) as a conservative choice for
LeRobot's inference_delay. Component numbers are copied from published
tables (RTX 4090, not measured on this site); the camera row is the worst-case
age of a frame at 30 fps.
"""

import math

H, S_MIN = 50, 25  # pi0 / pi0.5 horizon and the paper's minimum execution horizon
CAMERA_30FPS = 1000.0 / 30.0

SCENARIOS = (
    ("pi0 on-board", (("image encoders", 14.0), ("observation fwd", 32.0), ("10x action fwd", 27.0))),
    ("pi0 off-board", (("on-board total", 73.0), ("network", 13.0))),
    ("pi0.5+RTC LAN", (("model", 97.43), ("network", 6.89), ("image resize", 1.44), ("other", 3.00))),
    ("pi0.5+RTC +100ms", (("measured total", 108.76), ("injected", 100.0))),
)


def main() -> None:
    print(f"H={H}  s_min={S_MIN}  constraint d <= H - s  ->  d <= {H - S_MIN}")
    print(f"camera frame age at 30 fps: up to {CAMERA_30FPS:.1f} ms (added in the +cam rows)")
    print(f"{'scenario':<22} {'delta_ms':>8} {'d@50Hz':>7} {'ceil':>5} {'d@30Hz':>7} {'ceil':>5} {'fits':>5}")
    for name, parts in SCENARIOS:
        base = sum(ms for _, ms in parts)
        for label, delta in ((name, base), (name + " +cam", base + CAMERA_30FPS)):
            d50 = math.floor(delta / 20.0)
            d30 = math.floor(delta / CAMERA_30FPS)
            c50 = math.ceil(delta / 20.0)
            c30 = math.ceil(delta / CAMERA_30FPS)
            fits = c50 <= H - S_MIN
            print(f"{label:<22} {delta:>8.1f} {d50:>7} {c50:>5} {d30:>7} {c30:>5} {str(fits):>5}")
    print("sync inference would idle about d control steps per chunk; async/RTC hides them.")


if __name__ == "__main__":
    main()
```

How to read it:

- The RTC paper defines d = floor(δ / Δt). Its real-robot runs report d≈6 on the LAN and about 11 and 16 with +100 / +200 ms injected; those match the `ceil` column (**108.8 ms → 6**, **208.8 ms → 11**). When you set `inference_delay`, round up.
- The camera adds whole control steps: π0 on board goes from d=**3** to **5** at 50 Hz.
- Every row satisfies d ≤ H − s = 25, so a 50-step chunk still has room. Synchronous inference would idle about d steps per chunk; async (8.3) and RTC (10.2) hide them.
- These are published GPU numbers, not your robot. Measure your own end-to-end latency on the SO-101 before trusting a d; this page has no measured SO-101 figure.

## Compact VLAs on the device: a weights-only budget

The int8 toy above ends with weight bytes for 100M parameters. Real VLAs are far bigger, and the first question on an edge device is whether the weights fit at all. Three sizes, with parameter counts taken **from their papers** (not measured here):

| Label | Parameters (per the paper) | Source |
| --- | --- | --- |
| SmolVLA | 0.45B (about 100M of it the action expert) | arXiv 2506.01844 |
| π0-class | 3.3B (3B PaliGemma VLM + 300M action expert) | arXiv 2410.24164 |
| OpenVLA-class | 7B | arXiv 2406.09246 |

"π0-class" and "OpenVLA-class" mean "a model of that size"; later versions and fine-tuned checkpoints can differ. The SmolVLA paper says it is designed to be deployed on consumer-grade GPUs or even CPUs. That is its claim, per the paper, not a measurement on this site.

`vla_edge_budget_toy.py` computes **weights only**: params × bytes per parameter. The toy reports **GB = 10⁹ bytes**, which is not the same as GiB = 2³⁰ bytes (vendors sometimes quote GiB; 6.60 GB ≈ 6.15 GiB). Everything else is **excluded and labelled as excluded**: activations, the KV cache, vision-encoder and image buffers, the framework and CUDA context, and the OS. A weights figure is therefore a lower bound and never proof that a model fits. Part 2 links chunk length, control rate and sync idle to the async threshold from [6.3](/en/month/month-6/vla-models), g ≥ (E[ℓ_S] / Δt) / n, for a few what-if inference latencies ℓ_S. No device was measured, and Jetson and Raspberry Pi runs are not done on this page (本页未运行).

```python
#!/usr/bin/env python3
"""vla_edge_budget_toy.py: weights-only memory and chunk timing for compact VLAs (stdlib).

Part 1, memory. weights_GB = params x bytes_per_param / 1e9, for three model
sizes whose parameter counts are taken from their papers (labelled; not
measured here):
  SmolVLA        0.45e9  (arXiv 2506.01844: "450 million parameters")
  pi0-class      3.3e9   (arXiv 2410.24164: 3B PaliGemma + 300M action expert)
  OpenVLA-class  7e9     (arXiv 2406.09246: "7B-parameter")
Here GB = 10^9 bytes (decimal), not GiB = 2^30 bytes; vendors sometimes
quote GiB, so a 6.60 GB figure is about 6.15 GiB.
WEIGHTS ONLY. Activations, the KV cache, vision-encoder / image buffers, the
framework / CUDA context and the OS are EXCLUDED and not estimated: a weights
number is a lower bound, never "it fits".

Part 2, timing. Chunk of n actions at control period dt lasts n * dt. Sync
inference idles l_S per chunk; async (6.3, g = remaining-queue fraction that
triggers the next request) avoids idling when g >= (l_S / dt) / n. If that
g_min exceeds 1, even a request every tick cannot keep the queue fed. The
l_S values are lesson-chosen what-ifs, not device measurements; Jetson / Pi
runs are not done on this page (本页未运行).
usage: python3 vla_edge_budget_toy.py
"""
from __future__ import annotations

MODELS = (                       # label, params, source
    ("SmolVLA", 0.45e9, "2506.01844"),
    ("pi0-class", 3.3e9, "2410.24164"),
    ("OpenVLA-class", 7.0e9, "2406.09246"),
)
PRECISIONS = (("fp32", 4.0), ("bf16", 2.0), ("int8", 1.0), ("int4", 0.5))
EXCLUDED = ("activations", "KV cache", "vision-encoder / image buffers", "framework + CUDA context", "OS")
N_CHUNK = 50
RATES_HZ = (30, 50)
LATENCIES_S = (0.05, 0.293, 0.8, 2.0)   # what-if l_S; 0.293 s is the 6.3 toy's mean draw


def main() -> None:
    print("part 1: weights-only memory (GB = params x bytes / 1e9); parameter counts from the papers")
    print(f"{'model':<14} {'params':>7} {'arXiv':>10} " + " ".join(f"{p:>6}" for p, _ in PRECISIONS))
    for name, n, src in MODELS:
        print(f"{name:<14} {n / 1e9:6.2f}B {src:>10} " + " ".join(f"{n * b / 1e9:6.2f}" for _, b in PRECISIONS))
    print("EXCLUDED (not estimated): " + ", ".join(EXCLUDED))
    print()
    print(f"part 2: chunk timing, n={N_CHUNK}; g_min = (l_S / dt) / n (6.3); l_S values are what-ifs")
    print(f"{'Hz':>3} {'chunk_s':>7} {'l_S_s':>6} {'sync_idle_%':>11} {'g_min':>6}  verdict")
    for hz in RATES_HZ:
        dt = 1.0 / hz
        for lat in LATENCIES_S:
            chunk_s = N_CHUNK * dt
            idle = lat / (lat + chunk_s)
            g_min = (lat / dt) / N_CHUNK
            if g_min <= 1.0:
                verdict = f"async can hide it with g >= {g_min:.3f}"
            else:
                verdict = "even g = 1 underruns: shorter l_S, longer chunk or lower Hz"
            print(f"{hz:3d} {chunk_s:7.3f} {lat:6.3f} {100 * idle:11.1f} {g_min:6.3f}  {verdict}")
    g_check = (0.293 / (1 / 30)) / N_CHUNK
    assert abs(g_check - 0.176) < 5e-4, g_check
    assert MODELS[2][1] * 2.0 / 1e9 == 14.0
    print(f"check: 30 Hz, l_S=0.293 s, n=50 -> g_min={g_check:.3f} (matches the 6.3 toy); "
          "weights only, no device measured, Jetson / Pi 本页未运行")


if __name__ == "__main__":
    main()
```

How to read it:

- **Weights alone.** SmolVLA needs 0.90 GB in bf16 and 0.45 GB in int8. A π0-class model needs 6.60 GB in bf16, and an OpenVLA-class model 14.00 GB in bf16 and 3.50 GB in int4.
- **What is excluded is not small.** The OpenVLA paper reports GPU memory for quantised inference of 16.8 GB in bf16, 10.2 GB in int8 and 7.0 GB in int4 (its Table 2, per the paper). The toy's weights-only numbers are 14.00, 7.00 and 3.50 GB, so roughly 2.8–3.5 GB went to things the toy excludes in that setup. That gap is not a constant you can reuse on another device. The same table reports that int8 lost success there (58.1 % vs 71.3 % for bf16) while int4 matched bf16. Check accuracy after quantising, as the int8 section above says.
- **Chunk timing.** At 30 Hz a 50-action chunk lasts 1.667 s. With ℓ_S = 0.293 s (the mean draw in the 6.3 toy) sync idles about 15.0 % of the time, and async needs g ≥ 0.176, the same threshold 6.3 printed. At 50 Hz the same chunk lasts only 1.0 s, so the threshold rises to 0.293.
- **When async cannot help.** With ℓ_S = 2.0 s, g_min is 1.200 at 30 Hz and 2.000 at 50 Hz. Since g cannot exceed 1, even a request at every tick underruns. The fix is a shorter ℓ_S (smaller model, lower precision, faster device), a longer chunk or a lower control rate, not a different g.

The sync idle fraction here, ℓ_S / (ℓ_S + n·Δt), is the steady-state formula. The 6.3 toy measured 4.17 s idle out of 30 s (13.9 %) with random latency draws and whole ticks.

## Edge checklist

Read-only; none of it was run on this page (本页未运行). Tick what your device meets and mark the rest as unknown.

- **Memory**: model weights plus activations fit with headroom; the GR00T README asks for a GPU with 16 GB or more for inference.
- **Power and clocks**: fixed power mode and clocks before timing (on Jetson, a MAXN mode and `jetson_clocks`); otherwise numbers drift.
- **Heat**: time a long run, not one call; throttling shows up after minutes.
- **Batch 1**: deployment latency is batch 1; throughput figures at large batch do not apply.
- **Export path**: PyTorch → ONNX → TensorRT (or ONNX Runtime), checking outputs against the original at each step.
- **Precision**: bf16/fp16 first, int8 only with calibration data and an accuracy check.
- **Budget**: a filled latency table with measured values, and the d you will pass as `inference_delay`.
- **Compact VLA memory**: start from the paper's parameter count × bytes (weights only), then measure the excluded part (activations, KV cache, image buffers, runtime) on the device itself.
- **Async client**: with your measured ℓ_S, n and Δt, compute g_min = (ℓ_S / Δt) / n; above 1 means a smaller model, a longer chunk or a lower rate, not a different g.

For scale, the Isaac-GR00T README reports GR00T N1.7 at about **40 Hz** on an RTX PRO 6000 Blackwell Server Edition and about **28 Hz** on a Jetson AGX Thor with TensorRT (batch 1, LIBERO, MAXN with `jetson_clocks`). Those are the project's numbers, not measured here; no purchase is required for this lesson.

## Common mistakes

- **Training on the deployment device.** Train on a GPU (or rent one); deploy on the edge device.
- **Quantising per-tensor with outliers present.** One large weight inflates every other weight's error; use per-channel.
- **Assuming int8 is faster.** Without VNNI, Tensor Core int8 or Arm dot-product support it can be slower.
- **Budgeting model time only.** Camera age, pre-processing and network add whole control steps.
- **Calling weights-only memory "it fits".** params × bytes excludes activations, the KV cache and image buffers; OpenVLA's own table shows 2.8–3.5 GB more than its weights (per the paper).
- **Using a paper's parameter count as a device measurement.** 0.45B, 3.3B and 7B are from the papers; your latency and memory have to be measured on your device.
- **Tuning g when ℓ_S is longer than the chunk.** If g_min exceeds 1, no g helps.
- **Timing with dynamic clocks.** Fix power mode and clocks first, then measure over minutes.

## VLA-Adapter: Bridge Attention on a tiny backbone

[VLA-Adapter](https://arxiv.org/abs/2509.09372) (Yihao Wang, Pengxiang Ding, Lingxiao Li, Can Cui, Zirui Ge, Xinyang Tong, Wenxuan Song, Han Zhao, Wei Zhao, Pengxu Hou, Siteng Huang, Yifan Tang, Wenhui Wang, Ru Zhang, Jianyi Liu, Donglin Wang; arXiv **2509.09372**) is a tiny-scale paradigm: a lightweight **Policy** with **Bridge Attention** injects vision–language conditions (layer and type, including ActionQuery versus raw latents) into the action space, aiming for strong control **with a 0.5B backbone and without robotic data pre-training**. The abstract also reports fast inference and training “in just 8 hours on a single consumer-grade GPU”. Those 0.5B / 8-hour / LIBERO claims stay **以论文为准** and are **not** printed as toy results. GPU training, a real 0.5B run and LIBERO are **本页未运行**.

This is **not** the compact-VLA weights-only budget already on this page, **not** SmolVLA, and **not** OpenVLA-OFT.

The paper's §3.2 findings, read in the HTML and PDF, are that mid-layer raw features tend to beat deep raw features, deep ActionQuery tends to beat shallower ActionQuery, and using all layers is generally better. §3.3's Bridge Attention is two cross-attentions and one self-attention: action latents query raw conditions with a `tanh(g)` gate (`g` starts at 0) and query ActionQuery concatenated with proprio, then self-attend, with an L1 action loss (their eqs. 1–2). The Policy is reported at about 97M parameters when the backbone is Qwen2.5-0.5B (**以论文为准**).

### Fair setup

`vla_adapter_bridge_attention_toy.py` is **synthetic** and stdlib only. **Model assumptions:** each demo has a 2-D proprio state, a 2-D action, a vision vector that stores two object positions (plus filler in the precise regime), and a binary instruction. After the first run, four changes were made and are **not** claimed to have been fixed before that run: ActionQuery is a trained MLP rather than a frozen random mix; the tiny readout concatenates the bridge output with the ActionQuery vector and proprio, and the bridge-output block of that readout starts at 0; the large arm uses a two-layer 48-wide backbone stand-in so the tiny arm wins the size and FLOP proxy (the first run had a 24-wide single hidden layer whose parameter count was below the tiny policy); STEPS and LR moved from 250 / 0.05 to 300 / 0.10. The first-run `short_id` table is still produced by `_vla_adapter_firstrun.py` on the same seeds and printed below.

**Arms**, with **common random numbers** (per regime and seed every demo, every test point, and C's shuffle permutation are drawn once; batch `i` is the same set of demos for every arm; B and C share the same initialization); equal budget `STEPS = 300`, batch 8, learning rate 0.10, five seeds:

- **A_large** — a wider two-layer concat-MLP on a 48-wide backbone stand-in, no bridge.
- **B_bridge** — tiny features plus one-layer Bridge Attention (cross-attend action tokens to raw conditions and to ActionQuery+proprio, self-attend on the action tokens, `tanh(g)` raw gate with `g` starting at 0, residual FFN, then a readout over bridge output, ActionQuery and proprio).
- **C_shuffle** — the same tiny + bridge architecture and the same init as B, but conditions are shuffled across the batch at train and test time.

**Metrics:** test success % (`|a_hat − a| ≤ 0.25`), mean L1, parameter count, and a latency / FLOP proxy (multiply-adds in one forward). Size and FLOP do not depend on the seed.

**Regimes, written before the first run** (the architecture and step/learning-rate choices above were not):

- **short_id** — action `(p₀, −p₁)` from proprio; instruction and objects are irrelevant. A and B may near-tie on success; B consistent-wins size and the FLOP proxy.
- **need_vl** — action is the instructed object's position; VL conditions are required. B consistent better success than C; shuffled C consistent-loses.
- **precise** — action is a thin linear mix of a longer 16-D raw vector. If the tiny+bridge arm loses success to the large head, that split is kept.

```python
LR = 0.10
TOL = 0.25
NUM_ZERO = 1e-9
D_RAW_SHORT = 6
D_RAW_PREC = 16
D_PROP = 2
D_ACT = 2
D_BB = 48
D_HID = 48
D_TINY = 6
HQ = 8          # ActionQuery hidden width
N_ACT = 2
N_RAW = 2
N_AQ = 2

def zeros(r, c=None):
    if c is None:
        return [0.0] * r
    return [[0.0] * c for _ in range(r)]


def rand_mat(rng, r, c, sd=INIT_SD):
    return [[rng.gauss(0.0, sd) for _ in range(c)] for _ in range(r)]


def rand_vec(rng, n, sd=INIT_SD):
    return [rng.gauss(0.0, sd) for _ in range(n)]


def matvec(mat, v):
    return [sum(a * b for a, b in zip(row, v)) for row in mat]


def add_vec(a, b, s=1.0):
    return [x + s * y for x, y in zip(a, b)]


def axpy_mat(dst, src, s):
    for i, row in enumerate(src):
        for j, v in enumerate(row):
            dst[i][j] += s * v


def axpy_vec(dst, src, s):
    for i, v in enumerate(src):
        dst[i] += s * v


def clip_copy_mat(m):
    return [row[:] for row in m]


def relu(v):
    return [max(0.0, x) for x in v]


def softmax(logits):
    m = max(logits)
    ex = [math.exp(x - m) for x in logits]
    z = sum(ex)
    return [e / z for e in ex]


def dot(a, b):
    return sum(x * y for x, y in zip(a, b))


def outer(u, v):
    return [[ui * vj for vj in v] for ui in u]


def mean_sd(xs):
    mu = sum(xs) / len(xs)
    return mu, math.sqrt(sum((x - mu) ** 2 for x in xs) / (len(xs) - 1))


def num(x):
    if x != 0.0 and abs(x) < 5e-5:
        return f"{x:.3e}"
    return f"{x:.4f}"


def sign_note(diffs, m):
    n, opp, zero = len(diffs), sum(1 for d in diffs if d * m < 0), sum(1 for d in diffs if d == 0)
    if opp == 0 and zero == 0:
        return f"same sign on all {n} seeds"
    if opp == 0:
        return f"no seed has the opposite sign, {zero} of {n} equal"
    note = f"{opp} of {n} seeds {'has' if opp == 1 else 'have'} the opposite sign"
    return note + (f", {zero} of {n} equal" if zero else "")


def verdict(xa, xb):
    diffs = [a - b for a, b in zip(xa, xb)]
    if all(d == 0.0 for d in diffs):
        return "0.0000+-0.0000: tie: identical on every seed"
    m, s = mean_sd(diffs)
    if abs(m) < NUM_ZERO and s < NUM_ZERO:
        return f"{num(m)}+-{num(s)}: numerically zero (floating-point residue), effectively a tie"
    if abs(m) <= s:
        label = "near-tie / small gap, within seed noise (|m| <= sd)"
    elif abs(m) < 0.2 * min(abs(mean_sd(xa)[0]), abs(mean_sd(xb)[0])):
        label = "small but consistent gap, not a tie (|m| > sd)"
    else:
        label = "clear gap, not a tie (|m| > sd)"
    return f"{num(m)}+-{num(s)}: {label}; {sign_note(diffs, m)}"


def raw_dim(regime):
    return D_RAW_PREC if regime == "precise" else D_RAW_SHORT


def make_demo(regime, rng):
    d_raw = raw_dim(regime)
    k = 0 if rng.random() < 0.5 else 1
    o0 = [rng.uniform(-1.0, 1.0), rng.uniform(-1.0, 1.0)]
    o1 = [rng.uniform(-1.0, 1.0), rng.uniform(-1.0, 1.0)]
    prop = [rng.uniform(-1.0, 1.0), rng.uniform(-1.0, 1.0)]
    inst = [1.0, 0.0] if k == 0 else [0.0, 1.0]
    if regime == "precise":
        raw = (o0 + o1 + inst + [rng.uniform(-1.0, 1.0) for _ in range(d_raw - 6)])[:d_raw]
        action = None
    else:
        raw = o0 + o1 + inst
        if regime == "short_id":
            action = [prop[0], -prop[1]]
        else:
            action = (o0 if k == 0 else o1)[:]
    return {"raw": raw, "prop": prop, "action": action, "k": k}


def fill_precise_actions(demos, mix):
    for d in demos:
        d["action"] = [dot(mix[0], d["raw"]), dot(mix[1], d["raw"])]


def init_large(rng, d_raw):
    return {
        "Wbb": rand_mat(rng, D_BB, d_raw),
        "bbb": rand_vec(rng, D_BB),
        "W1": rand_mat(rng, D_HID, D_BB + D_PROP),
        "b1": rand_vec(rng, D_HID),
        "W2": rand_mat(rng, D_ACT, D_HID),
        "b2": rand_vec(rng, D_ACT),
    }


def init_bridge(rng, d_raw):
    wo = rand_mat(rng, D_ACT, N_ACT * D_TINY + D_TINY + D_PROP)
    # bridge-output block of the readout starts at 0 (chosen after the first run)
    for i in range(D_ACT):
        for j in range(N_ACT * D_TINY):
            wo[i][j] = 0.0
    return {
        "Wr": rand_mat(rng, N_RAW * D_TINY, d_raw),
        "br": rand_vec(rng, N_RAW * D_TINY),
        "Wq1": rand_mat(rng, HQ, d_raw, sd=0.2),
        "bq1": zeros(HQ),
        "Wq2": rand_mat(rng, D_TINY, HQ, sd=0.2),
        "bq2": zeros(D_TINY),
        "Wp": rand_mat(rng, D_TINY, D_PROP),
        "bp": rand_vec(rng, D_TINY),
        "Wa": rand_mat(rng, N_ACT * D_TINY, D_ACT),
        "ba": rand_vec(rng, N_ACT * D_TINY),
        "g": 0.0,
        "Wmix": rand_mat(rng, D_TINY, 3 * D_TINY),
        "bmix": rand_vec(rng, D_TINY),
        "W1": rand_mat(rng, D_TINY, D_TINY),
        "b1": rand_vec(rng, D_TINY),
        "W2": rand_mat(rng, D_TINY, D_TINY),
        "b2": rand_vec(rng, D_TINY),
        "Wo": wo,
        "bo": rand_vec(rng, D_ACT),
    }


def count_params(p):
    n = 0
    for k, v in p.items():
        if k == "g" or isinstance(v, float):
            n += 1
        elif v and isinstance(v[0], list):
            n += sum(len(row) for row in v)
        else:
            n += len(v)
    return n


def flops_large(d_raw):
    return D_BB * d_raw + D_HID * (D_BB + D_PROP) + D_ACT * D_HID


def flops_bridge(d_raw):
    f = N_RAW * D_TINY * d_raw
    f += HQ * d_raw + D_TINY * HQ  # AQ MLP
    f += D_TINY * D_PROP + N_ACT * D_TINY * D_ACT

    def attn(nq, nk):
        return nq * nk * D_TINY + nq * nk * D_TINY

    f += attn(N_ACT, N_RAW) + attn(N_ACT, N_AQ) + attn(N_ACT, N_ACT)
    f += N_ACT * D_TINY * 3 * D_TINY
    f += 2 * N_ACT * D_TINY * D_TINY
    f += D_ACT * (N_ACT * D_TINY + D_TINY + D_PROP)
    return f


def shared_draws(regime, seed):
    rng = random.Random(3000 * STREAM[regime] + seed)
    d_raw = raw_dim(regime)
    prec_mix = None
    if regime == "precise":
        prec_mix = [[rng.gauss(0.0, 0.4) for _ in range(d_raw)] for _ in range(2)]
    demos = [make_demo(regime, rng) for _ in range(STEPS * BATCH)]
    test = [make_demo(regime, rng) for _ in range(TEST)]
    if prec_mix is not None:
        fill_precise_actions(demos, prec_mix)
        fill_precise_actions(test, prec_mix)
    shuffles = []
    for _ in range(STEPS):
        perm = list(range(BATCH))
        rng.shuffle(perm)
        if perm == list(range(BATCH)) and BATCH > 1:
            perm[0], perm[1] = perm[1], perm[0]
        shuffles.append(perm)
    test_perm = list(range(TEST))
    rng.shuffle(test_perm)
    return {
        "d_raw": d_raw,
        "demos": demos,
        "test": test,
        "shuffles": shuffles,
        "test_perm": test_perm,
        "inits": {"A": init_large(rng, d_raw), "B": init_bridge(rng, d_raw)},
    }


SCALE = 1.0 / math.sqrt(D_TINY)


def xattn_forward(Q, K, V):
    outs, caches = [], []
    for q in Q:
        scores = [dot(q, k) * SCALE for k in K]
        p = softmax(scores)
        o = [0.0] * len(V[0])
        for w, v in zip(p, V):
            axpy_vec(o, v, w)
        outs.append(o)
        caches.append((q, scores, p))
    return outs, caches


def xattn_backward(do_list, caches, Q, K, V):
    dQ = [zeros(len(Q[0])) for _ in Q]
    dK = [zeros(len(K[0])) for _ in K]
    dV = [zeros(len(V[0])) for _ in V]
    for i, (do, (q, scores, p)) in enumerate(zip(do_list, caches)):
        for j, pj in enumerate(p):
            axpy_vec(dV[j], do, pj)
        dp = [dot(do, V[j]) for j in range(len(V))]
        dotp = sum(pj * dpj for pj, dpj in zip(p, dp))
        ds = [pj * (dpj - dotp) for pj, dpj in zip(p, dp)]
        for j, dsj in enumerate(ds):
            axpy_vec(dQ[i], K[j], dsj * SCALE)
            axpy_vec(dK[j], q, dsj * SCALE)
    return dQ, dK, dV


def tokens_from(mat, bias, vec, n, d):
    flat = add_vec(matvec(mat, vec), bias)
    return [flat[i * d:(i + 1) * d] for i in range(n)], flat


def aq_forward(params, raw):
    z = add_vec(matvec(params["Wq1"], raw), params["bq1"])
    h = relu(z)
    aq = add_vec(matvec(params["Wq2"], h), params["bq2"])
    return aq, z, h


def linear_backward_matvec(W, x, dy):
    dW = outer(dy, x)
    db = dy[:]
    dx = [sum(W[k][j] * dy[k] for k in range(len(W))) for j in range(len(x))]
    return dW, db, dx


def zeros_like_params(p):
    z = {}
    for k, v in p.items():
        if k == "g" or isinstance(v, float):
            z[k] = 0.0
        elif v and isinstance(v[0], list):
            z[k] = zeros(len(v), len(v[0]))
        else:
            z[k] = zeros(len(v))
    return z


def copy_params(p):
    out = {}
    for k, v in p.items():
        if k == "g" or isinstance(v, float):
            out[k] = v
        elif v and isinstance(v[0], list):
            out[k] = clip_copy_mat(v)
        else:
            out[k] = v[:]
    return out


def add_params(dst, src, s):
    for k, v in src.items():
        if k == "g" or isinstance(v, float):
            dst[k] += s * v
        elif v and isinstance(v[0], list):
            axpy_mat(dst[k], v, s)
        else:
            axpy_vec(dst[k], v, s)


def bridge_forward(params, raw, prop):
    raw_toks, raw_flat = tokens_from(params["Wr"], params["br"], raw, N_RAW, D_TINY)
    aq, zq, hq = aq_forward(params, raw)
    pr_tok = add_vec(matvec(params["Wp"], prop), params["bp"])
    aq_toks = [aq, pr_tok]
    a0 = [0.0] * D_ACT
    act_toks, act_flat = tokens_from(params["Wa"], params["ba"], a0, N_ACT, D_TINY)
    ca1, c1 = xattn_forward(act_toks, raw_toks, raw_toks)
    ca2, c2 = xattn_forward(act_toks, aq_toks, aq_toks)
    sa, cs = xattn_forward(act_toks, act_toks, act_toks)
    gate = math.tanh(params["g"])
    mixed, mid = [], []
    for t in range(N_ACT):
        cat = [gate * x for x in ca1[t]] + ca2[t] + sa[t]
        h = add_vec(matvec(params["Wmix"], cat), params["bmix"])
        z = add_vec(matvec(params["W1"], h), params["b1"])
        r = relu(z)
        h2 = add_vec(h, add_vec(matvec(params["W2"], r), params["b2"]))
        mixed.append(h2)
        mid.append((cat, h, z, r))
    flat = []
    for tok in mixed:
        flat.extend(tok)
    feat = flat + aq + list(prop)
    y = add_vec(matvec(params["Wo"], feat), params["bo"])
    cache = {
        "raw": raw, "prop": prop, "a0": a0, "aq": aq, "zq": zq, "hq": hq,
        "raw_toks": raw_toks, "aq_toks": aq_toks, "act_toks": act_toks,
        "ca1": ca1, "c1": c1, "ca2": ca2, "c2": c2, "sa": sa, "cs": cs,
        "gate": gate, "mid": mid, "mixed": mixed, "feat": feat, "y": y,
    }
    return y, cache


def bridge_backward(params, cache, dy):
    g = zeros_like_params(params)
    dWo, dbo, dfeat = linear_backward_matvec(params["Wo"], cache["feat"], dy)
    axpy_mat(g["Wo"], dWo, 1.0)
    axpy_vec(g["bo"], dbo, 1.0)
    n_flat = N_ACT * D_TINY
    d_flat = dfeat[:n_flat]
    d_aq_res = dfeat[n_flat:n_flat + D_TINY]
    # d_prop_res = dfeat[n_flat + D_TINY:]  # no param solely from this skip besides Wo
    d_mixed = [d_flat[i * D_TINY:(i + 1) * D_TINY] for i in range(N_ACT)]
    d_cat = []
    for t in range(N_ACT):
        cat, h, z, r = cache["mid"][t]
        dh2 = d_mixed[t]
        dW2, db2, dr = linear_backward_matvec(params["W2"], r, dh2)
        axpy_mat(g["W2"], dW2, 1.0)
        axpy_vec(g["b2"], db2, 1.0)
        dz = [dr[i] if z[i] > 0.0 else 0.0 for i in range(D_TINY)]
        dW1, db1, dh_from_ff = linear_backward_matvec(params["W1"], h, dz)
        axpy_mat(g["W1"], dW1, 1.0)
        axpy_vec(g["b1"], db1, 1.0)
        dh = add_vec(dh2, dh_from_ff)
        dWm, dbm, dcat = linear_backward_matvec(params["Wmix"], cat, dh)
        axpy_mat(g["Wmix"], dWm, 1.0)
        axpy_vec(g["bmix"], dbm, 1.0)
        d_cat.append(dcat)
    gate = cache["gate"]
    dca1 = [d_cat[t][0:D_TINY] for t in range(N_ACT)]
    dca2 = [d_cat[t][D_TINY:2 * D_TINY] for t in range(N_ACT)]
    dsa = [d_cat[t][2 * D_TINY:3 * D_TINY] for t in range(N_ACT)]
    dg = 0.0
    dca1_pre = []
    for t in range(N_ACT):
        dca1_pre.append([gate * v for v in dca1[t]])
        dg += sum(dca1[t][i] * cache["ca1"][t][i] for i in range(D_TINY))
    g["g"] += dg * (1.0 - gate * gate)
    dQ1, dK1, dV1 = xattn_backward(dca1_pre, cache["c1"], cache["act_toks"], cache["raw_toks"], cache["raw_toks"])
    dQ2, dK2, dV2 = xattn_backward(dca2, cache["c2"], cache["act_toks"], cache["aq_toks"], cache["aq_toks"])
    dQs, dKs, dVs = xattn_backward(dsa, cache["cs"], cache["act_toks"], cache["act_toks"], cache["act_toks"])

    d_aq_toks = [add_vec(dK2[j], dV2[j]) for j in range(N_AQ)]
    # AQ token is both aq_toks[0] and the residual branch
    d_aq = add_vec(d_aq_toks[0], d_aq_res)
    d_raw_flat = []
    for tok in d_raw_toks:
        d_raw_flat.extend(tok)
    dWr, dbr, _ = linear_backward_matvec(params["Wr"], cache["raw"], d_raw_flat)
    axpy_mat(g["Wr"], dWr, 1.0)
    axpy_vec(g["br"], dbr, 1.0)
    # AQ MLP
    dWq2, dbq2, dhq = linear_backward_matvec(params["Wq2"], cache["hq"], d_aq)
    axpy_mat(g["Wq2"], dWq2, 1.0)
    axpy_vec(g["bq2"], dbq2, 1.0)
    dzq = [dhq[i] if cache["zq"][i] > 0.0 else 0.0 for i in range(HQ)]
    dWq1, dbq1, _ = linear_backward_matvec(params["Wq1"], cache["raw"], dzq)
    axpy_mat(g["Wq1"], dWq1, 1.0)
    axpy_vec(g["bq1"], dbq1, 1.0)

    axpy_vec(g["bp"], dbp, 1.0)

    dWa, dba, _ = linear_backward_matvec(params["Wa"], cache["a0"], d_act_flat)
    axpy_mat(g["Wa"], dWa, 1.0)
    axpy_vec(g["ba"], dba, 1.0)

def large_forward(params, raw, prop):
    zbb = add_vec(matvec(params["Wbb"], raw), params["bbb"])
    bb = relu(zbb)
    x = bb + list(prop)
    z = add_vec(matvec(params["W1"], x), params["b1"])
    h = relu(z)
    y = add_vec(matvec(params["W2"], h), params["b2"])
    return y, (zbb, bb, x, z, h)


def large_backward(params, raw, cache, dy):
    zbb, bb, x, z, h = cache
    dW2, db2, dh = linear_backward_matvec(params["W2"], h, dy)
    dz = [dh[i] if z[i] > 0.0 else 0.0 for i in range(len(z))]
    dW1, db1, dx = linear_backward_matvec(params["W1"], x, dz)
    dbb = dx[:D_BB]
    dzbb = [dbb[i] if zbb[i] > 0.0 else 0.0 for i in range(D_BB)]
    dWbb, dbbb, _ = linear_backward_matvec(params["Wbb"], raw, dzbb)
    return {"Wbb": dWbb, "bbb": dbbb, "W1": dW1, "b1": db1, "W2": dW2, "b2": db2}


def l1_grad(y, target):
    dy, loss = [], 0.0
    for yi, ti in zip(y, target):
        d = yi - ti
        loss += abs(d)
        dy.append(1.0 if d > 0 else (-1.0 if d < 0 else 0.0))
    return loss, dy


def apply_shuffle(batch, perm):
    raws = [batch[i]["raw"] for i in perm]
    out = []
    for i, demo in enumerate(batch):
        d = dict(demo)
        d["raw"] = raws[i]
        out.append(d)
    return out


def train_large(draws):
    p = copy_params(draws["inits"]["A"])
    for s in range(STEPS):
        batch = draws["demos"][s * BATCH:(s + 1) * BATCH]
        acc = zeros_like_params(p)
        for d in batch:
            y, cache = large_forward(p, d["raw"], d["prop"])
            _loss, dy = l1_grad(y, d["action"])
            dy = [v / BATCH for v in dy]
            g = large_backward(p, d["raw"], cache, dy)
            add_params(acc, g, 1.0)
        add_params(p, acc, -LR)
    return p


def train_bridge(draws, shuffle=False):
    p = copy_params(draws["inits"]["B"])
    for s in range(STEPS):
        batch = draws["demos"][s * BATCH:(s + 1) * BATCH]
        if shuffle:
            batch = apply_shuffle(batch, draws["shuffles"][s])
        acc = zeros_like_params(p)
        for d in batch:
            y, cache = bridge_forward(p, d["raw"], d["prop"])
            _loss, dy = l1_grad(y, d["action"])
            dy = [v / BATCH for v in dy]
            g = bridge_backward(p, cache, dy)
            add_params(acc, g, 1.0)
        add_params(p, acc, -LR)
    return p


def eval_large(p, draws):
    ok, l1 = 0, 0.0
    for d in draws["test"]:
        y, _ = large_forward(p, d["raw"], d["prop"])
        err = [a - b for a, b in zip(y, d["action"])]
        l1 += sum(abs(e) for e in err)
        if math.sqrt(sum(e * e for e in err)) <= TOL:
            ok += 1
    n = len(draws["test"])
    return {"success_%": 100.0 * ok / n, "l1": l1 / n}


def eval_bridge(p, draws, shuffle=False):
    tes = draws["test"]
    if shuffle:
        tes = apply_shuffle(tes, draws["test_perm"])
    ok, l1 = 0, 0.0
```
