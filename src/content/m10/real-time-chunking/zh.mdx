## 空等帧 vs 接缝

动作块策略在执行一个块的同时计算下一个块。会出两类不同的问题：

| 问题 | 现象 | 解法 |
| --- | --- | --- |
| 空等帧 | 机械臂停下来等推理 | 异步推理（8.3） |
| 不连续 | 新块接手时机械臂一抖 | <Term id="real-time-chunking">实时动作块（RTC）</Term> |

LeRobot 的 RTC 文档也这样划分，并建议两者一起用。ACT 的 temporal ensembling（6.2）走另一条路：每步都查询策略，对同一时间索引的多份预测加权平均。这要求每个控制周期都推理一次；RTC 论文报告，注入 100 ms 或 200 ms 额外延迟时，temporal ensembling 触发了机器人的保护性停机。

## 冻结与软掩码

RTC（Black、Galliker 与 Levine，arXiv **2506.07339**）把下一个块看成推理期的 inpainting 问题；不需要重训，适用于扩散或流匹配策略，如 π0、π0.5、SmolVLA。

记号（Δt 为控制周期，δ 为从观测到拿到可用动作块的时间）：

- **H**：预测长度（块长）。
- **s**：新一次推理开始前，已从上一块执行掉的动作数。
- **d = floor(δ / Δt)**：以控制步计的推理延迟。本课简化条件：d ≤ s ≤ H − d（RTC 原文未写此式）。

新块去噪期间，前 d 个动作已经按旧块执行掉了，所以它们被**冻结**。再往后，<Term id="soft-mask">软掩码</Term> W 决定新块要在多大程度上贴近旧块剩下的部分（论文式 5）：

| 下标 i | W[i] |
| --- | --- |
| i 小于 d | 1（冻结） |
| d ≤ i，且 i 小于 H − s | `c·(e^c − 1)/(e − 1)`，其中 `c = (H − s − i)/(H − s − d + 1)` |
| i ≥ H − s | 0（自由） |

一个块的时间轴（H=16、s=8、d=2，即下面的玩具）：

| 步 | 0–1 | 2–7 | 8–15 |
| --- | --- | --- | --- |
| 区段 | 冻结（旧块） | 软区（衰减） | 自由（新块） |
| W | 1.00 | 0.68 → 0.01 | 0.00 |

真正的方法里，W 在每一步去噪时进入一个引导项（向量–雅可比积，并用最大权重 β 截断）；论文取 β = 5。按论文测量，这个引导让每个去噪步慢约 2.5 倍，所以下面的玩具不去实现它。

## 跑线性替身

`rtc_blend_toy.py` 保留掩码、去掉网络。旧计划是匀速斜坡（每步 0.05）；新块来自「另一种策略」（0.20 + 0.03·i）。**naive** 先用冻结前缀，然后直接播放新块；**blend** 事后计算 `W·旧 + (1 − W)·新`。这种事后混合是 RTC 引导去噪的简化线性替身，不是方法本身。

```python
"""rtc_blend_toy.py: chunk seam, naive switch vs soft-mask blend (stdlib).

Simplified LINEAR stand-in for real-time chunking (RTC, arXiv 2506.07339).
Real RTC puts the soft mask W inside a guidance term during flow-matching
denoising (a vector-Jacobian product, clipped by beta). Here we skip the
network and apply W directly as a post-hoc blend:

    blended[i] = W[i] * prev_left[i] + (1 - W[i]) * fresh[i]

W follows Eq. 5 of the RTC paper:
    W[i] = 1                              if i < d
    W[i] = c * (e^c - 1) / (e - 1)        if d <= i < H - s,  c = (H-s-i)/(H-s-d+1)
    W[i] = 0                              if i >= H - s

H = prediction horizon, s = actions executed from the previous chunk before
this inference started, d = inference delay in control steps.
"""

import math

H = 16
S = 8
DELAYS = (0, 2, 4)


def prev_chunk() -> list[float]:
    """Old plan: a steady ramp (rad), 0.05 per step."""
    return [0.05 * k for k in range(H)]


def fresh_chunk() -> list[float]:
    """New plan from a newer observation: a different 'strategy' (lower, slower)."""
    return [0.20 + 0.03 * i for i in range(H)]


def soft_mask(d: int) -> list[float]:
    w = []
    for i in range(H):
        if i < d:
            w.append(1.0)
        elif i < H - S:
            c = (H - S - i) / (H - S - d + 1)
            w.append(c * (math.exp(c) - 1.0) / (math.e - 1.0))
        else:
            w.append(0.0)
    return w


def executed(d: int, use_blend: bool) -> list[float]:
    """Last executed old action, then what the robot actually plays next."""
    prev = prev_chunk()
    left = prev[S:] + [0.0] * S  # right-pad to length H (paper: Algorithm 1)
    fresh = fresh_chunk()
    w = soft_mask(d) if use_blend else [1.0 if i < d else 0.0 for i in range(H)]
    new = [w[i] * left[i] + (1.0 - w[i]) * fresh[i] for i in range(H)]
    # actions 0..d-1 run from the old chunk while inference is in flight
    return [prev[S - 1]] + left[:d] + new[d:]


def stats(seq: list[float]) -> tuple[float, float]:
    steps = [abs(b - a) for a, b in zip(seq, seq[1:])]
    acc = [abs(seq[k + 1] - 2 * seq[k] + seq[k - 1]) for k in range(1, len(seq) - 1)]
    return max(steps), max(acc)


def main() -> None:
    print(f"H={H} s={S}  prev ramp 0.05/step, fresh = 0.20 + 0.03*i (other strategy)")
    print(f"{'d':>2} {'mode':<6} {'max_step':>8} {'max_acc':>8} {'tail=fresh':>10}")
    for d in DELAYS:
        for mode in ("naive", "blend"):
            seq = executed(d, mode == "blend")
            mstep, macc = stats(seq)
            tail_ok = all(
                abs(seq[1 + i] - fresh_chunk()[i]) < 1e-12 for i in range(H - S, H)
            )
            print(f"{d:>2} {mode:<6} {mstep:>8.3f} {macc:>8.3f} {str(tail_ok):>10}")
    w = soft_mask(2)
    print("W (d=2): " + " ".join(f"{v:.2f}" for v in w))
    print("naive jumps once at the seam; the blend spreads it over the overlap,")
    print("and the last s actions still follow the fresh chunk.")


if __name__ == "__main__":
    main()
```

## LeRobot 的 RTCConfig

LeRobot 用 `RTCConfig` 配置 RTC，运行时在请求下一块时传入延迟。下表取自 LeRobot RTC 文档（以 LeRobot v0.6.x 文档为准，命令可能随版本变化）：

| 选项 | 默认值 | 含义 |
| --- | --- | --- |
| `execution_horizon` | 10 | 有多少步被引导贴近旧块；常用 8–12 |
| `max_guidance_weight` | 10.0 | 引导权重上限；文档称 10.0 对 10 步流匹配最优 |
| `prefix_attention_schedule` | EXP | 掩码形状：LINEAR、EXP、ONES 或 ZEROS |
| `inference_delay`（运行时） | — | 即 d，传给 `predict_action_chunk(..., inference_delay=..., prev_chunk_left_over=...)` |

```bash

    --inference.type=rtc --inference.rtc.execution_horizon=10 \
    --inference.rtc.max_guidance_weight=10.0 ...
```

## 论文测到了什么

在真机上用 π0.5（H=50、Δt=20 ms、s_min=25），RTC 论文报告：带 RTC 的模型延迟约 97 ms，不带约 76 ms；注入超过 300 ms 的延迟仍然稳健；完成任务比同步推理快约 20 %。几种掩码形状里指数衰减最好，线性紧随其后。这些是论文在 GPU 和真机上的结果，本页未运行。[10.3](/zh/month/month-10/edge-deploy-checklist) 会把这类延迟换算成 d。

## 常见错误

- **把玩具的混合当成 RTC。** 玩具是事后混合；真正的 RTC 在每一步去噪时引导。
- **远程推理时还开着 ACT 的 temporal ensembling。** LeRobot 远程推理文档要求 ACT 关闭 temporal ensembling。
- **只按模型耗时设 `inference_delay`。** 相机、网络和预处理也要算（10.3）。
- **指望 RTC 消除空等帧。** 那是异步推理（8.3）的事；两者一起用。
