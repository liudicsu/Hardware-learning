一个关节被要求转到 60°，它却停在 55.5°：稳稳地顶住重力，却永远到不了目标。一台平衡车被要求待在原地，它平衡得很好，却慢慢滚过地板，直到撞上什么东西。两种失败的根源相同：只对<Term id="error">误差</Term>作出反应的控制器，可以很稳、很顺，却仍然是错的。

本课是本站补充内容。课程会在第 5 个月“控制理论：从 PID 开始”里正式讲控制：MATLAB Tech Talks、在平衡车上记录 P、PD、PID 的阶跃响应，最后是 LQR。这一课放在这里有两个原因：它要完成第 2 个月第 6 课留下的选做挑战；第 5 课的 SO-101 机械臂本身就是一组位置环。第 5 个月会更深入、更形式化；这里先给你现在就用得上的直觉。

## P、I、D 各管什么

本课程里的每一个反馈控制器都在做同样的四件事，周而复始：测量你关心的量，和目标比较，算出误差，针对误差出力。然后它在固定的频率上再做一遍，不管上一次修正有没有生效。控制器永远不会“判断自己已经到了”；它只是不断缩小它能看见的误差。

教科书里的 PID 公式只有一行：

```text
输出 = Kp × 误差 + Ki × (误差 × dt 的累加) + Kd × (变化率)
```

三项，三种职责。<Term id="proportional-term">比例项</Term> P 按“差多远”成比例地推：误差翻倍，推力也翻倍。<Term id="integral-term">积分项</Term> I 把误差随时间的累积加起来，所以一个一直不消失的小误差，最终会变成很大的指令；它就是那个一直推、直到<Term id="steady-state-error">稳态误差</Term>消失的项，比如机械臂关节上的重力负载。<Term id="derivative-term">微分项</Term> D 对测量值变化的快慢作出反应，给接近目标的过程踩刹车：关节快速冲向目标时，D 会从指令里减掉一部分，让它别冲过头。

在质量–弹簧–阻尼模型里，P 项对应弹簧（力与位移成正比），D 项对应阻尼器（力与速度成正比），I 项则是一个与误差累积量成正比的恒定偏置力。只有弹簧时，系统会振荡，并可能停在离目标还差一段距离的地方；只有阻尼器时，静止状态下不产生任何力；积分项则持续提供那个偏置力，直到剩余的稳态误差被消掉。

为什么只有 P 时，遇到恒定负载会留下误差？因为控制器只能靠“存在误差”来产生力矩。如果关节需要 0.227 N·m 才能顶住重力，那么静止时电机必须输出 0.227 N·m，而 P 控制器输出的是 Kp × error。让两者相等再解：

```text
Kp = 0.05 N·m/度
误差 = 0.227 / 0.05 = 4.5°
手臂停在 60 − 4.5 = 55.5°
```

机械臂没有坏，控制器也没有不稳定。它只是找到了唯一一个“推力刚好等于重力”的角度。把 Kp 调大，误差会变小，但不会变成零；只有积分项才能在零误差时继续输出力矩。

有两个工程细节，能把教科书 PID 变成机器人上真正能用的 PID。第一，微分要取测量值的变化率，而不是误差的变化率。如果 D 对误差求导，而目标突然从 0° 跳到 60°，误差也会瞬间跳变，微分项在一个采样周期里看到巨大的变化率，于是给电机一个猛烈的“微分冲击”（derivative kick），可实际上没有任何东西真的动了。对测量值求导就没有这个问题：目标跳变会改变误差，但不会改变已经测到的角度，所以 D 保持安静。本课的代码用 `rate = (measurement − previous measurement) / dt`，再减去 `kd × rate`。第二，循环必须跑在固定频率上，也就是第 2 个月第 2 课讲过的定时纪律。PID 假设每一次循环的 `dt` 都一样；如果这一圈用了 5 ms、下一圈用了 15 ms，积分项和微分项就会用错时间，同一组增益在不同时刻代表的含义都不一样。

<Callout type="warn" title="不要把会积分饱和或微分冲击的 PID 直接上真机">
目标阶跃时若对误差求导，或电机已经顶到力矩上限时积分还在累加，关节受到的冲击可能超过机械设计预期。真机上就是撞硬限位、打滑舵盘，或夹到手指。对测量值求导，从第一次试 Ki 起就打开抗饱和，并在仿真里先测大阶跃，再在硬件上提高 Ki。
</Callout>

## 一个关节，四种控制器

要看清 P、I、D 各自的作用，最好的办法是让四种控制器在同一个关节上跑一遍。下面的模型只有一个关节，可以想成 SO-101 的肩关节带一根短臂。它从水平的 0° 出发，被要求抬到 60°。重力按 0.4 N·m × cos(角度) 往下拉，电机最多只能给 1 N·m，还有一点黏性摩擦，控制器每 200 Hz 算一次。模型里的增益用的是模型自己的单位，不是能直接抄进固件的 PWM 数值。

<CodeSource path="tools/sim/models/pid_sim.py" />

```python
"""pid_sim.py: P, PI, PID and integral windup on one arm joint lifting against gravity.

Toy model of a single joint (think of an SO-101 shoulder with a short arm): the motor
torque is limited, gravity pulls the arm down by 0.4 N*m * cos(angle), and there is a
little friction. The controller runs at 200 Hz and is asked to move the joint from
0 degrees (horizontal) to 60 degrees at t = 0.
"""
import math

J = 0.004          # kg*m^2, arm inertia seen at the joint
B = 0.05           # N*m per rad/s, viscous friction
GRAV = 0.4         # N*m, gravity torque with the arm horizontal
MAX_TORQUE = 1.0   # N*m the motor can give
DT = 0.005         # 200 Hz control loop


def run(kp, ki=0.0, kd=0.0, anti_windup=True, target=60.0, seconds=3.0):
    q, w, integral, t = 0.0, 0.0, 0.0, 0.0       # angle (rad), speed (rad/s)
    peak, settle = 0.0, None
    prev = q
    while t < seconds:
        error = target - math.degrees(q)
        rate = (math.degrees(q) - math.degrees(prev)) / DT   # derivative of the measurement
        prev = q
        unclipped = kp * error + ki * integral - kd * rate
        torque = max(-MAX_TORQUE, min(MAX_TORQUE, unclipped))
        if not anti_windup or torque == unclipped:            # only integrate while not saturated
            integral += error * DT
        for _ in range(5):                                    # physics at 1 ms
            alpha = (torque - B * w - GRAV * math.cos(q)) / J
            w += alpha * 0.001
            q += w * 0.001
        t += DT
        deg = math.degrees(q)
        peak = max(peak, deg)
        if abs(deg - target) > 1.0:
            settle = None
        elif settle is None:
            settle = t
    over = max(0.0, peak - target)
    s = f"{settle:.2f} s" if settle is not None else "never"
    return f"final {math.degrees(q):5.1f} deg, overshoot {over:4.1f} deg, within 1 deg from {s}"


if __name__ == "__main__":
    print("P    kp 0.05                  ", run(0.05))
    print("P    kp 0.2                   ", run(0.2))
    print("PD   kp 0.05, kd 0.002        ", run(0.05, kd=0.002))
    print("PI   kp 0.05, ki 0.1          ", run(0.05, ki=0.1))
    print("PID  kp 0.05, ki 0.1, kd 0.002", run(0.05, ki=0.1, kd=0.002))
    print("  ...same, no anti-windup     ", run(0.05, ki=0.1, kd=0.002, anti_windup=False))
    print("PID  kp 0.05, ki 0.4, kd 0.002", run(0.05, ki=0.4, kd=0.002))
    print("  ...same, no anti-windup     ", run(0.05, ki=0.4, kd=0.002, anti_windup=False))
```

逐行看输出。P、Kp = 0.05 停在 55.5°，正好是上面算出的差 4.5°；路上还冲过头（<Term id="overshoot">超调</Term>）10.8°——机械臂有惯性，比例项把它拉回来之前，它已经越过目标了。P、Kp = 0.2 更接近，停在 59.0°，因为静止时它的误差大约是 1°，此时 0.2 × 1.0° = 0.2 N·m，而 59° 处的重力是 0.4 × cos 59° = 0.4 × 0.515 = 0.206 N·m，两边几乎相等，于是它就停在那里。它始终进不了“误差 1° 以内”的范围，因为 1° 的误差正好是 Kp = 0.2 产生 0.2 N·m 所需要的误差；平衡点就落在 1° 这条线外侧一点点。继续加大 Kp，最终误差会更小，但超调会变大：同一条比例曲线推得更狠，接近过程里储存的能量也更多。

PD 加上 Kd = 0.002，把超调完全消掉（0.0°），但最终角度仍然是 55.5°。这是关于 D 最重要的一课：它只在“有东西在动”时起作用。机械臂一旦静止，变化率为零，D 的贡献就是零，稳态误差仍然停在 P 留下的位置。D 改善的是过程，不是终点。

PI 加上 Ki = 0.1，能到 60.0°，但超调 11.5°，0.92 s 后才进入并保持在 1° 范围内，即以 1° 为误差带的<Term id="settling-time">稳定时间</Term>是 0.92 s。积分最终会在零误差时补上重力力矩，所以终点对了；代价是机械臂还在接近时积分仍在推，于是冲过头。PID 三项齐全：Kp 0.05、Ki 0.1、Kd 0.002，到 60.0°，超调只有 0.1°，0.24 s 就进入 1° 范围。对这个关节来说，它显然是这组里最好的：积分修好终点，微分管住到达，P 干主要的活。

### 模型里的数字从哪里来

模型里的每个常数，在真实关节上都对应一个能测量或能查到的量。

- **重力力矩 0.4 N·m。** 重力对关节的力矩等于运动部分的重量乘以从轴线到其质心的水平距离，τ = m × g × r。连杆水平时它最大，连杆抬起时按 cos(角度) 减小，这就是模型里的 cos 项。真实关节上可以直接测：舵机断电，把连杆末端搭在厨房秤上、使连杆保持水平，记下搭点到轴线的距离 L，把读数换算成力，F = 读数（kg）× 9.81 m/s²，再相乘，τ = F × L。断电的减速箱仍有摩擦，还可能部分自锁，自己托住连杆的一部分重量，所以每次读数前轻敲一下连杆，多读几次取平均。在 L = 0.2 m 处读到 0.204 kg，就是 0.2 m 处 2.0 N，即 0.40 N·m。
- **转动惯量 0.004 kg·m²。** 对于集中的负载，第 3 课的转动惯量近似为 J = m × r²。这两个常数描述的是同一个负载：0.42 kg、质心离轴 0.098 m，得到 J = 0.42 × 0.098² = 0.0040 kg·m²，τ = 0.42 × 9.81 × 0.098 = 0.40 N·m。真实连杆的质量是分布开的，不集中在一点，所以 m × r² 只是下限；在 CAD 工具里设好材料密度后，质量属性报告会给出完整的值。电机转子还会经过减速箱加上 n² × J_转子（第 3 课），这部分要加到连杆的值上。
- **电机上限 1 N·m。** SO-101 用的 STS3215 舵机的堵转扭矩是 7.4 V 时 19.5 kg·cm、6 V 时 16.5 kg·cm（第 5 课；飞特规格书第 5-4 项），即 1.91 N·m 和 1.62 N·m，也就是舵机在零速、电流最大时能出的最大扭矩。它的额定负载（设计上可以持续承担的扭矩）是 7.4 V 时 5 kg·cm、6 V 时 4 kg·cm（第 5-8 项），约 0.49 N·m 和 0.39 N·m。标准版用 5 V 供电：持续负载在 5 V 下按 ≤0.4 N·m 的上限估；飞特未给 5 V 额定值，按电压线性折算约 0.33 N·m（0.39 × 5 / 6），属未经验证的估计。模型里 0.4 N·m 的重力力矩已经接近这个上限。因此模型里的 1 N·m 上限是介于额定值和堵转值之间的一个偏乐观的短时峰值：舵机在短暂修正时能给出，但不能持续保持。
- **摩擦 0.05 N·m/(rad/s)。** 粘性摩擦是唯一查不到的常数。在这个模型里它是假设值，给关节一点阻尼；真实关节上的做法是记录一次阶跃响应，再调整 B，直到模型的响应与之吻合。
- **循环频率 200 Hz。** 频率取决于闭环运动有多快。只有比例增益时，关节就像挂在刚度为 Kp 的弹簧上的质量，它的固有频率（没有摩擦时振荡的快慢）是 ωn = √(Kp / J)。Kp = 0.05 N·m/度，即 0.05 × 180 / π = 2.86 N·m/rad，所以 ωn = √(2.86 / 0.004) = 26.8 rad/s，即 4.26 Hz。数字控制常用的经验法则是采样频率取 ωn 的 20 到 60 倍（[Real-Time Computing，闭环控制一章](https://rtcbook.org/closed-loop-control/summary/)），这里是 535 到 1606 rad/s，即 85 到 256 Hz。200 Hz 是 1257 rad/s，为 ωn 的 47 倍，在这个范围内。

## 积分饱和

电机的输出上限，正是积分项容易出事的地方。开始时误差是 60°，光 P 就要 0.05 × 60 = 3 N·m，而电机最多给 1 N·m，于是输出被削在 1 N·m：控制器饱和了。如果输出被削住时积分还继续把误差加进去，积分项就会累积出一个远大于电机实际输出力矩的指令；等机械臂终于到了，这部分指令依然存在，于是把它推过目标，积分还得慢慢退回来。

具体算一下：在 200 Hz 下，0.1 s 有 20 次循环；如果误差大约是 60°，积分在这 0.1 s 里会增加约 60 × 0.1 = 6 度·秒。Ki = 0.1 时，这相当于 0.1 × 6 = 0.6 N·m 的指令；Ki = 0.4 时就是 0.4 × 6 = 2.4 N·m。这些力矩电机根本没有输出过，但积分记得它们。

输出的最后四行正好量出了这件事：Ki = 0.1 时，有抗饱和的 PID 超调 0.1°，没有抗饱和是 8.8°；Ki = 0.4 时，有抗饱和 8.9°，没有抗饱和 39.0°。积分增益越大，存得越快，冲得越狠。

1. 保持 Kp = 0.050、Ki = 0.10、Kd = 0.0020、抗积分饱和开启，读取最终角度 = 60.0°、超调量 = 0.1°、进入 ±1° 的时间 = 0.24 s。
2. 将 Ki 设为 0.40，读取超调量 = 8.9°、进入 ±1° 的时间 = 0.56 s。
3. 关闭抗积分饱和，读取超调量 = 39.0°、进入 ±1° 的时间 = 0.64 s。
4. 开启抗积分饱和并将 Ki 设为 0.00，读取最终角度 = 55.5°、进入 ±1° 的时间 = 从未进入。
5. 将 Ki 设为 0.10、Kd 设为 0.0000，读取超调量 = 11.5°、进入 ±1° 的时间 = 0.92 s。结论：Ki = 0 时稳态误差等于重力力矩除以 Kp：0.4 N·m × cos 55.5° = 0.227 N·m，0.227 / 0.05 = 4.5°，因此 60° − 4.5° = 55.5°；抗积分饱和在力矩达到 1 N·m 饱和时阻止积分继续累积。

模型里的修法只有一个条件：只在输出没有饱和时积分。代码就是 `if not anti_windup or torque == unclipped:`。当请求力矩超过上限时，`torque` 和 `unclipped` 不相等，积分被冻住；等机械臂近到光靠 P 已经不会再让电机满载，积分才开始工作。别的修法原理相同：把积分限制在一个范围内（平衡车的外环就是这么做的），或者在目标跳变时把积分清零，免得上一段动作的旧误差漏到新动作里。任何一条都比“让积分在电机满输出时继续跑”强。

## 有章法地调参

调参不是凭经验试数字，而是一个有顺序的短流程，每次只改一处。顺序很重要，因为后面的增益依赖前面的结果。

1. **先用一个很小的 Kp 确认方向**。给关节一个小目标阶跃，看它往哪边动。如果它朝远离目标的方向动，先把控制器输出的符号翻过来（或者对调电机线），再谈别的。正反馈回路不管增益多小，输出都会一直增长到饱和。
2. **加大 Kp，直到它响应够快并开始振荡，然后退回大约一半**。振荡点说明回路的增益已经超过阻尼；取一半是实用的起点，不是定律。
3. **加 Kd 压住超调**。D 会放大传感器噪声，因为对带噪声的信号求导，等于把快速抖动按频率放大。把变化率滤波，或者直接用陀螺仪测角速度：平衡车就是用陀螺仪，所以它的 D 项不需要对噪声很大的角度求导。
4. **加一点 Ki 消掉剩下的误差，并且从一开始就开抗饱和**。小步加；积分是最慢的一项，也最容易饱和。
5. **每次只改一个增益，把每一次尝试写进调参日志**。记录增益、超调、稳定时间、你看到和听到的现象。第 2 个月就要求过同样的日志；它是你判断“到底是哪一处改动起了作用”的唯一依据。

循环频率必须明显高于系统运动的速度。200 Hz 的循环每 5 ms 修正一次，对平衡车或小关节都绰绰有余。慢循环会带来延迟：控制指令作用在已经变化过的状态上，等控制器反应过来，被控量已经继续变化，回路的相位裕度因此减小。如果提不高频率，就把增益降下来；慢循环配高增益，就是一台会来回振荡的机器。

第 3 课讲的齿隙，会限制你把 Kp 和 Ki 推到多高——尤其是编码器装在齿轮之后时。齿隙里面，电机对机械臂根本没有抓握力；高增益回路会冲过空隙、超调、反向、再冲回来，形成一个小幅极限环。关节在静止时嗡嗡响或来回找位，除了微分噪声，第二个要怀疑的就是齿隙。真正的修法是降增益、加预紧，或者把编码器挪到输出端；继续加增益只会更糟。

## 串级回路

<Term id="cascade-control">串级</Term>（cascade）就是两个反馈回路套在一起。内环快，控制变化快的东西，比如俯仰角；外环慢，控制变化慢的东西，比如轮速，办法是改内环的目标值。外环不直接驱动电机，它只移动内环正在努力保持的那个<Term id="setpoint">设定点</Term>。

<Diagram id="pid-cascade" />

规则是：外环必须明显比内环慢。这里内环 200 Hz，外环 25 Hz，慢了 8 倍。外环的输出还被限制在 ±3° 的倾角以内。两条规则服务同一个目的：外环犯的错，不能把机器人弄倒。平衡的最终决定权仍然在内环；外环只是“建议”一个小倾角。

这两个数字都可以推出来。外环的频率由测速决定。编码器每走 π × 65 mm / 90 = 2.27 mm 计一个数，速度等于一个时间窗内的计数除以窗长，所以一个计数就是它能显示的最小速度台阶：如果外环像内环一样每 5 ms 跑一次，台阶是 2.27 mm / 5 ms = 0.45 m/s；每 8 拍跑一次（40 ms），台阶是 2.27 mm / 40 ms = 0.057 m/s。5 ms 的窗对任何更慢的速度只能读出 0 或 ±0.45 m/s，这个台阶接近 1 m/s 最高速度的一半，增益怎么调都没法据此控制速度。40 ms 的窗仍然以 0.057 m/s 为台阶，这也是后面外环增益一高、设定值就跳来跳去的原因。窗越长台阶越细，但报出的速度越滞后；换一个每转计数更多的编码器，或者两路信号的每个边沿都计数，就能在同样频率下得到更细的台阶。

±3° 的限幅来自电机的加速度上限。要让车身保持一个不变的倾角 θ，轮子必须以 a = g × tan θ 加速；3° 时是 9.81 × tan 3° = 0.51 m/s²，不到电机能给的 6 m/s²（MAX_ACCEL）的十分之一，所以电机的大部分能力仍留给内环去保持平衡。同一个公式也给出硬极限：6 m/s² 时 tan θ = 6 / 9.81，θ = 31.5°，超过大约 31°，即使满加速度也拉不回车身。模型在 40° 时判定机器人倒下，与 balance_sim.py 和下面固件里的 CUTOFF_DEG 相同。限幅也给外环的 P 项封了顶：kp_s = 12 度/(m/s) 时，速度误差到 3 / 12 = 0.25 m/s，设定值就到 3°。

为什么只有内环时平衡车会自己滚走？因为 IMU 永远不可能装得绝对正。如果传感器读 0° 时，车身实际上已经前倾 1°，那么“保持 pitch = 0”就等于“保持前倾 1°”。重力把车往前拉，内环驱动轮子追到身体下面，车就加速；它一直加速到轮子到达最高转速，然后倒下。模型把这些都加进去了：1° 的安装误差、1 m/s 的最高轮速，还有每转 90 个计数、只数 A 相上升沿的粗编码器（和固件一致）。

```python
"""cascade_sim.py: finish the Month 2 balancer with an outer speed loop (a cascade).

Same toy inverted pendulum as balance_sim.py (centre of mass 0.10 m above the axle, the
controller sets wheel acceleration, complementary filter with a 0.5 s time constant),
plus the things that make a real balancer roll away:
  * the IMU is mounted 1 degree off, so "pitch = 0" is not quite the balance point
  * the wheels have a top speed, and a coarse encoder (90 counts per turn of a 65 mm wheel)
Inner loop: PD on pitch at 200 Hz. Outer loop: PI on wheel speed at 25 Hz, which moves
the inner loop's SETPOINT. 60 s run; at t = 30 s someone pushes the robot.
"""
import math
import random

G, L = 9.81, 0.10            # gravity, height of the centre of mass (m)
MAX_ACCEL = 6.0              # m/s^2 the motors can deliver
MOTOR_TAU = 0.02             # wheels reach a new acceleration in ~20 ms
MAX_SPEED = 1.0              # m/s, wheel top speed
MOUNT_ERROR = 1.0            # deg, IMU reads this much more than the true tilt
WHEEL_TURN = math.pi * 0.065 # m per wheel turn (65 mm wheel)
COUNTS_PER_TURN = 90         # encoder counts per wheel turn (A edges only, as in the sketch)
KP, KD = 0.8, 0.04           # inner PD, same gains as balance_sim.py


def run(outer=None, kp_s=0.0, ki_s=0.0, push=40.0, go=None, seconds=60.0, seed=3, trace=None):
    """outer=None: inner loop only; outer="P" or "PI" adds the speed loop.
    kp_s is in deg of setpoint per m/s of speed error, ki_s in deg per metre.
    go=(t, speed): from time t on, ask for this wheel speed instead of 0."""
    rng = random.Random(seed)
    dt = 0.005
    theta, omega, accel = math.radians(3.0), 0.0, 0.0
    x, v = 0.0, 0.0
    est, setpoint, integral = 0.0, 0.0, 0.0
    last_counts, tick, t, next_ctrl = 0, 0, 0.0, 0.0
    far, pushed, sq, n = 0.0, False, 0.0, 0
    x_before, push_far, settled = 0.0, 0.0, None
    log = []
    while t < seconds:
        if t >= next_ctrl:                                   # --- 200 Hz controller tick ---
            next_ctrl += dt
            gyro = math.degrees(omega) + rng.gauss(0, 0.3)
            acc = math.degrees(theta) + MOUNT_ERROR + rng.gauss(0, 2.5)
            a = 0.5 / (0.5 + dt)
            est = a * (est + gyro * dt) + (1 - a) * acc
            if outer and tick % 8 == 0:                      # --- 25 Hz outer loop ---
                counts = math.floor(x / WHEEL_TURN * COUNTS_PER_TURN)
                speed = (counts - last_counts) / COUNTS_PER_TURN * WHEEL_TURN / (8 * dt)
                last_counts = counts
                target = go[1] if go and t >= go[0] else 0.0
                error = target - speed
                if outer == "PI":
                    integral += error * 8 * dt
                    limit = 3.0 / ki_s                       # anti-windup: the integral alone
                    integral = max(-limit, min(limit, integral))  # may ask for at most 3 deg
                setpoint = max(-3.0, min(3.0, kp_s * error + ki_s * integral))
            tick += 1
            command = KP * (est - setpoint) + KD * gyro
            command = max(-MAX_ACCEL, min(MAX_ACCEL, command))
            if trace and trace[0] <= t < trace[1] and tick % 8 == 1:
                log.append(f"t={t:5.2f} s  setpoint {setpoint:+5.2f} deg  tilt {math.degrees(theta):+5.2f} deg  "
                           f"wheels {v:+.2f} m/s")
        # --- physics at 1 ms ---
        accel += (command - accel) * 0.001 / MOTOR_TAU
        a_real = accel
        if (v >= MAX_SPEED and a_real > 0) or (v <= -MAX_SPEED and a_real < 0):
            a_real = 0.0                                     # motors are flat out
        alpha = (G * math.sin(theta) - a_real * math.cos(theta)) / L
        omega += alpha * 0.001
        theta += omega * 0.001
        v += a_real * 0.001
        x += v * 0.001
        if not pushed and t >= 30.0:
            omega += math.radians(push)
            pushed, x_before = True, x
        if pushed:
            push_far = max(push_far, abs(x - x_before))
            if settled is None and t >= 35.0:
                settled = abs(x - x_before)                  # 5 s after the push
        if 40.0 < t < 60.0:
            sq += math.degrees(theta) ** 2
            n += 1
        t += 0.001
        if not go:
            far = max(far, abs(x))
        if abs(math.degrees(theta)) > 40:
            return f"fell over after {t:.1f} s, {x:+.2f} m from the start", log
    return (f"upright, farthest {far / WHEEL_TURN:.2f} wheel turns from the start; push moved it "
            f"{push_far / WHEEL_TURN:.2f} turns, {settled / WHEEL_TURN:.2f} turns off 5 s later; "
            f"wobble {math.sqrt(sq / n):.1f} deg rms"), log


if __name__ == "__main__":
    print("inner loop only:         ", run()[0])
    print("outer P   (12):          ", run("P", kp_s=12)[0])
    print("outer PI  (12, 12):      ", run("PI", kp_s=12, ki_s=12)[0])
    print("outer PI  (60, 60):      ", run("PI", kp_s=60, ki_s=60)[0])
    print("outer PI (12, 12), asked to drive at +0.2 m/s from t = 40 s:")
    print("\n".join(run("PI", kp_s=12, ki_s=12, go=(40.0, 0.2), seconds=41.0, trace=(39.96, 40.6))[1]))
```

### 为什么先往反方向动

最后一段轨迹是在 t = 40 s 时要求以 +0.2 m/s 前进。设定点先跳到 +3°，也就是前倾。但看轮子：它先向后走，−0.04、−0.06、−0.03 m/s，然后才真正往前，在 40.56 s 达到 +0.21 m/s。这不是 bug。要让车身向前倾，内环必须先让轮子向后加速，车身才会绕接地点向前转；等车身已经前倾，内环再驱动轮子向前，追到身体下面。

停下来时反过来也一样：要刹车，它先稍微加速，取得一个后倾角，然后才慢下来。工程上把这叫非最小相位（non-minimum-phase）行为。对你来说只有一条实用规则：不要去“修”最开始那一下反方向运动。那是<Term id="inverted-pendulum">倒立摆</Term>的物理，强行压掉它，机器人反而会倒。

```cpp
// Self-balancer with a cascade: the Month 2 balancer (inner PD on pitch, 200 Hz) plus an
// outer PI loop on wheel speed (25 Hz) that moves the inner loop's SETPOINT.
// Uno + TB6612FNG + two gearmotors with encoders + MPU-6050, wired as in Month 2 Lesson 6,
// plus: left encoder A -> D2, B -> D10; right encoder A -> D3, B -> D11.
// Get the inner loop balancing first (Month 2), then copy your KP/KD here.
#include <Wire.h>

const int PWMA = 5, AIN1 = 7, AIN2 = 8;     // left motor
const int PWMB = 6, BIN1 = 4, BIN2 = 12;    // right motor
const int STBY = 9;
const int ENC_LA = 2, ENC_LB = 10;          // A channels on the two interrupt pins
const int ENC_RA = 3, ENC_RB = 11;

const uint8_t MPU = 0x68;
const float ACCEL_LSB_PER_G = 16384.0;
const float GYRO_LSB_PER_DPS = 131.0;

const unsigned long PERIOD_US = 5000;       // inner loop: 200 Hz
const float DT = PERIOD_US / 1e6;
const int OUTER_EVERY = 8;                  // outer loop: every 8th tick = 25 Hz
const float OUTER_DT = DT * OUTER_EVERY;
const float ALPHA = 0.5 / (0.5 + DT);       // complementary filter, 0.5 s time constant

// Encoder: counting rising edges of A only = 1/4 of the full quadrature resolution.
// Example: 12 CPR motor encoder (3 rising edges of A per motor turn) x 30:1 gearbox, 65 mm wheel.
const float METERS_PER_COUNT = 3.14159 * 0.065 / (3 * 30);

float KP = 25.0, KD = 0.8;                  // inner PD: YOUR tuned Month 2 values
float KP_S = 3.0;                           // outer P: deg of setpoint per m/s of speed error
float KI_S = 3.0;                           // outer I: deg of setpoint per metre
const float SETPOINT_MAX = 3.0;             // the outer loop may lean the robot at most 3 deg
const float CUTOFF_DEG = 40.0;

volatile long leftCount = 0, rightCount = 0;
float pitch = 0, gyroBias = 0, setpoint = 0, integral = 0, speed = 0, targetSpeed = 0;
long lastPos = 0;
bool running = false;
unsigned int tick = 0;
unsigned long nextTick = 0, worstLoopUs = 0, lastReport = 0;

// If a wheel counts backwards when it rolls forward, swap that motor's A and B wires.
void leftEdge()  { leftCount  += digitalRead(ENC_LB) ? -1 : 1; }
void rightEdge() { rightCount += digitalRead(ENC_RB) ? -1 : 1; }

void setMotor(int pwmPin, int in1, int in2, int speed) {
  speed = constrain(speed, -255, 255);
  digitalWrite(in1, speed > 0);
  digitalWrite(in2, speed < 0);
  analogWrite(pwmPin, abs(speed));
}

void readImu(float &accelPitch, float &rate) {
  Wire.beginTransmission(MPU);
  Wire.write(0x3B);
  Wire.endTransmission(false);
  Wire.requestFrom(MPU, (uint8_t)14);
  int16_t v[7];
  for (int i = 0; i < 7; i++) v[i] = (Wire.read() << 8) | Wire.read();
  accelPitch = atan2(v[0] / ACCEL_LSB_PER_G, v[2] / ACCEL_LSB_PER_G) * 180.0 / PI;
  rate = v[5] / GYRO_LSB_PER_DPS - gyroBias;
}

void outerLoop() {                          // 25 Hz: wheel speed -> setpoint
  noInterrupts();
  long pos = (leftCount + rightCount) / 2;
  interrupts();
  speed = (pos - lastPos) * METERS_PER_COUNT / OUTER_DT;   // m/s
  lastPos = pos;
  float error = targetSpeed - speed;
  integral += error * OUTER_DT;
  float iMax = SETPOINT_MAX / KI_S;         // anti-windup: the I term alone stays within 3 deg
  integral = constrain(integral, -iMax, iMax);
  setpoint = constrain(KP_S * error + KI_S * integral, -SETPOINT_MAX, SETPOINT_MAX);
}

void setup() {
  int outs[] = {PWMA, AIN1, AIN2, PWMB, BIN1, BIN2, STBY};
  for (int p : outs) pinMode(p, OUTPUT);
  digitalWrite(STBY, HIGH);
  int ins[] = {ENC_LA, ENC_LB, ENC_RA, ENC_RB};
  for (int p : ins) pinMode(p, INPUT_PULLUP);
  attachInterrupt(digitalPinToInterrupt(ENC_LA), leftEdge, RISING);
  attachInterrupt(digitalPinToInterrupt(ENC_RA), rightEdge, RISING);
  Serial.begin(115200);
  Wire.begin();
  Wire.setClock(400000);
  Wire.beginTransmission(MPU);
  Wire.write(0x6B);
  Wire.write(0);
  Wire.endTransmission();

  float sum = 0, a, r;                      // gyro bias: hold still for one second
  for (int i = 0; i < 200; i++) { readImu(a, r); sum += r; delay(5); }
  gyroBias = sum / 200;
  readImu(a, r);
  pitch = a;
  Serial.print(F("gyro bias (deg/s): "));
  Serial.println(gyroBias, 2);
  nextTick = micros();
}

void loop() {
  if ((long)(micros() - nextTick) < 0) return;
  unsigned long start = micros();
  nextTick += PERIOD_US;

  float accelPitch, rate;
  readImu(accelPitch, rate);
  pitch = ALPHA * (pitch + rate * DT) + (1 - ALPHA) * accelPitch;

  if (fabs(pitch) > CUTOFF_DEG) running = false;
  if (!running && fabs(pitch) < 5.0) {      // stood back up: start both loops from zero
    running = true;
    integral = 0;
    setpoint = 0;
    noInterrupts();
    lastPos = (leftCount + rightCount) / 2;
    interrupts();
  }

  if (running) {
    if (++tick % OUTER_EVERY == 0) outerLoop();
    int out = (int)(KP * (pitch - setpoint) + KD * rate);
    setMotor(PWMA, AIN1, AIN2, out);
    setMotor(PWMB, BIN1, BIN2, out);
  } else {
    setMotor(PWMA, AIN1, AIN2, 0);
    setMotor(PWMB, BIN1, BIN2, 0);
  }

  unsigned long used = micros() - start;
  if (used > worstLoopUs) worstLoopUs = used;
  if (millis() - lastReport >= 1000) {
    lastReport = millis();
    Serial.print(F("pitch "));
    Serial.print(pitch, 1);
    Serial.print(F("  setpoint "));
    Serial.print(setpoint, 2);
    Serial.print(F("  speed "));
    Serial.print(speed, 3);
    Serial.print(F("  worst loop us "));
    Serial.println(worstLoopUs);
    worstLoopUs = 0;
  }
}
```

和 Month 2 相比，新增的部分是：

- 编码器中断只数 A 相的上升沿，再读 B 相判断方向；如果某个轮子向前滚时计数却在减小，把那个电机 A、B 两根线对调。
- `METERS_PER_COUNT` = π × 0.065 / (3 × 30) = 0.00227 m：12 CPR 的电机编码器（电机每转 3 个 A 相上升沿）配 30:1 减速箱和 65 mm 轮子。换电机就要改这个数。
- `outerLoop()` 每第 8 个 tick 跑一次（25 Hz）。读计数时短暂关中断，免得两个 long 读到一半被中断改掉；然后算 m/s，再做 PI：积分被限制在 3 / KI_S（这样光靠 I 项最多只能要求 3°），设定点限制在 ±3°。
- 机器人被扶正重新开始时，积分、设定点和位置基准都清零，免得旧的误差把它直接推倒。
- 外环增益 3 和 3 是保守的起点。模型喜欢 12 和 12，但你的机器人不是模型。

### 上真车调试

1. 先让内环自己平衡（第 2 个月），把你调好的 KP、KD 抄进来。外环先别开。
2. 把 KP_S 和 KI_S 设成 0。用手滚动机器人，看串口打印的速度：向前必须是正。轮子转一整圈是 π × 0.065 = 0.204 m；如果读数和你滚过的距离对不上，先查 `METERS_PER_COUNT` 和编码器接线。
3. 一点一点加 KP_S，再加 KI_S。把机器人拿在手里，你应该感觉到它顶着你的推力往回来——轮子想重新钻到身体下面。如果它往反方向倾，说明 KP_S 的符号错了。
4. 盯住串口里的设定点。如果它一直停在 +3.00 或 −3.00，说明外环饱和了：增益太大，或者速度符号反了。饱和的外环没有在控制，它只是在要求最大倾角。
5. 记录每一次尝试：内环增益、外环增益、设定点怎么动、车跑了多远、声音听起来怎样。

本站编者没有在真实机器人上跑过这套串级。把这些增益当成起点，不要当成结果。你的电机、轮子、编码器计数和 IMU 安装角度都会改变这些数字。

## 超前–滞后校正

PID 用固定的几样东西塑造回路：一个增益、一个积分器和一个带滤波的微分。**超前–滞后校正器**（lead–lag compensator）再加一样工具：一对零极点，放在需要相位或需要低频增益的地方。本节在同一个被控对象上比较本课的 PID 加与不加超前–滞后环节。它**不是** Smith 预估器，**不是**陷波滤波器，也**不是**第 5 个月的离散 LQR。

<Resource id="wiki-leadlag" />

**实际打开并读过正文的来源（HTML 正文）。** **Wikipedia — Lead–lag compensator：** 超前和滞后校正器都向开环传递函数里加一对零极点，`Y/X = (s − z)/(s − p)`；超前校正 `|z| < |p|`，滞后校正 `|z| > |p|`。超前–滞后校正把两者串起来，通常 `|p1| > |z1| > |z2| > |p2|`。超前部分在高频提供相位超前，把根轨迹往左推（响应更快、更稳定）；滞后部分减小稳态误差，它的零点和极点应当靠得很近、靠近原点。文中还提到，实现时更偏向用积分器，因为求导会放大噪声。以原文为准。

### 零点、极点与换来的相位

写成直流增益为 1 的形式，超前环节是 `(s/z + 1) / (s/p + 1)`，`z < p`。它的相位超前在 `ω = √(z·p)` 处最大，最大值 `φ` 决定了比值：

<Formula label="超前比">p / z = (1 + sin φ) / (1 − sin φ)</Formula>

**算例。** `φ = 30°` 时：`p / z = 1.5 / 0.5 = 3`。以穿越频率 `WC = 20 rad/s` 为中心：`z = 20 / √3 = 11.55 rad/s`，`p = 20 × √3 = 34.64 rad/s`。代价是高频增益：这个环节的增益从直流的 1 升到高频的 `p / z = 3`（+9.5 dB），所以传感器噪声和穿越频率以上的谐振都被放大到 3 倍。滞后环节 `z2 = 2 rad/s`、`p2 = 0.667 rad/s` 把低频增益提高到 3 倍，在 `WC` 处只付出 `atan(10) − atan(30) = −3.8°` 的相位。

### 公平设置

`lead_lag_vs_pid_toy.py` 是**合成**模型，只用标准库。**模型假设：** 线性时不变关节 `G(s) = 1 / (s (TM s + 1))`，`TM = 0.05 s`，后面串一个电机与被测连杆角之间的柔性传动模态 `wr² / (s² + 2 zr wr s + wr²)`（传感器与执行器不同位）；负载力矩加在被控对象输入端；**没有**执行器限幅，所以本节没有积分饱和，也不需要抗饱和；微分作用在误差上（不像本课前面那样作用在测量值上），各组共用一个 50 ms 的参考前置滤波，所以阶跃不会产生微分冲击；测量噪声是 0.5 mrad 的高斯噪声；设计者确切知道被控对象。

| 组 | 控制器（1 ms 采样，每一节都用 Tustin 离散化） |
|---|---|
| A_pid | `Kc × (1 + 1/(TI s) + TD s / (TD/N s + 1))`，`TI = 0.25 s`，`TD = 0.025 s`，`N = 8` |
| B_leadlag | A 的形状 × 超前（`φ = 30°`，以 `WC` 为中心）× 滞后（`z2 = WC/10`，`p2 = z2/3`） |
| C_swapped | 把 B 的超前环节零极点对调：在需要超前的地方放了一个滞后 |

**所有组、所有情形用同一套配方：** 形状固定（不针对被控对象重新整定），每组的 `Kc` 都选成在真实被控对象上 `|L(j·WC)| = 1`，所以各组共用同一个 20 rad/s 的穿越频率。**公共随机数：** 每个种子的三个参考阶跃、三个负载力矩阶跃和整段测量噪声只抽一次，送给每一组。5 个种子；指标是 ISE（经共用前置滤波后的跟踪误差平方积分，单位 10⁻³ rad²·s）、最差一次阶跃的超调（%）和 `du_rms`，即控制量相邻两次采样之差的均方根（执行器抖动）。相位裕度和幅值裕度是离散 Bode 的**代理**：Tustin 控制器 × 连续被控对象 × 半个采样周期的 ZOH 延迟，取所有穿越点中最小的裕度。**ISE 看不见**执行器抖动和幅值裕度，所以三者都打印出来。

**积分步长及其稳定性判据。** 被控对象在零阶保持下用 RK4 积分，`H = TS/4 = 0.25 ms`。对被控对象的一个模态 `λ`，RK4 稳定的条件是 `|R(H·λ)| ≤ 1`，`R(z) = 1 + z + z²/2 + z³/6 + z⁴/24`；在负实轴上就是 `H·|λ| < 2.785`。toy 打印被控对象各模态允许的最大稳定步长（刚性关节 139.3 ms，带柔性模态时 70.9 ms 和 73.5 ms），并用 assert 确认 `H` 远小于它；测试检查 0.98 倍和 1.02 倍处的边界，并确认 `H` 与 `H/2` 的结果相差在 10⁻⁶ 以内。**积分器稳定不等于回路稳定：** 闭环稳不稳由控制器决定，下面就有一组在积分器仍然准确的情况下闭环发散。

| 情形 | 柔性模态 |
|---|---|
| well_damped | 无（刚性关节） |
| resonant | `wr = 40 rad/s = 2·WC`，`zr = 0.3` |
| resonant_light | `wr = 40 rad/s`，`zr = 0.2` |

```python
#!/usr/bin/env python3
"""Synthetic PID vs PID + lead-lag on a joint with a compliant mode. Stdlib only.

Plant (linear, LTI, no actuator limit):
  G(s) = 1 / (s (TM s + 1)) * wr^2 / (s^2 + 2 zr wr s + wr^2)
  motor + inertia (TM = 0.05 s), then a compliant transmission mode (wr, zr) between
  motor and the measured link angle (non-collocated sensor). The rigid case drops
  the mode. Torque disturbance enters at the plant input.

Controllers (sampled at TS = 1 ms, every section discretised with Tustin):
  A_pid       Kc * (1 + 1/(TI s) + TD s / (TD/N s + 1))
  B_leadlag   A's shape * lead (s/z+1)/(s/p+1), |z| < |p|, centred on WC with
              PHI = 30 deg (p/z = (1+sin PHI)/(1-sin PHI)) * lag with |z2| > |p2|
              (z2 = WC/10, p2 = z2/3)
  C_swapped   B with the lead's pole and zero swapped (a lag where lead was needed)
  Same design rule for every arm: one fixed recipe (not tuned per regime), and Kc
  is chosen so |L(j WC)| = 1 on the actual plant, so all arms share crossover WC.

Common random numbers: per seed the three reference steps, three load-torque
steps and the measurement-noise sequence (sd 0.5 mrad) are drawn once and fed to
every arm. Integration: RK4 with H = TS/4 under zero-order-hold control. RK4 is
stable for a mode lambda when |R(H lambda)| <= 1, R(z) = 1+z+z^2/2+z^3/6+z^4/24;
the toy prints max |R| over the plant's non-zero modes and asserts it is < 1.

Labels: tie = identical on every seed; |paired mean| <= sd = near-tie / small gap
within seed noise; |m| > sd = consistent gap (small if |m| < 20 % of the smaller
arm mean, else clear), always with a sign count. Margins are a discrete Bode
proxy (Tustin controller x continuous plant x ZOH half-sample delay).
Real servo / motor bench: 本页未运行. Wikipedia definitions: 以原文为准.
"""
from __future__ import annotations

import cmath
import math
import random

TS = 1e-3  # s, controller sample time
SUB = 4  # RK4 sub-steps per sample
H = TS / SUB
TM = 0.05  # s, motor mechanical time constant
WC = 20.0  # rad/s, shared crossover target
TI, TD, N = 5.0 / WC, 0.5 / WC, 8.0
PHI = math.radians(30.0)
ALPHA = (1 + math.sin(PHI)) / (1 - math.sin(PHI))
BETA = 3.0
T_END = 6.0
NOISE = 5e-4  # rad, measurement noise sd
DIVERGED = 10.0  # rad, abort threshold (the references never exceed 3 rad)
SEEDS = (0, 1, 2, 3, 4)
ARMS = ("A_pid", "B_leadlag", "C_swapped")
# name, wr (0 = rigid), zr
REGIMES = (("well_damped", 0.0, 0.0), ("resonant", 40.0, 0.3), ("resonant_light", 40.0, 0.2))


def sections(arm: str) -> list[tuple[float, float]]:
    """(zero, pole) pairs of the first-order sections cascaded after the PID."""
    if arm == "A_pid":
        return []
    z, p = WC / math.sqrt(ALPHA), WC * math.sqrt(ALPHA)
    if arm == "C_swapped":
        z, p = p, z
    return [(z, p), (WC / 10.0, WC / 10.0 / BETA)]


def plant(w: float, wr: float, zr: float) -> complex:
    s = 1j * w
    g = 1.0 / (s * (TM * s + 1.0))
    return g * wr * wr / (s * s + 2 * zr * wr * s + wr * wr) if wr else g


def shape(arm: str, w: float) -> complex:
    s = 1j * w
    c = 1.0 + 1.0 / (TI * s) + TD * s / (TD / N * s + 1.0)
    for z, p in sections(arm):
        c *= (s / z + 1.0) / (s / p + 1.0)
    return c


def gain(arm: str, wr: float, zr: float) -> float:
    return 1.0 / abs(shape(arm, WC) * plant(WC, wr, zr))


def margins(arm: str, wr: float, zr: float) -> tuple[float, float]:
    """Smallest phase margin over all |L| = 1 crossings and smallest gain margin
    (dB) over -180 deg crossings with |L| < 1; unwrapped phase from 0.1 rad/s."""
    k = gain(arm, wr, zr)
    pms, gms = [], []
    prev = None
    off = 0.0
    n = 20000
    for i in range(n + 1):
        w = 10 ** (-1 + i * (math.log10(math.pi / TS) + 1) / n)
        loop = k * shape(arm, w) * plant(w, wr, zr) * cmath.exp(-0.5j * w * TS)
        mag, ph = abs(loop), math.degrees(cmath.phase(loop))
        if prev is None:
            while ph > -90.0:
                ph -= 360.0
            off = ph - math.degrees(cmath.phase(loop))
        else:
            ph += off
            while ph - prev[1] > 180.0:
                ph -= 360.0
                off -= 360.0
            while ph - prev[1] < -180.0:
                ph += 360.0
                off += 360.0
            if (prev[0] - 1.0) * (mag - 1.0) < 0:
                pms.append(180.0 + ph)
            for line in (-180.0, -540.0):
                if (prev[1] - line) * (ph - line) < 0 and mag < 1.0:
                    gms.append(-20 * math.log10(mag))
        prev = (mag, ph)
    return min(pms), (min(gms) if gms else math.inf)


class Controller:
    """PI (trapezoid) + filtered D (Tustin), then Tustin first-order sections."""

    def __init__(self, arm: str, k: float) -> None:
        c = 2.0 / TS
        self.k, self.i, self.e_prev, self.d = k, 0.0, 0.0, 0.0
        tf = TD / N
        self.db0, self.da1 = TD * c / (tf * c + 1.0), (1.0 - tf * c) / (tf * c + 1.0)
        self.secs = []
        for z, p in sections(arm):
            a0 = c / p + 1.0
            self.secs.append([(c / z + 1.0) / a0, (1.0 - c / z) / a0, (1.0 - c / p) / a0, 0.0, 0.0])

    def step(self, e: float) -> float:
        self.i += TS / TI * (e + self.e_prev) / 2.0
        self.d = self.db0 * (e - self.e_prev) - self.da1 * self.d
        self.e_prev = e
        x = e + self.i + self.d
        for sec in self.secs:
            b0, b1, a1, xp, yp = sec
            y = b0 * x + b1 * xp - a1 * yp
            sec[3], sec[4] = x, y
            x = y
        return self.k * x


def deriv(x: list[float], u: float, wr: float, zr: float) -> list[float]:
    v, th, y, yd = x
    if not wr:
        return [(u - v) / TM, v, v, 0.0]
    return [(u - v) / TM, v, yd, wr * wr * (th - y) - 2 * zr * wr * yd]


def rk4(x: list[float], u: float, wr: float, zr: float, h: float = H) -> list[float]:
    k1 = deriv(x, u, wr, zr)
    k2 = deriv([a + h / 2 * b for a, b in zip(x, k1)], u, wr, zr)
    k3 = deriv([a + h / 2 * b for a, b in zip(x, k2)], u, wr, zr)
    k4 = deriv([a + h * b for a, b in zip(x, k3)], u, wr, zr)
    return [a + h / 6 * (b + 2 * c + 2 * d + e) for a, b, c, d, e in zip(x, k1, k2, k3, k4)]


def rk4_amp(z: complex) -> float:
    return abs(1 + z + z * z / 2 + z ** 3 / 6 + z ** 4 / 24)


def rk4_h_max(lam: complex) -> float:
    """Largest step with |R(h lambda)| <= 1 along this mode (bisection)."""
    lo, hi = 0.0, 10.0 / abs(lam)
    for _ in range(60):
        mid = (lo + hi) / 2
        lo, hi = (mid, hi) if rk4_amp(mid * lam) <= 1.0 else (lo, mid)
    return lo


def modes(wr: float, zr: float) -> list[complex]:
    out = [complex(-1.0 / TM)]
    if wr:
        out += [complex(-zr * wr, s * wr * math.sqrt(1 - zr * zr)) for s in (1, -1)]
    return out


def shared_draws(seed: int) -> tuple[list, list, list]:
    """Common random numbers: one draw per seed, fed to every arm and regime."""
    rng = random.Random(seed)
    steps = [(0.2 + 2.0 * i, rng.choice((-1.0, 1.0)) * rng.uniform(0.2, 1.0)) for i in range(3)]
    loads = [(1.2 + 2.0 * i, 0.3 * rng.uniform(-1.0, 1.0)) for i in range(3)]
    noise = [rng.gauss(0.0, NOISE) for _ in range(round(T_END / TS))]
    return steps, loads, noise


def simulate(arm: str, wr: float, zr: float, draws: tuple, sub: int = SUB) -> dict | None:
    steps, loads, noise = draws
    ctrl = Controller(arm, gain(arm, wr, zr))
    x, rf, u_prev = [0.0] * 4, 0.0, 0.0
    ise = du2 = 0.0
    over = [0.0] * len(steps)
    for i, nz in enumerate(noise):
        t = i * TS
        r = sum(a for t0, a in steps if t >= t0)
        rf += TS / 0.05 * (r - rf)  # shared reference prefilter, 50 ms
        u = ctrl.step(rf - (x[2] + nz))
        d = sum(a for t0, a in loads if t >= t0)
        for _ in range(sub):
            x = rk4(x, u + d, wr, zr, TS / sub)
        if abs(x[2]) > DIVERGED:
            return None
        ise += (rf - x[2]) ** 2 * TS
        du2 += (u - u_prev) ** 2
        u_prev = u
        for j, (t0, a) in enumerate(steps):
            if t0 <= t < t0 + 1.0:
                over[j] = max(over[j], math.copysign(1.0, a) * (x[2] - r) / abs(a))
    return {"ise": 1e3 * ise, "over": 100.0 * max(over), "du": math.sqrt(du2 / len(noise))}


def mean_sd(xs: list[float]) -> tuple[float, float]:
    mu = sum(xs) / len(xs)
    return mu, math.sqrt(sum((x - mu) ** 2 for x in xs) / (len(xs) - 1))


def sign_note(diffs: list[float], m: float) -> str:
    """How many seeds disagree in sign with the paired mean (zeros listed apart)."""
    n, opp, zero = len(diffs), sum(1 for d in diffs if d * m < 0), sum(1 for d in diffs if d == 0)
    if opp == 0 and zero == 0:
        return f"same sign on all {n} seeds"
    note = f"{opp} of {n} seeds {'has' if opp == 1 else 'have'} the opposite sign"
    return note + (f", {zero} of {n} equal" if zero else "")


def fmt_pair(m: float, s: float) -> str:
    """Paired mean+-sd; extra decimals when 4 would print a signed zero such as -0.0000."""
    if m != 0.0 and abs(m) < 5e-5:
        return f"{m:.6f}+-{s:.6f}"
    return f"{m:.4f}+-{s:.4f}"


def verdict(xa: list[float], xb: list[float]) -> str:
    """Paired xa - xb per seed: mean+-sd, then the label and the sign count."""
    diffs = [a - b for a, b in zip(xa, xb)]
    if all(d == 0.0 for d in diffs):
        return "0.0000+-0.0000: tie: identical on every seed"
    m, s = mean_sd(diffs)
    if abs(m) <= s:
        label = "near-tie / small gap, within seed noise (|m| <= sd)"
    elif abs(m) < 0.2 * min(mean_sd(xa)[0], mean_sd(xb)[0]):
        label = "small but consistent gap, not a tie (|m| > sd)"
    else:
        label = "clear gap, not a tie (|m| > sd)"
    return f"{fmt_pair(m, s)}: {label}; {sign_note(diffs, m)}"
```
