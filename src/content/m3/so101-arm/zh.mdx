## 为什么是 SO-101

这是 Month 3 的压轴课：经过前四课的 CAD、3D 打印、减速器和控制环，这一课要把零件变成一台机器人。SO-101 是 TheRobotStudio 与 Hugging Face 开源的一台机械臂，采用 Apache-2.0 许可。它有 5 个<Term id="degrees-of-freedom">自由度</Term>（degrees of freedom），外加一个夹爪，由 6 个小体积<Term id="bus-servo">总线舵机</Term>（bus servo）驱动；设计上是一对<Term id="leader-follower">主臂（leader）与从臂（follower）</Term>：你用手扳动主臂，从臂跟着复制动作。5 个自由度指的是给工具端定位的轴：底座水平转、肩部抬升、肘部弯曲，再加上腕部的俯仰与翻转。夹爪是第 6 个电机，但不是定位轴，它负责抓住手臂够到的东西。从臂是干活的那台，主臂是输入设备；两者机械结构相近，差别在于主臂按“给人推”来选减速比。课程的购买指南把它排在整条学习路线所有硬件采购的第一位，而这一课正是要让这个排名站得住脚。

这种复制叫<Term id="teleoperation">遥操作</Term>（teleoperation），它是录制演示数据的手段，不是演示花招。用手移动主臂、让从臂重复，正是录制演示数据的方式：主臂给出动作，从臂给出机器人自己的关节读数，两者合起来就是 Month 6 要用的数据。这台臂是 Month 5 和 Month 6 的平台，Month 6 就用它录制演示数据。它不是一次性项目，所以现在把组装做干净、把校准做准确，后面都会省回来。

关于核实情况的说明：本站编者没有组装或运行过 SO-101。下面的步骤依据官方 LeRobot SO-101 文档（v0.6.x，2026 年 10 月核对）。命令行工具在不同版本之间会变，动手前请回原文档再核对一遍；如果本课和当前文档冲突，以文档为准。

官方仓库里的物料清单（BOM）：主从一对 $229.88，单个从臂 $121.94，不含打印件。打印件不是小开销：仓库要求 PLA+、15 % 填充、0.2 mm 层高、0.4 mm 喷嘴，正好是第 2 课《3D 打印：材料、校准与公差》材料表里那种 PLA+ 活。整套大约 1 kg 耗材，下一节比较路线时这个数要算进去。这个数是本课的**估计值**，不是仓库公布的数字。给一个上限：钉住版本中两条臂打印件的整板 STL 文件 Prusa_Follower_SO101.stl 和 Prusa_Leader_SO101.stl（Bambu Lab A1 mini 整板体积相同；Ender 从臂整板为 571.3 cm³）实体体积分别是 571.4 cm³ 和 614.6 cm³，合计 571.4 + 614.6 = 1186.0 cm³，按 PLA 的 1.24 g/cm³（[Prusament PLA 数据表](https://prusament.com/wp-content/uploads/2022/10/PLA_Prusament_TDS_2021_10_EN.pdf)）计算，所有零件全实心打印约为 1.47 kg。15 % 填充时每个零件内部大部分是空的，实际用量远低于这个上限；切片软件会按你的设置给出用量，以那个数为准。

仓库和 LeRobot 使用同一套关节名与电机 ID。现在就记住，因为后面每条命令、每次校准都会用到：

- **1 `shoulder_pan`**：让整条臂绕底座左右转。
- **2 `shoulder_lift`**：抬起、放下大臂，它承担机械臂自身的大部分重量。
- **3 `elbow_flex`**：在肘部弯曲小臂。
- **4 `wrist_flex`**：让手腕上下俯仰。
- **5 `wrist_roll`**：让小臂轴线上的手腕翻转。
- **6 `gripper`**：张开、闭合两根手指。

编号从底座往工具端走，接线方向却相反：串行线从夹爪一路<Term id="daisy-chain">菊花链</Term>回底座，shoulder_pan（ID 1）插在控制板上。组装时记住这张图，就能理解为什么设置脚本从夹爪开始、一路往底座退。

## 选你的路线

买 SO-101 没有唯一正确路线，因为最贵的部分不一定是钱。仿真给你完整的软件路径，但没有手感；便宜的连杆臂教你机械，却不教本课要用的总线协议；单个从臂是真硬件，却不能录主从演示。下表列出课程考虑的几条路。价格是各商店页面上的价格，2026-10-23 核实；价格都会变，下单前请自己确认。

## 总线舵机与数据包

第 2 个月用过的业余（hobby）舵机吃一根 PWM 脉冲，转到一个角度就完了。它没有总线上的名字，没法说“我在这里”，也没法回报自己在干什么。SO-101 每臂用 6 个飞特 STS3215 总线舵机，每一个都是小型的闭环执行器：有 ID，有 12 位磁编码器（magnetic encoder，每圈 4096 步），壳子里还有自己的位置环（position loop）。这个位置环就是第 4 课《PID 与控制：积分饱和与串级回路》里 PID 的同一套思想，只不过它跑在舵机里，不在你的单片机上：你发一个目标，舵机驱动电机，直到编码器说到了。4096 步是编码器的分辨率，不是整条臂的精度：减速器回差、舵机盘安装误差和打印件柔性，都会在编码器之后继续叠加误差。

6 个舵机共享一条<Term id="half-duplex">半双工</Term>（half-duplex）串行线，电机与电机菊花链相连；LeRobot 把这条线跑在 1 Mbit/s。半双工意味着一对线要双向传，但不能同时：发送时线路由发送端驱动，接收端同时读不出数据，所以控制器发完一帧必须转为接收，等应答回来。每个包里带 ID，用来在总线上寻址对应的那一个舵机；<Term id="checksum">校验和</Term>（checksum）则是为了防住那种“只错了一个比特，却让关节冲向错误位置”的情况。每个舵机都能听到每个数据包，只有 ID 对上的那个才回答。还可以向舵机读取位置、速度、负载、电压和温度，所以总线舵机能告诉你它在使劲或发热，而不是默默堵转。

舵机有不同的减速比，两条臂用的不是同一组。从臂 6 个关节全是 1/345；主臂混用，好让它在该撑住的地方撑住，其余地方又容易被手扳动：

| 关节 | 主臂减速比 |
| --- | --- |
| shoulder_pan | 1/191 |
| shoulder_lift | 1/345 |
| elbow_flex | 1/191 |
| wrist_flex | 1/147 |
| wrist_roll | 1/147 |
| gripper | 1/147 |

这就是第 3 课《传动与回差：齿轮、皮带与轴承》反驱（backdriving）算术的硬件版。经过减速比 n，你在输出端感到的摩擦按 n 放大，<Term id="moment-of-inertia">转子惯量</Term>按 n² 放大。拿腕部的 1/147 和从臂的 1/345 比：345 / 147 = 2.35，所以从臂的 1/345 关节摩擦感约为 2.35 倍，转子惯量感为 (345/147)² ≈ 5.51 倍。主臂腕部因此轻得多；shoulder_lift 保留 1/345，是因为那个关节要托住整条臂。主臂不是更弱的臂，它的减速比是按人手拖动的操作方式选的。

这三种减速比对应飞特的三个料号，BOM 里单价都是 $13.89：C001 是 1/345，C044 是 1/191，C046 是 1/147。README 链接的主臂套装是 3 × C046、2 × C044、1 × C001，所以一对里的 7 个 C001 就是从臂的 6 个加上主臂 shoulder_lift 的 1 个。这些舵机外观一样。按卖家为每一袋标明的料号来辨认，每个舵机在装进它的关节之前都留在原袋里；本课没有核实舵机本身的标签上印了什么。如果只查一个，就查 shoulder_lift：它承受的重力矩最大，因为它要托起它之后的全部结构，所以两条臂上它都必须是 C001。

舵机自己的规格也给关节能定位到多准设了下限。有两个数：编码器的一步，以及齿轮回差（齿与齿之间的空隙）。角度误差换算到工具处的位置误差，等于半径乘以弧度表示的角度：

```text
encoder resolution (C001 spec, 7-8):  360 / 4096 = 0.088 deg per step
gear backlash (C001 and C018 spec, 6-11):  <= 0.5 deg
at an example radius of 200 mm from the joint axis:
  one step:  200 x 0.088 x pi / 180 = 0.31 mm
  backlash:  200 x 0.5   x pi / 180 = 1.75 mm
```

200 mm 只是示例半径，不是 SO-101 的实际臂展；请用你的关节到工具的距离。回差这一项大约是编码器一步的 6 倍，而且它是数据表给的上限，不是实测值。打印连杆的弯曲会叠加到这两项上，必须在你自己的臂上实测，例如用已知的力推工具，读出它移动了多少。

线上协议简单到可以用眼睛读。每条消息都是一个数据包：

```text
0xFF 0xFF  ID  LENGTH  INSTRUCTION  PARAMS...  CHECKSUM
LENGTH = 参数个数 + 2
CHECKSUM = ~(ID + LENGTH + INSTRUCTION + PARAMS) & 0xFF   （和的低字节取反）
两字节的值按小端序（低字节在前）
```

本课用到的寄存器来自 LeRobot 使用的 STS 控制表：Torque_Enable 40、Goal_Position 42、Present_Position 56。Torque_Enable 是一字节；两个位置寄存器各两字节，这里就用得上<Term id="little-endian">小端序</Term>（little-endian）。下面的程序手工构造数据包并校验一个回复。它是电脑上的普通 Python 程序，不是仿真，也没接舵机：只打印字节。

<CodeSource path="examples/month-3/so101-arm/sts_packet.py" />

```python
"""sts_packet.py: build and check Feetech STS3215 bus-servo packets by hand.

The SO-101 arm's six STS3215 servos share one serial wire (half duplex, 1 Mbit/s in LeRobot).
Every message is a packet:
    0xFF 0xFF  ID  LENGTH  INSTRUCTION  PARAMS...  CHECKSUM
LENGTH = number of params + 2, CHECKSUM = ~(ID + LENGTH + INSTRUCTION + PARAMS) & 0xFF.
A servo answers with  0xFF 0xFF ID LENGTH ERROR PARAMS... CHECKSUM.
Two-byte values are little-endian (low byte first). Register addresses are from the STS
control table used by LeRobot: Torque_Enable 40, Goal_Position 42, Present_Position 56.
No hardware needed: this only prints bytes.
"""
PING, READ, WRITE = 0x01, 0x02, 0x03
TORQUE_ENABLE, GOAL_POSITION, PRESENT_POSITION = 40, 42, 56
STEPS_PER_TURN = 4096                       # 12-bit magnetic encoder


def checksum(body):
    return ~sum(body) & 0xFF


def packet(servo_id, instruction, params=()):
    body = [servo_id, len(params) + 2, instruction, *params]
    return bytes([0xFF, 0xFF, *body, checksum(body)])


def hexs(data):
    return " ".join(f"{b:02X}" for b in data)


def parse_status(data):
    """Check a reply and return (id, error byte, params)."""
    if data[:2] != b"\xff\xff":
        raise ValueError("no 0xFF 0xFF header")
    servo_id, length, error = data[2], data[3], data[4]
    params = data[5:5 + length - 2]
    if checksum(data[2:5 + length - 2]) != data[5 + length - 2]:
        raise ValueError("bad checksum: the bytes were corrupted on the wire")
    return servo_id, error, params


if __name__ == "__main__":
    goal = 2048                                     # half a turn = the middle of the range
    print(f"{'ping servo 1:':32s}", hexs(packet(1, PING)))
    print(f"{'torque on, servo 1:':32s}", hexs(packet(1, WRITE, [TORQUE_ENABLE, 1])))
    print(f"{'goal position 2048, servo 1:':32s}", hexs(packet(1, WRITE, [GOAL_POSITION, goal & 0xFF, goal >> 8])))
    print(f"{'read present position, servo 6:':32s}", hexs(packet(6, READ, [PRESENT_POSITION, 2])))

    reply = bytes([0xFF, 0xFF, 0x06, 0x04, 0x00, 0x2C, 0x0C])   # a made-up answer from servo 6
    reply += bytes([checksum(reply[2:])])
    sid, err, params = parse_status(reply)
    steps = params[0] | params[1] << 8
    print(f"reply {hexs(reply)} -> servo {sid}, error {err}, position {steps} "
          f"= {steps * 360 / STEPS_PER_TURN:.1f} deg")
    broken = reply[:-2] + bytes([reply[-2] ^ 0x01]) + reply[-1:]  # flip one bit on the wire
    try:
        parse_status(broken)
    except ValueError as e:
        print(f"reply {hexs(broken)} -> {e}")
```

真实输出：

```text
$ python3 sts_packet.py
ping servo 1:                    FF FF 01 02 01 FB
torque on, servo 1:              FF FF 01 04 03 28 01 CE
goal position 2048, servo 1:     FF FF 01 05 03 2A 00 08 C4
read present position, servo 6:  FF FF 06 04 02 38 02 B9
reply FF FF 06 04 00 2C 0C BD -> servo 6, error 0, position 3116 = 273.9 deg
reply FF FF 06 04 00 2C 0D BD -> bad checksum: the bytes were corrupted on the wire
```

<Diagram id="sts-packet-fields" />

先走前四行。ping 发给 1 号舵机，不带参数，所以 LENGTH = 2（指令加校验和），校验和 = ~(1 + 2 + 1) & 0xFF = 0xFB。扭矩使能包有两个参数：寄存器地址 40 和值 1，所以 LENGTH = 4，校验和 = ~(1 + 4 + 3 + 40 + 1) & 0xFF = ~49 & 0xFF = 0xCE。目标位置包有三个参数：地址 42，以及 2048 的低字节和高字节。读位置包向 6 号舵机要寄存器 56 起的两个字节。

目标位置包的校验和，手算一遍：

```text
ID 01 + LENGTH 05 + WRITE 03 + 地址 2A + 低字节 00 + 高字节 08 = 0x3B（十进制 1 + 5 + 3 + 42 + 0 + 8 = 59）
取反：0xFF − 0x3B = 0xC4 → 与最后一个字节一致
2048 = 0x0800 → 低字节 00，高字节 08
回复参数 2C 0C → 0x0C2C = 3116 步 → 3116 × 360 / 4096 = 273.9°
```

<strong>动手实验。</strong>本实验展示 STS3215 数据包如何编码 ID、指令与参数，以及校验和如何检测传输中出错的字节。

1. 选择 goal 数据包，将舵机 ID 设为 1、目标位置设为 2048，读取数据包字节 = FF FF 01 05 03 2A 00 08 C4。
2. 将目标位置设为 1024，读取数据包字节 = FF FF 01 05 03 2A 00 04 C8（0x0400 小端 = 00 04；校验和 = ~(和) 的低字节）。
3. 将舵机 ID 设为 2、目标位置设为 2048，读取数据包字节 = FF FF 02 05 03 2A 00 08 C3。
4. 将回复 FF FF 06 04 00 2C 0C BD 粘贴到回复输入框，读取解析后的回复“舵机 6，错误 0，位置 3116 = 273.9°”。
5. 将回复中的 0C 改为 0D，读取“校验和不对：字节在传输中出错”。结论：校验和 = 0xFF − (ID…最后一个参数之和 & 0xFF)；翻转一位就会不匹配。

回复行也按同样方式解。LENGTH 是 4，因为除了校验和，还有两个数据字节和一个错误字节。错误字节为 0，说明舵机没有报告错误。参数 2C 0C 是小端序：0x0C2C = 3116，3116 / 4096 圈就是 273.9°。最后一行把高位数据字节的一个比特翻转，0C 变成 0D，校验和在有人把 0x0D2C 当成真实位置之前就抓住了它。校验和的意义正在于此：它不修复消息，它拒绝消息。

飞特自己的 Python SDK 可以交叉验证这套手算。装好 SDK（`pip install feetech-servo-sdk`）之后，下一个程序把同样的四个包写进一个假串口，再和 `sts_packet.py` 的字节比较。同样没有舵机；假串口只是把 SDK 本来要发的东西记下来。

<CodeSource path="examples/month-3/so101-arm/compare_sdk.py" />

```python
"""compare_sdk.py: check sts_packet.py against Feetech's own Python SDK, no servo needed.

The SDK writes its packets to a fake serial port that just records the bytes.
Needs:  pip install feetech-servo-sdk   (tested with 1.0.0; it also installs pyserial)
"""
import scservo_sdk as scs

import sts_packet as mine


class FakePort:
    """Just enough of scservo_sdk.PortHandler for the SDK to send a packet."""
    is_using = False
    baudrate = 1_000_000

    def __init__(self):
        self.sent = b""

    def clearPort(self):
        pass

    def setPacketTimeout(self, length):
        pass

    def writePort(self, packet):
        self.sent = bytes(packet)
        return len(packet)


def sent_by_sdk(call):
    port = FakePort()
    call(scs.PacketHandler(0), port)          # 0 = STS byte order (little-endian)
    return port.sent


cases = [
    ("ping 1", lambda h, p: h.txPacket(p, [0, 0, 1, 2, scs.INST_PING, 0]), mine.packet(1, mine.PING)),
    ("torque on 1", lambda h, p: h.write1ByteTxOnly(p, 1, 40, 1), mine.packet(1, mine.WRITE, [40, 1])),
    ("goal 2048 on 1", lambda h, p: h.write2ByteTxOnly(p, 1, 42, 2048), mine.packet(1, mine.WRITE, [42, 0x00, 0x08])),
    ("read position 6", lambda h, p: h.readTx(p, 6, 56, 2), mine.packet(6, mine.READ, [56, 2])),
]
for name, call, expected in cases:
    got = sent_by_sdk(call)
    print(f"{name:16s} SDK {mine.hexs(got):27s} {'same' if got == expected else 'DIFFERENT'}")
```

真实输出：

```text
$ pip install feetech-servo-sdk
$ python3 compare_sdk.py
ping 1           SDK FF FF 01 02 01 FB           same
torque on 1      SDK FF FF 01 04 03 28 01 CE     same
goal 2048 on 1   SDK FF FF 01 05 03 2A 00 08 C4  same
read position 6  SDK FF FF 06 04 02 38 02 B9     same
```

每一行都是 `same`。飞特 SDK 写进假串口的字节，和手工构造的完全一致，说明长度字段和校验和都对。LeRobot 底层用的就是这个 SDK，所以通过 LeRobot 发出的包也是同样的形状。用机械臂时你永远不需要手搓数据包，但当某个舵机突然不说话时，知道线上“应该”是什么，才能判断问题出在供电、接线、ID 还是数据损坏。

## 供电

供电是最容易因选错而损坏硬件的一步，电源电压必须与舵机版本匹配。标准 SO-101 使用 5 V 电源（来源 A），而 5 V 落在飞特为 7.4 V 版 STS3215 规定的 4 V–7.4 V 输入电压范围之内（来源 B）。在 5 V 下，扭矩会略低于按 6 V 给出的 16.5 kg·cm（来源 A）。可选的 12 V 版从臂舵机必须改用 12 V、5 A 及以上的电源，而不是 5 V 电源（来源 A）；主臂始终使用 7.4 V 版舵机（来源 A）。

| 机械臂 / 舵机版本 | Feetech 型号 | 输入电压范围（Feetech） | SO-ARM100 README 的供电 | 堵转扭矩（Feetech） |
| --- | --- | --- | --- | --- |
| 从臂，标准 7.4 V | ST-3215-C001 | 4–7.4 V | 5 V | 16.5 kg·cm @ 6 V，19.5 kg·cm @ 7.4 V |
| 从臂，可选 12 V | ST-3215-C018 | 4–14 V | 12 V，≥ 5 A | 30 kg·cm @ 12 V |
| 主臂（始终 7.4 V） | 7.4 V STS3215（按 README BOM 为 C001/C044/C046） | 4–7.4 V（C001 规格） | 5 V | — |

<Callout type="danger" title="12 V 电源只能接 12 V 版舵机">
绝不要把 12 V 电源接到装有 7.4 V 舵机的机械臂上；主臂在任何情况下都属于这一类。12 V 远高于 Feetech 对 7.4 V 版给出的 4–7.4 V 输入范围。插电前，先对照舵机标签上的电压和电源铭牌上的额定值；7.4 V 舵机和 12 V 舵机应分臂、分电源使用，因为同一条臂的所有舵机通过菊花链共用同一路电源。
</Callout>

来源：A — [SO-ARM100 README · Sourcing Parts (IMPORTANT note)](https://github.com/TheRobotStudio/SO-ARM100/blob/a758567c3978dfeefe282ede0500085a48fe8f78/README.md#L72-L73)；B — [Feetech STS3215 (C001) specification, §5](https://www.feetechrc.com/Data/feetechrc/upload/file/20200611/6372749961523760249976542.pdf)；C — [Feetech ST-3215-C018 product page](https://www.feetechrc.com/en/525603.html) 与 [specification, §5](https://www.feetechrc.com/Data/feetechrc/upload/file/20240507/6385067068652648096680943.pdf)。

电源还必须给得出足够的电流。按规格把六个舵机的电流加起来：

```text
12 V 从臂，六个 ST-3215-C018（C018 规格书 5-9 和 5-5）：
  额定   6 x 0.9 A = 5.4 A
  堵转   6 x 2.7 A = 16.2 A
5 V 从臂，六个 ST-3215-C001（C001 规格书 5-9 和 5-5，均为 6 V 下的数据）：
  额定   6 x 0.5 A = 3.0 A
  堵转   6 x 2.0 A = 12.0 A
```

README 要求 12 V 电源至少 5 A；六个 C018 在额定电流下已经要 5.4 A，所以 12 V 电源要选额定值高于 5.4 A 的。堵转数字是最坏情况——所有关节同时被卡住——而且不会持续：两份规格都写明，运行电流大于 2 A 并持续 2 s 后，舵机关闭输出并进入过流保护（§7-11）。标准臂这边，飞特给出的 C001 额定电流是 6 V 下的，不是 5 V 下的，所以 3.0 A 的总数是估计值；它在 BOM 所链接 5 V 电源（Facmogu AL-0540，5 V 4 A）的 4 A 额定值之内。堵转就放不下了。C001 的堵转电流在 6 V 下是 2 A、7.4 V 下是 2.5 A（§5-5），所以六个关节同时卡住约需 6 × 2 A = 12 A（按 6 V 数据估计），是 AL-0540 的 4 A 的三倍。这里也不能指望过流保护：5 V 下每个 C001 的堵转电流 ≤ 5 V / 2.5 Ω ≈ 2.0 A（由 §5-10 的端子电阻 2.5 Ω 估算，规格书未给 5 V 数据）。作为上限，这与规格书一致：6 V 下 §5-5 的堵转电流 2 A 小于 6 V / 2.5 Ω = 2.4 A。所以“大于 2 A 并持续 2 s”的条件可能根本不会满足。真正起作用的是同一张表里紧挨着的过载（Over Load）保护：堵转超过堵转值的 80 % 并持续 2 s 后进入保护（§7-11）。80 % / 2 s 和 2 A / 2 s 这两个门限都是出厂默认值，但飞特的资料在电流上并不一致：C001 规格书给的是 2 A / 2 s（§7-11），飞特的[在线 STS 存储表](https://ftservo.github.io/ftservo-wiki/en/reference/parameter/memory-sts/)里 Protection_Current（地址 28，单位 6.5 mA）的默认值是 511，即 511 × 6.5 mA ≈ 3.32 A（不过它的说明里又写最大可设 500 × 6.5 mA = 3250 mA），而第三方转载的 2019 年表格（V3.6，固件 2.43；[matthieuvigne/STS_servos 里的 STS3215 Memory Table.xlsx](https://github.com/matthieuvigne/STS_servos/blob/4d2278432a2b12027d04d0449e1e6f97df812d68/extras/STS3215%20Memory%20Table.xlsx)）写的是 500，即 500 × 6.5 mA = 3.25 A；想知道你的舵机是哪个值，可以自己读 28 号寄存器。过载这一侧是一致的：两份表里 Overload_Torque（地址 36，单位 1 %）都默认 80，保护时间（地址 35，单位 10 ms）都默认 200 × 10 ms = 2 s。夹爪是例外：LeRobot 配置 SO 从臂时，只给夹爪舵机写入 Max_Torque_Limit 500、Protection_Current 250 和 Overload_Torque 25（[so_follower.py 第 169–171 行，LeRobot v0.6.1](https://github.com/huggingface/lerobot/blob/v0.6.1/src/lerobot/robots/so_follower/so_follower.py#L169-L171)）。按两份表，Max_Torque_Limit（地址 16）的单位是 0.1 %，所以 500 是最大扭矩的 50 %；Protection_Current（地址 28）的单位是 6.5 mA，所以 250 是 250 × 6.5 mA = 1.625 A；Overload_Torque（地址 36）是启动过载计时的负载门限，所以夹爪的负载一旦超过最大扭矩的 25 %（飞特没有说明是相对地址 16 的设定值还是满堵转扭矩；堵转时两种理解下都会超过）并持续 2 s，就进入保护。进入保护后输出的扭矩由另一个寄存器 Protective_Torque（地址 34，默认 20 %）决定，LeRobot 没有写它；LeRobot 的代码注释把 Overload_Torque 说成过载时的扭矩，这与飞特的表不符。在线存储表把扭矩限制（地址 16 和 48）和 Present_Load（地址 60）的单位都定为 0.1 %，并把地址 60 定义为驱动电机输出的占空比，所以 50 % 的扭矩限制一旦在上电后生效，也会把夹爪的驱动占空比限制在一半左右。

不过按两份表，真正生效的扭矩限制是地址 48，它只在上电时从地址 16 载入；而 LeRobot v0.6.1 只写地址 16（从不写地址 48），也不重启舵机，所以 50 % 的限制要从舵机下一次上电起才生效；开放中的 [LeRobot PR #4783](https://github.com/huggingface/lerobot/pull/4783) 的作者也写道，改过的值“may need a power cycle to apply”（可能要断电重启才生效），但他没有在硬件上验证过。限制生效后，夹爪堵转时电流约为 0.5 × 5 V / 2.5 Ω ≈ 1.0 A，低于 1.625 A 的保护电流，所以预计过载保护（负载超过 25 % 并持续 2 s）会先动作。在此之前（例如 LeRobot 配置舵机后的第一次使用），夹爪仍可能以满占空比驱动，最高约 5 V / 2.5 Ω ≈ 2.0 A，高于 1.625 A；过载条件也同样满足，而两个计时的默认值都是 2 s（Protection_Time，地址 35；Over_Current_Protection_Time，地址 38；都是 200 × 10 ms），所以哪个保护先动作并不确定。即使 28、36 号寄存器也要上电后才生效，满占空比堵转仍会超过出厂的 80 % 过载门限。飞特没有公开固件实现，所以这些都只是估计。

两份规格书还写明，重新发位置指令会清除过载和过流保护标志（§7-11），而 LeRobot 每次 send_action() 都会发送 Goal_Position（[so_follower.py 第 229 行](https://github.com/huggingface/lerobot/blob/v0.6.1/src/lerobot/robots/so_follower/so_follower.py#L229)），所以遥操作时下一条指令就会清除保护标志（规格书没有说明重发相同的目标位置是否算新指令）；不能指望保护长期护住舵机，仍应避免让夹爪长时间堵转。两份表都针对一般的 STS3215 / STS 系列，而不是 C001 这个型号；这些寄存器的地址和单位在两份表里相同。LeRobot 也会给每个关节写别的寄存器：Operating_Mode（位置模式）、P/I/D 系数 16/0/32（出厂 P 为 32；[config_so_follower.py 第 45–47 行](https://github.com/huggingface/lerobot/blob/v0.6.1/src/lerobot/robots/so_follower/config_so_follower.py#L45-L47)）、Return_Delay_Time 0 和加速度寄存器 254（[feetech.py 第 209–217 行](https://github.com/huggingface/lerobot/blob/v0.6.1/src/lerobot/motors/feetech/feetech.py#L209-L217)）、Phase 寄存器的第 4 位（在 STS3215 上清零，选单圈角度反馈；[feetech.py 第 219–225 行](https://github.com/huggingface/lerobot/blob/v0.6.1/src/lerobot/motors/feetech/feetech.py#L219-L225)），校准时还会写 Homing_Offset 和位置限位（[feetech.py 第 268–273 行](https://github.com/huggingface/lerobot/blob/v0.6.1/src/lerobot/motors/feetech/feetech.py#L268-L273)）。16、28、36 号寄存器在两份表里都属于 EEPROM 区，而 LeRobot 是在 Lock（地址 55）为 0 时写入它们的：configure() 在 torque_disabled() 里运行（[so_follower.py 第 160 行](https://github.com/huggingface/lerobot/blob/v0.6.1/src/lerobot/robots/so_follower/so_follower.py#L160)），它先给每个电机写 Lock 0（[feetech.py 第 291–294 行](https://github.com/huggingface/lerobot/blob/v0.6.1/src/lerobot/motors/feetech/feetech.py#L291-L294)），而在线存储表说 Lock 为 0 时写入 EEPROM 的值断电后仍会保留。所以夹爪舵机断电重启、换用别的软件、或者被换到别的关节上，都还会保持 500 / 250 / 25，直到有程序再次改写这些寄存器。但其余五个关节的出厂扭矩限制和保护门限（16、28、36 号寄存器）保持不变，12 A 的堵转总数仍是一个保守的上限。

## 组装并设置 ID

组装分两半：软件要装好、能看见控制板；电机要先拿到各自的 ID，否则后面都无从谈起。先做软件，因为当你已经知道串口和工具都正常时，一个 ID 设错的电机要好查得多。

### 安装 LeRobot

按 LeRobot 的安装指南，把它装进一个独立的 Python 环境。LeRobot 会拉进一大套依赖，和系统 Python 混在一起很容易把别的东西弄坏。克隆仓库、激活环境之后，在克隆目录里安装 Feetech 扩展：

```bash
pip install -e ".[feetech]"
```

`-e` 是可编辑安装，命令直接来自你的仓库副本；`[feetech]` 会装上和 STS3215 通信的串口 SDK。如果命令失败，先确认你在有 `pyproject.toml` 的那个目录，再回安装页核对当前 Python 版本和系统依赖。

<Resource id="lerobot-so101" />

### 找到串口

每条臂有自己的控制板和 USB 口。运行：

```bash
lerobot-find-port
```

工具会列出串口，让你拔掉一块板再按回车，然后告诉你哪个串口消失了。插回去，对另一块板重复。把哪个口是主臂、哪个是从臂记下来，写在纸上或写在要用的命令旁边。Linux 下名字像 `/dev/ttyACM0` 和 `/dev/ttyACM1`，但重新插拔后可能变，所以要查，不要猜。下面的例子用 `/dev/ttyACM0` 给从臂、`/dev/ttyACM1` 给主臂；换成你自己的。

### 一次一个舵机

新舵机出厂全是 ID 1。一次接两个，它们会对同一个包一起应答，设置脚本分不清谁是谁。这就是官方流程一次只接一个电机的原因。ID 和总线波特率会写进舵机的 <Term id="eeprom">EEPROM</Term>，写一次就留在那里，直到你改它。替换用的新舵机到手时又是 ID 1，所以把“哪个舵机装在哪个关节”记下来。

```bash
lerobot-setup-motors \
    --robot.type=so101_follower \
    --robot.port=/dev/ttyACM0
```

脚本先问夹爪电机，把它设成 ID 6，然后依次是 wrist_roll、wrist_flex、elbow_flex、shoulder_lift，最后 shoulder_pan = 1。每次只把脚本要的那个电机接到板上，不要和另一个菊花链在一起。每次按回车前检查供电和三针线；这个阶段一根松线看起来和坏舵机一模一样。然后对主臂做同样的事：

```bash
lerobot-setup-motors \
    --teleop.type=so101_leader \
    --teleop.port=/dev/ttyACM1
```

开始前把主臂那套不同减速比的舵机和从臂的分开，并贴标签。两套从外面看一样，把 1/147 的舵机装进从臂的肩部是很容易犯的错：臂会动，但没有从臂设计所需的扭矩。

### 组装要点

官方指南里的细节值得照做：

- 先清掉所有支撑材料；指南建议用小螺丝刀从支撑底下撬。残留的一小块足以让关节装不到位。
- 每放一个电机，就先把一根三针线插进它，再装下一块零件。等零件合拢，插座就很难够到了。
- 大多数关节用两个舵机盘；上面那个用 M3×6 螺丝，下面那个不拧（腕部旋转电机只装一个舵机盘）。
- 电机用 M2×6 螺丝固定，是套件里最小的螺丝；打印件用 M3×6 螺丝固定在舵机盘上。
- 从夹爪往底座方向菊花链，最后把 shoulder_pan（ID 1）插到控制板上。

把两种螺丝分开放，打印件按关节分袋；M2×6 和 M3×6 混在一堆里，用眼睛很难分清。两条通用的实操建议。第一，拧进塑料打印件的螺丝不要过力；螺纹远在你觉得“拧紧”之前就滑了，滑掉的螺柱不是再加力能救的。第二，每装好一个关节，先用手转一遍。如果发卡，先找出原因再往下走：被舵机盘压住的线、轴承座里的支撑碎片，都不会自己好，而且会让校准和遥操作看起来像软件问题，实际是机械问题。

舵机盘（horn）是套在舵机输出轴上的带齿圆盘，打印连杆就拧在它上面。飞特规定输出轴为 25T/OD5.9mm，即 25 齿、外径 5.9 mm 的花键，舵机盘螺丝为 M3×6（C001 与 C018 规格，§6-9 和 §6-13）。舵机另一侧的第二个舵机盘给连杆提供第二个支撑，使它不只靠输出轴撑着；组装指南写明“No screws are required for the bottom horn”（下面那个舵机盘不需要螺丝；[LeRobot SO-101 指南](https://huggingface.co/docs/lerobot/so101)）。M2×6 螺丝把舵机本身固定在打印的舵机座里。花键有 25 个齿，所以舵机盘只能以 360° / 25 = 14.4° 为一档重新装上，相当于 14.4 × 4096 / 360 = 163.84 个编码器步。校准记录的是按当时舵机盘位置得到的各关节范围，所以舵机盘拆下再装回时，哪怕只错了一个齿，也要把那条臂重新校准一次。

## 校准与遥操作

校准让主臂和从臂在同一个物理姿态下报出同一组数字。舵机型号一样，但舵机盘、打印件和编码器零点不一样；一条臂上的原始计数 1830，在另一条臂上可能对应另一个角度。校准记录每个关节行程的中点和两端，建立“原始计数到关节角度”的映射。两条臂都要做，而且每次启动这条臂都用同一个保存名。

这也是“在一台臂上训练的策略能跑在另一台臂上”的前提，正是 Month 6 的关键。只有两条臂对“中间”和“两端”的理解一致，演示数据才可比。校准不是玩之前勾掉的一项，它是后面所有操作所在的坐标系。

先校准从臂：

```bash
lerobot-calibrate \
    --robot.type=so101_follower \
    --robot.port=/dev/ttyACM0 \
    --robot.id=my_follower
```

再校准主臂：

```bash
lerobot-calibrate \
    --teleop.type=so101_leader \
    --teleop.port=/dev/ttyACM1 \
    --teleop.id=my_leader
```

两条臂的流程一样：把臂摆到每个关节都在行程中点的位置，按回车；然后慢慢把每个关节走完整个行程，让工具看到两端。不要硬顶机械限位；走到行程尽头就停。`id` 是校准保存时用的名字，不是电机 ID，也不是序列号。每次启动这条臂都用同一个名字，否则会载入另一份校准数据，关节零位与当前装配对不上。

两条臂都校准好之后，遥操作就是一条命令：

```bash
lerobot-teleoperate \
    --robot.type=so101_follower \
    --robot.port=/dev/ttyACM0 \
    --robot.id=my_follower \
    --teleop.type=so101_leader \
    --teleop.port=/dev/ttyACM1 \
    --teleop.id=my_leader
```

一开始慢慢移动主臂，手放在从臂电源附近。开始前把桌子清空：从臂会忠实复制你的动作，包括快速撞向杯子的那一下。第一分钟用来检查方向和行程，不是用来评判跟随精度。

出问题时，从外往内查：

- **找不到某个电机**：查供电、USB 和该电机的三针线。Waveshare 板要把两个跳线放在 B（USB）通道；通道错了，板子有电但电脑什么都看不到。
- **从臂一启动就猛跳**：它是在另一个姿态或另一个 id 下校准的。用你打算使用的姿态和 id 重新校准。
- **某个关节方向反了或有偏移**：重新校准那条臂。不要靠改命令来修；错的是映射，不是命令。
- **舵机发热，或夹爪夹住物体后嗡嗡响**：它在顶着一个东西。位置环会保留一个稳态误差并持续出力，正是第 4 课讲的稳态行为。松开夹持或降低目标；不要让它响几分钟。

## 练习：组装、校准、录视频

本课的练习就是这次组装本身。把 SO-101 装起来，给两条臂设好 ID 1–6，校准每个舵机，用主臂遥操作从臂；然后拍一段从臂跟随主臂的短视频。下一课你要设计并打印自己的 TPU 夹爪手指，在三种不同形状的物体上测试；这段视频和这次校准，是让那次比较有意义的前提。

一份按工作顺序排列的清单：

- 路线已选定，下单前把总价写下来。
- 结构件按仓库设置打印：PLA+、15 % 填充、0.2 mm 层高、0.4 mm 喷嘴。
- 两条臂都设好 ID 1–6，主臂那套不同减速比的舵机分开放。
- 两条臂都完成校准，保存的 id 写在命令旁边。
- 一段从臂跟随主臂的短视频，包含一次慢动作和一次用到手腕的动作。
- 记下所有出过的问题和修法。下次组装出毛病时，你会回头读的就是这些笔记。

拍视频时把整条臂和桌面都拍进去，不要只拍夹爪：之后回看时，你要分得清是抓取失败，还是路径撞到了东西。如果视频里某个关节明显滞后，先查机械和校准，再怀疑软件。

如果整套主从臂超出预算，便宜路线仍然能学到本课的大部分。单个从臂保留完整软件路径：能装、能校准、能读关节、能用 Python 发指令，以后再加主臂。MuJoCo 让你在没有任何硬件时跑同一套软件；缺的是手感、线缆和舵机吃力时的声音。两条捷径都不浪费时间，只要记录清楚每条路线练到的是哪一部分技能。

<Callout type="warn" title="从臂不是玩具">
从臂的力量足以夹痛手指，也能把桌上的东西扫下去。保持工作区整洁，把线缆和杯子放到臂的活动范围之外，在它上面动手时先断电。一条正在动的臂不知道你的手在哪里。
</Callout>

第 6 课接着往前走：夹爪手指。它们小、迭代便宜，也是证明你“会设计、不只是会组装”的那一部分。一台能动的臂，加上你自己为它设计的手指，比一套只会跑厂家演示的套件更能回答“你会不会造机器人”。

**本课要点**

- 每臂 6 只 STS3215 总线舵机，每只有 12 位、每圈 4096 步的编码器：1024 步就是 90°。
- 每条消息都是 `0xFF 0xFF ID LENGTH INSTRUCTION PARAMS CHECKSUM`，CHECKSUM = ~(和) & 0xFF；给 1 号舵机的 ping 是 FF FF 01 02 01 FB，给 2 号舵机时校验和是 FA。
- 半双工总线跑在 1 Mbit/s，从夹爪菊花链回底座；设置脚本先把夹爪设为 ID 6，再一路退回到 shoulder_pan = 1。
- 减速比：从臂 6 个关节全是 1/345，而主臂混用 1/191、1/147 和 1/345，所以 345 / 147 = 2.35 倍摩擦、(345/147)² ≈ 5.51 倍转子惯量。
- 供电与成本：标准装机用 5 V，落在 4–7.4 V 范围内；物料清单一对 $229.88（单从臂 $121.94），打印件估计约 1 kg PLA+（15 % 填充、0.2 mm 层高；实际用量看切片软件）。

**常见错误**

- 一次接两只新舵机：它们出厂都是 ID 1，设置脚本分不清谁是谁。
- 把主臂 1/147 的舵机装进从臂：臂会动，但从臂没有足够的扭矩。
- 把 12 V 电源接到 7.4 V 舵机上，远超 4–7.4 V 的输入范围。
- 关节有偏移或方向反了就去改遥操作命令；错的是映射，应当重新校准那条臂。
