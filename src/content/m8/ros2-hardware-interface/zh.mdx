## 硬件组件回调

control.ros.org（Jazzy）《Writing a Hardware Component》：类继承 `hardware_interface::{System|Actuator|Sensor}Interface`，实现 LifecycleNodeInterface 方法与接口钩子：

- `on_init`
- `on_configure` / `on_cleanup` / `on_shutdown`
- `on_activate` / `on_deactivate`
- `on_error`
- `export_state_interfaces` / `export_command_interfaces`（Jazzy 也可按 URDF 里 `ros2_control` 标签自动导出）
- 可选 `prepare_command_mode_switch` / `perform_command_mode_switch`
- 每个控制周期的 **`read`** / **`write`**

串口在 `on_configure` 打开；使能在 `on_activate`；`read` 把总线状态写入状态接口；`write` 下发命令。不要在 `read`/`write` 里分配内存或做会阻塞的 Hub 调用。

## 托管节点生命周期 ≠ HardwareComponent 状态机

<Resource id="ros2-node-lifecycle" />

**锁定：** 下面的玩具实现的是 [design.ros2.org — Managed nodes](https://design.ros2.org/articles/node_lifecycle.html) 里的 **ROS 托管节点** 状态机，**不是** `HardwareComponentInterface` 状态机。二者绝不能等同。

| | **托管 ROS 生命周期节点** | **ros2_control `HardwareComponentInterface`** |
|---|---|---|
| 是什么 | 按设计文档暴露生命周期服务/话题的节点 | 实现 `LifecycleNodeInterface` 的插件；**不是**独立托管节点 |
| 谁切换 | 监管进程经生命周期服务 | `ResourceManager` / Controller Manager（`set_hardware_component_state` 等） |
| 错误路径 | 设计：`ErrorProcessing` → Unconfigured 或 Finalized | 历史 issue 指出行为可能**并非**与设计文档 1:1——引 [ros2_control#2079](https://github.com/ros-controls/ros2_control/issues/2079) 作讨论，不当成第二个要实现的 SM |
| 追踪 | 真实生命周期节点上的 `rcl_lifecycle_*` | 硬件路径未必发出相同 tracepoint——如实说明 |

API 指针：[`HardwareComponentInterface`](https://control.ros.org/rolling/doc/api/classhardware__interface_1_1HardwareComponentInterface.html)。Controller Manager 的精确切换表随发行版漂移——散文级对照即可；玩具只停在托管节点设计 SM。

设计中的主状态：`Unconfigured`、`Inactive`、`Active`、`Finalized`。本课用到的转移状态：`ErrorProcessing`。从 `Unconfigured` 合法离开是 `configure` → `Inactive` 与 `shutdown` → `Finalized`。**从 `Unconfigured` 发 `activate` 非法**，必须 **拒绝**（主状态不变）。这**不**表示节点永远到不了 Active——随后合法的 `configure` 再 `activate` 可以成功。玩具必须展示恢复路径，绝不能教「一次非法 activate ⇒ 永久死亡」。

**回调结果路径**（设计文档 — Configuring / ErrorProcessing）：

- `configure` **SUCCESS** → `Inactive`
- `configure` **FAILURE** → `Unconfigured`
- `configure` **ERROR** / 异常 → `ErrorProcessing`
- `on_error` **SUCCESS** → `Unconfigured`
- `on_error` **FAILURE** → `Finalized`

### `lifecycle_sm_toy.py`

```python
#!/usr/bin/env python3
"""lifecycle_sm_toy.py: ROS 2 *managed-node* lifecycle state machine (stdlib).

LOCKED: this toy implements the managed ROS lifecycle node SM from
  https://design.ros2.org/articles/node_lifecycle.html
It is NOT the ros2_control HardwareComponentInterface state machine.
Hardware components are plugins transitioned by ResourceManager /
Controller Manager; do not equate the two SMs (see lesson MDX contrast).

Primary states (design): Unconfigured, Inactive, Active, Finalized.
Transition state used here: ErrorProcessing.
Supervisory transitions used here: configure, activate, deactivate,
cleanup, shutdown. Illegal requests are rejected and leave the primary
state unchanged — they do NOT permanently brick the node.

Callback result paths (design doc, Configuring / ErrorProcessing):
  configure SUCCESS  → Inactive
  configure FAILURE  → Unconfigured
  configure ERROR/exception → ErrorProcessing
  on_error SUCCESS   → Unconfigured
  on_error FAILURE   → Finalized

Script A: configure → activate → Active.
Script B: activate from Unconfigured (illegal, reject) → still
          Unconfigured; then configure → activate → Active (recovery).
Script C: configure → activate → shutdown → Finalized.
Script D: configure(FAILURE) → Unconfigured (stays / returns).
Script E: configure(ERROR) → ErrorProcessing; on_error(SUCCESS) → Unconfigured.
Script F: configure(ERROR) → ErrorProcessing; on_error(FAILURE) → Finalized.
Metrics: illegal_rejects, reached_active, final_state, callback_results.

Tracing / LTTng / real HardwareComponent load = 本页未运行.
usage: python3 lifecycle_sm_toy.py
"""
from __future__ import annotations

# Primary states from the design doc.
UNCONFIGURED = "Unconfigured"
INACTIVE = "Inactive"
ACTIVE = "Active"
FINALIZED = "Finalized"
ERROR_PROCESSING = "ErrorProcessing"

# Legal supervisory edges when the callback succeeds: (state, transition) -> new_state
# From design: Unconfigured --configure--> Inactive
#              Unconfigured --shutdown--> Finalized
#              Inactive --activate--> Active
#              Inactive --cleanup--> Unconfigured
#              Inactive --shutdown--> Finalized
#              Active --deactivate--> Inactive
#              Active --shutdown--> Finalized
LEGAL_SUCCESS = {
    (UNCONFIGURED, "configure"): INACTIVE,
    (UNCONFIGURED, "shutdown"): FINALIZED,
    (INACTIVE, "activate"): ACTIVE,
    (INACTIVE, "cleanup"): UNCONFIGURED,
    (INACTIVE, "shutdown"): FINALIZED,
    (ACTIVE, "deactivate"): INACTIVE,
    (ACTIVE, "shutdown"): FINALIZED,
}

# Callback outcomes the toy can inject on a request.
SUCCESS = "SUCCESS"
FAILURE = "FAILURE"
ERROR = "ERROR"  # exception / non-failure error code → ErrorProcessing


class ManagedLifecycleNode:
    """Minimal managed-node lifecycle — design adjacency + callback results."""

    def __init__(self) -> None:
        self.state = UNCONFIGURED
        self.illegal_rejects = 0
        self.transition_log: list[str] = []

    def request(self, transition: str, result: str = SUCCESS) -> bool:
        # on_error is only legal from ErrorProcessing.
        if transition == "on_error":
            if self.state != ERROR_PROCESSING:
                self.illegal_rejects += 1
                self.transition_log.append(
                    f"on_error:REJECT(from={self.state})"
                )
                return False
            if result == SUCCESS:
                new_state = UNCONFIGURED
                self.transition_log.append(
                    f"on_error:SUCCESS({ERROR_PROCESSING}->{new_state})"
                )
                self.state = new_state
                return True
            # FAILURE or any other code → Finalized (design).
            new_state = FINALIZED
            self.transition_log.append(
                f"on_error:FAILURE({ERROR_PROCESSING}->{new_state})"
            )
            self.state = new_state
            return False

        key = (self.state, transition)
        if key not in LEGAL_SUCCESS:
            self.illegal_rejects += 1
            self.transition_log.append(
                f"{transition}:REJECT(from={self.state})"
            )
            return False

        if result == SUCCESS:
            new_state = LEGAL_SUCCESS[key]
            self.transition_log.append(
                f"{transition}:OK({self.state}->{new_state})"
            )
            self.state = new_state
            return True

        if result == FAILURE:
            # Design (Configuring): onConfigure FAILURE → back to Unconfigured.
            # For other transitions the design routes non-success to ErrorProcessing
            # except configure's explicit failure code; we model only configure's
            # FAILURE→Unconfigured path here (the required teaching).
            if transition == "configure":
                new_state = UNCONFIGURED
                self.transition_log.append(
                    f"configure:FAILURE({self.state}->{new_state})"
                )
                self.state = new_state
                return False
            # Non-configure FAILURE treated as error path.
            new_state = ERROR_PROCESSING
            self.transition_log.append(
                f"{transition}:FAILURE({self.state}->{new_state})"
            )
            self.state = new_state
            return False

        # ERROR / exception → ErrorProcessing (design).
        new_state = ERROR_PROCESSING
        self.transition_log.append(
            f"{transition}:ERROR({self.state}->{new_state})"
        )
        self.state = new_state
        return False


def run_script(name: str, steps: list) -> dict:
    """steps: list of transition str, or (transition, result) tuples."""
    node = ManagedLifecycleNode()
    for step in steps:
        if isinstance(step, tuple):
            transition, result = step
            node.request(transition, result)
        else:
            node.request(step)
    reached = 1 if any("->Active" in e for e in node.transition_log) else 0
    return {
        "script": name,
        "steps": steps,
        "illegal_rejects": node.illegal_rejects,
        "reached_active": reached,
        "final_state": node.state,
        "log": node.transition_log,
    }


def _fmt_steps(steps: list) -> str:
    parts = []
    for s in steps:
        if isinstance(s, tuple):
            parts.append(f"{s[0]}({s[1]})")
        else:
            parts.append(s)
    return ",".join(parts)


def main() -> None:
    print(
        "lifecycle_sm_toy sm=ros2_managed_node "
        "source=design.ros2.org/articles/node_lifecycle.html"
    )
    print(
        "note: NOT HardwareComponentInterface SM; "
        "ResourceManager transitions that plugin (prose map only)"
    )
    print(
        "callback_paths: configure FAILURE→Unconfigured; "
        "ERROR/exception→ErrorProcessing; "
        "on_error SUCCESS→Unconfigured, FAILURE→Finalized"
    )

    a = run_script("A", ["configure", "activate"])
    b = run_script("B", ["activate", "configure", "activate"])
    c = run_script("C", ["configure", "activate", "shutdown"])
    d = run_script("D", [("configure", FAILURE)])
    e = run_script("E", [("configure", ERROR), ("on_error", SUCCESS)])
    f = run_script("F", [("configure", ERROR), ("on_error", FAILURE)])

    for r in (a, b, c, d, e, f):
        print(
            f"script_{r['script']}: steps={_fmt_steps(r['steps'])} "
            f"illegal_rejects={r['illegal_rejects']} "
            f"reached_active={r['reached_active']} "
            f"final_state={r['final_state']}"
        )
        print(f"script_{r['script']}_log={' | '.join(r['log'])}")

    assert a["illegal_rejects"] == 0
    assert a["reached_active"] == 1
    assert a["final_state"] == ACTIVE

    assert b["illegal_rejects"] == 1
    assert b["reached_active"] == 1
    assert b["final_state"] == ACTIVE
    # LOCKED: illegal activate must NOT mean permanently dead.
    assert b["final_state"] == ACTIVE
    print("never_permanent_death_after_illegal_activate=1")

    assert c["illegal_rejects"] == 0
    assert c["reached_active"] == 1
    assert c["final_state"] == FINALIZED
    print("reached_finalized_via_shutdown=1")

    assert d["illegal_rejects"] == 0
    assert d["reached_active"] == 0
    assert d["final_state"] == UNCONFIGURED
    print("configure_failure_returns_unconfigured=1")

    assert e["illegal_rejects"] == 0
    assert e["final_state"] == UNCONFIGURED
    print("on_error_success_returns_unconfigured=1")

    assert f["illegal_rejects"] == 0
    assert f["final_state"] == FINALIZED
    print("on_error_failure_goes_finalized=1")

    print(
        "ok: managed-node lifecycle toy "
        "(LTTng/ros2_tracing/HW plugin load 本页未运行)"
    )


if __name__ == "__main__":
    main()
```

```python
#!/usr/bin/env python3
"""servo_bus_sim.py: simulate hardware read/write cycle jitter → timeout counts.

Models a ros2_control-style loop at CONTROL_HZ. Each tick must finish both
read() and write() within the period. Bus latency is base + jitter; when the
sum exceeds the period the tick is a TIMEOUT (deadline miss).

Modes:
  naive — always pay full read+write cost.
  budget_guard — if projected read+write would exceed the period, skip the
                 blocking write and apply a cheap hold (HOLD_MS). That can still
                 miss if read alone is huge, but usually cuts timeouts.

Pinned seed and constants keep expected/ stable. Pure CPU; no real serial.
The so101_hw/ skeleton beside this file is for your Jazzy workspace
(marked 「本页未运行」 in the lesson).
usage: python3 servo_bus_sim.py
"""
from __future__ import annotations

import random

CONTROL_HZ = 100
PERIOD_MS = 1000.0 / CONTROL_HZ  # 10.0
BASE_READ_MS = 2.0
BASE_WRITE_MS = 2.5
JITTER_MS = 6.0  # uniform [0, JITTER_MS] added to read and to write
HOLD_MS = 0.4  # cheap "hold last command" path under budget_guard
TICKS = 200
SEED = 8


def run(budget_guard: bool) -> tuple[int, float, int]:
    """Return (timeouts, max_overshoot_ms, holds_used)."""
    rng = random.Random(SEED)
    timeouts = 0
    max_over = 0.0
    holds = 0
    for _ in range(TICKS):
        read_ms = BASE_READ_MS + rng.random() * JITTER_MS
        write_ms = BASE_WRITE_MS + rng.random() * JITTER_MS
        if budget_guard and (read_ms + write_ms) > PERIOD_MS:
            total = read_ms + HOLD_MS
            holds += 1
        else:
            total = read_ms + write_ms
        over = total - PERIOD_MS
        if over > 0:
            timeouts += 1
            max_over = max(max_over, over)
    return timeouts, max_over, holds


def main() -> None:
    t_naive, o_naive, _ = run(False)
    t_guard, o_guard, holds = run(True)
    print(f"servo_bus_sim control_hz={CONTROL_HZ} period_ms={PERIOD_MS:g} ticks={TICKS} seed={SEED}")
    print(f"naive_timeouts={t_naive} naive_max_overshoot_ms={o_naive:.3f}")
    print(f"guard_timeouts={t_guard} guard_max_overshoot_ms={o_guard:.3f} holds={holds}")
    print(f"timeout_reduction={t_naive - t_guard}")
    print("ok: CPU bus jitter toy (no real STS3215 bus, page not run)")


if __name__ == "__main__":
    main()
```

## 常见错误

- **把托管节点生命周期服务等同于 HardwareComponent 切换。** 发起者不同；玩具只做托管节点。
- **教「非法 activate ⇒ 永久死亡」。** 拒绝、留在 Unconfigured，再经 configure → activate 恢复。
- **在 `read` 里打开串口。** 只在 `on_configure` 配置一次，保证周期确定。
- **每次 `write` 都 `new` 向量。** 在 configure 时预分配。
- **不做 JointLimiter。** 8.5 的软件看门狗不能代替向 ros2_control 声明位置/速度限制。
- **指望本站 CI 加载你的 `.so`。** 学员包 CI ≠ Hardware-learning 网站 CI。

## Batch-6 H2：CAN 故障限制（+180 min）

通用 **CAN 后端**可以把通信故障上报硬件接口，但这不表示 SO-101 的串口舵机总线变成了 CAN。本节新增独立的 Classic CAN 诊断模型，不重做生命周期状态机。**不是 CiA402 状态位，也不是 EtherCAT**；bus-off 恢复**不是急停**，也不代表允许重新使能执行器；继续保留独立的 [8.5 故障锁存 / 操作员确认路径](/zh/month/month-8/safety-reliability)。

### 实际打开的规则与精确边界

<Resource id="bosch-can20-confinement" />
<Resource id="nxp-can20-protocol" />

下表来自实际打开的 **Bosch CAN 2.0, Part A pp. 24–26, Fault Confinement**（1991 年 9 月，公开镜像）。NXP 的 **BCANPSV2.0 Rev. 3 §5.2** 交叉核对阈值、成功递减与复位规则；延长显性序列的条件采用 Bosch 原文。**以规范为准**；这是 Classic CAN 阅读练习，不是 ISO 11898 或 CAN FD 的完整实现。

| 已满足前置条件的事件 | 计数变化 | 条件 / 例外 |
|---|---|---|
| 发送器发出错误标志 | **TEC +8** | 普通路径，不包含下面两个例外。 |
| 成功发送 | **TEC −1** | 收到 ACK 且到 EOF 均无错误；最低为 0。 |
| 接收器检测到普通错误 | **REC +1** | 排除发送主动错误 / 过载标志时的位错误。 |
| 接收器错误标志后的第一位为显性 | **REC +8** | 单独条件；一条报文可能同时适用多条规则。 |
| 发送主动错误 / 过载标志时检测到位错误 | **TEC +8 或 REC +8** | 分别更新发送器或接收器计数；不是普通 REC +1。 |
| 满足条件的过长显性序列 | **TEC +8 或 REC +8** | Bosch 规则 6：主动错误 / 过载从第 **14** 个连续显性位开始，被动错误后从第 **8** 个开始，此后每八个再增加。 |
| 成功接收并发送 ACK | 1…127 时 **REC −1** | 0 保持 0；**REC >127 时设到 119…127**。玩具确定性选择 **127**，不是“一律减一”。 |

两个不增加 TEC 的发送例外为：(1) 已被动，未看到显性 ACK，**且发送被动错误标志期间没有显性位**；(2) 指定的 RTR 之前仲裁填充位情形：发出隐性却读到显性。玩具接收已经满足这些条件的事件。因此，孤立节点仅因反复无人 ACK 可进入被动态，并不必然因此 bus-off。

**TEC 或 REC >127 即 error-passive**（≥128）；两者都 ≤127 才回到 active。**TEC >255 才 bus-off**（≥256），**255 时还不是**；仅 REC 高不能触发 bus-off。按规则 9，导致进入被动态的那次错误仍发主动错误标志，之后的错误才发被动标志。本模型只计算计数 / 状态结果，不生成错误标志波形或发送暂停时序。

### 共享时隙与恢复

两个发送案例共享 **43 个时隙**：16 次错误注入机会、8 次成功、17 次错误机会、最后两次请求。健康反事实不受影响，噪声发送器承受已满足条件的错误。它是确定性的敏感性对照，不宣称两者实际故障结果相同，也不是随机性能评测。成功报文、状态变化、被抑制请求分别统计。

Bus-off 节点不能驱动 TX、ACK 或错误标志。恢复资格需要 **128 次各含 11 个连续隐性位**，即无中断空闲流中的 **128×11=1408** 位。十个隐性位后插入显性位不构成一次；显性位打断当前连续段，但不清除之前完整的次数。玩具按不重叠的 11 位组计数，到达资格后仍需显式 `request_recovery()`；控制器使能 / 复位策略因实现而异，模型不自动重新武装机器人。1408 位下限不是通用的毫秒恢复时间。

#!/usr/bin/env python3
"""Classic CAN event-level confinement; Bosch CAN 2.0 Part A pp.24-26.
Opened primary spec: https://www.canlab.cz/sites/default/files/pages/download/Can2spec.pdf
Inputs are QUALIFIED rule events, not a bit/CRC/arbitration/ACK decoder.
Normal tx_error is not the passive-ACK or arbitration-stuff exception.
REC>127 on successful receive is reset to 127 (one permitted 119..127 choice).
Recovery counts non-overlapping 11-recessive groups, then needs a toy request;
controller enable/reset policy and real SocketCAN/transceiver are not run here.
Not CiA402 status bits, EtherCAT, an e-stop or a safety certification.
"""
from dataclasses import dataclass

EVENTS = {"tx_error", "tx_ok", "tx_flag_bit", "tx_extension",
          "tx_passive_ack_exception", "tx_arbitration_stuff_exception",
          "rx_error", "rx_ok", "rx_after_flag_dominant", "rx_flag_bit", "rx_extension"}


def extension_events(flag, consecutive):
    """Rule 6 qualification only: 14th for active/overload, 8th after passive.
    Additional increments follow each further eight dominant bits. Caller must
    supply the correctly scoped sequence; this is not a wire-level parser.
    """
    if flag not in ("active", "overload", "passive") or consecutive < 0:
        raise ValueError("invalid qualified dominant sequence")
    first = 8 if flag == "passive" else 14
    return max(0, 1 + (consecutive - first) // 8)


@dataclass
class Node:
    tec: int = 0
    rec: int = 0
    accepted: int = 0
    blocked: int = 0
    recessive_run: int = 0
    sequences: int = 0
    off: bool = False

    def __post_init__(self):
        if self.tec < 0 or self.rec < 0:
            raise ValueError("negative counter")
        self.off = self.off or self.tec > 255

    @property
    def state(self):
        if self.off:
            return "bus-off"
        return "error-passive" if max(self.tec, self.rec) > 127 else "error-active"

    def apply(self, event):
        if event not in EVENTS:
            raise ValueError("unknown qualified event")
        if self.off:
            self.blocked += 1  # No TX/ACK/error flag is issued while off.
            return False
        if event in ("tx_error", "tx_flag_bit", "tx_extension"):
            self.tec += 8
        elif event == "tx_ok":
            self.tec = max(0, self.tec - 1)
            self.accepted += 1
        elif event == "tx_passive_ack_exception":
            if self.state != "error-passive":
                raise ValueError("requires passive, no dominant ACK or passive-flag bit")
        elif event == "tx_arbitration_stuff_exception":
            pass  # Qualified recessive-stuff/dominant-detected arbitration exception.
        elif event == "rx_error":
            self.rec += 1
        elif event in ("rx_after_flag_dominant", "rx_flag_bit", "rx_extension"):
            self.rec += 8
        elif event == "rx_ok":
            self.rec = 127 if self.rec > 127 else max(0, self.rec - 1)
            self.accepted += 1
        self.off = self.tec > 255
        return True

    def observe(self, bits):
        """1=recessive, 0=dominant; interrupted runs cannot form an 11-bit group."""
        if any(bit not in "01" for bit in bits):
            raise ValueError("bits must be 0/1")
        if not self.off:
            return
        for bit in bits:
            self.recessive_run = self.recessive_run + 1 if bit == "1" else 0
            if self.recessive_run == 11:
                self.sequences = min(128, self.sequences + 1)
                self.recessive_run = 0

    def request_recovery(self):
        if not self.off or self.sequences < 128:
            return False
        self.tec = self.rec = self.recessive_run = self.sequences = 0
        self.off = False
        return True


def shared_schedule():
    return (True,) * 16 + (False,) * 8 + (True,) * 17 + (False,) * 2


def transmitter_trace(noisy):
    node, checkpoints = Node(), []
    for slot, injected in enumerate(shared_schedule(), 1):
        node.apply("tx_error" if noisy and injected else "tx_ok")
        if slot in (16, 24, 40, 41, 43):
            checkpoints.append((slot, node.tec, node.rec, node.state))
    return node, checkpoints


def main():
    print("Classic CAN qualified events; shared 43 slots, deterministic, no stochastic seeds")
    print("normal TX +8/-1; REC +1/-1 plus qualified +8; passive >127; bus-off TEC>255")
    print("arm slot TEC REC state")
    for name, noisy in (("healthy", False), ("noisy_tx", True)):
        node, trace = transmitter_trace(noisy)
        for row in trace:
            print(name, *row)
        print(f"{name} accepted={node.accepted} blocked_while_off={node.blocked}")
    print("boundary TEC REC state")
    for tec, rec in ((127, 127), (128, 0), (255, 0), (256, 0), (0, 512)):
        print("boundary", tec, rec, Node(tec, rec).state)
    print("receive event before_REC after_REC")
    for event, rec in (("rx_error", 0), ("rx_ok", 1), ("rx_ok", 0),
                       ("rx_after_flag_dominant", 120), ("rx_flag_bit", 120),
                       ("rx_extension", 120), ("rx_ok", 128)):
        node = Node(rec=rec)
        node.apply(event)
        print("receive", event, rec, node.rec)
    print("rule6 flag count increments_of_8")
    for flag, count in (("active", 13), ("active", 14), ("active", 22),
                        ("overload", 14), ("passive", 7), ("passive", 8), ("passive", 16)):
        print("rule6", flag, count, extension_events(flag, count))
    node = Node(tec=128)
    node.apply("tx_passive_ack_exception")
    print(f"passive_ACK_exception TEC={node.tec}; alone-node ACK loss is not forced bus-off")
    node.apply("tx_arbitration_stuff_exception")
    print(f"arbitration_stuff_exception TEC={node.tec}")
    node = Node(tec=256)
    print(f"no_wait recovered={int(node.request_recovery())} state={node.state}")
    node.observe(("1" * 10 + "0") * 128)
    print(f"interrupted_10R_1D sequences={node.sequences} recovered={int(node.request_recovery())}")
    node.observe("1" * (127 * 11 + 10))
    print(f"1407R sequences={node.sequences} partial={node.recessive_run} recovered={int(node.request_recovery())}")
    node.observe("1")
    ready = node.sequences
    recovered = node.request_recovery()
    print(f"1408R sequences_before_reset={ready} recovered={int(recovered)} TEC={node.tec} REC={node.rec} state={node.state}")
    print("REC>127 receive-success chooses 127 from allowed 119..127; no universal register implementation")
    print("Not CiA402 status bits / EtherCAT / e-stop; real CAN + SocketCAN: 本页未运行; 以规范为准")


if __name__ == "__main__":
    main()
