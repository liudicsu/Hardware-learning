## 你在给什么编程

### 一块芯片就是一台完整的计算机

微控制器（microcontroller）是把一整台小型计算机做进一颗芯片：里面有处理器、存储器，还有负责跟外界打交道的引脚、定时器和串口。它跟你桌上的电脑有一个关键区别：它只运行一个程序——也就是你烧进去的那一个——通电瞬间自动开始，一直跑到断电。没有桌面、没有登录、没有操作系统在后台调度别的应用。正是这种简单，让它能在微秒级别响应传感器，并且年复一年地稳定干下去。

本课用的板子是经典 Arduino Uno，它的核心是 ATmega328P。下面这些数字值得背下来，它们来自两个原始出处：[ATmega328P 数据手册](https://ww1.microchip.com/downloads/aemDocuments/documents/MCU08/ProductDocuments/DataSheets/ATmega48A-PA-88A-PA-168A-PA-328-P-DS-DS40002061B.pdf)（首页给出存储器容量，DC Characteristics 表给出引脚电流限制）和 Arduino 的 [Uno Rev3 技术规格](https://store.arduino.cc/products/arduino-uno-rev3)（时钟与板级电流）；请以这两处为准核对，而不是以教程为准：

- **16 MHz 主频**：芯片每个时钟周期大约执行一条简单指令，所以时间尺度是微秒级。
- **32 KB 闪存（flash）**：放你编译好的程序，断电不丢。其中 0.5 KB 被引导程序（bootloader）占用。
- **2 KB 随机存储器（RAM）**：放变量、缓冲区和栈。小得可怜——字符串里每个字符占 1 字节，一条 100 字符的提示就吃掉 5 % 的 RAM。
- **5 V 逻辑电平**：输出 HIGH 约等于 5 V，LOW 约等于 0 V。

flash 和 RAM 的区别不只在容量，还在存储机制：flash 是非易失的程序存储器，内容在断电和复位后仍然保留，CPU 通过专门的取指/取数指令直接从其中读取；RAM 是易失的工作内存，每次复位都会清零，在 Uno 上只有 2 KB。把常量字符串放进 RAM，会占用这块最紧张的内存；下文“串口”一节会说明如何用 `F()` 宏把字符串留在 flash 里。

### Uno 的引脚地图

板子边缘的引脚分成三组：

- **数字引脚 D0–D13**：每一个都能当输入或输出，读写 HIGH / LOW。本课大多数传感器和执行器都接在这里。
- **模拟输入 A0–A5**：接到一个 10 位<Term id="adc">模数转换器</Term>上。引脚不够用时，它们也能当普通数字引脚。
- **标着 `~` 的 PWM 引脚：3、5、6、9、10、11**：它们能输出快速方波，你可以控制它的平均电压。下文的 <Term id="pwm">PWM</Term> 一节整节都在讲它们。

此外还有电源引脚：**5 V**、**3.3 V**（来自板载稳压器，按 Uno Rev3 技术规格最多 50 mA：够给一个传感器模块供电，不足以驱动舵机、电机或 LED 灯带）、**GND**、**Vin**、**RESET**。任何外接电路都必须与板子共地，这一点课末的“常见错误”还会强调。

动手接线前先记住一条：**D0 和 D1 是连到 USB 芯片的串口线**。Uno 靠它们和电脑通信，上传程序、打开串口监视器都离不开。现在请把这两根引脚留空。以后真需要第二个串口，可以用软件串口库占用别的引脚，或者换一块硬件串口更多的板子。

### 从源码到闪存：上传到底做了什么

流程不长，但每一步都有讲究：

1. 从 arduino.cc 安装 **Arduino IDE 2**。
2. 用 USB 线把 Uno 连上电脑，系统里应该多出一个串口。
3. 在 **工具 → 开发板** 里选 **Arduino Uno**，在 **工具 → 端口** 里选刚出现的端口（Windows 上类似 `COM5`，macOS 上是 `/dev/cu.usbmodem...`，Linux 上一般是 `/dev/ttyACM0`）。
4. 点 **上传**。IDE 先把你的程序编译成机器码，再复位板子，由芯片里的一小段引导程序（bootloader）把程序写进 flash。

编译错误和上传错误是两码事。编译错误说明代码根本没到板子——要看第一条红字，不是最后一条。上传错误通常是端口选错、端口被占用，或者线只供电不传数据。如果压根没有新端口出现，先换一根 USB 线再考虑重装驱动；只有充电功能的线非常常见，症状正是“插上没反应”。

## 一个程序的结构

### setup() 与 loop()

每个 Arduino 程序（sketch）都有同一副骨架。复位之后，引导程序把控制权交给你的程序，程序先调用一次 `setup()`，然后无限次调用 `loop()`，一遍又一遍，直到断电或再次复位。它不会自动结束，也没有“程序跑完”这回事。

这个结构刚好贴合硬件：`setup()` 用来做只该发生一次的事——配置引脚、启动串口、初始化库；`loop()` 是主行为——读输入、判断、驱动输出、再重复。如果你在 `loop()` 里塞一个长时间阻塞的操作，这段时间里其他一切都会停止响应。下面这个程序既演示了结构，也演示了这个麻烦。

### 逐行读一遍

<CodeSource path="examples/month-2/arduino-io/blink_custom/blink_custom.ino" />

```cpp
// Blink with an uneven rhythm: 200 ms on, 800 ms off.
const int LED_PIN = LED_BUILTIN;  // pin 13 on an Uno

void setup() {
  pinMode(LED_PIN, OUTPUT);
}

void loop() {
  digitalWrite(LED_PIN, HIGH);
  delay(200);
  digitalWrite(LED_PIN, LOW);
  delay(800);
}
```

<Wokwi board="uno" files={["examples/month-2/arduino-io/blink_custom/blink_custom.ino", "examples/month-2/arduino-io/blink_custom/diagram.json"]} />

- 第一行是注释，编译器直接忽略。注释是写给下一个人的，而那个人通常是三周后的你自己。
- `const int LED_PIN = LED_BUILTIN;` 给引脚编号起了个名字。`LED_BUILTIN` 是各开发板预定义的常量，在 Uno 上等于 13。给引脚起名字，以后改接线只要改一行，不用在文件里翻找。
- `pinMode(LED_PIN, OUTPUT)` 把引脚从<Term id="high-impedance">高阻态</Term>输入改成能主动驱动线路的输出。这一步不能省：对一个仍是输入模式的引脚发输出指令，几乎看不到任何效果——课末的“常见错误”会解释这个错误。
- `digitalWrite(LED_PIN, HIGH)` 让引脚在内部接到 5 V；`LOW` 则接到地。板载 LED 和它的限流电阻已经在板上，不需要外接元件。
- `delay(200)` 不是“后台等一会儿”，而是**冻结整个程序** 200 毫秒。这期间不读任何输入、不处理串口、不改任何输出。单纯闪灯无所谓，但机器人要随时注意按键或障碍物，这就成问题了。下一课会用一个基于 `millis()` 的非阻塞计时器取代 `delay()`。

还要注意标点：每条语句以分号结尾，C++ 区分大小写，`digitalWrite` 能用，`digitalwrite` 不行。

### 周期、频率与占空比

LED 亮 200 ms、灭 800 ms，一个完整的亮灭循环就是 1000 ms。于是得到三个有用的数字：

```text
period      = 200 ms + 800 ms = 1000 ms = 1 s
frequency   = 1 / period = 1 / 1 s = 1 Hz
blinks/min  = 1 blink/s × 60 s/min = 60 blinks/min
duty cycle  = on-time / period = 200 ms / 1000 ms = 0.20 = 20 %
```

频率是周期的倒数：周期 1 s 就是每秒一个循环，即 1 Hz。占空比（duty cycle）是每个周期里处于 HIGH 的时间占比，是个比值、没有单位，乘 100 就是百分数。这里的 LED 只有五分之一的时间亮着，所以看起来比常亮的更暗。

## 数字输入与上拉

### 悬空的引脚不是零

数字输入引脚不是“默认读 0 V 的电压表”。它其实是一个高阻抗放大器，负责判断引脚上的电压更接近 5 V 还是 0 V。什么都不接时，引脚没有确定的电压：输入级阻抗极高，几乎没有阻性通路能把这个电压固定住，于是手、附近导线或市电通过电容耦合进来的少量电荷，就足以把引脚电压抬过或压过<Term id="logic-thresholds">VIH/VIL 判决阈值</Term>（在 5 V 的 Uno 上，VIH = 3.0 V、VIL = 1.5 V，见第 1 个月 · 元件、原理图与晶体管开关），`digitalRead()` 也就随机返回 HIGH 或 LOW。

这种状态叫**浮空（floating）**，也是“一碰板子就正常、手一松就抽风”这类经典故障的根源。规矩是硬的：**每个数字输入都必须被接到一个确定的电平，直接接或经电阻接都行**。

### 内部上拉

ATmega328P 的每个数字引脚内部都有一个可开关的<Term id="pull-up-pull-down">上拉电阻</Term>（pull-up resistor），大约 20–50 kΩ 接到 5 V。在 `pinMode()` 里选 `INPUT_PULLUP` 就把它接上了。此时只要没有别的东西驱动，引脚就被轻轻拉在 5 V。

把按键接在引脚和 GND 之间，逻辑就变成：

- **没按下**：上拉电阻说了算，引脚停在 5 V，读到 HIGH。
- **按下**：开关是一条接近 0 Ω 的通路，轻松压过上拉电阻，引脚被拉到 0 V，读到 LOW。

<Diagram id="pullup-internal" />

这种接法叫 **active low（低电平有效）**，因为“有效”的按下状态对应低电平。它是按键最常见的接法，也带来一条安全后果：用了 `INPUT_PULLUP`，按键另一端必须接 **GND**，绝不能接 5 V——从引脚到 5 V 的按键一按下就等于把电源短路到地。

按下时上拉电流约 5 V / 30 kΩ ≈ 0.17 mA，小到可以忽略。外接一只 10 kΩ 电阻效果相同，但用内部的能省下元件和走线。

### 只在状态变化时打印

<CodeSource path="examples/month-2/arduino-io/button_pullup/button_pullup.ino" />

```cpp
// Button between pin 2 and GND, internal pull-up enabled.
// Pressed = LOW. Print only when the state changes.
const int BUTTON_PIN = 2;
const int LED_PIN = LED_BUILTIN;

int lastState = HIGH;  // not pressed

void setup() {
  pinMode(BUTTON_PIN, INPUT_PULLUP);
  pinMode(LED_PIN, OUTPUT);
  Serial.begin(115200);
  Serial.println("ready");
}

void loop() {
  int state = digitalRead(BUTTON_PIN);
  digitalWrite(LED_PIN, state == LOW ? HIGH : LOW);
  if (state != lastState) {
    Serial.println(state == LOW ? "pressed" : "released");
    lastState = state;
  }
}
```

<Wokwi board="uno" files={["examples/month-2/arduino-io/button_pullup/button_pullup.ino", "examples/month-2/arduino-io/button_pullup/diagram.json"]} />

`Serial.begin(115200)` 以每秒 115200 比特启动串口，`Serial.println("ready")` 先发一行，用来确认板子复位并跑到了 `setup()`。三元表达式 `state == LOW ? HIGH : LOW` 是精简版 if-else：按下就让 LED 亮，否则灭。于是板载 LED 跟着按键走。

真正关键的思路是 `if (state != lastState)` 这一段。如果去掉它，程序每秒会打印几千次按键状态，把监视器刷满一模一样的行，反而盖掉了真正重要的那一刻。保存上一次的状态，就能做到**每次变化只打印一行**。

你也许会看到一次按下打印出两三行。真实按键的金属触点不会干净地闭合，会在几毫秒内来回弹跳，产生好几次快速的 HIGH/LOW 切换。程序只是把每一次电平变化都打印出来。下一课会加入消抖（debounce），让一次按下只产生一个事件。

## 模拟输入：ADC

### 10 位 ADC

世界是模拟的：温度、光线、位置、声音都连续变化。Uno 的模数转换器（ADC）把电压变成一个程序能用的数字。它是**10 位**转换器，也就是能给出 2^10 = 1024 个取值，编号从 0 到 1023。

- `analogRead(A0)` 返回 **0 到 1023** 之间的整数。
- 0 对应 0 V，1023 对应参考电压；Uno 默认参考电压是 5 V。
- 一次转换大约需要 100 µs，所以可以在紧凑的循环里读，但也不是瞬间完成。ATmega328P 数据手册规定一次转换需要 13 个 ADC 时钟周期（ADC 使能后的第一次需要 25 个），Arduino 核心把 ADC 时钟设为 16 MHz / 128 = 125 kHz：13 / 125 kHz = 104 µs。
- 只有 A0–A5 接到 ADC 上。给模拟引脚加超过 5 V（或负电压）可能损坏芯片，测更高电压要先用分压器。

### 从原始值到电压

换算就是一个简单比例：

<Formula label="ADC 原始值转电压（Uno）">V = raw × 5.0 / 1023</Formula>

ATmega328P 数据手册给出的换算是 ADC = V_IN × 1024 / V_REF，所以严格说最大码值 1023 对应的是比 5 V 低一个步长的电压。Arduino 官方示例改用 1023 作除数，让最大码值正好显示为 5.00 V；本课沿用这个约定。两种除数只差 0.1 %，远小于充当参考电压的 5 V 电源本身的误差。

一个算例：

```text
raw = 512
V = 512 × 5.0 / 1023
  = 2560 / 1023
  = 2.502 V ≈ 2.50 V

one step = 5 V / 1024 = 0.00488 V ≈ 4.9 mV   (the datasheet's step size)
```

所以量程中点大约是 2.5 V，每一格（一个计数）大约 4.9 mV。这个<Term id="lsb">步长</Term>就是 5 V 参考下 Uno 能分辨的最小电压变化。如果你想分辨 1 mV，Uno 的 ADC 光靠自己做不到，需要放大或换更小的参考电压。

### 整数运算的坑

这是新手传感器代码里最常见的 bug。在 Uno 上，`int` 是**16 位有符号**类型，最大值只有 32767。看看这两种写法：

```text
int raw = analogRead(A0);

raw * 5 / 1023        // 整数运算：512 × 5 = 2560，/ 1023 = 2，结果只可能是 0..5
raw * 1000 / 1023     // 1023 × 1000 = 1 023 000，16 位 int 直接溢出
```

第一行全程整数运算，每一步除法都丢掉小数部分，结果塌缩成整数伏特；第二行在除法之前乘法就<Term id="integer-overflow">溢出</Term>了，得到的是毫无意义的（往往是负数）结果。解法是让其中一个操作数变成浮点数：

```text
float volts = raw * 5.0 / 1023.0;   // 5.0 强制走浮点运算
```

另一种办法是调整顺序、用 `long` 以毫伏为单位算：`raw * 5000L / 1023`，但写 `5.0` 更清楚。还要记住 `Serial.println(volts)` 默认只打印两位小数，`Serial.println(volts, 3)` 才会给你三位。

### 电位器就是分压器

电位器（potentiometer）就是带一个滑动触点（wiper）的电阻。把两头分别接 5 V 和 GND，把滑动端接到 A0，它就构成了第一个月学过的分压器：滑动端的电压与旋钮转过的角度成正比，从一端 0 V 到另一端 5 V，`analogRead()` 再把它变成 0–1023。

这就是标准的旋钮电路，也值得体会它省了多少东西：同样的分压公式、同样的 5 V 电源，只是把两个固定电阻换成了一个传感器。如果读数在两端附近乱跳，先检查滑动端是不是真的接好了——浮空的 ADC 输入，行为和浮空的数字输入很像。

提前看一眼后面的内容：ESP32 的 ADC 是 **12 位**，返回 0–4095，参考电压约 3.3 V。它在量程两端明显不那么线性，所以在那种芯片上，上面的简单公式只是个起点。

## PWM：analogWrite 其实不是模拟量

### 占空比

Uno 没有真正的模拟输出，没有能把引脚稳定保持在 2.51 V 的数模转换器。它有的是**脉宽调制（PWM，pulse-width modulation）**：一个引脚在 0 V 和 5 V 之间飞快切换，而处于 HIGH 的时间比例由你的程序控制。这个比例就是**占空比**。

`analogWrite(pin, value)` 接受 0 到 255 的值：

- 0 表示一直 LOW（占空比 0 %）。
- 255 表示一直 HIGH（占空比 100 %）。
- 128 表示每个周期里大约一半时间 HIGH。

Uno 的 PWM 频率由定时器决定：引脚 3、9、10、11 大约是 **490 Hz**，引脚 5、6 大约是 **980 Hz**。所以周期分别约为 2 ms 和 1 ms。这两个数来自 Arduino 核心对定时器的设置：所有定时器都以 16 MHz / 64 = 250 kHz 计数。Timer0（引脚 5、6）用快速 PWM，从 0 数到 255，所以 250 kHz / 256 = 976.6 Hz。Timer1（引脚 9、10）和 Timer2（引脚 3、11）用相位修正 PWM，先加到 255 再减回来，一个周期 510 步：250 kHz / 510 = 490.2 Hz。只有标了 `~` 的引脚能做这件事。对非 PWM 引脚调用 `analogWrite()`，得不到成比例的电压输出。

### 平均电压

如果负载的反应比 PWM 周期慢得多，它感受到的就是平均值：

<Formula label="PWM 平均电压">V_avg = (value / 255) × 5 V</Formula>

一个算例：

```text
value = 128
duty  = 128 / 255 = 0.50196 ≈ 50.2 %
V_avg = 0.50196 × 5 V = 2.510 V ≈ 2.51 V
```

<Diagram id="pwm-duty-average" />

LED 根本跟不上 490 Hz 的方波，人眼把一次次闪光积分起来，看到的就是一盏更暗的灯，大致相当于引脚稳定在 2.51 V。直流电机转子有惯性，同样响应平均值——第 4 课正是用它调速。但换成扬声器就会听到 490 Hz 的啸叫，换成快速逻辑输入则会看到一个个脉冲：信号本身始终是数字的，只是平均效果像模拟量。

### 用 RC 滤波“看见”平均值

<Falstad title="PWM 被 RC 滤波平均后的波形" circuit="pwmAverage" height={460} />

这个电路里的方波源是 490 Hz、0–5 V、占空比 25 % 的 PWM 信号。1 kΩ 电阻和 10 µF 电容构成<Term id="low-high-pass-filter">低通滤波</Term>，时间常数 τ = R × C = 1 kΩ × 10 µF = 10 ms。一个 PWM 周期只有约 2 ms，所以滤波器一次就平均了好几个周期。右侧示波器和电压标签会稳定在 0.25 × 5 V = **1.25 V** 附近，还带一点小纹波，因为电容每个周期仍在微微充放电。

动手试试：

1. 运行电路，看波形稳定下来，对照预测值 1.25 V。
2. 双击电源，把 **Duty Cycle** 改成 0.75，平均值应升到约 0.75 × 5 V = **3.75 V**。
3. 把电容改小到 100 nF，看纹波变大——滤波器已经平均不好了。

关键提醒：**Arduino 里并没有这只电容**。RC 滤波只是让你把平均值看清楚的测量工具。LED 或电机响应同样的平均值，靠的是它们自身的物理惯性，而不是电容。

## 从旋钮到亮度：一个完整程序

### 把 0–1023 映射到 0–255

ADC 给出 0–1023，`analogWrite()` 要 0–255。最快的换算就是整数除以 4：`raw / 4`。两个数都是整数，小数部分直接丢掉。在量程顶端，1023 / 4 = 255.75 变成 255，正好是 PWM 的最大值。精确的换算应是 raw × 255 / 1023；raw = 818 时它给出 203.9，而 `raw / 4` 给出 204。两者最多差一个 PWM 步，任何 LED 都看不出来。

通用的 `map(raw, 0, 1023, 0, 255)` 函数做同样的事，多了点运算，但范围不常规时更好读。

### 程序

接线：电位器两端接 5 V 和 GND，滑动端接 A0；9 号引脚 → 220 Ω 电阻 → LED 阳极，LED 阴极 → GND（元件与下面 Wokwi 图相同）。电阻决定 LED 电流。对于正向电压约 2.0 V 的红色 LED，引脚为 HIGH 时 I = (5 V − 2.0 V) / 220 Ω = 13.6 mA，低于每个引脚建议的 20 mA（引脚自身的输出压降会让实际值略低）。占空比为 128 时，平均电流为 128 / 255 × 13.6 mA ≈ 6.8 mA。没有电阻时，只有引脚的输出电阻限制电流，引脚可能被驱动到超过 40 mA 的绝对最大值。

<CodeSource path="examples/month-2/arduino-io/pot_pwm/pot_pwm.ino" />

```cpp
// Potentiometer wiper on A0 sets the brightness of an LED on pin 9 (PWM).
const int POT_PIN = A0;
const int LED_PIN = 9;  // a pin marked ~ on the Uno

void setup() {
  pinMode(LED_PIN, OUTPUT);
  Serial.begin(115200);
}

void loop() {
  int raw = analogRead(POT_PIN);       // 0..1023
  int duty = raw / 4;                  // 0..255 for analogWrite
  float volts = raw * 5.0 / 1023.0;    // what the pin actually saw
  analogWrite(LED_PIN, duty);

  // "name:value" pairs separated by commas -> one line per trace in the Serial Plotter
  Serial.print("raw:");
  Serial.print(raw);
  Serial.print(",duty:");
  Serial.print(duty);
  Serial.print(",volts:");
  Serial.println(volts, 2);
  delay(20);  // ~50 lines per second is plenty for a human
}
```

即使用 `analogWrite()` 控制引脚，`pinMode(LED_PIN, OUTPUT)` 仍然不能少——它配置的是引脚的输出驱动器。`delay(20)` 把循环限制到每秒约 50 次。没有它，Uno 每秒会打印几千行，监视器快到看不清，串口本身还会成为瓶颈。人手转个旋钮，每秒 50 个样本足够，画图也足够。

同时打印原始值和换算后的值是有意为之：原始值告诉你 ADC 看到了什么，是排查接线的最好工具；duty 和 volts 告诉你程序接下来会做什么。当读数看起来不对时，你能立刻判断问题出在传感器还是出在换算。

## 串口：你最重要的调试工具

### 波特率必须一致

Arduino 没有屏幕。除了一颗 LED，它唯一能告诉你“自己在想什么”的方式就是串口。这个工具你会用上好几个月，所以一开始就得学对。

`Serial.begin(115200)` 把传输速度设为每秒 115200 比特，串口监视器（Serial Monitor）也必须设成同一个值。不一致时，接收方在错误的时刻采样每一位，每个字节都被解错：你看到的是满屏乱码，而不是文字。这不是板子坏了，也不是线坏了。看到 `⸮⸮⸮` 这类东西，先查<Term id="baud-rate">波特率</Term>（baud rate）菜单。9600 是老默认值，大量旧教程还在用；115200 更快，也是本课统一使用的值。

还有一个容易让人困惑的现象：打开串口监视器会拉低 Uno 的复位线，板子重新启动、`setup()` 再跑一遍。所以每次开窗都会看到 `ready`。这很正常，但也意味着你没法用监视器观察复位之前发生的事。

### 该打印什么

好的串口输出能回答一个问题。养成这些习惯：

- **每个值都加标签**。光写 `512`，可能是引脚、时间、计数或电压；写成 `raw:512` 就不会有歧义。
- **原始值和换算值都打印**。它们分别用于诊断不同的问题。
- **跟时间有关时打印时间戳**。`millis()` 返回上电以来的毫秒数，打印它就能量出一段代码真正花了多久。
- **在变化时打印，或控制在合理频率**。每秒 50 行读得过来，每秒 5000 行读不过来，还会拖慢程序。
- **用绘图器看趋势**。同样的 `名称:数值` 行，在监视器里是文字，在绘图器里就变成滚动曲线，看噪声或电位器卡顿容易得多。

### 隐藏的时间成本

串口输出不是免费的。在 115200 波特率下，线上每个字节按 10 位发送：1 位起始位、8 位数据位、1 位停止位，没有校验位。于是：

```text
one character = 10 bits / 115 200 bit/s = 86.8 µs ≈ 87 µs
40 characters = 40 × 86.8 µs = 3472 µs ≈ 3.5 ms
```

一条 40 字符的行需要约 3.5 ms 才能发完。听起来微不足道，每秒发一次也的确无所谓。但 Uno 的**发送缓冲区只有 64 字节**。`Serial.print()` 把文字拷进缓冲区就立刻返回，由硬件慢慢往外发；一旦缓冲区满了，下一次调用就会**阻塞**，直到有空位。如果一个循环每秒要打印一千条 40 字符的行，相当于每秒要发送 3.5 秒的内容，程序将大部分时间都在等串口，其他任务跟着卡顿。

还有 RAM 成本。在 Uno 上，字符串常量默认占 RAM，而你只有 2 KB。把常量文字用 `F()` 宏包起来，比如 `Serial.println(F("pressed"))`，字符串就会留在 flash 里、用到时才拷出来，省下宝贵的 RAM。这是个小习惯，但等你加上库和缓冲区之后，它会变得必不可少。

## 常见错误与检查清单

下面这些是你真的会遇到的坑，大致按出现频率排列：

- **忘了 `pinMode(pin, OUTPUT)`**。引脚默认是输入。此时 `digitalWrite(pin, HIGH)` 只是打开内部上拉电阻，而不是把引脚强驱动到 5 V，LED 只得到零点几毫安，顶多微亮甚至不亮。输出“没反应”时，先检查引脚模式。
- **直接用引脚驱动负载**。单个引脚安全输出约 **20 mA**，**40 mA 是绝对上限**，整颗芯片还有总电流限制。电机、继电器、LED 灯带动辄几百毫安，必须用三极管或 MOSFET 加独立电源，见第一个月。
- **输入引脚悬空**。没接线的按键引脚会随机读数。用 `INPUT_PULLUP` 或外接电阻，并记住此时按键另一端接的是 GND。
- **占用 D0 和 D1**。它们是 USB 串口线。外接电路接在这两个引脚上，会干扰上传和串口监视器。把电路挪到别的引脚去。
- **整数溢出**。Uno 的 `int` 到 32767 就到顶，10 位读数乘 1000 会溢出。乘法之前先用 `long` 或浮点数。
- **换算里的整数除法**。`raw * 5 / 1023` 只给出整数伏特，`raw / 1023` 则永远得 0。写上 `5.0` 或 `1023.0` 强制浮点运算。
- **开发板或端口选错**。代码编译成了别的芯片，或者上传到了别的设备。上传失败时，确认选的是 “Arduino Uno”，以及插板子时新出现的那个端口。
- **没有共地**。Arduino 和外接电路必须把 GND 连在一起。没有共同参考点，电压就没有意义、信号也会莫名其妙——哪怕其他每根线都接对了。

## I2C 上拉与总线电容时序

### 三种模式的上升时间限制，不是通用 300 ns

| Fm（Fast-mode） | **300 ns** |
| Fm+（Fast-mode Plus） | **120 ns** |

### RC 假设与共享流量

从 `V(t)/Vdd = 1 − exp(−t/(Rp Cbus))` 得到 **30 %–70 %** 上升时间 `tr = ln(7/3) Rp Cbus ≈ 0.8473 Rp Cbus`。从理想零电压到 70 % 则是 `t70 = −ln(0.3) Rp Cbus`，两者不能混用。Cbus 为**合成**：板 30 pF + 3 个器件 × 10 pF + 线电容（短线 40 pF、长线 340 pF），得到 **100 pF / 400 pF**。没有声称某个固定米数的电缆必然失败。

每臂传相同合成字节 **A5 00 FF 5A**：每字节 8 数据槽 + 1 ACK 槽，共 **36 个 SCL 释放沿**。这不是 TMP102 事务或 ACK 模拟器，只评估共享的时钟边沿。合成总线为 3.3 V，低相 **1500 ns**、释放高窗口 **1000 ns**、周期 **2500 ns**（400 kHz）。300 ns 上升限制占 2500 ns bit 周期的 **0.12**。不盲用 50 % 占空比，低相因此满足已打开的 1300 ns 最小值。稳定高电平时间为 `max(0, 1000 ns − t70)`，还要留出 600 ns 高电平要求。下降时间理想化为零，不是完整时序合规验证。慢边沿可能让接收方错过高电平或 ACK 时序；本模型只标风险，不观测真实失败。不能在未核对所有器件耐压时，把这些上拉改接 Uno 的 5 V 电源。

```python
    # ACK is a slot, NOT a simulated response. All slots release SCL once.
    return tuple(slot for byte in message for slot in
                 tuple((byte >> bit) & 1 for bit in range(7, -1, -1)) + (None,))
```

## RS-485：同样的 UART 字节走端接差分对
串口一节讲了 UART 帧格式（起始位、八个数据位、停止位）和波特率不匹配的样子。RS-485 保留这些帧，换的是导线。收发器把 TX 变成**差分对 A/B**，可以走几百米，并让多个节点共用。本节只讲这个物理层。它**不是**上面的波特率乱码，不是 CAN 错误计数（4.5 的 TEC/REC），不是 CRC，也**不是 Modbus** 或任何应用层协议。

**实际打开的资料。**

- **TI SLLA272（*The RS-485 Design Guide*，Rev. D）：**
  - 总线共模范围 **−7 V 到 +12 V**，最多 **32 个单位负载**。
  - 驱动器在 **54 Ω** 上至少输出 **1.5 V** 差分，接收器能检测低至 **200 mV** 的差分。
  - 工业双绞线 **Z0 = 120 Ω**，主干**两端各接 120 Ω** 端接。
  - 支线的电长度应短于驱动器上升时间的十分之一：`L_stub ≤ t_r/10 · v · c`。其表 6-1 对 100 ns 上升时间给出 **7 ft**。
  - 半双工时，驱动 / 接收使能（DE/RE）必须保证**同一时刻只有一个驱动器在驱动**（总线争用）。
- **Wikipedia RS-485：** 推荐线形（菊花链）拓扑而非星形；未端接端口的反射会破坏数据。
- **Arduino UART 指南：** UART 是异步的，没有共享时钟，两端只能依靠约定的波特率与帧格式。

这些文档里的数字以原文为准。各文档对极性的命名不同：Wikipedia 把二进制 1 写成 V_A − V_B < −200 mV。玩具里直接把正差分当作逻辑 1；请以你的收发器数据手册为准。

### 一行讲清反射

在 Z0 线上传播的波遇到阻抗 Z，反射系数为 `Γ = (Z − Z0)/(Z + Z0)`。120 Ω 端接给出 Γ = 0。未端接端（一个 12 kΩ 单位负载）**≈ +0.98**，20 Ω 驱动端 **−0.71**。支线从已端接主干末端引出处看到 120 Ω ∥ 120 Ω = 60 Ω，所以 Γ = **−1/3**。反射来回弹跳，直到线路稳定。如果接收器采样或等待起始位时弹跳还很大，UART 就会解出错误字节。差分接收是另一半：同等耦合到 A 和 B 上的噪声是共模，接收器会忽略它。

### 公平设置

`rs485_termination_toy.py` 是**合成**的，只用标准库。它用反射格（bounce lattice）线路模型驱动比较器和 UART 8N1 解码器；解码器在半个位处确认起始位，并在每一位中间采样。所有臂以**同一波特率**发送**同样的 17 个字节**，驱动器和主干也相同：

- **驱动器：** 戴维南 ±5 V、内阻 20 Ω，边沿 100 ns。
- **主干：** 120 m、120 Ω 双绞线，速度 0.78 c，即**单程 513 ns**，每程幅度保留 0.95。

所有臂还共享**每个种子同一串噪声**：τ = 200 ns 低通、σ = 2 V 的共模噪声（大部分时间落在 −7…+12 V 内），以及 0.08 V 差分噪声。差分接收器把 1 % 的共模噪声当作合成失配吃进去。

| 臂 | 线路与接收器 |
|---|---|
| A_term_diff | 主干两端各 120 Ω，差分接收器（±200 mV，中间保持原状态） |

```python
#!/usr/bin/env python3
"""Synthetic RS-485 line toy: lossy transmission-line bounce lattice + UART
(8N1) receiver. NOT a TDR measurement, NOT Modbus, NOT a CAN error counter.
Stdlib only.

Every arm sends the SAME 16 bytes at the SAME baud through the SAME Thevenin
driver (+-5 V open-circuit, 20 ohm, 100 ns linear edge), the same 120 m trunk
(Z0 = 120 ohm, velocity 0.78 c, 0.95 amplitude per pass) and the same per-seed
noise streams (common-mode and differential). Arms differ only in line
arrangement / receiver type:
  A_term_diff     120 ohm at both trunk ends, differential receiver (+-200 mV)
  B_unterm_diff   no termination, differential receiver
  B2_stub_diff    both ends terminated, receiver on a 15 m unterminated stub
  C_term_single   same terminated trunk, but one wire against ground: the
                  receiver sees the full common-mode noise (threshold at
                  half swing +- 200 mV hysteresis)
Differential receivers see 1 % of the common-mode noise (synthetic mismatch).
A 0 -> 1 noise glitch can create a false start bit: this is how ringing and
noise turn into byte errors in a UART receiver that samples mid-bit.
"""
import math
import random

Z0 = 120.0
RS = 20.0
VOPEN = 5.0
EDGE_NS = 100.0
VEL = 0.78 * 299_792_458.0
TRUNK_M = 120.0
STUB_M = 15.0
LOSS = 0.95
RIN = 12_000.0           # one unit load, receiver input
VTH = 0.2
CM_SIGMA = 2.0       # V, within the -7..+12 V common-mode range
CM_TAU_NS = 200.0
DIFF_SIGMA = 0.08
CM_LEAK = 0.01
PAYLOAD = bytes(b"RS485\x00\xff\x55\xaa\x0f\xf0 A/B!\n")
SEEDS = (0, 1, 2, 3, 4)
SCENARIOS = (("1Mbps", 1_000_000, 5.0), ("125kbps", 125_000, 20.0))
ARMS = ("A_term_diff", "B_unterm_diff", "B2_stub_diff", "C_term_single")


def par(a, b):
    return a * b / (a + b)


def bits_of(payload):
    out = [1] * 12                     # idle
    for byte in payload:
        out.append(0)                  # start
        out += [(byte >> k) & 1 for k in range(8)]   # LSB first
        out.append(1)                  # stop
    return out + [1] * 12


def drive(bits, spb, dt):
    """Thevenin open-circuit voltage with a linear edge of EDGE_NS."""
    edge = max(1, int(round(EDGE_NS / dt)))
    v = []
    level = VOPEN if bits[0] else -VOPEN
    for b in bits:
        target = VOPEN if b else -VOPEN
        start = level
        for k in range(spb):
            v.append(start + (target - start) * min(1.0, (k + 1) / edge))
        level = target
    return v


def lattice(vs, dt, arm):
    """Bounce-diagram simulation. Returns receiver differential voltage."""
    single = arm == "C_term_single"
    term = arm != "B_unterm_diff"
    stub = arm == "B2_stub_diff"
    rt_near = Z0 if term else None
    rth = par(RS, rt_near) if rt_near else RS
    gain = rt_near / (rt_near + RS) if rt_near else 1.0
    gs = (rth - Z0) / (rth + Z0)
    t1 = max(1, int(round(TRUNK_M / VEL / (dt * 1e-9))))
    t2 = max(1, int(round(STUB_M / VEL / (dt * 1e-9)))) if stub else 0
    r_tap = Z0 if term else RIN
    n = len(vs)
    fwd = [0.0] * n        # launched forward on trunk at source
    back = [0.0] * n       # launched backward on trunk at tap
    s_fwd = [0.0] * n      # launched forward into stub at tap
    rx = [0.0] * n
    g_rx = (RIN - Z0) / (RIN + Z0)
    for k in range(n):
        b_arr = LOSS * back[k - t1] if k >= t1 else 0.0
        fwd[k] = vs[k] * gain * Z0 / (rth + Z0) + gs * b_arr
        a = LOSS * fwd[k - t1] if k >= t1 else 0.0
        if stub:
            c = g_rx * s_fwd[k - t2] if k >= t2 else 0.0
            ytot = 2 / Z0 + 1 / r_tap
            v = 2 * (a / Z0 + c / Z0) / ytot
            back[k] = v - a
            s_fwd[k] = v - c
            rx[k] = (1 + g_rx) * s_fwd[k - t2] if k >= t2 else 0.0
        else:
            ytot = 1 / Z0 + 1 / r_tap
            v = 2 * (a / Z0) / ytot
            back[k] = v - a
            rx[k] = v
    return rx, t1 + t2


def noise(n, dt, seed):
    rng_cm = random.Random(10_000 + seed)
    rng_d = random.Random(20_000 + seed)
    a = math.exp(-dt / CM_TAU_NS)
    scale = CM_SIGMA * math.sqrt(1 - a * a)
    cm, d, x = [], [], rng_cm.gauss(0, CM_SIGMA)
    for _ in range(n):
        x = a * x + scale * rng_cm.gauss(0, 1)
        cm.append(x)
        d.append(rng_d.gauss(0, DIFF_SIGMA))
    return cm, d


def receive(v, single, swing):
    """Comparator with hysteresis -> logic stream."""
    hi, lo = (swing / 2 + VTH, swing / 2 - VTH) if single else (VTH, -VTH)
    state, out = 1, []
    for x in v:
        if x >= hi:
            state = 1
        elif x <= lo:
            state = 0
        out.append(state)
    return out


def uart_decode(logic, spb):
    out, framing, k = [], 0, 0
    n = len(logic)
    while k < n - 10 * spb:
        if logic[k] == 0 and logic[k - 1] == 1:
            if logic[k + spb // 2] != 0:
                k += 1
                continue              # glitch rejected by half-bit check
            byte = 0
            for j in range(8):
                byte |= logic[k + spb // 2 + (j + 1) * spb] << j
            if logic[k + spb // 2 + 9 * spb] != 1:
                framing += 1
            out.append(byte)
            k += spb // 2 + 9 * spb
        else:
            k += 1
    return out, framing


def byte_errors(sent, got):
    errs = sum(a != b for a, b in zip(sent, got)) + abs(len(sent) - len(got))
    first = next((j for j, (a, b) in enumerate(zip(sent, got)) if a != b), None)
    if first is None and len(sent) != len(got):
        first = min(len(sent), len(got))
    return errs, first


def run(arm, baud, dt, seed):
    spb = int(round(1e9 / baud / dt))
    bits = bits_of(PAYLOAD)
    vs = drive(bits, spb, dt)
    line, delay = lattice(vs, dt, arm)
    n = len(line)
    skip = 6 * spb   # ignore the power-up charging of the line during idle
    dc = line[skip - 1]   # settled idle (logic 1) level at the receiver
    cm, dn = noise(n, dt, seed)
    single = arm == "C_term_single"
    if single:
        # one wire swings 0..2*level, referenced to ground; same driver
        sig = [x + abs(dc) for x in line]
        rxv = [s + c for s, c in zip(sig, cm)]
        swing = 2 * abs(dc)
    else:
        rxv = [x + CM_LEAK * c + d for x, c, d in zip(line, cm, dn)]
        swing = 0.0
    logic = receive(rxv[skip:], single, swing)
    got, framing = uart_decode([1] + logic, spb)
    errs, first = byte_errors(PAYLOAD, bytes(got))
    sent_edges = sum(1 for a, b in zip(bits, bits[1:]) if a != b)
    rx_edges = sum(1 for a, b in zip(logic, logic[1:]) if a != b)
    # eye margin at the bit centres as seen by the receiver (after the line delay)
    edge = int(round(EDGE_NS / dt))
    centres = [(j * spb + spb // 2 + delay + edge // 2, bits[j]) for j in range(6, len(bits))]
    margin = min((rxv[c] - swing / 2) * (1 if b else -1) for c, b in centres if c < n) - VTH
    overshoot = max(abs(x) for x in line[skip:]) / max(abs(dc), 1e-9)
    idle_ma = 1000 * VOPEN / (RS + (Z0 / 2 if arm != "B_unterm_diff" else RIN))
    return errs, first, framing, rx_edges - sent_edges, margin, overshoot, idle_ma


def mean_sd(xs):
    mu = sum(xs) / len(xs)
    return mu, math.sqrt(sum((x - mu) ** 2 for x in xs) / (len(xs) - 1))
```

### 当作取舍来读

**1 Mbps、120 m 时**，端接差分对每个字节都解对，眼图余量 **3.16 V**。不端接时，每个种子都有 **17 个字节中的 16 个**出错，另有 2 个帧错误和 44 个多余跳变，峰值达到稳定电平的 **4.71×**。每个种子计数相同，因为原因是反射而不是噪声：往返约 1026 ns，差不多一个位，每次弹跳都落在后面的位上。15 m 支线在这个玩具里能正确解码（余量 **3.10 V**，过冲 **1.35×**）：违反支线规则在这里只损失余量、增加过冲，没有丢字节；练习 3 会把它推得更远。单端线用的是同样已端接的主干，却丢了 **6.60 ± 2.19** 个字节，因为没有任何东西抵消共模噪声。

**125 kbps 时**，不端接的线路也全部解对：弹跳早在位中点之前就平息了（过冲 **2.31×**）。端接也不是免费的：两只 120 Ω 让空闲总线从驱动器取 **62.50 mA**，不端接只有 **0.42 mA**。即便如此，这个玩具结果**不等于真实总线可以不端接**：SLLA272 说线路应当始终端接，而玩具没有失效保护偏置、没有更多节点，也没有真实电缆。单端臂仍然失败（**8.00 ± 1.58** 个字节），因为它的问题是共模噪声，不是反射。**不宣布赢家**：每个臂换来的东西不同，玩具也不是 TDR 或合规测试。真实收发器、电缆与 TDR：**本页未运行**。

**失效保护偏置：让空闲总线保持安静。** 没有节点发送时，所有驱动器都处于关闭状态，两只端接电阻把 A 与 B 拉向同一电压，于是差分电压接近 0 V。这落在接收器 ±200 mV 的不确定区间内，噪声可能翻转接收器输出，UART 也可能看到随机的起始位。失效保护偏置多加两只电阻：A 上拉到电源，B 下拉到地。它们与端接电阻构成分压器，在总线空闲时把 V_AB 保持在接收门限之外（|V_diff| ≥ 200 mV，再加上预期噪声）。接收器于是稳定读出逻辑 1，与 UART 空闲线的电平相同。SLLA272 第 7 节给出 V_AB = 200 mV + V_noise；在最低电源 4.75 V、V_AB = 0.25 V、Z0 = 120 Ω 时，用两只 523 Ω 的偏置电阻。它还指出，偏置最多增加 20 个单位负载，而现代收发器内置的失效保护只有约 10 mV 的噪声裕量。各厂商对 A、B 的标注并不一致，决定哪根线上拉之前请先看收发器数据手册。数值以原文为准，上面的玩具没有偏置。延伸阅读：TI SLLA070 第 3 节解释了空闲或开路总线为什么需要失效保护。

## ADC 有效位数：10 位并不总是 10 位

模拟输入一节把 Uno 的 ADC 当成理想 10 位尺：`V = raw × 5.0 / 1023`，一步约 4.9 mV。那是**标称**分辨率。前端噪声和轻微失真会在码字用尽之前就吃掉可用位数。本节只讲这个缺口。它**不是**第 1 个月的 DMM GUM 不确定度玩具，也**不是**再写一遍理想 10 位公式。

- **Wikipedia — Effective number of bits：** `ENOB = (SINAD_dB − 1.76) / 6.02`。ENOB 可以是小数；即使用 12 个码位的转换器，计入噪声与失真后有效位仍可能更少。

### 理想位数与有效位数

仅量化就会限制 SNR。步长 `q = V_ref / 2ⁿ` 时，理想正弦 SNR 为 `6.02n + 1.76` dB。反过来，任意测得的 SINAD 都可以映回有效位数：

<Formula label="由 SINAD 得到 ENOB">ENOB = (SINAD_dB − 1.76) / 6.02</Formula>

前端噪声或奇次谐波抬高非音调底时，SINAD 下降，ENOB 随之下降——即便转换器仍输出 10 位码字。

### 公平设定

`adc_enob_noise_toy.py` 是**合成**的，只用标准库。每个臂看到**同一**相干音调（1024 点中的第 17 根谱线，幅度为 0.95 × V_ref/2，绕中点）和**同一** n = 10、V_ref = 5 V 的 mid-riser 量化器：

| 臂 | 量化前的污染 |
|---|---|
| A_ideal | 无（只有量化） |
| B_noise | 加性高斯噪声，σ = 3.5 LSB |
| C_distort | 同样噪声 + 轻微奇次立方（归一化摆幅上 `k3 = 0.045`） |

指标来自相干 DFT：音调功率对仅噪声谱线（SNR）、对全部非音调谱线（SINAD），再由 SINAD 得到 ENOB。结果为五多种子的 mean±sd。玩具**不**声称测得了某颗芯片的 ENOB。

```python
#!/usr/bin/env python3
"""Synthetic ADC ENOB / front-end noise toy. Stdlib only.

Shared analog tone and shared sample aperture for every arm. Arms differ only
in front-end corruption before an ideal mid-riser n-bit quantizer:
  A_ideal       quantizer alone (quantization noise only)
  B_noise       same quantizer + additive front-end Gaussian noise
  C_distort     same noise + mild odd cubic nonlinearity

Metrics: SNR and SINAD from a coherent DFT tone bin, then
ENOB = (SINAD_dB - 1.76) / 6.02 (Wikipedia ENOB; TI SLAA013 ideal SNR
6.02n + 1.76 dB). Not a SAR datasheet measurement. Real ADC lab: 本页未运行.
"""
from __future__ import annotations

import cmath
import math
import random

N_BITS = 10
N_LEVELS = 1 << N_BITS
VREF = 5.0
LSB = VREF / N_LEVELS
FS_AMP = 0.95 * (VREF / 2.0)  # stay off the rails
N_SAMPLES = 1024
TONE_BIN = 17  # coherent: cycles = TONE_BIN over N_SAMPLES
NOISE_SIGMA = 3.5 * LSB  # front-end noise, synthetic
DISTORT_K3 = 0.045  # mild cubic on normalized swing, synthetic
SEEDS = (0, 1, 2, 3, 4)
ARMS = ("A_ideal", "B_noise", "C_distort")


def ideal_snr_db(n: int) -> float:
    return 6.02 * n + 1.76


def quantize(v: float) -> float:
    """Ideal mid-riser midtread-style clip to [0, VREF], return reconstructed volts."""
    code = int(math.floor(v / LSB))
    if code < 0:
        code = 0
    elif code > N_LEVELS - 1:
        code = N_LEVELS - 1
    # reconstruct at code centre
    return (code + 0.5) * LSB


def tone_samples() -> list[float]:
    """Shared clean full-scale-ish sine centered at VREF/2."""
    mid = VREF / 2.0
    out = []
    for k in range(N_SAMPLES):
        phase = 2.0 * math.pi * TONE_BIN * k / N_SAMPLES
        out.append(mid + FS_AMP * math.sin(phase))
    return out


def apply_arm(clean: list[float], arm: str, seed: int) -> list[float]:
    rng = random.Random(10_000 + seed)
    mid = VREF / 2.0
    out = []
    for v in clean:
        x = v
        if arm in ("B_noise", "C_distort"):
            x = x + rng.gauss(0.0, NOISE_SIGMA)
        if arm == "C_distort":
            # odd cubic on swing about mid; shared coefficient, not a datasheet INL
            u = (x - mid) / (VREF / 2.0)
            x = mid + (VREF / 2.0) * (u + DISTORT_K3 * (u ** 3))
        out.append(quantize(x))
    return out


def dft_bin(xs: list[float], bin_k: int) -> complex:
    n = len(xs)
    acc = 0j
    for k, x in enumerate(xs):
        acc += x * cmath.exp(-2j * math.pi * bin_k * k / n)
    return acc


def snr_sinad(xs: list[float]) -> tuple[float, float]:
    """Return (SNR_dB, SINAD_dB) from coherent single-tone DFT."""
    n = len(xs)
    # remove DC
    mean = sum(xs) / n
    yc = [x - mean for x in xs]
    # positive bins 1 .. n/2-1; tone at TONE_BIN; image at n-TONE_BIN ignored as conjugate
    tone = dft_bin(yc, TONE_BIN)
    # power: |X|^2 for one-sided use 2*|X|^2/n^2 for sinusoid amplitude^2/2
    tone_p = 2.0 * (abs(tone) ** 2) / (n * n)
    # noise+distortion: all other bins except DC and Nyquist twin
    nd_p = 0.0
    noise_only_p = 0.0
    harmonics = {2 * TONE_BIN, 3 * TONE_BIN, 4 * TONE_BIN, 5 * TONE_BIN}
    harmonics = {h for h in harmonics if 0 < h < n // 2}
    for k in range(1, n // 2):
        if k == TONE_BIN:
            continue
        p = 2.0 * (abs(dft_bin(yc, k)) ** 2) / (n * n)
        nd_p += p
        if k not in harmonics:
            noise_only_p += p
    # floor guards
    snr = 10.0 * math.log10(tone_p / max(noise_only_p, 1e-30))
    sinad = 10.0 * math.log10(tone_p / max(nd_p, 1e-30))
    return snr, sinad


def enob(sinad_db: float) -> float:
    return (sinad_db - 1.76) / 6.02


def mean_sd(xs: list[float]) -> tuple[float, float]:
    mu = sum(xs) / len(xs)
    var = sum((x - mu) ** 2 for x in xs) / (len(xs) - 1)
    return mu, math.sqrt(var)


def main() -> None:
    clean = tone_samples()
    print(
        "Synthetic ADC ENOB toy; shared tone/aperture; not a datasheet SAR measurement"
    )
    print(
        f"n_bits={N_BITS} Vref={VREF:.1f}V LSB={LSB*1e3:.4f}mV N={N_SAMPLES} "
        f"tone_bin={TONE_BIN} fs_amp={FS_AMP:.4f}V "
        f"noise_sigma={NOISE_SIGMA/LSB:.2f}LSB distort_k3={DISTORT_K3} seeds={len(SEEDS)}"
    )
    print(
        f"ideal_SNR_formula={ideal_snr_db(N_BITS):.2f}dB "
        f"(TI SLAA013 / Wikipedia: 6.02n+1.76); ENOB=(SINAD-1.76)/6.02"
    )
    print("arm SNR_dB SINAD_dB ENOB_bits (mean+-sd over seeds)")
    for arm in ARMS:
        snrs, sinads, enobs = [], [], []
        for seed in SEEDS:
            xs = apply_arm(clean, arm, seed)
            snr, sinad = snr_sinad(xs)
            snrs.append(snr)
            sinads.append(sinad)
            enobs.append(enob(sinad))
        cols = [mean_sd(snrs), mean_sd(sinads), mean_sd(enobs)]
        print(
            f"{arm} "
            + " ".join(f"{m:.3f}+-{s:.3f}" for m, s in cols)
        )
    print(
        "No winner declared: noise and distortion trade differently; "
        "toy ENOB is not a measured chip rating"
    )
    print("Real ADC / scope / INA lab: 本页未运行; Wikipedia+TI numbers 以原文为准")


if __name__ == "__main__":
    main()
```

3. 多种子不变，把 `NOISE_SIGMA` 加倍。运行前预测哪些臂会动，以及 C 的 SNR–SINAD 间隙会缩小还是变大。
4. 设 `DISTORT_K3 = 0`，确认 C 向 B 靠拢。说明哪个指标必须一致、哪个仍可能略有差别。
5. 任何真机实验前（本页未运行），列出本玩具省略的孔径抖动、参考噪声与 INL；不要把玩具 ENOB 当成芯片指标。

## 光耦隔离：CTR、LED 电流与隔离屏障

<Resource id="wiki-opto" />

上面各节的输入引脚都和驱动它们的东西共用 Arduino 的地。机器上一个 24 V 的传感器或继电器触点就不是这样：电机启动或线缆拾取浪涌时，它的地可能跳动几十伏。**实际打开的来源（已读 HTML 正文）。** **Wikipedia — Opto-isolator**（修订版 1381742785；以原文为准）：光耦用光在两个相互隔离的电路之间传递电信号，防止一侧的高电压影响接收端。条目说市售器件能承受最高 10 kV 的输入–输出电压和速度最高 25 kV/μs 的电压瞬变，它的主要作用就是挡住这类高电压和瞬变，它也能断开地环路。它是**单向**的（条目也提到例外），**不能传输功率**，典型器件只能调制输出侧已有的能量，所以 MCU 一侧仍要有自己的电源和上拉。它的电流传输比（**CTR**）表列出：光电二极管型 0.1–0.2 %，光电晶体管型 2–120 %，达林顿型 100–600 %。条目提醒，设计时要给参数波动留出充足余量，数据手册列的是最坏值；它还引用 Bob Pease 的观察：同一生产批次的 4N28，CTR 从 15 % 到 100 % 以上不等，而手册只给出最小值 10 %。这些都是条目的陈述，以原文为准；下面没有一条是玩具的输出。

本节**不是**上面的 RS-485 一节：RS-485 保留共地，只在收发器允许的共模范围内抗共模噪声，而光耦去掉的是电气上的直接通路。它也**不是** ADC ENOB 一节，更**不是**耐压或浪涌实验室测试。真实光耦、厂商 CTR 曲线和隔离测试仪都**本页未运行**。

<Formula label="带上拉的光电晶体管输出（声明的玩具模型）">I_C = min(CTR · I_F, (VCC − VCE_SAT) / RL);   V_out = max(VCE_SAT, VCC − I_C · RL) with the LED on, VCC with it off;   pin < V_IL reads 0, pin > V_IH reads 1</Formula>

**算例（手算，玩具也会打印）。** 取 `VCC = 3.3 V`、`RL = 4700 Ω`、`VCE_SAT = 0.2 V`，把引脚完全拉低所需的集电极电流是 `(3.3 − 0.2) / 4700 = 0.6596 mA`。按玩具的标称 CTR 50 %，至少要 `0.6596 / 0.5 = 1.3191 mA` 的 LED 电流。10 mA 的臂余量很大。1 mA 的臂只得到 `0.5 × 1 mA = 0.5000 mA`，引脚只降到 `3.3 − 0.5000 mA × 4700 Ω = 0.9500 V`，刚好低于 `V_IL = 0.9900 V`：器件稍弱一点就落进无效区。如果 CTR 老化到四分之一，同样的 1 mA 只给出 `0.1250 mA`，引脚停在 `2.7125 V`，高于 `V_IH = 2.3100 V`，点亮的 LED 被读成熄灭。直连路径上，玩具里最大的浪涌会在这个模型中额定 `3.6000 V` 的引脚上加 `200 V × 0.1 = 20.0000 V`。

**积分步长。** 无：每一位都是一个静态工作点，没有 LED 或光电晶体管的时间常数（不模拟上升、下降时间）。

### 公平设置

`optocoupler_ctr_isolation_toy.py` 是**合成**的，只用标准库。**模型假设:** CTR 是集总的，不随电流和温度变化；单个光电晶体管，`VCE_SAT` 固定；读取阈值 `V_IL = 0.3 × VCC`、`V_IH = 0.7 × VCC`；直连路径是 24 V 现场信号经分压（`3.0 / 24`）接入，并且共地，所以现场侧共模浪涌中声明的一部分 `K_CM = 0.1` 会到达引脚；隔离屏障另一侧只有 `K_ISO = 1e-4` 到达，作为杂散电容的替身。每个（工况，种子）一个光耦器件，`CTR = 0.5 × exp(0.3 g)`，两个光耦臂共用。所有数值都是**声明的玩具参数**，不是任何器件的手册值。

| 臂 | 到引脚的路径 | LED 电流 |
|---|---|---|
| A_direct | 24 V 信号经分压，共地 | 无 |
| B_opto | 光耦，带上拉的反相输出 | 10 mA |
| C_underdriven | 同一个光耦器件 | 1 mA |

**共用随机数:** 每个（工况，种子）用一个随机流先抽器件的 CTR 系数，再为 200 位中的每一位抽现场位、引脚噪声（sd 0.05 V）、浪涌标志（概率 0.2）和浪涌大小（20 到 200 V），全部在任何臂运行之前抽好，三个臂共用。五个种子。指标：`logic_err`（读错或落在无效区的位的比例）和 `overvolt`（引脚超过 3.6 V 的位的比例），都按种子给出均值±sd。

| 工况 | 现场侧 | 预先声明 |
|---|---|---|
| quiet_legal | 无浪涌，标称 CTR | A 与 B 的 logic_err **可能**近似平局或打平，**保留**；C 如实给出 |
| surge | 20 % 的位上有共模浪涌 | B 的 overvolt 和 logic_err **一致**低于 A（直连 GPIO 输），**保留** |
| low_ctr | 无浪涌，CTR 老化到四分之一 | C 的 logic_err **一致**高于 B，并且**可能**输给 A，**保留** |

```python
#!/usr/bin/env python3
"""Synthetic optocoupler (opto-isolator) CTR and galvanic-isolation toy for a
microcontroller digital input. Stdlib only.

Every constant below is a DECLARED TOY PARAMETER, not a datasheet value: no
vendor part, no real isolation rating, no CTR curve. A 24 V field signal reaches
a 3.3 V input pin either directly through a divider that shares ground (A), or
through an optocoupler whose LED is driven at 10 mA (B) or 1 mA (C).

Opto output (inverting, LED on -> pin pulled low):
  I_avail = CTR * I_F, I_sat = (VCC - VCE_SAT) / RL
  V_out = max(VCE_SAT, VCC - min(I_avail, I_sat) * RL) with the LED on, VCC off.
Read rule: pin < V_IL -> 0, pin > V_IH -> 1, in between -> invalid (an error).
The direct pin sees bit*V_FIELD*K_DIV + K_CM*v_cm + noise; the opto pin sees only
K_ISO*v_cm of the field-side common-mode surge v_cm (a stray-capacitance stand-in).
CTR is lumped: one part per (regime, seed), CTR = CTR_NOM * exp(0.3 g), shared by
both opto arms (same part, different LED current); low_ctr ages it by AGE.

Common random numbers: one random.Random(f"{regime}/{seed}") stream per
(regime, seed) draws g, then for every bit the field bit, the pin noise, the
surge flag and the surge amplitude, in that fixed order, before any arm is
evaluated; all arms share them.

Regimes and parameters were written before the first run.

Labels: tie = identical on every seed; numerically zero = |paired mean| and sd
both < 1e-9; |m| <= sd = near-tie; |m| > sd = consistent gap (small if |m| < 20 %
of the smaller arm mean, else clear), with a sign count. ROUND_HALF_UP output.
Not an RS-485 or ADC model. Real coupler / isolation tester: 本页未运行.
"""
import math
import random
from decimal import ROUND_HALF_UP, Decimal, getcontext

getcontext().rounding = ROUND_HALF_UP

SEEDS = (0, 1, 2, 3, 4)
NUM_ZERO = 1e-9

VCC = 3.3
RL = 4700.0
VCE_SAT = 0.2
V_IL = 0.3 * VCC
V_IH = 0.7 * VCC
ABS_MAX = VCC + 0.3
V_FIELD = 24.0
K_DIV = 3.0 / 24.0
K_CM = 0.1
K_ISO = 1e-4
CTR_NOM = 0.5
CTR_SPREAD = 0.3
SIG_PIN = 0.05
N_BITS = 200
P_SURGE = 0.2
SURGE_LO, SURGE_HI = 20.0, 200.0
AGE = 0.25
I_F_B = 10e-3
I_F_C = 1e-3

METRICS = ("logic_err", "overvolt")
ARMS = ("A_direct", "B_opto", "C_underdriven")
PAIRS = (("B", "A"), ("C", "B"), ("C", "A"))

# name: (surge on?, CTR age factor, declared expectation); written before the first run
REGIMES = {
    "quiet_legal": (False, 1.0, "A vs B may near-tie (or tie) on logic_err - keep; C as it comes"),
    "surge": (True, 1.0, "B consistently below A on overvolt and logic_err (direct GPIO loses) - keep"),
    "low_ctr": (False, AGE, "C consistently above B on logic_err (under-driven coupler loses) and may lose to A on logic_err - keep"),
}


def mean_sd(xs):
    if all(x == xs[0] for x in xs):
        return xs[0], 0.0  # identical values: no floating residue in mean or sd
    mu = sum(xs) / len(xs)
    return mu, math.sqrt(sum((x - mu) ** 2 for x in xs) / (len(xs) - 1))


def num(x):
    """Half-up rounding on the shortest decimal repr; tiny non-zero values in scientific form."""
    if x != 0.0 and abs(x) < 5e-4:
        return format(Decimal(repr(x)), ".3e")
    s = format(Decimal(repr(x)), ".4f")
    return "0.0000" if s == "-0.0000" else s


def sign_note(diffs, m):
    n, opp, zero = len(diffs), sum(1 for d in diffs if d * m < 0), sum(1 for d in diffs if d == 0)
    if opp == 0 and zero == 0:
        return f"same sign on all {n} seeds"
    if opp == 0:
        return f"no seed has the opposite sign, {zero} of {n} equal"
    note = f"{opp} of {n} seeds {'has' if opp == 1 else 'have'} the opposite sign"
    return note + (f", {zero} of {n} equal" if zero else "")


def fmt_pair(m, s):
    return f"{num(m)}+-{num(s)}"


def verdict(xa, xb):
    diffs = [a - b for a, b in zip(xa, xb)]
    if all(d == 0.0 for d in diffs):
        return "0.0000+-0.0000: tie: identical on every seed"
    m, s = mean_sd(diffs)
    if abs(m) < NUM_ZERO and s < NUM_ZERO:
        return f"{fmt_pair(m, s)}: numerically zero (floating-point residue), effectively a tie"
    if abs(m) <= s:
        label = "near-tie / small gap, within seed noise (|m| <= sd)"
    elif abs(m) < 0.2 * min(abs(mean_sd(xa)[0]), abs(mean_sd(xb)[0])):
        label = "small but consistent gap, not a tie (|m| > sd)"
    else:
        label = "clear gap, not a tie (|m| > sd)"
    return f"{fmt_pair(m, s)}: {label}; {sign_note(diffs, m)}"


def draws(regime, seed):
    rng = random.Random(f"{regime}/{seed}")
    g = rng.gauss(0.0, 1.0)
    bits = []
    for _ in range(N_BITS):
        bit = 1 if rng.random() < 0.5 else 0
        noise = rng.gauss(0.0, SIG_PIN)
        flag = rng.random() < P_SURGE
        v_cm = rng.uniform(SURGE_LO, SURGE_HI)
        bits.append((bit, noise, flag, v_cm))
    return g, bits


def read_pin(v):
    if v < V_IL:
        return 0
    if v > V_IH:
        return 1
    return None


def opto_out(bit, ctr, i_f, rl):
    if not bit:
        return VCC
    i_sat = (VCC - VCE_SAT) / rl
    return max(VCE_SAT, VCC - min(ctr * i_f, i_sat) * rl)


def run_arm(arm, g, bits, surge_on, age, k_cm=K_CM, rl=RL, i_f_c=I_F_C):
    ctr = CTR_NOM * math.exp(CTR_SPREAD * g) * age
    err = over = 0
    for bit, noise, flag, v_cm in bits:
        cm = v_cm if (surge_on and flag) else 0.0
        if arm == "A_direct":
            pin = bit * V_FIELD * K_DIV + k_cm * cm + noise
            got = read_pin(pin)
        else:
            i_f = I_F_B if arm == "B_opto" else i_f_c
            pin = opto_out(bit, ctr, i_f, rl) + K_ISO * cm + noise
            r = read_pin(pin)
            got = None if r is None else 1 - r
        if got != bit:
            err += 1
        if pin > ABS_MAX:
            over += 1
    return {"logic_err": err / N_BITS, "overvolt": over / N_BITS}


def run_regime(regime, **kw):
    surge_on, age, _ = REGIMES[regime]
    out = {a: {m: [] for m in METRICS} for a in ARMS}
    for seed in SEEDS:
        g, bits = draws(regime, seed)
        for a in ARMS:
            r = run_arm(a, g, bits, surge_on, age, **kw)
            for m in METRICS:
                out[a][m].append(r[m])
    return out


def letter(arm):
    return arm[0]


def by_letter(res, x):
    return next(v for k, v in res.items() if letter(k) == x)


def main():
    print("Synthetic optocoupler CTR and isolation toy: direct GPIO vs a well-driven and an under-driven coupler")
    print("every constant is a declared toy parameter, not a datasheet value; real coupler / isolation tester: 本页未运行")
    print(f"VCC={num(VCC)} V RL={num(RL)} ohm VCE_SAT={num(VCE_SAT)} V V_IL={num(V_IL)} V V_IH={num(V_IH)} V ABS_MAX={num(ABS_MAX)} V")
    print(f"V_FIELD={num(V_FIELD)} V K_DIV={num(K_DIV)} K_CM={num(K_CM)} K_ISO={num(K_ISO)} CTR_NOM={num(CTR_NOM)} CTR spread exp(0.3 g) SIG_PIN={num(SIG_PIN)} V")
    print(f"N_BITS={N_BITS} P_SURGE={num(P_SURGE)} v_cm uniform({num(SURGE_LO)}, {num(SURGE_HI)}) V AGE={num(AGE)} I_F B={num(I_F_B * 1e3)} mA C={num(I_F_C * 1e3)} mA")
    print("Regimes and parameters were written before the first run")
    i_sat = (VCC - VCE_SAT) / RL
    print(f"hand_calc I_sat = (3.3 - 0.2)/4700 = {num(i_sat * 1e3)} mA collector current to pull the pin to VCE_SAT")
    print(f"hand_calc minimum I_F at CTR_NOM = I_sat/CTR_NOM = {num(i_sat / CTR_NOM * 1e3)} mA")
    print(f"hand_calc C at nominal CTR: I_C = 0.5 x 1 mA = 0.5000 mA -> V_out = 3.3 - 0.5e-3 x 4700 = {num(VCC - 0.5e-3 * RL)} V against V_IL = {num(V_IL)} V")
    print(f"hand_calc worst surge on the direct pin = 200 x K_CM = {num(SURGE_HI * K_CM)} V against ABS_MAX = {num(ABS_MAX)} V")
    print(f"hand_calc aged C: I_C = 0.25 x 0.5 x 1 mA = {num(AGE * CTR_NOM * 1e-3 * 1e3)} mA -> V_out = {num(VCC - AGE * CTR_NOM * 1e-3 * RL)} V, above V_IH = {num(V_IH)} V")
    for regime, (surge_on, age, declared) in REGIMES.items():
        res = run_regime(regime)
        print(f"{regime}:")
        print(f"  declared: {declared}")
        for a in ARMS:
            print("  " + a + " " + " ".join(f"{m} {fmt_pair(*mean_sd(res[a][m]))}" for m in METRICS))
        for x, y in PAIRS:
            for m in METRICS:
                print(f"  paired {x}-{y} {m}: {verdict(by_letter(res, x)[m], by_letter(res, y)[m])}")
    print("alternative parameters (declared before the run, same seeds, not adopted):")
    r = run_regime("low_ctr", rl=10000.0)
    print(f"  low_ctr with RL = 10000 ohm: paired C-B logic_err: {verdict(r['C_underdriven']['logic_err'], r['B_opto']['logic_err'])}")
    r = run_regime("surge", k_cm=0.02)
    print(f"  surge with K_CM = 0.02: paired B-A overvolt: {verdict(r['B_opto']['overvolt'], r['A_direct']['overvolt'])}")
    r = run_regime("low_ctr", i_f_c=2e-3)
    print(f"  low_ctr with C at I_F = 2 mA: paired C-B logic_err: {verdict(r['C_underdriven']['logic_err'], r['B_opto']['logic_err'])}")

    print("Real coupler / isolation tester / vendor CTR curve: 本页未运行; Wikipedia figures 以原文为准")
```

### 读三个工况

本页标签按以下顺序使用：只有每个种子的配对差都恰好为零才叫 **tie: identical on every seed**；`|配对均值|` 与其 sd 都小于 1e-9 时叫 **numerically zero (floating-point residue), effectively a tie**；`|配对均值| ≤ sd` 时叫 **near-tie / small gap, within seed noise**；否则是**一致**的差距（`|配对均值| > sd`），`|m|` 小于两臂均值中较小者的 20 % 时叫 **small**，否则叫 **clear**。每条一致的结果都带 5 个种子上的同号计数。配对差为 B−A、C−B 和 C−A。每个工况有自己的随机流，所以光耦器件以及 C 的余量在不同工况之间不同。

- **quiet_legal。** 直连引脚和驱动充足的光耦每一位都读对：B−A `logic_err` 是 **tie: identical on every seed**。声明**成立**。C 臂（驱动不足的光耦）读错 0.1930±0.2643 的位，C−B 是**近似平局**，没有种子反号，5 个中有 3 个相等：三个种子上器件够强，另外两个种子上它落进无效区，正如 0.9500 V 的手算所提醒的。
- **surge。** 直连引脚在 0.1790±0.0444 的位上超过 3.6 V，读错 0.1050±0.0158；驱动充足的光耦两样都没有。B−A `overvolt` 为 -0.1790±0.0444，B−A `logic_err` 为 -0.1050±0.0158，都是 **clear**，5 个种子全部同号。声明**成立**。驱动不足的光耦同样把浪涌挡在引脚之外（C−A `overvolt` -0.1790±0.0444，clear），但读错 0.3510±0.1996 的位：C−B `logic_err` 0.3510±0.1996，C−A `logic_err` 0.2460±0.2007，标签都是 clear，C−A 有 1 个种子反号。屏障保护了引脚，却没有让弱驱动读对。
- **low_ctr。** CTR 老化到四分之一时，10 mA 仍能让输出饱和，B 每一位都读对；1 mA 则在 LED 点亮时让引脚落在无效区或高电平：C−B `logic_err` 为 0.5260±0.0475，clear，5 个种子全部同号，C−A 同样是 0.5260±0.0475。声明**成立**，这个输也**保留**。在逻辑电平上，驱动不足的光耦连没有遭受浪涌的普通直连引脚都比不过。这是逻辑电平上的输，不是隔离上的输。

**没有成立的预先声明。** 这个玩具里没有：quiet 的打平、surge 中直连引脚的输和 low_ctr 中 C 的输都成立。有两个结果没有预先声明：quiet_legal 里 C 的近似平局掩盖了两个坏种子；surge 里 C 读错的位比直连引脚还多，但仍然保护了引脚。

**首次运行后的代码改动。** 无。玩具按写好的样子运行了一次，首次输出与 `expected/` 文件逐字节相同。

**看到结果后做的选择。** 无。阈值、驱动电流、CTR 分布、浪涌模型和三个打印的备选都在首次运行前写定，并在相同种子上运行。low_ctr 上改用 10 kΩ 上拉，C−B `logic_err` 仍是 0.5260±0.0475；浪涌份额减小到 `K_CM = 0.02`，B−A `overvolt` 仍为 -0.0980±0.0323，clear；low_ctr 上把 C 的驱动加到 2 mA，C−B 仍是 0.5260±0.0475。它们都没有替换默认设置。

本页**不宣布通用的赢家**。只有在驱动仍能让输出饱和的前提下，屏障才能把现场浪涌挡在引脚之外：LED 电流乘以最坏情况的 CTR，必须留有余量地超过手算出的集电极电流。真实光耦与隔离测试仪都**本页未运行**。

**本课要点**

- Uno（ATmega328P）：16 MHz，32 KB 闪存（其中 0.5 KB 为引导程序），2 KB RAM，5 V 逻辑；3.3 V 引脚最多提供 50 mA。
- 每个数字输入都需要确定的电平：用 `INPUT_PULLUP`（20–50 kΩ）并将按键接到 GND 时，松开读 HIGH、按下读 LOW。
- 10 位 ADC：V = raw × 5.0 / 1023（Arduino 的惯例写法），一步 = 5 V / 1024 ≈ 4.9 mV，一次转换 13 / 125 kHz = 104 µs。
- Uno 上的 `int` 是 16 位（最大 32767）：读数参与乘法之前，先写成 `5.0` 或改用 `long`。
- PWM：`analogWrite` 把占空比设为 value / 255，引脚 3、9、10、11 为 490 Hz，引脚 5、6 为 976.6 Hz；负载看到 V_avg = 占空比 × 5 V。
- 引脚上的 LED 需要串联电阻：5 V 下 220 Ω 为 2.0 V 红色 LED 提供 13.6 mA。
- 115200 波特率下一个字符需要 86.8 µs；64 字节发送缓冲区写满后，`Serial.print()` 会阻塞。

- I2C RC 在固定字节下筛查 Sm/Fm/Fm+ 上升限制与 bit / 高电平 / 灌电流预算，不把标志当成实测丢包。

- RS-485 把同样的 UART 帧放到差分对上，主干两端各接 120 Ω；在共享载荷的反射玩具里，不端接的 120 m 线路在 1 Mbps 下 17 个字节错 16 个，在 125 kbps 下一个不错，端接代价是 62.50 mA 空闲驱动电流，单端线在两种速率下都因共模噪声失败。

- ENOB 把测得的 SINAD 换成有效位：共享音调下理想约 9.92 位，加前端噪声约 6.32 位，再加轻微失真约 5.84 位——码字仍是 10 位，不是手册额定值。
