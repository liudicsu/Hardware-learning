## 为什么 delay() 会毁掉机器人

机器人从来不会一次只做一件事。行驶时它还要盯着避障传感器、以固定频率跑控制环、让状态 LED 闪烁、随时接收串口指令。Arduino 只有一颗小 CPU 和一个 `loop()`，任何让 `loop()` 停下的东西，都会把这些工作一起停掉。

`delay(1000)` 就是典型例子。它的意思不是“亮着 LED 同时继续干别的”，而是“整个程序在这里停一秒”。这一秒里不读传感器、不看按键、不更新电机、也不处理串口字节。闪灯是人的时间尺度，机器人不是。

算一笔小机器人以 0.5 m/s 行驶的账：

```text
机器人速度：      0.5 m/s
delay() 时长：    1000 ms = 1 s
行驶距离：        0.5 m/s × 1 s = 0.5 m
换算成厘米：      0.5 m × 100 = 50 cm
```

五十厘米的“盲开”。常见避障传感器也许只看 20–40 cm，机器人很容易在这段盲区里撞上桌腿；等 delay 结束再读，拿到的也是 50 cm 前的旧世界。按键同样：一次在 delay 里开始又结束的按下，程序根本不知道。串口缓冲区也会被塞满，字符丢失。控制环还会忽快忽慢。

所以主循环的原则是：永远不等。每一轮只问“现在有什么事到期？”，看一眼时钟，做完就返回。状态 LED 要每 250 ms 翻转，不需要占用 CPU 250 ms，只需要一个时间戳和一次比较。

## millis() 计时模式

`millis()` 返回复位以来的毫秒数，类型是 `unsigned long`，Uno 上为 32 位。它不阻塞：只是读一个由<Term id="hardware-timer">硬件定时器</Term>在后台累加的计数器，然后立刻返回。这是非阻塞计时（non-blocking timing）的基础。

模式分三步：在 `loop()` 开头取一次时钟；用当前时间减去上次执行的时间戳，与周期比较；到期就推进时间戳并执行任务：

```text
if (now - last >= PERIOD) {
  last += PERIOD;
  ...do the thing...
}
```

`last` 和 `now` 都是 `unsigned long` 时间戳。减法得到经过的时间，比较是在问“是否至少过去一个完整周期”。没到期就跳过，继续往下走。

下面这个完整程序让两颗 LED 以不同频率闪烁：

<CodeSource path="examples/month-2/timing-interrupts/two_blinks/two_blinks.ino" />

```cpp
// Two LEDs blinking at different rates, no delay() anywhere.
const int LED_A = 8;
const int LED_B = 9;
const unsigned long PERIOD_A = 250;  // ms between toggles
const unsigned long PERIOD_B = 400;

unsigned long lastA = 0;
unsigned long lastB = 0;
bool stateA = false;
bool stateB = false;

void setup() {
  pinMode(LED_A, OUTPUT);
  pinMode(LED_B, OUTPUT);
  Serial.begin(115200);
}

void loop() {
  unsigned long now = millis();

  if (now - lastA >= PERIOD_A) {
    lastA += PERIOD_A;          // keep a steady rhythm
    stateA = !stateA;
    digitalWrite(LED_A, stateA);
    Serial.print(now);
    Serial.println(" A");
  }

  if (now - lastB >= PERIOD_B) {
    lastB += PERIOD_B;
    stateB = !stateB;
    digitalWrite(LED_B, stateB);
    Serial.print(now);
    Serial.println(" B");
  }

  // ...room for reading sensors, here, every pass through loop()
}
```

`lastA` 从 0 开始，所以第一次翻转在 250 ms 而不是 0 ms，通常正合适。若某任务要立刻执行一次，可把时间戳初始化成 `millis() - PERIOD`，或在 `setup()` 里先调用一次。

### millis() 背后的硬件定时器

`millis()` 背后的计数器是 Timer0，它是 ATmega328P 三个硬件定时器之一。Arduino 核心把它的预分频设为 64，因此 Timer0 每 64 个时钟周期前进一次，其 8 位计数器每 256 次计数溢出一次。每次溢出都会触发一个中断，其处理程序（核心 `wiring.c` 中的 `TIMER0_OVF_vect`）负责更新毫秒计数：

```text
one count      = 64 / 16 MHz = 4 µs
one overflow   = 256 × 4 µs = 1024 µs = 1.024 ms
per second     = 1 s / 1.024 ms = 976.5625 overflows
```

一次溢出是 1.024 ms，而不是 1 ms。因此处理程序每次溢出加 1 ms，并把多出来的 24 µs 累积到一个分数计数器中；每当这个分数累积满一毫秒，就再补 1 ms。第一次修正在第 42 次溢出时到来，此时为 43.008 ms，`millis()` 会从 41 直接跳到 43；平均每秒发生 976.5625 × 3 / 125 = 23.4375 次修正，所以平均每秒增加 976.5625 + 23.4375 = 1000 次。`millis()` 平均而言是准确的，但分辨率只有 1 ms，而且偶尔会跳过一个值，因此绝不要用 `millis() == target` 做判断。`micros()` 读取同一个计数器，分辨率为 4 µs。Timer0 也是第 1 课中在引脚 5 和 6 上产生 976.6 Hz PWM 的那个定时器。

### last += PERIOD 与 last = now 的区别

两种写法都能闪灯，但 `loop()` 迟到时行为不同。迟到很常见：慢速串口打印、传感器转换、耗时库函数。问题是：这点迟到被忘掉，还是加到之后每个周期上。

假设周期是 250 ms，每次翻转都被晚了 3 ms 才处理：

```text
周期 = 250 ms，每次翻转都晚 3 ms 才被处理

last = now：
  第 1 次翻转在 250 + 3 = 253 ms，last = 253
  第 2 次在 253 + 250 + 3 = 506 ms，last = 506
  ……
  第 10 次在 10 × 253 = 2530 ms

last += PERIOD：
  第 1 次在 253 ms，但 last = 250
  第 2 次应在 500 ms，实际 503 ms，last = 500
  ……
  第 10 次在 2500 + 3 = 2503 ms
```

用 `last = now`，每个周期实际变成 253 ms，误差会累积：100 次后慢 300 ms，1000 次后慢 3 s。控制环频率会慢慢变化，比固定偏移更糟。用 `last += PERIOD`，时间表锚定在 250 ms 的整数倍上；每次仍晚 3 ms，但不累积，长期平均精确为 250 ms。

注意：若任务耗时超过一个周期，`last += PERIOD` 更新后可能仍在过去，下一轮会立刻补跑。这通常正是时间表想要的；若宁愿丢掉漏掉的节拍，就用 `last = now` 或把时间戳向前钳位。

## millis() 溢出，以及为什么减法是安全的

Uno 的 `unsigned long` 是 32 位，`millis()` 数到 4 294 967 295 后<Term id="wraparound">回到 0</Term>。总共 2^32 ms：

```text
2^32 ms = 4 294 967 296 ms
        = 4 294 967.296 s
        ≈ 49.7 天
```

对要连续运行数月的设备来说，这个回绕是必须处理的。

标准写法能穿过回绕。C/C++ 无符号减法按 2^32 取模，所以即使 `now` 是回绕后的小数、`last` 是回绕前的大数，`now - last` 仍是真实经过时间（间隔小于 49.7 天）。

比较式 `now > last + PERIOD` 活不过回绕，因为它比的是绝对时刻。下面这个 PC 小程序用同样的 32 位无符号运算：

<CodeSource path="examples/month-2/timing-interrupts/overflow.c" />

```c
#include <stdio.h>
#include <stdint.h>
int main(void) {
  uint32_t last = 4294967000u;   // 296 ms before millis() wraps
  uint32_t now  = 200u;          // 200 ms after the wrap
  printf("now - last  = %lu ms\n", (unsigned long)(uint32_t)(now - last));
  printf("now > last + 250 ? %s\n", (now > last + 250u) ? "yes" : "no");
  printf("wrap after  = %.1f days\n", 4294967296.0 / 1000 / 60 / 60 / 24);
  return 0;
}
```

以及它完全一致的输出：

```text
now - last  = 496 ms
now > last + 250 ? no
wrap after  = 49.7 days
```

`last` 在回绕前 296 ms，`now` 在回绕后 200 ms，真实经过 296 + 200 = 496 ms，减法如实给出。比较版拿 200 和 `last + 250` = 4 294 967 250 比，得到“不大于”，于是认为周期未到；它会一直这么认为约 49.7 天，直到 `now` 自己回绕。带这个 bug 的机器人会卡表七周。

规则：永远比较经过的时间 `now - start >= interval`，绝不比较绝对时刻。时间戳用 `unsigned long`，不用 `int` 或 `long`。Uno 的 `int` 只有 16 位，约 32 秒就溢出；有符号溢出在 C++ 里还是未定义行为。

## 状态机

新手常把行为写成一串脚本：前进两秒、左转一秒、再前进三秒。中间用 `delay()`，机器人在这段时间里对任何事都没反应，撞墙也继续推。<Term id="state-machine">状态机（state machine）</Term>换了个模型：机器人始终处于少数几个状态之一，并有明确规则决定何时离开、进入另一个状态。每轮 `loop()` 检查状态、输入和时钟，决定是否转换（transition）。

`enum` 给状态起名，`switch` 决定每个状态做什么。本课游戏有 `WAITING`、`LIT`、`SHOW_RESULT` 三个状态：

<Diagram id="reaction-timer-states" />

每条箭头都有条件，没有一条叫“等一会儿”。`WAITING` 只检查：随机时间到了吗？按键按下了吗？`LIT` 只检查按键；`SHOW_RESULT` 只检查两秒到了吗。每项检查只要几微秒，所以循环始终有响应。

两个习惯：随机值在进入状态时决定，不要每轮重抽，否则等待会不断重置；进入动作放在转换里，比如设置 `state = LIT` 时点亮 LED 并记下 `litAt`，状态本身就不必记住灯是否已亮。

以后加功能也容易：灯亮时响蜂鸣器，就加到进入 `LIT` 的转换；出结果后 500 ms 内忽略按键，就加一个时间戳和条件。原则只有一条：每个状态都要快速判断完，内部绝不等待。

## 中断

中断（interrupt）让硬件事件打断正常流程：CPU 执行完当前指令，保存位置，跳到<Term id="isr">中断服务程序（interrupt service routine, ISR）</Term>，执行完再回到 `loop()` 原处。

从事件发生到你的函数第一行执行之间的延迟是可以算出来的，但需要先补充两个 CPU 术语。ATmega328P 的 CPU 所有运算都在 32 个通用寄存器（general-purpose registers，R0 到 R31）中完成：它们是 CPU 内部的小型存储单元，与 RAM 以及第 5 课通过 I2C 读取的外设配置寄存器（外设寄存器）相互独立。栈（stack）是 RAM 中的一块区域，CPU 把之后必须恢复的值暂存在这里；把一个寄存器值存入栈称为压栈（push），需要 2 个时钟周期。中断可能在 `loop()` 的任何两条指令之间到来，因此在处理程序使用寄存器之前，`loop()` 保存在这些寄存器中的值会被压入栈，并在 `loop()` 恢复运行前恢复。状态寄存器（status register，SREG）也是上下文的一部分：它保存的旗标（flag）描述上一条算术指令的结果，例如结果是否为零或是否产生了进位，而 `loop()` 中的 `if` 可能正要检查这些旗标。这称为保存上下文（saving the context）。

有了这些术语，时间线如下。ATmega328P 数据手册（7.7.1 节，Interrupt Response Time）给出：让 CPU 压入返回地址（即 `loop()` 中要返回的位置）至少需要 4 个时钟周期（这是最小值；如果 CPU 处于睡眠模式，还要多 4 个周期），再经过向量表跳转需要 3 个周期；向量表是 Flash 中的固定列表，每个中断源对应一条跳转指令。随后 CPU 运行 Arduino 核心中针对该引脚的分发例程。此刻 `attachInterrupt()` 并不参与：它早在 `setup()` 调用它时就已经运行过，所做的只是把你函数的地址存进 RAM。分发例程保存上下文，并通过这个存储的地址调用你的函数。在 arduino:avr 1.8.8 编译的 Uno 程序反汇编中，分发例程在调用之前需要 39 个周期：

```text
硬件响应     4 个周期  压入返回地址
向量跳转     3 个周期  跳转到核心中该引脚的处理程序
保存上下文  30 个周期  把 15 个寄存器压入栈，每个 2 周期
查找并调用   9 个周期  复制状态寄存器、清零一个工作寄存器（2），
                       从 RAM 读取你函数的地址（4），调用它（3）
合计        46 个周期 / 16 MHz = 2.875 µs ≈ 2.9 µs
```

如果事件发生在一条多周期指令执行期间，这条指令会先执行完；如果另一个中断（例如 `millis()` 背后的 Timer0 溢出）正在被处理，你的中断要等那个处理程序返回。约 3 µs 足够在主循环忙于其他事情时抓住持续几十微秒的编码器脉冲。

Arduino Uno 上只有 2 号和 3 号引脚支持外部中断，分别叫 INT0 和 INT1。调用形式是：

```text
attachInterrupt(digitalPinToInterrupt(pin), isr, mode);
```

`digitalPinToInterrupt(pin)` 把引脚号换成硬件中断号；跳过它在编号不一致的板子上会静默失败。`isr` 是函数名，`mode` 取 `LOW`、`CHANGE`、`RISING`、`FALLING`。`RISING` 低变高触发，`FALLING` 高变低触发，`CHANGE` 两边都触发。`LOW` 是电平触发，只要保持低就可能反复触发，不适合按键。

### ISR 的规矩

ISR 会临时抢占正在运行的程序，因此必须遵守这些规则：

- **保持短小**。只设标志、存时间戳、加计数，具体的处理留给 `loop()`。
- **不用 `delay()`，不用 `Serial`**。`Serial.print()` 很慢且可能依赖中断，在 ISR 里可能卡死；`delay()` 同样依赖中断。
- **`millis()` 可读，但在 ISR 执行期间不前进**。更新它的定时器中断要等你返回；ISR 太长会丢时间。
- **共享变量加 `volatile`**。它告诉编译器值随时可能变，每次都要重新读内存，不能缓存。
- **多字节变量原子复制**。8 位 CPU 读 4 字节 `unsigned long` 要几条指令；中途被 ISR 改动会读到新旧混合值。用 `noInterrupts()` / `interrupts()` 包住，临界区只放几条指令。

最后一条最易低估：源码里一个变量，机器码里是四次字节读取。不要长时间关中断，而是快速复制到局部变量，之后只用副本：

```text
noInterrupts();
bool gotPress = pressed;
unsigned long t = pressedAt;
pressed = false;
interrupts();
```

忘了 <Term id="volatile">`volatile`</Term>，编译器可能只读一次 `pressed`，发现是 false 就永远用这份缓存。ISR 设了 true，`loop()` 却看不见。典型症状：加一句调试打印就正常，删掉又坏，因为打印迫使它重新读内存。

什么时候用中断？事件太短或太频繁、轮询（polling）抓不住时：第 4 课的编码器脉冲、传感器短脉冲、反应计时需要精确时间戳的按键。普通按键在快速循环里轮询加消抖，通常更简单。中断也不能救阻塞的循环：`loop()` 卡在 `delay()` 里，ISR 只能置标志，响应仍要等。

## 触点弹跳与消抖

按键内部是两块会互相撞击的金属。撞上时不会立刻稳定，而是在几毫秒内弹开、接触、再弹开；松开也一样。快速采样的单片机会看到一串 HIGH/LOW 跳变。接上拉时松开为高，按下拉到 GND，弹跳表现为一串快速脉冲，最后才稳定为低。

数每个下降沿，一次按下可能变成五次、十次；每次按下都启动动作，动作就会重复。硬件解法是 RC 低通加施密特触发输入（如 74HC14）：RC 让电压变化变慢，施密特把缓慢噪声边沿整形成一次干净跳变。常见 10 kΩ + 100 nF，τ = 1 ms。

软件解法是<Term id="debouncing">时间型消抖（time-based debounce）</Term>：输入一变化就记时刻，只有稳定保持 N 毫秒才接受新状态。N 通常 10–50 ms；太短弹跳会漏进来，太长会吞掉快速点按。

下面这段 Python 仿真模拟每次边沿抖动几毫秒的按键，比较“数边沿”和“时间消抖”：

<CodeSource path="tools/sim/models/debounce_sim.py" />

```python
"""debounce_sim.py: why one button press can look like several, and how a time-based debounce fixes it."""
import random

STEP_MS = 0.1  # simulate in 0.1 ms steps


def bouncy_button(presses, seed=1):
    """Return a list of (time_ms, level) samples. 1 = released (pull-up), 0 = pressed."""
    rng = random.Random(seed)
    events = []  # (time_ms, new_level)
    for start, hold in presses:
        for edge_time, final in ((start, 0), (start + hold, 1)):
            t = edge_time
            level = final
            # contacts chatter for up to ~8 ms before settling
            while t < edge_time + rng.uniform(3, 8):
                events.append((t, level))
                level = 1 - level
                t += rng.uniform(0.2, 3.0)
            events.append((t, final))
    samples, level, i = [], 1, 0
    t = 0.0
    end = max(e[0] for e in events) + 50
    while t < end:
        while i < len(events) and events[i][0] <= t:
            level = events[i][1]
            i += 1
        samples.append((round(t, 1), level))
        t += STEP_MS
    return samples


def naive_presses(samples):
    """Count every HIGH->LOW transition."""
    count, last = 0, 1
    for _, level in samples:
        if last == 1 and level == 0:
            count += 1
        last = level
    return count


def debounced_presses(samples, debounce_ms):
    """Accept a new state only after the raw input has been stable for debounce_ms."""
    count, stable, last_raw, changed_at = 0, 1, 1, 0.0
    for t, level in samples:
        if level != last_raw:
            last_raw, changed_at = level, t
        if last_raw != stable and t - changed_at >= debounce_ms:
            stable = last_raw
            if stable == 0:
                count += 1
    return count


if __name__ == "__main__":
    presses = [(100, 300), (700, 150), (1200, 400), (2000, 80), (2500, 250)]  # (start ms, hold ms)
    samples = bouncy_button(presses)
    print(f"real presses:        {len(presses)}")
    print(f"naive edge count:    {naive_presses(samples)}")
    for d in (2, 10, 20, 50):
        print(f"debounced, {d:>2} ms:   {debounced_presses(samples, d)}")
```

### 如何选择消抖时间

普通轻触按键取 10–30 ms；长导线、嘈杂环境或老旧按键可取 50 ms。消抖时间必须短于最短的真实按下。仿真里 80 ms 的按下接近 50 ms 上限，仍能检测；若只按 40 ms，50 ms 消抖就会吞掉它。反应游戏里手快的人可能只按 30–50 ms，所以 30 ms 更合适。

反应时间程序还用了“安静线路”规则：按下的第一个边沿，如果线路此前已超过 30 ms 没有边沿，就立刻接受；随后几毫秒的弹跳边沿距上一个边沿都不超过 30 ms，因此被拒绝。这样只计一次，又不会给测量增加 30 ms 延迟。轮询式消抖通常会加这段延迟。

## 项目：反应时间小游戏

本月的实践任务：做一个小游戏测反应速度。LED 先灭，随机等 2–5 秒后亮；尽快按键，反应时间以毫秒打印到串口。灯亮前按算犯规，该轮作废；程序记住最好成绩。

接线：LED 用 13 号引脚（Uno 板载），无需外接灯和电阻；按键一端接 2 号引脚、一端接 GND。2 号是 INT0；`INPUT_PULLUP` 让松开读 HIGH、按下读 LOW。

<CodeSource path="examples/month-2/timing-interrupts/reaction_timer/reaction_timer.ino" />

```cpp
// Reaction-timer game.
// LED on pin 13 lights after a random 2-5 s wait; press the button (pin 2 to GND)
// as fast as you can. Pressing before the LED lights is a foul.
const int LED_PIN = 13;
const int BUTTON_PIN = 2;               // pin 2 = external interrupt INT0 on the Uno
const unsigned long DEBOUNCE_MS = 30;

enum State { WAITING, LIT, SHOW_RESULT };
State state = WAITING;

volatile unsigned long pressedAt = 0;   // written by the ISR, read by loop()
volatile bool pressed = false;

unsigned long waitStart = 0;
unsigned long waitTime = 0;
unsigned long litAt = 0;
unsigned long best = 0;
unsigned long resultAt = 0;

void onButton() {                       // interrupt service routine: keep it tiny
  unsigned long t = millis();
  static unsigned long lastEdge = 0;
  bool isDown = digitalRead(BUTTON_PIN) == LOW;
  if (isDown && t - lastEdge > DEBOUNCE_MS) {  // a quiet line that just went LOW = real press
    pressedAt = t;
    pressed = true;
  }
  lastEdge = t;                         // every edge, including bounces, restarts the quiet timer
}

void startRound() {
  digitalWrite(LED_PIN, LOW);
  waitTime = random(2000, 5001);
  waitStart = millis();
  noInterrupts();
  pressed = false;
  interrupts();
  state = WAITING;
  Serial.println(F("Get ready..."));
}

void setup() {
  pinMode(LED_PIN, OUTPUT);
  pinMode(BUTTON_PIN, INPUT_PULLUP);
  Serial.begin(115200);
  randomSeed(analogRead(A0));           // floating analog pin = noisy seed
  attachInterrupt(digitalPinToInterrupt(BUTTON_PIN), onButton, CHANGE);
  startRound();
}

void loop() {
  unsigned long now = millis();

  noInterrupts();                       // copy shared variables atomically
  bool gotPress = pressed;
  unsigned long t = pressedAt;
  pressed = false;
  interrupts();

  switch (state) {
    case WAITING:
      if (gotPress) {
        Serial.println(F("Foul! You pressed too early."));
        resultAt = now;
        state = SHOW_RESULT;
      } else if (now - waitStart >= waitTime) {
        digitalWrite(LED_PIN, HIGH);
        litAt = millis();
        state = LIT;
      }
      break;

    case LIT:
      if (gotPress) {
        unsigned long reaction = t - litAt;
        digitalWrite(LED_PIN, LOW);
        Serial.print(F("Reaction: "));
        Serial.print(reaction);
        Serial.print(F(" ms"));
        if (best == 0 || reaction < best) {
          best = reaction;
          Serial.print(F("  (new best!)"));
        }
        Serial.println();
        resultAt = now;
        state = SHOW_RESULT;
      }
      break;

    case SHOW_RESULT:
      if (now - resultAt >= 2000) startRound();   // next round after 2 s
      break;
  }
}
```

程序照着状态图写。`startRound()` 灭灯、抽随机等待、清按下标志、进入 `WAITING`。中断在 2 号引脚每个边沿运行：每个边沿记入 `lastEdge`；只有引脚为低、且距上个边沿超过 30 ms 才算按下。干净按下的第一个下降沿前面通常安静很久，所以立刻被接受；随后几毫秒的弹跳被拒绝。松开边沿读高，不会算按下，但同样重置计时器。

`loop()` 在临界区复制共享变量。`volatile` 只保证重新读内存，不保证四字节读取原子；关中断确保 ISR 不会改到一半。标志也在同一临界区清除，复制期间来的按下不会丢。

反应时间是 `t - litAt`：`t` 是 ISR 抓到的边沿时刻，`litAt` 是灯亮时刻，不是 `loop()` 发现按下的时刻。循环若正在打印，发现可能晚好几毫秒；用电边沿时间戳，测量才不受影响。

`random(2000, 5001)` 返回 2000–5000（上界不含）。`randomSeed(analogRead(A0))` 用悬空模拟引脚的噪声作种子；真板每次复位序列不同，仿真器里引脚可能读到常数，序列会重复。`F()` 把字符串留在 Flash，节省 Uno 的 SRAM。

## 常见错误与检查清单

本课最容易让人困惑的错误：

- `delay()` 藏在库或辅助函数里。调用点不一定直接出现在 `loop()` 中，所以要顺着 `loop()` 调用的每个函数查一遍。
- 比较绝对时刻（`now > last + PERIOD`），而不是经过的时间（`now - last >= PERIOD`）。它可能正常工作几周，然后在回绕时失效。
- 时间戳用 `int` 或有符号 `long`，而不是 `unsigned long`。Uno 上的 `int` 大约 32 秒就溢出了。
- 与 ISR 共享的变量忘了 `volatile`。循环会一直读缓存的旧值。
- 在 ISR 里调用 `Serial.print()` 或 `delay()`。两者都可能卡住板子或丢失时间。
- 把中断挂到不支持外部中断的引脚上。Uno 上只有 2 号和 3 号可用。
- 消抖时间比最短的真实按下还长。快速点按会消失。
- 读取多字节共享变量时没有关中断。读到的值可能混着新旧字节。

**本课要点**

- `delay()` 会阻塞整个程序：以 0.5 m/s 行驶时，`delay(1000)` 意味着 50 cm 的行驶中没有任何传感器读数。
- 非阻塞模式：`if (now - last >= PERIOD) { last += PERIOD; ... }`；`last += PERIOD` 让长期速率保持精确，`last = now` 会把每次迟到都累加到时间表上。
- `millis()` 来自 Timer0：预分频 64，每 1.024 ms 溢出一次，每秒约 23.4 次修正，分辨率 1 ms；`micros()` 的分辨率为 4 µs。
- 32 位 `millis()` 在 2^32 ms ≈ 49.7 天后回绕；跨回绕时 `now - last` 仍然正确，`now > last + PERIOD` 则不行。
- Uno 上经 `attachInterrupt()` 的中断延迟：从事件到你的函数第一行为 4 + 3 + 30 + 9 = 46 个周期 ≈ 2.9 µs。
- ISR 规矩：保持短小，不调用 `delay()` 或 `Serial`，通过 `volatile` 共享数据，关中断复制多字节值。
- 消抖：时间型消抖在输入稳定 10–50 ms 后才接受新状态；反应计时器则在线路静默 30 ms 后立即接受第一个边沿，并拒绝随后的弹跳。
