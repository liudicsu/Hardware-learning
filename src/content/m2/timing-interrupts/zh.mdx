## 为什么 delay() 会毁掉机器人

机器人从来不会一次只做一件事。行驶时它还要盯着避障传感器、以固定频率跑控制环、让状态 LED 闪烁、随时接收串口指令。Arduino 只有一颗小 CPU 和一个 `loop()`，任何让 `loop()` 停下的东西，都会把这些工作一起停掉。

`delay(1000)` 就是典型例子。它的意思不是“亮着 LED 同时继续干别的”，而是“整个程序在这里停一秒”。这一秒里不读传感器、不看按键、不更新电机、也不处理串口字节。闪灯是人的时间尺度，机器人不是。

算一笔小机器人以 0.5 m/s 行驶的账：

```text
机器人速度：      0.5 m/s
delay() 时长：    1000 ms = 1 s
行驶距离：        0.5 m/s × 1 s = 0.5 m
换算成厘米：      0.5 m × 100 = 50 cm
```

五十厘米的“盲开”。常见避障传感器也许只看 20–40 cm，机器人很容易在这段盲区里撞上桌腿；等 delay 结束再读，拿到的也是 50 cm 前的旧世界。按键同样：一次在 delay 里开始又结束的按下，程序根本不知道。串口缓冲区也会被塞满，字符丢失。控制环还会忽快忽慢。

所以主循环的原则是：永远不等。每一轮只问“现在有什么事到期？”，看一眼时钟，做完就返回。状态 LED 要每 250 ms 翻转，不需要占用 CPU 250 ms，只需要一个时间戳和一次比较。

## millis() 计时模式

`millis()` 返回复位以来的毫秒数，类型是 `unsigned long`，Uno 上为 32 位。它不阻塞：只是读一个由<Term id="hardware-timer">硬件定时器</Term>在后台累加的计数器，然后立刻返回。这是非阻塞计时（non-blocking timing）的基础。

模式分三步：在 `loop()` 开头取一次时钟；用当前时间减去上次执行的时间戳，与周期比较；到期就推进时间戳并执行任务：

```text
if (now - last >= PERIOD) {
  last += PERIOD;
  ...do the thing...
}
```

`last` 和 `now` 都是 `unsigned long` 时间戳。减法得到经过的时间，比较是在问“是否至少过去一个完整周期”。没到期就跳过，继续往下走。

下面这个完整程序让两颗 LED 以不同频率闪烁：

<CodeSource path="examples/month-2/timing-interrupts/two_blinks/two_blinks.ino" />

```cpp
// Two LEDs blinking at different rates, no delay() anywhere.
const int LED_A = 8;
const int LED_B = 9;
const unsigned long PERIOD_A = 250;  // ms between toggles
const unsigned long PERIOD_B = 400;

unsigned long lastA = 0;
unsigned long lastB = 0;
bool stateA = false;
bool stateB = false;

void setup() {
  pinMode(LED_A, OUTPUT);
  pinMode(LED_B, OUTPUT);
  Serial.begin(115200);
}

void loop() {
  unsigned long now = millis();

  if (now - lastA >= PERIOD_A) {
    lastA += PERIOD_A;          // keep a steady rhythm
    stateA = !stateA;
    digitalWrite(LED_A, stateA);
    Serial.print(now);
    Serial.println(" A");
  }

  if (now - lastB >= PERIOD_B) {
    lastB += PERIOD_B;
    stateB = !stateB;
    digitalWrite(LED_B, stateB);
    Serial.print(now);
    Serial.println(" B");
  }

  // ...room for reading sensors, here, every pass through loop()
}
```

`lastA` 从 0 开始，所以第一次翻转在 250 ms 而不是 0 ms，通常正合适。若某任务要立刻执行一次，可把时间戳初始化成 `millis() - PERIOD`，或在 `setup()` 里先调用一次。

### millis() 背后的硬件定时器

`millis()` 背后的计数器是 Timer0，它是 ATmega328P 三个硬件定时器之一。Arduino 核心把它的预分频设为 64，因此 Timer0 每 64 个时钟周期前进一次，其 8 位计数器每 256 次计数溢出一次。每次溢出都会触发一个中断，其处理程序（核心 `wiring.c` 中的 `TIMER0_OVF_vect`）负责更新毫秒计数：

```text
one count      = 64 / 16 MHz = 4 µs
one overflow   = 256 × 4 µs = 1024 µs = 1.024 ms
per second     = 1 s / 1.024 ms = 976.5625 overflows
```

一次溢出是 1.024 ms，而不是 1 ms。因此处理程序每次溢出加 1 ms，并把多出来的 24 µs 累积到一个分数计数器中；每当这个分数累积满一毫秒，就再补 1 ms。第一次修正在第 42 次溢出时到来，此时为 43.008 ms，`millis()` 会从 41 直接跳到 43；平均每秒发生 976.5625 × 3 / 125 = 23.4375 次修正，所以平均每秒增加 976.5625 + 23.4375 = 1000 次。`millis()` 平均而言是准确的，但分辨率只有 1 ms，而且偶尔会跳过一个值，因此绝不要用 `millis() == target` 做判断。`micros()` 读取同一个计数器，分辨率为 4 µs。Timer0 也是第 1 课中在引脚 5 和 6 上产生 976.6 Hz PWM 的那个定时器。

### last += PERIOD 与 last = now 的区别

两种写法都能闪灯，但 `loop()` 迟到时行为不同。迟到很常见：慢速串口打印、传感器转换、耗时库函数。问题是：这点迟到被忘掉，还是加到之后每个周期上。

假设周期是 250 ms，每次翻转都被晚了 3 ms 才处理：

```text
周期 = 250 ms，每次翻转都晚 3 ms 才被处理

last = now：
  第 1 次翻转在 250 + 3 = 253 ms，last = 253
  第 2 次在 253 + 250 + 3 = 506 ms，last = 506
  ……
  第 10 次在 10 × 253 = 2530 ms

last += PERIOD：
  第 1 次在 253 ms，但 last = 250
  第 2 次应在 500 ms，实际 503 ms，last = 500
  ……
  第 10 次在 2500 + 3 = 2503 ms
```

用 `last = now`，每个周期实际变成 253 ms，误差会累积：100 次后慢 300 ms，1000 次后慢 3 s。控制环频率会慢慢变化，比固定偏移更糟。用 `last += PERIOD`，时间表锚定在 250 ms 的整数倍上；每次仍晚 3 ms，但不累积，长期平均精确为 250 ms。

注意：若任务耗时超过一个周期，`last += PERIOD` 更新后可能仍在过去，下一轮会立刻补跑。这通常正是时间表想要的；若宁愿丢掉漏掉的节拍，就用 `last = now` 或把时间戳向前钳位。

## millis() 溢出，以及为什么减法是安全的

Uno 的 `unsigned long` 是 32 位，`millis()` 数到 4 294 967 295 后<Term id="wraparound">回到 0</Term>。总共 2^32 ms：

```text
2^32 ms = 4 294 967 296 ms
        = 4 294 967.296 s
        ≈ 49.7 天
```

对要连续运行数月的设备来说，这个回绕是必须处理的。

标准写法能穿过回绕。C/C++ 无符号减法按 2^32 取模，所以即使 `now` 是回绕后的小数、`last` 是回绕前的大数，`now - last` 仍是真实经过时间（间隔小于 49.7 天）。

比较式 `now > last + PERIOD` 活不过回绕，因为它比的是绝对时刻。下面这个 PC 小程序用同样的 32 位无符号运算：

<CodeSource path="examples/month-2/timing-interrupts/overflow.c" />

```c
#include <stdio.h>
#include <stdint.h>
int main(void) {
  uint32_t last = 4294967000u;   // 296 ms before millis() wraps
  uint32_t now  = 200u;          // 200 ms after the wrap
  printf("now - last  = %lu ms\n", (unsigned long)(uint32_t)(now - last));
  printf("now > last + 250 ? %s\n", (now > last + 250u) ? "yes" : "no");
  printf("wrap after  = %.1f days\n", 4294967296.0 / 1000 / 60 / 60 / 24);
  return 0;
}
```

以及它完全一致的输出：

```text
now - last  = 496 ms
now > last + 250 ? no
wrap after  = 49.7 days
```

`last` 在回绕前 296 ms，`now` 在回绕后 200 ms，真实经过 296 + 200 = 496 ms，减法如实给出。比较版拿 200 和 `last + 250` = 4 294 967 250 比，得到“不大于”，于是认为周期未到；它会一直这么认为约 49.7 天，直到 `now` 自己回绕。带这个 bug 的机器人会卡表七周。

规则：永远比较经过的时间 `now - start >= interval`，绝不比较绝对时刻。时间戳用 `unsigned long`，不用 `int` 或 `long`。Uno 的 `int` 只有 16 位，约 32 秒就溢出；有符号溢出在 C++ 里还是未定义行为。

## 状态机

新手常把行为写成一串脚本：前进两秒、左转一秒、再前进三秒。中间用 `delay()`，机器人在这段时间里对任何事都没反应，撞墙也继续推。<Term id="state-machine">状态机（state machine）</Term>换了个模型：机器人始终处于少数几个状态之一，并有明确规则决定何时离开、进入另一个状态。每轮 `loop()` 检查状态、输入和时钟，决定是否转换（transition）。

`enum` 给状态起名，`switch` 决定每个状态做什么。本课游戏有 `WAITING`、`LIT`、`SHOW_RESULT` 三个状态：

<Diagram id="reaction-timer-states" />

每条箭头都有条件，没有一条叫“等一会儿”。`WAITING` 只检查：随机时间到了吗？按键按下了吗？`LIT` 只检查按键；`SHOW_RESULT` 只检查两秒到了吗。每项检查只要几微秒，所以循环始终有响应。

两个习惯：随机值在进入状态时决定，不要每轮重抽，否则等待会不断重置；进入动作放在转换里，比如设置 `state = LIT` 时点亮 LED 并记下 `litAt`，状态本身就不必记住灯是否已亮。

以后加功能也容易：灯亮时响蜂鸣器，就加到进入 `LIT` 的转换；出结果后 500 ms 内忽略按键，就加一个时间戳和条件。原则只有一条：每个状态都要快速判断完，内部绝不等待。

## 中断

中断（interrupt）让硬件事件打断正常流程：CPU 执行完当前指令，保存位置，跳到<Term id="isr">中断服务程序（interrupt service routine, ISR）</Term>，执行完再回到 `loop()` 原处。

从事件发生到你的函数第一行执行之间的延迟是可以算出来的，但需要先补充两个 CPU 术语。ATmega328P 的 CPU 所有运算都在 32 个通用寄存器（general-purpose registers，R0 到 R31）中完成：它们是 CPU 内部的小型存储单元，与 RAM 以及第 5 课通过 I2C 读取的外设配置寄存器（外设寄存器）相互独立。栈（stack）是 RAM 中的一块区域，CPU 把之后必须恢复的值暂存在这里；把一个寄存器值存入栈称为压栈（push），需要 2 个时钟周期。中断可能在 `loop()` 的任何两条指令之间到来，因此在处理程序使用寄存器之前，`loop()` 保存在这些寄存器中的值会被压入栈，并在 `loop()` 恢复运行前恢复。这称为保存上下文（saving the context）。被保存的上下文还包括一个寄存器：状态寄存器（status register，SREG），它保存的旗标（flag）描述上一条算术指令的结果，例如结果是否为零或是否产生了进位，而 `loop()` 中的 `if` 可能正要检查这些旗标。

有了这些术语，时间线如下。ATmega328P 数据手册（7.7.1 节，Interrupt Response Time）给出：让 CPU 压入返回地址（即 `loop()` 中要返回的位置）至少需要 4 个时钟周期（这是最小值），再经过向量表跳转需要 3 个周期；向量表是 Flash 中的固定列表，每个中断源对应一条跳转指令。如果 CPU 处于睡眠状态，响应还要多 4 个周期，而且这 4 个周期是加在该睡眠模式的振荡器启动时间之上的：按 Uno 的熔丝设置，从掉电模式（power-down）或省电模式（power-save）唤醒都需要 16K CK = 16,384 个周期 ≈ 1.0 ms（9.3 节，表 9-4，该列标题为 “Start-up Time from Power-down and Power-save”）；在空闲模式（idle）下振荡器一直运行，不增加启动时间。随后 CPU 运行 Arduino 核心中针对该引脚的分发例程。此刻 `attachInterrupt()` 并不参与：它早在 `setup()` 调用它时就已经运行过，所做的只是把你函数的地址存进 RAM。分发例程保存上下文，并通过这个存储的地址调用你的函数。在 arduino:avr 1.8.8 编译的 Uno 程序反汇编中，分发例程在调用之前需要 39 个周期：

```text
  4 个周期  硬件响应：压入返回地址
  3 个周期  向量跳转：跳转到核心中该引脚的处理程序
 30 个周期  保存上下文：把 15 个寄存器压入栈，每个 2 周期
  9 个周期  查找并调用：
            · 复制状态寄存器、清零一个工作寄存器（2）
            · 从 RAM 读取你函数的地址（4）
            · 调用它（3）
 46 个周期  合计：46 / 16 MHz = 2.875 µs ≈ 2.9 µs
```

如果事件发生在一条多周期指令执行期间，这条指令会先执行完；如果另一个中断（例如 `millis()` 背后的 Timer0 溢出）正在被处理，你的中断要等那个处理程序返回。约 3 µs 足够在主循环忙于其他事情时抓住持续几十微秒的编码器脉冲。

Arduino Uno 上只有 2 号和 3 号引脚支持外部中断，分别叫 INT0 和 INT1。调用形式是：

```text
attachInterrupt(digitalPinToInterrupt(pin), isr, mode);
```

`digitalPinToInterrupt(pin)` 把引脚号换成硬件中断号；跳过它在编号不一致的板子上会静默失败。`isr` 是函数名，`mode` 取 `LOW`、`CHANGE`、`RISING`、`FALLING`。`RISING` 低变高触发，`FALLING` 高变低触发，`CHANGE` 两边都触发。`LOW` 是电平触发，只要保持低就可能反复触发，不适合按键。

### ISR 的规矩

ISR 会临时抢占正在运行的程序，因此必须遵守这些规则：

- **保持短小**。只设标志、存时间戳、加计数，具体的处理留给 `loop()`。
- **不用 `delay()`，不用 `Serial`**。`Serial.print()` 很慢且可能依赖中断，在 ISR 里可能卡死；`delay()` 同样依赖中断。
- **`millis()` 可读，但在 ISR 执行期间不前进**。更新它的定时器中断要等你返回；ISR 太长会丢时间。
- **共享变量加 `volatile`**。它告诉编译器值随时可能变，每次都要重新读内存，不能缓存。
- **多字节变量原子复制**。8 位 CPU 读 4 字节 `unsigned long` 要几条指令；中途被 ISR 改动会读到新旧混合值。用 `noInterrupts()` / `interrupts()` 包住，临界区只放几条指令。

最后一条最易低估：源码里一个变量，机器码里是四次字节读取。不要长时间关中断，而是快速复制到局部变量，之后只用副本：

```text
noInterrupts();
bool gotPress = pressed;
unsigned long t = pressedAt;
pressed = false;
interrupts();
```

忘了 <Term id="volatile">`volatile`</Term>，编译器可能只读一次 `pressed`，发现是 false 就永远用这份缓存。ISR 设了 true，`loop()` 却看不见。典型症状：加一句调试打印就正常，删掉又坏，因为打印迫使它重新读内存。

什么时候用中断？事件太短或太频繁、轮询（polling）抓不住时：第 4 课的编码器脉冲、传感器短脉冲、反应计时需要精确时间戳的按键。普通按键在快速循环里轮询加消抖，通常更简单。中断也不能救阻塞的循环：`loop()` 卡在 `delay()` 里，ISR 只能置标志，响应仍要等。

## 触点弹跳与消抖

按键内部是两块会互相撞击的金属。撞上时不会立刻稳定，而是在几毫秒内弹开、接触、再弹开；松开也一样。快速采样的单片机会看到一串 HIGH/LOW 跳变。接上拉时松开为高，按下拉到 GND，弹跳表现为一串快速脉冲，最后才稳定为低。

数每个下降沿，一次按下可能变成五次、十次；每次按下都启动动作，动作就会重复。硬件解法是 RC 低通加施密特触发输入（如 74HC14）：RC 让电压变化变慢，施密特把缓慢噪声边沿整形成一次干净跳变。常见 10 kΩ + 100 nF，τ = 1 ms。

软件解法是<Term id="debouncing">时间型消抖（time-based debounce）</Term>：输入一变化就记时刻，只有稳定保持 N 毫秒才接受新状态。N 通常 10–50 ms；太短弹跳会漏进来，太长会吞掉快速点按。

下面这段 Python 仿真模拟每次边沿抖动几毫秒的按键，比较“数边沿”和“时间消抖”：

<CodeSource path="tools/sim/models/debounce_sim.py" />

```python
"""debounce_sim.py: why one button press can look like several, and how a time-based debounce fixes it."""
import random

STEP_MS = 0.1  # simulate in 0.1 ms steps


def bouncy_button(presses, seed=1):
    """Return a list of (time_ms, level) samples. 1 = released (pull-up), 0 = pressed."""
    rng = random.Random(seed)
    events = []  # (time_ms, new_level)
    for start, hold in presses:
        for edge_time, final in ((start, 0), (start + hold, 1)):
            t = edge_time
            level = final
            # contacts chatter for up to ~8 ms before settling
            while t < edge_time + rng.uniform(3, 8):
                events.append((t, level))
                level = 1 - level
                t += rng.uniform(0.2, 3.0)
            events.append((t, final))
    samples, level, i = [], 1, 0
    t = 0.0
    end = max(e[0] for e in events) + 50
    while t < end:
        while i < len(events) and events[i][0] <= t:
            level = events[i][1]
            i += 1
        samples.append((round(t, 1), level))
        t += STEP_MS
    return samples


def naive_presses(samples):
    """Count every HIGH->LOW transition."""
    count, last = 0, 1
    for _, level in samples:
        if last == 1 and level == 0:
            count += 1
        last = level
    return count


def debounced_presses(samples, debounce_ms):
    """Accept a new state only after the raw input has been stable for debounce_ms."""
    count, stable, last_raw, changed_at = 0, 1, 1, 0.0
    for t, level in samples:
        if level != last_raw:
            last_raw, changed_at = level, t
        if last_raw != stable and t - changed_at >= debounce_ms:
            stable = last_raw
            if stable == 0:
                count += 1
    return count


if __name__ == "__main__":
    presses = [(100, 300), (700, 150), (1200, 400), (2000, 80), (2500, 250)]  # (start ms, hold ms)
    samples = bouncy_button(presses)
    print(f"real presses:        {len(presses)}")
    print(f"naive edge count:    {naive_presses(samples)}")
    for d in (2, 10, 20, 50):
        print(f"debounced, {d:>2} ms:   {debounced_presses(samples, d)}")
```

### 如何选择消抖时间

普通轻触按键取 10–30 ms；长导线、嘈杂环境或老旧按键可取 50 ms。消抖时间必须短于最短的真实按下。仿真里 80 ms 的按下接近 50 ms 上限，仍能检测；若只按 40 ms，50 ms 消抖就会吞掉它。反应游戏里手快的人可能只按 30–50 ms，所以 30 ms 更合适。

反应时间程序还用了“安静线路”规则：按下的第一个边沿，如果线路此前已超过 30 ms 没有边沿，就立刻接受；随后几毫秒的弹跳边沿距上一个边沿都不超过 30 ms，因此被拒绝。这样只计一次，又不会给测量增加 30 ms 延迟。轮询式消抖通常会加这段延迟。

## 项目：反应时间小游戏

本月的实践任务：做一个小游戏测反应速度。LED 先灭，随机等 2–5 秒后亮；尽快按键，反应时间以毫秒打印到串口。灯亮前按算犯规，该轮作废；程序记住最好成绩。

接线：LED 用 13 号引脚（Uno 板载），无需外接灯和电阻；按键一端接 2 号引脚、一端接 GND。2 号是 INT0；`INPUT_PULLUP` 让松开读 HIGH、按下读 LOW。

<CodeSource path="examples/month-2/timing-interrupts/reaction_timer/reaction_timer.ino" />

```cpp
// Reaction-timer game.
// LED on pin 13 lights after a random 2-5 s wait; press the button (pin 2 to GND)
// as fast as you can. Pressing before the LED lights is a foul.
const int LED_PIN = 13;
const int BUTTON_PIN = 2;               // pin 2 = external interrupt INT0 on the Uno
const unsigned long DEBOUNCE_MS = 30;

enum State { WAITING, LIT, SHOW_RESULT };
State state = WAITING;

volatile unsigned long pressedAt = 0;   // written by the ISR, read by loop()
volatile bool pressed = false;

unsigned long waitStart = 0;
unsigned long waitTime = 0;
unsigned long litAt = 0;
unsigned long best = 0;
unsigned long resultAt = 0;

void onButton() {                       // interrupt service routine: keep it tiny
  unsigned long t = millis();
  static unsigned long lastEdge = 0;
  bool isDown = digitalRead(BUTTON_PIN) == LOW;
  if (isDown && t - lastEdge > DEBOUNCE_MS) {  // a quiet line that just went LOW = real press
    pressedAt = t;
    pressed = true;
  }
  lastEdge = t;                         // every edge, including bounces, restarts the quiet timer
}

void startRound() {
  digitalWrite(LED_PIN, LOW);
  waitTime = random(2000, 5001);
  waitStart = millis();
  noInterrupts();
  pressed = false;
  interrupts();
  state = WAITING;
  Serial.println(F("Get ready..."));
}

void setup() {
  pinMode(LED_PIN, OUTPUT);
  pinMode(BUTTON_PIN, INPUT_PULLUP);
  Serial.begin(115200);
  randomSeed(analogRead(A0));           // floating analog pin = noisy seed
  attachInterrupt(digitalPinToInterrupt(BUTTON_PIN), onButton, CHANGE);
  startRound();
}

void loop() {
  unsigned long now = millis();

  noInterrupts();                       // copy shared variables atomically
  bool gotPress = pressed;
  unsigned long t = pressedAt;
  pressed = false;
  interrupts();

  switch (state) {
    case WAITING:
      if (gotPress) {
        Serial.println(F("Foul! You pressed too early."));
        resultAt = now;
        state = SHOW_RESULT;
      } else if (now - waitStart >= waitTime) {
        digitalWrite(LED_PIN, HIGH);
        litAt = millis();
        state = LIT;
      }
      break;

    case LIT:
      if (gotPress) {
        unsigned long reaction = t - litAt;
        digitalWrite(LED_PIN, LOW);
        Serial.print(F("Reaction: "));
        Serial.print(reaction);
        Serial.print(F(" ms"));
        if (best == 0 || reaction < best) {
          best = reaction;
          Serial.print(F("  (new best!)"));
        }
        Serial.println();
        resultAt = now;
        state = SHOW_RESULT;
      }
      break;

    case SHOW_RESULT:
      if (now - resultAt >= 2000) startRound();   // next round after 2 s
      break;
  }
}
```

程序照着状态图写。`startRound()` 灭灯、抽随机等待、清按下标志、进入 `WAITING`。中断在 2 号引脚每个边沿运行：每个边沿记入 `lastEdge`；只有引脚为低、且距上个边沿超过 30 ms 才算按下。干净按下的第一个下降沿前面通常安静很久，所以立刻被接受；随后几毫秒的弹跳被拒绝。松开边沿读高，不会算按下，但同样重置计时器。

`loop()` 在临界区复制共享变量。`volatile` 只保证重新读内存，不保证四字节读取原子；关中断确保 ISR 不会改到一半。标志也在同一临界区清除，复制期间来的按下不会丢。

反应时间是 `t - litAt`：`t` 是 ISR 抓到的边沿时刻，`litAt` 是灯亮时刻，不是 `loop()` 发现按下的时刻。循环若正在打印，发现可能晚好几毫秒；用电边沿时间戳，测量才不受影响。

`random(2000, 5001)` 返回 2000–5000（上界不含）。`randomSeed(analogRead(A0))` 用悬空模拟引脚的噪声作种子；真板每次复位序列不同，仿真器里引脚可能读到常数，序列会重复。`F()` 把字符串留在 Flash，节省 Uno 的 SRAM。

## 常见错误与检查清单

本课最容易让人困惑的错误：

- `delay()` 藏在库或辅助函数里。调用点不一定直接出现在 `loop()` 中，所以要顺着 `loop()` 调用的每个函数查一遍。
- 比较绝对时刻（`now > last + PERIOD`），而不是经过的时间（`now - last >= PERIOD`）。它可能正常工作几周，然后在回绕时失效。
- 时间戳用 `int` 或有符号 `long`，而不是 `unsigned long`。Uno 上的 `int` 大约 32 秒就溢出了。
- 与 ISR 共享的变量忘了 `volatile`。循环会一直读缓存的旧值。
- 在 ISR 里调用 `Serial.print()` 或 `delay()`。两者都可能卡住板子或丢失时间。
- 把中断挂到不支持外部中断的引脚上。Uno 上只有 2 号和 3 号可用。
- 消抖时间比最短的真实按下还长。快速点按会消失。
- 读取多字节共享变量时没有关中断。读到的值可能混着新旧字节。

## 独立硬件看门狗必须观察任务进展
卡死主循环里检查的软件超时救不了同一循环。逻辑挂起时定时中断可能仍推进 `millis()`，但阻塞代码不再判断超时；禁用中断还可能冻结 Timer0。硬件看门狗有独立振荡器 / 计数器：`WDR` 喂狗重启计数，复位模式无需主循环配合也能到期。这里**不是 8.5 的软件命令流看门狗**，不是执行器安全锁存，更不是急停或认证。

| 0010 | 8192 | 64 ms |
| 0011 | 16384 | 0.125 s |
| 0100 | 32768 | 0.25 s |

### 同一挂起，三种喂狗来源

`hw_wdt_kick_toy.py` 用**合成理想 1 ms tick**，名义 **16 tick** 截止及 **100 tick** 观察期。它选手册最短名义间隔，却不模拟振荡器容差、CPU 周期或重新启动。只记录**第一次复位**并停止，建模 WDRF 保存与清零，不保证安全重启。每个挂起场景都在 tick30 卡住主逻辑，但普通定时 ISR 仍运行；完成循环步骤后按5 tick 节奏喂狗。各组共享时钟、初始计数与挂起事件：

| 组 | 健康运行 | tick30 主循环挂起 | 首次复位/结束前完成的循环步数 |
|---|---|---|---|
| 不喂狗 | tick16 复位 | tick16 已复位（尚未注入挂起） | 15 / 15 |
| 主循环进展后喂狗 | 存活到100 | 最后喂狗25，tick41 复位，WDRF=0x08 | 100 / 29 |
| ISR/定时器喂狗 | 存活到100 | 不复位，**掩盖挂起** | 100 / 29 |

模型先判断硬件到期，**再处理同 tick 的喂狗**；年龄16 已太晚。定时器活着不等于应用有进展，喂狗应以必要工作 / 健康检查完成为门槛。ISR 掩盖示例前提是中断仍可响应；CPU 停止或禁用中断不会继续喂狗。不能在 ISR 无条件喂狗就声称主循环已被监控。

### 通用窗口看门狗常识，不冒充 AVR 特性

另设**通用窗口扩展**：年龄小于8 的喂狗也报错，年龄16 到期，因此离散规则的允许区间为 **[8,16)**。每5 tick 喂狗在5 发生**过早喂狗故障**；每10 tick 正常，但若30 挂起、上次喂狗20，则36 到期。原来过早喂也会错。**这不是 ATmega328P 的硬件窗口看门狗功能**，不把 AVR 原因位分配给该通用故障。全部时序、挂起与进展计数都是确定性合成输入，不作随机种子声明。

```python
#!/usr/bin/env python3
"""Independent discrete WDT counter; NOT the 8.5 software command watchdog.
Ideal synthetic 1-ms ticks, nominal 16-tick deadline, 5-tick progress/kick cadence.
Only first reset is recorded (stop, not a simulated reboot). Timer ISR can run
while main logic is stuck; an ISR kick then hides that hang. Real oscillator
variation, boot/fuse setup and CPU cycle timing are not simulated.
Generic window extension is NOT an ATmega328P hardware feature claim.
"""
TIMEOUT, DURATION, WDRF = 16,100,0x08
ARMS=("no_kick","main_loop","isr_timer")
# Opened ATmega328P 7810D Table 10-3: WDP3..0, oscillator cycles, typical ms at5V.
PRESCALE=((0,2048,16),(1,4096,32),(2,8192,64),(3,16384,125),
          (4,32768,250),(5,65536,500),(6,131072,1000),(7,262144,2000),
          (8,524288,4000),(9,1048576,8000))


def run(arm, hang_at=None, kick_period=5, window_min=None):
    if arm not in ARMS:
        raise ValueError("unknown kick source")
    last_kick=progress=0
    reset_at,reason=None,"none"
    for now in range(1,DURATION+1):
        # Expiration wins a tie: a kick at the upper deadline is too late here.
        if now-last_kick>=TIMEOUT:
            reset_at,reason=now,"timeout"
            break
        running=hang_at is None or now<hang_at
        progress+=int(running)
        kick=now%kick_period==0 and (arm=="isr_timer" or (arm=="main_loop" and running))
        if kick:
            if window_min is not None and now-last_kick<window_min:
                reset_at,reason=now,"window_early"
                break
            last_kick=now
    # Snapshot models early boot read of WDRF only; generic window has no AVR flag.
    saved_mcusr=WDRF if reset_at is not None and window_min is None else 0
    cleared_mcusr=0
    hidden=hang_at is not None and reset_at is None
    return dict(reset_at=reset_at,reason=reason,progress=progress,hidden=hidden,
                saved_mcusr=saved_mcusr,cleared_mcusr=cleared_mcusr)


def main():
    print("Independent HW WDT surrogate; ideal tick=1ms nominal timeout=16 ticks duration=100")
    print("same hang at30 or no hang; kick cadence5; expire-before-kick tie; first reset stops run")
    print("scenario arm reset_tick cause main_progress saved_MCUSR cleared_MCUSR hidden_hang")
    for scenario,hang in (("healthy",None),("main_hang",30)):
        for arm in ARMS:
            r=run(arm,hang)
            when="none" if r["reset_at"] is None else str(r["reset_at"])
            print(f"{scenario} {arm} {when} {r['reason']} {r['progress']} 0x{r['saved_mcusr']:02X} 0x{r['cleared_mcusr']:02X} {int(r['hidden'])}")
    print("Opened 7810D Table10-3: WDP3..0 cycles typical_ms_at5V (not precision deadlines)")
    for code,cycles,ms in PRESCALE:
        print(f"{code:04b} {cycles} {ms}")
    print("generic window model ONLY: min_age=8 upper=16; NOT ATmega328P window hardware")
    for label,period,hang in (("too_early",5,None),("in_window",10,None),("hung",10,30)):
        r=run("main_loop",hang,period,8)
        when="none" if r["reset_at"] is None else str(r["reset_at"])
        print(f"{label} period={period} reset={when} cause={r['reason']}")
    print("WDE reset mode / WDIE interrupt-only differ; capture MCUSR.WDRF before clearing")
    print("Synthetic timing; no certification or e-stop claim; AVR fuse/reset lab: 本页未运行")


if __name__=="__main__":
    main()
```

## Timer1 输入捕获与软件边沿轮询

本页已经讲过 `delay()` 为什么会让机器人盲开、`millis()` 模式以及 Timer0 / 预分频 64 / 1.024 ms 溢出算术、为什么 `now - last` 能跨过 32 位回绕、如何在关中断下复制共享的 `unsigned long`、触点弹跳、反应计时器草图，以及独立硬件看门狗。那些切口保持原样。本节要讲的是另一份官方契约：ATmega328P 16 位定时器 / 计数器 1 在 7810D §15.6 中的**输入捕获单元**（以及该节点名的 §15.11 位：ICNC1、ICES1、ICIE1、ICF1、ICR1H/L）。这**不是**再讲一遍共享的 16 位值必须关中断再复制，**不是**改写中断一节里「轮询与精确时间戳」那段或反应计时器的 `millis()` 表述，也**不是** Timer1 的 PWM、相位修正 PWM、CTC 或输出比较课。

官方 7810D §15.6（以文档为准）写到，该单元 “can capture external events and give them a time-stamp indicating time of occurrence”，输入可以来自 **ICP1** 引脚，也可以改走模拟比较器输出。“The time-stamps can then be used to calculate frequency, duty-cycle, and other features of the signal applied.” 合格边沿到来时，“the 16-bit value of the counter (TCNT1) is written to the input capture register (ICR1). The input capture flag (ICF1) is set at the same system clock as the TCNT1 value is copied into ICR1 register.” 若置位 ICIE1，该标志会产生输入捕获中断；中断执行时 ICF1 会自动清零，也可以由软件向该 I/O 位写逻辑 1 来清除。

官方读 ICR1 的顺序是 “first reading the low byte (ICR1L) and then the high byte (ICR1H)”，经由高字节临时寄存器 TEMP。写 ICR1——仅在把 ICR1 用作 TOP 的波形产生模式下——则是先高后低。该节指向 §15.3 的 16 位访问说明。这里只把这次序当作数据手册约束来引用；本页不把已有的 `unsigned long` 原子复制表述改写成第二节 §15.3 课，也不烧录数据手册里的 C 示例（例如 `TIM16_ReadTCNT1`）（本页未运行）。

“The time between two events is critical. If the processor has not read the captured value in the ICR1 register before the next event occurs, the ICR1 will be overwritten with a new value. In this case the result of the capture will be incorrect.” “When using the input capture interrupt, the ICR1 register should be read as early in the interrupt handler routine as possible.”

噪声消除器（ICNC1）对输入连续监视四个采样，四个必须相等。使能后，它 “introduces additional four system clock cycles of delay from a change applied to the input, to the update of the ICR1 register. The noise canceler uses the system clock and is therefore not affected by the prescaler.” 改触发源本身也可能引发一次捕获，因此改完后必须清 ICF1。测占空比 “requires that the trigger edge is changed after each capture”；改边沿之后，ICF1 “must be cleared by software”。“For measuring frequency only, the clearing of the ICF1 flag is not required (if an interrupt handler is used).” 本玩具测量的是上升沿时间戳及其间隔（频率类用法），并不在每次捕获后切换 ICES。

§15.6 说这些时间戳可以用来计算频率或占空比，但**并没有**印出闭合的频率公式。本页出现的国际单位制周期或频率，都是按课程声明的定时器节拍和 ΔICR 做的手算，不是官方 §15.6 公式。同一份数据手册（表 15-6）给出的官方预分频系数是 N is 1, 8, 64, 256 or 1024。本节在第一次运行前声明 N = 8、 f_clk = 16 MHz；16 MHz 就是本页 Timer0 已经用过的时钟（`64 / 16 MHz = 4 µs`），不是新编的板级通用缺省值。ICNC 声明为**关闭**，因此官方的四周期延迟不加进去。手算：一拍是 8 / 16 MHz = 0.5000 us；四个系统时钟是 4 / 16 MHz = 0.2500 us。官方 AVR 烧录 / 逻辑分析仪：本页未运行。

### 已打开的契约

同一份预先声明的引脚时间表送到三个臂。臂 A 是按声明循环周期做的软件上升沿轮询：时间戳是第一次看到低到高采样的那次轮询时刻，因此只在两次轮询之间保持高电平的短脉冲可能被错过。臂 B 是官方契约替身：在合格上升沿（ICES1 = 1）上，把定时器计数值在同一拍写入深度为 1 的 ICR（ICNC 关闭）。臂 C 是预先声明的**失败**，而且**只有一种**失败模式，在第一次运行前就选定：ICES 对调（下降沿）。该模式保留；本页不在运行时留下开放的或列表，也不把撕裂或反序的 16 位读取当作臂 C。

### 公平设定

`timer1_input_capture_vs_poll_toy.py` 是**合成的**，只用标准库。**模型假定**是课程声明的定时器时钟 f_clk = 16 MHz 与预分频 N = 8（官方表 15-6，clkI/O/8）；ICNC 关闭；官方 ICES = 1（上升沿）；臂 C 的 ICES = 0（下降沿）；软件轮询周期 20 拍（手算 20 × 0.5000 us = 10.0000 us）。稀疏上升沿在 200、1000 和 1800 拍，每拍高电平持续 40 拍，因此官方上升周期是 800 拍（手算 400.0000 us，2500.0000 Hz）。短脉冲：从第 1 拍起 16 个上升沿，周期 8 拍、脉宽 3 拍，都短于 20 拍的轮询。覆盖：上升沿在 100 和 108 拍，ICR 只在 120 拍读取。本玩具是已打开契约的带标签替身，不是数据手册 C 示例的移植，也不需要 root 或真实 AVR。

| 臂 | 计算内容 |
|---|---|
| A_poll | 按声明的 20 拍循环周期做软件上升沿轮询；时间戳是轮询时刻 |
| B_icr | 官方深度为 1 的 ICR：上升沿把 TCNT 拷入；第二次未读边沿会覆盖 ICR |
| C_ices | 同一条官方捕获路径，但把 ICES 对调成下降沿（预先声明的失败） |

**公共随机数**是五个种子。每种情形都是确定性的（固定边沿时间表；五个种子重复同一组数字）。度量是捕获次数、首次捕获时间戳，以及至少有两次捕获时的平均周期，按种子报 mean+-sd。国际单位制的微秒和赫兹数字都标为手算。小与明显的分界因子打印为 `0.2000`（较小臂均值的 20 %）。**没有积分步长**（精确的整数定时器拍和闭合时间戳）。比较**看不到**真实的 ICP1 引脚，也看不到任何已烧录的 AVR 示例。官方 AVR 烧录 / 逻辑分析仪：本页未运行。不声称本玩具在真实开发板上运行过。

**四种情形，写在第一次运行之前**如下。周期远长于声明轮询间隔的稀疏边沿——A 对 B 应为精确**打平**或官方**近平**（`|m| <= sd`）；短于轮询的短脉冲 / 边沿——B 应**明显好于** A（软件采样漏检或偏晚）；读取 ICR 之前又来第二次事件——官方覆盖，迟读或只保留首次的行为予以披露并保留；臂 C 在声明的错误 ICES 情形上应**失败**。

```python
#!/usr/bin/env python3
"""Synthetic Timer1 input-capture vs software edge-poll stand-in.

Stdlib only. A labeled stand-in of the opened ATmega328P 7810D section 15.6
Input Capture Unit contract, not a port of the datasheet C examples and not
a flash or logic-analyzer run.

Arms:
  A_poll   software rising-edge polling at a declared loop period. The
           timestamp is the poll instant when a low-to-high sample is
           first seen, so a short pulse that stays high only between
           polls can be missed.
  B_icr    official-contract stand-in: on a qualifying rising edge
           (ICES=1), copy TCNT into a one-deep ICR at that same timer
           tick. ICNC is declared off, so the official four system-clock
           noise-canceler delay is not added. A second qualifying edge
           before ICR is read overwrites ICR.
  C_ices   pre-declared lose mode: ICES swapped (falling edge). One
           mode only, declared before the first run. Kept.

Common random numbers: seeds 0-4. Every regime is deterministic
(fixed edge schedules; the five seeds repeat the same figures).

Regimes (declared before the first run):
  sparse_edges    rising period much longer than the poll interval
                  -> A vs B exact or official near-tie
  short_pulses    pulse width and period shorter than the poll
                  -> B clearly better than A (missed software samples)
  icr_overwrite   second rising edge before ICR is read
                  -> official overwrite; late-read and keep-first
                     behaviour disclosed and kept
  wrong_ices      C uses falling-edge select on the sparse schedule
                  -> C loses on the first-capture stamp

ATmega328P 7810D section 15.6 以文档为准. Official AVR flash / logic
analyzer: 本页未运行.
"""
from __future__ import annotations

import math

SEEDS = (0, 1, 2, 3, 4)
NUM_ZERO = 1e-9
CLEAR_FRAC = 0.2000  # small-vs-clear factor; printed before the first official run
F_CLK_HZ = 16_000_000  # lesson-declared, matching this page's Timer0 64 / 16 MHz = 4 us arithmetic
N_PRESCALER = 8  # official Table 15-6 clkI/O/8; N in {1, 8, 64, 256, 1024}
TICK_S = N_PRESCALER / F_CLK_HZ  # 0.5000 us, labelled 手算
ICNC_ON = False
ICNC_DELAY_CLK = 4  # official delay when ICNC is on; not applied
ICES_RISING = 1  # official ICES1=1, rising (positive) edge
ICES_FALLING = 0  # C's pre-declared lose mode: ICES swapped
POLL_PERIOD_TICKS = 20
POLL_PERIOD_ALT_TICKS = 1  # named alternative, not adopted
SPARSE_RISES = (200, 1000, 1800)
SPARSE_WIDTH_TICKS = 40
SHORT_FIRST_RISE = 1
SHORT_PERIOD_TICKS = 8
SHORT_WIDTH_TICKS = 3
SHORT_N_PULSES = 16
OVERWRITE_RISES = (100, 108)
OVERWRITE_WIDTH_TICKS = 4
LATE_READ_TICKS = 120
ARMS = ("A_poll", "B_icr", "C_ices")
REGIMES = ("sparse_edges", "short_pulses", "icr_overwrite", "wrong_ices")


def tick_to_us(ticks: float) -> float:
    return ticks * TICK_S * 1e6


def pin_high(t: int, rises: tuple[int, ...], width: int) -> bool:
    return any(r <= t < r + width for r in rises)


def falling_edges(rises: tuple[int, ...], width: int) -> tuple[int, ...]:
    return tuple(r + width for r in rises)


def qualifying_edges(ices: int, rises: tuple[int, ...], width: int) -> tuple[int, ...]:
    return rises if ices == ICES_RISING else falling_edges(rises, width)


def poll_captures(rises: tuple[int, ...], width: int, poll: int, t_end: int) -> list[int]:
    """Software rising-edge poll: timestamp is the poll instant."""
    found: list[int] = []
    prev = 0
    t = 0
    while t <= t_end:
        level = 1 if pin_high(t, rises, width) else 0
        if prev == 0 and level == 1:
            found.append(t)
        prev = level
        t += poll
    return found


def icr_captures(ices: int, rises: tuple[int, ...], width: int, read_immediately: bool) -> list[int]:
    """Official one-deep ICR. If read_immediately, each capture is saved before the next edge."""
    edges = qualifying_edges(ices, rises, width)
    if read_immediately:
        return list(edges)
    if not edges:
        return []
    # Unread: each new qualifying edge overwrites ICR; only the last remains.
    return [edges[-1]]


def first_kept(ices: int, rises: tuple[int, ...], width: int) -> int | None:
    """Disclosed keep-first behaviour: ignore the official overwrite."""
    edges = qualifying_edges(ices, rises, width)
    return edges[0] if edges else None


def mean_period(captures: list[int]) -> float | None:
    if len(captures) < 2:
        return None
    gaps = [b - a for a, b in zip(captures, captures[1:])]
    return sum(gaps) / len(gaps)


def mean_sd(xs: list[float]) -> tuple[float, float]:
    mu = sum(xs) / len(xs)
    if len(xs) == 1:
        return mu, 0.0
    return mu, math.sqrt(sum((x - mu) ** 2 for x in xs) / (len(xs) - 1))


def num(x: float) -> str:
    if x != 0.0 and abs(x) < 5e-5:
        return f"{x:.3e}"
    return f"{x:.4f}"


def sign_note(diffs: list[float], m: float) -> str:
    n, opp, zero = len(diffs), sum(1 for d in diffs if d * m < 0), sum(1 for d in diffs if d == 0)
    if opp == 0 and zero == 0:
        return f"same sign on all {n} seeds"
    if opp == 0:
        return f"no seed has the opposite sign, {zero} of {n} equal"
    note = f"{opp} of {n} seeds {'has' if opp == 1 else 'have'} the opposite sign"
    return note + (f", {zero} of {n} equal" if zero else "")


def verdict(xa: list[float], xb: list[float]) -> str:
    diffs = [a - b for a, b in zip(xa, xb)]
    if all(d == 0.0 for d in diffs):
        return "0.0000+-0.0000: tie: identical on every seed"
    m, s = mean_sd(diffs)
    if abs(m) < NUM_ZERO and s < NUM_ZERO:
        return f"{num(m)}+-{num(s)}: numerically zero (floating-point residue), effectively a tie"
    if abs(m) <= s:
        label = "near-tie / small gap, within seed noise (|m| <= sd)"
    elif abs(m) < CLEAR_FRAC * min(abs(mean_sd(xa)[0]), abs(mean_sd(xb)[0])):
        label = "small but consistent gap, not a tie (|m| > sd)"
    else:
        label = "clear gap, not a tie (|m| > sd)"
    return f"{num(m)}+-{num(s)}: {label}; {sign_note(diffs, m)}"


def seed_repeat(value: float) -> list[float]:
    return [value] * len(SEEDS)


def print_pair(label: str, xa: list[float], xb: list[float], unit: str) -> None:
    print(f"  paired {label}: {verdict(xa, xb)} {unit}".rstrip())


def run_sparse(poll: int) -> dict[str, list[int]]:
    t_end = SPARSE_RISES[-1] + SPARSE_WIDTH_TICKS + poll
    return {
        "A_poll": poll_captures(SPARSE_RISES, SPARSE_WIDTH_TICKS, poll, t_end),
        "B_icr": icr_captures(ICES_RISING, SPARSE_RISES, SPARSE_WIDTH_TICKS, True),
        "C_ices": icr_captures(ICES_FALLING, SPARSE_RISES, SPARSE_WIDTH_TICKS, True),
    }


def run_short(poll: int) -> dict[str, list[int]]:
    rises = tuple(SHORT_FIRST_RISE + i * SHORT_PERIOD_TICKS for i in range(SHORT_N_PULSES))
    t_end = rises[-1] + SHORT_WIDTH_TICKS + poll
    return {
        "A_poll": poll_captures(rises, SHORT_WIDTH_TICKS, poll, t_end),
        "B_icr": icr_captures(ICES_RISING, rises, SHORT_WIDTH_TICKS, True),
        "C_ices": icr_captures(ICES_FALLING, rises, SHORT_WIDTH_TICKS, True),
    }


def run_overwrite() -> dict[str, object]:
    t_end = LATE_READ_TICKS
    a = poll_captures(OVERWRITE_RISES, OVERWRITE_WIDTH_TICKS, POLL_PERIOD_TICKS, t_end)
    official_last = icr_captures(ICES_RISING, OVERWRITE_RISES, OVERWRITE_WIDTH_TICKS, False)
    kept = first_kept(ICES_RISING, OVERWRITE_RISES, OVERWRITE_WIDTH_TICKS)
    c = icr_captures(ICES_FALLING, OVERWRITE_RISES, OVERWRITE_WIDTH_TICKS, False)
    return {
        "A_poll": a,
        "B_icr_late": official_last,
        "keep_first": kept,
        "C_ices_late": c,
        "rising_edges": OVERWRITE_RISES,
    }


def print_arm_stats(name: str, captures: list[int], metric: str) -> tuple[list[float], list[float]]:
    n = seed_repeat(float(len(captures)))
    first = seed_repeat(float(captures[0]) if captures else math.nan)
    period = mean_period(captures)
    print(f"  {name} n_capt {num(n[0])}+-{num(0.0)}")
    if captures:
        print(f"  {name} first_ticks {num(first[0])}+-{num(0.0)} first_us {num(tick_to_us(first[0]))}+-{num(0.0)} (hand_calc)")
    else:
        print(f"  {name} first_ticks none first_us none")
    if period is not None:
        per = seed_repeat(period)
        print(
            f"  {name} period_ticks {num(per[0])}+-{num(0.0)} period_us {num(tick_to_us(period))}+-{num(0.0)} (hand_calc)"
        )
    else:
        per = []
        print(f"  {name} period_ticks none period_us none")
    return n, (first if captures else []), per


def main() -> None:
    sparse = run_sparse(POLL_PERIOD_TICKS)
    short = run_short(POLL_PERIOD_TICKS)
    short_alt = run_short(POLL_PERIOD_ALT_TICKS)
    overw = run_overwrite()

    hc_tick_us = TICK_S * 1e6
    hc_icnc_us = ICNC_DELAY_CLK / F_CLK_HZ * 1e6
    hc_poll_us = tick_to_us(POLL_PERIOD_TICKS)
    hc_sparse_period_ticks = float(SPARSE_RISES[1] - SPARSE_RISES[0])
    hc_sparse_first_a = float(SPARSE_RISES[0])
    hc_sparse_first_c = float(SPARSE_RISES[0] + SPARSE_WIDTH_TICKS)
    hc_short_n_b = float(SHORT_N_PULSES)
    hc_short_n_a = 0.0
    hc_overwrite_b = float(OVERWRITE_RISES[1])
    hc_keep_first = float(OVERWRITE_RISES[0])
    hc_overwrite_a = float(OVERWRITE_RISES[0])  # poll lands on the first rising
    hc_freq_sparse = 1.0 / (hc_sparse_period_ticks * TICK_S)

    print(
        "Synthetic Timer1 input-capture vs software edge-poll toy; "
        "stdlib stand-in only; not a flash or logic-analyzer run"
    )
    print(
        f"f_clk={F_CLK_HZ}Hz N={N_PRESCALER} tick_us={hc_tick_us:.4f} "
        f"(hand_calc N/f_clk) ICNC={int(ICNC_ON)} icnc_delay_clk={ICNC_DELAY_CLK} "
        f"icnc_delay_us={hc_icnc_us:.4f} (hand_calc, not applied)"
    )
    print(
        f"ICES_B={ICES_RISING} ICES_C={ICES_FALLING} (pre-declared C lose mode: wrong ICES only) "
        f"poll_ticks={POLL_PERIOD_TICKS} poll_us={hc_poll_us:.4f} (hand_calc) "
        f"seeds={len(SEEDS)} clear_frac={CLEAR_FRAC:.4f} "
        f"hand_calc work_plan 30+25+50+40+35=180"
    )
    print(
        "no integration step: exact integer timer ticks; SI period and frequency are hand_calc "

    )
    print(
        f"hand_calc sparse period_ticks={hc_sparse_period_ticks:.10f} "
```

### 读四种情形

本页标签按以下顺序使用。**tie: identical on every seed** 只在成对的每种种子差分都恰好为零时使用；**numerically zero (floating-point residue), effectively a tie** 用于成对均值的绝对值和标准差都低于 1e-9 时（这类行不打印符号计数）；**near-tie / small gap, within seed noise** 用于 `|paired mean| <= sd`（`|m| <= sd`）；否则就是**一致**的差距（`|paired mean| > sd`），若 `|m|` 小于较小臂均值的 20 % 则称**小**，否则称**明显**；20 % 规则只用来在这两个词之间选择。每条一致的行都带 5 个种子上的同号计数，若有反号种子也会报出；单靠符号计数不能让差距变成一致。差距用未四舍五入的值计算。

- **sparse_edges.** 上升周期是 800 拍，远长于 20 拍的轮询，而且每个上升沿都落在轮询时刻上。A 和 B 都打印 `n_capt 3.0000+-0.0000`、`first_ticks 200.0000+-0.0000`（手算 `100.0000 us`）和 `period_ticks 800.0000+-0.0000`（手算 `400.0000 us`，`2500.0000 Hz`）。成对 A-B 的 `period_ticks` 和 `first_ticks` 都是 `0.0000+-0.0000: tie: identical on every seed`。这是**打平**，不是「明显」差距，也不是数值上为零的浮点残差（打印的 `residual_step-closed_A_first=0.000e+00ticks`）。闭合手算是 `first_A=B=200.0000000000`。该格保留。
- **short_pulses.** 16 个脉宽 3 拍、周期 8 拍的上升沿都严格落在 20 拍轮询之间，轮询始终采到低电平。A 打印 `n_capt 0.0000+-0.0000`，没有首次时间戳，也没有周期。B 打印 `n_capt 16.0000+-0.0000`、`first_ticks 1.0000+-0.0000`（手算 `0.5000 us`）和 `period_ticks 8.0000+-0.0000`（手算 `4.0000 us`）。成对 A-B 的 `n_capt` 是 `-16.0000+-0.0000: clear gap, not a tie (|m| > sd); same sign on all 5 seeds`。B **明显更好**；软件轮询错过了每一发脉冲。该格保留（`residual_step-closed_A_n=0.000e+00`，`residual_step-closed_B_n=0.000e+00`）。
- **icr_overwrite.** 上升沿发生在 100 和 108 拍；ICR 只在 120 拍读取。因此官方的 B 保存的是被**覆盖**后的时间戳 `108.0000+-0.0000` 拍（后一个边沿）。若只保留首次，会得到 `100.0000+-0.0000`；这种行为予以披露，而且**不是**官方捕获。软件轮询落在第一次上升沿上，之后看不到新的上升采样，于是报 `first_ticks 100.0000+-0.0000`。成对 B-keep_first 的 `ICR_ticks` 是 `8.0000+-0.0000: small but consistent gap, not a tie (|m| > sd); same sign on all 5 seeds`——8 拍小于较小臂均值 100 的 20 %，所以按本课规则称这个差距为**小**，而不是明显。官方覆盖本身是后一个时间戳 108 而不是 100，该格保留（`residual_step-closed_B_ICR=0.000e+00ticks`）。
- **wrong_ices.** C 在同一份稀疏时间表上选用下降沿。B 的首次时间戳仍是 `200.0000+-0.0000` 拍；C 的首次时间戳是下降沿 `240.0000+-0.0000` 拍（手算 `120.0000 us`）。成对 C-B 的 `first_ticks` 是 `40.0000+-0.0000: clear gap, not a tie (|m| > sd); same sign on all 5 seeds`。在脉宽恒定时，C 的下降沿到下降沿周期仍与官方上升周期相同；C 在首次捕获时间戳上**失败**。该格保留（`residual_step-closed_C_first=0.000e+00ticks`）。

**本课要点**

- `delay()` 会阻塞整个程序：以 0.5 m/s 行驶时，`delay(1000)` 意味着 50 cm 的行驶中没有任何传感器读数。
- 非阻塞模式：`if (now - last >= PERIOD) { last += PERIOD; ... }`；`last += PERIOD` 让长期速率保持精确，`last = now` 会把每次迟到都累加到时间表上。
- `millis()` 来自 Timer0：预分频 64，每 1.024 ms 溢出一次，每秒约 23.4 次修正，分辨率 1 ms；`micros()` 的分辨率为 4 µs。
- 32 位 `millis()` 在 2^32 ms ≈ 49.7 天后回绕；跨回绕时 `now - last` 仍然正确，`now > last + PERIOD` 则不行。
- Uno 上经 `attachInterrupt()` 的中断延迟：从事件到你的函数第一行为 4 + 3 + 30 + 9 = 46 个周期 ≈ 2.9 µs。
- ISR 规矩：保持短小，不调用 `delay()` 或 `Serial`，通过 `volatile` 共享数据，关中断复制多字节值。
- 消抖：时间型消抖在输入稳定 10–50 ms 后才接受新状态；反应计时器则在线路静默 30 ms 后立即接受第一个边沿，并拒绝随后的弹跳。
- Timer1 输入捕获（ATmega328P 7810D §15.6）在合格边沿把 TCNT1 拷进深度为 1 的 ICR1：稀疏边沿上软件轮询与官方捕获**打平**（周期 `800.0000+-0.0000` 拍、首次时间戳 `200.0000+-0.0000` 拍，每种种子都相同）；短脉冲上官方臂捕获全部 `16.0000+-0.0000` 个上升沿，轮询错过每一发（成对 A-B n_capt `-16.0000+-0.0000`，明显，5 个种子同号）；第二次未读事件用 `108.0000` 拍**覆盖** ICR（只保留首次的 `100.0000` 予以披露并保留；8 拍的差距是小而一致）；错误的 ICES 在首次捕获时间戳上**失败**（成对 C-B `40.0000+-0.0000` 拍，明显）——这是标准库替身；官方 AVR 烧录 / 逻辑分析仪本页未运行。
