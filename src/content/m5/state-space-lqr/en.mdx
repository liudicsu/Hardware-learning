The last lesson described the arm joint with a transfer function: one input, one output. <Term id="state-space">State space</Term> keeps every internal state in a vector x and writes the dynamics as `x' = A x + B u`. That is exactly what a balancer needs, because position, speed, angle and angular rate all matter at once. The plant here starts as the joint from [Lesson 1](/en/month/month-5/control-modelling), then becomes the cart-pole from Month 2.

## Two plants, one form

For the joint, let x = [q, w], where q is the angle and w = q'. The torque is the single input u. With J = 0.004 kg·m² and B = 0.05 N·m per rad/s, the equation J q'' + B q' = u becomes a two-row state equation. The first row is q' = w. The second row is w' = −(B/J) w + (1/J) u = −12.5 w + 250 u, so A = [[0, 1], [0, −12.5]] and B = [[0], [250]]. One equation now carries both the angle and the speed.

<Formula label="State space: every state in one vector">x' = A x + B u</Formula>

The cart-pole is Month 2's balancer cut down to a cart of M = 0.5 kg and a point mass m = 0.2 kg at L = 0.3 m. The input is a horizontal force F. The nonlinear equations (angle from upright) are `a = (F + m L ω² sinθ − m g sinθ cosθ)/(M + m − m cos²θ)` for the cart and `θ'' = (g sinθ − a cosθ)/L` for the pole. Linearised about upright, take ∂/∂θ at θ = 0, ω = 0 with `a ≈ F/M` to obtain `−m g/M = −3.92`, `1/M = 2.00`, `(M+m)g/(M L) = 45.78` and `−1/(M L) = −6.67`. With x = [position, speed, angle, rate], the model prints:

Read the rows as equations. The second row is speed: p'' = −(m g / M) θ + (1/M) F. The number −3.92 is −m g / M = −0.2 × 9.81 / 0.5; a positive lean pushes the cart backwards. The number 2.00 is 1/M = 1/0.5, the acceleration per newton. The fourth row is angle: θ'' = ((M + m) g / (M L)) θ − (1 / (M L)) F. The number 45.78 is (0.7 × 9.81) / (0.5 × 0.3), the gravity term that makes upright unstable. The number −6.67 is −1 / (0.5 × 0.3): a positive force tips the pole negative.
```python
"""lqr_sim.py: state space, LQR on a cart-pole, and a small MPC on the Month 3 arm joint.

Part 1 writes a cart-pole (the Month 2 balancer reduced to its essentials: a cart that is
pushed by a force and a pole balanced on it) in state space, x = [position, speed, angle,
angular rate], linearised about upright, discretised at 100 Hz. LQR gains come from
iterating the discrete Riccati equation. The gains are then tested on the full nonlinear
cart-pole, with the force limited to 10 N.
Part 2 moves the arm joint from lesson 1 (J = 0.004, B = 0.05, gravity cancelled by
feedforward) through 1 rad with a torque limit, comparing LQR whose output is simply
clipped with an MPC that knows the limit. Standard library only.
"""
import math

# ---------------------------------------------------------------- small matrix helpers
def mul(a, b):
    return [[sum(a[i][k] * b[k][j] for k in range(len(b))) for j in range(len(b[0]))] for i in range(len(a))]


def add(a, b, s=1.0):
    return [[a[i][j] + s * b[i][j] for j in range(len(a[0]))] for i in range(len(a))]


def tr(a):
    return [list(r) for r in zip(*a)]


def eye(n, v=1.0):
    return [[v if i == j else 0.0 for j in range(n)] for i in range(n)]


def discretise(a, b, dt):
    """Zero-order-hold discretisation by a Taylor series of the matrix exponential."""
    n = len(a)
    phi, gam, term = eye(n), [[dt * x[0]] for x in b], eye(n)
    for k in range(1, 25):
        term = [[v * dt / k for v in r] for r in mul(term, a)]           # (A dt)^k / k!
        phi = add(phi, term)
        gam = add(gam, [[v * dt / (k + 1)] for v in [r[0] for r in mul(term, b)]])
    return phi, gam


def lqr(phi, gam, q, r, iters=5000):
    """Iterate P = Q + A'PA - A'PB (R + B'PB)^-1 B'PA; return K for u = -K x."""
    p = q
    for _ in range(iters):
        bp = mul(tr(gam), p)
        s = r + mul(bp, gam)[0][0]
        k = [[v / s for v in mul(bp, phi)[0]]]
        p = add(q, mul(tr(phi), mul(p, add(phi, mul(gam, k), -1.0))))
    return k[0]


# ---------------------------------------------------------------- part 1: cart-pole
M, m, L, G, DT, FMAX = 0.5, 0.2, 0.3, 9.81, 0.01, 10.0
A_CP = [[0, 1, 0, 0], [0, 0, -m * G / M, 0], [0, 0, 0, 1], [0, 0, (M + m) * G / (M * L), 0]]
B_CP = [[0], [1 / M], [0], [-1 / (M * L)]]


def cartpole(x, f, dt=0.001):
    """Full nonlinear cart-pole (point mass m at distance L), angle from upright."""
    p, v, th, w = x
    s, c = math.sin(th), math.cos(th)
    acc = (f + m * L * w * w * s - m * G * s * c) / (M + m - m * c * c)
    alpha = (G * s - acc * c) / L
    return [p + v * dt, v + acc * dt, th + w * dt, w + alpha * dt]


def balance(k, deg, seconds=4.0, show=False):
    x = [0.0, 0.0, math.radians(deg), 0.0]
    fpeak = 0.0
    for i in range(int(seconds / DT)):
        f = max(-FMAX, min(FMAX, -sum(ki * xi for ki, xi in zip(k, x))))
        fpeak = max(fpeak, abs(f))
        if show and i % 50 == 0:
            print(f"  t = {i * DT:3.1f} s  x = {x[0]:6.3f} m  angle = {math.degrees(x[2]):6.2f} deg  force = {f:6.2f} N")
        for _ in range(10):
            x = cartpole(x, f)
        if abs(x[2]) > math.pi / 2:
            return None, fpeak
    return x, fpeak


def part1():
    phi, gam = discretise(A_CP, B_CP, DT)
    print("Cart-pole, x = [position, speed, angle, rate], 100 Hz")
    print("  A (continuous) rows:", "  ".join("[" + ", ".join(f"{v:.2f}" for v in r) + "]" for r in A_CP))
    print("  B (continuous):     ", "[" + ", ".join(f"{r[0]:.2f}" for r in B_CP) + "]")
    for name, qd, r in (("Q = diag(1, 1, 10, 1), R = 1   ", (1, 1, 10, 1), 1.0),
                        ("Q = diag(100, 1, 10, 1), R = 1 ", (100, 1, 10, 1), 1.0),
                        ("Q = diag(1, 1, 10, 1), R = 0.01", (1, 1, 10, 1), 0.01)):
        q = [[qd[i] if i == j else 0.0 for j in range(4)] for i in range(4)]
        k = lqr(phi, gam, q, r)
        print(f"{name}  K = [" + ", ".join(f"{v:7.2f}" for v in k) + "]")
        if name.startswith("Q = diag(1, 1, 10, 1), R = 1 "):
            k_first = k
        x, fpeak = balance(k, 10)
        print(f"    from 10 deg: after 4 s x = {x[0]:6.3f} m, angle = {math.degrees(x[2]):5.2f} deg, peak force {fpeak:5.2f} N")
    print("Nonlinear run with the first K, starting 10 deg off upright:")
    balance(k_first, 10, seconds=3.0, show=True)
    biggest = max(d for d in range(1, 90) if balance(k_first, d, seconds=6.0)[0] is not None
                  and abs(balance(k_first, d, seconds=6.0)[0][2]) < 0.01)
    print(f"  largest start angle it still recovers from (force limit {FMAX:.0f} N): {biggest} deg")


# ---------------------------------------------------------------- part 2: MPC on the joint
J, BV, T, UMAX, N = 0.004, 0.05, 0.005, 0.6, 40
PHI_J, GAM_J = discretise([[0, 1], [0, -BV / J]], [[0], [1 / J]], T)


def jstep(x, u):
    return [PHI_J[0][0] * x[0] + PHI_J[0][1] * x[1] + GAM_J[0][0] * u,
            PHI_J[1][0] * x[0] + PHI_J[1][1] * x[1] + GAM_J[1][0] * u]


def mpc(x, target, kq, warm):
    """Minimise sum over N steps of kq*(q-target)^2 + 0.01*w^2 + u^2, |u| <= UMAX,
    by projected gradient descent on the N future torques; return them all."""
    u = warm[1:] + warm[-1:]
    lr = 2e-4
    for _ in range(150):
        xs = [x]
        for uk in u:
            xs.append(jstep(xs[-1], uk))
        lam = [0.0, 0.0]                  # backward pass: gradient of the cost wrt each u
        grad = [0.0] * N
        for k in range(N - 1, -1, -1):
            q, w = xs[k + 1]
            lam = [2 * kq * (q - target) + PHI_J[0][0] * lam[0] + PHI_J[1][0] * lam[1],
                   2 * 0.01 * w + PHI_J[0][1] * lam[0] + PHI_J[1][1] * lam[1]]
            grad[k] = 2 * u[k] + GAM_J[0][0] * lam[0] + GAM_J[1][0] * lam[1]
        u = [max(-UMAX, min(UMAX, uk - lr * g)) for uk, g in zip(u, grad)]
    return u


def move(kind, seconds=1.0):
    k = lqr(PHI_J, GAM_J, [[400.0, 0], [0, 0.01]], 1.0)
    x, target, peak, settle = [0.0, 0.0], 1.0, 0.0, None
    plan = [0.0] * N
    sat = 0
    for i in range(int(seconds / T)):
        if kind == "lqr":
            u = max(-UMAX, min(UMAX, -(k[0] * (x[0] - target) + k[1] * x[1])))
        else:
            plan = mpc(x, target, 400.0, plan)
            u = plan[0]
        sat += abs(u) >= UMAX - 1e-9
        x = jstep(x, u)
        peak = max(peak, x[0])
        if abs(x[0] - target) > math.radians(1):
            settle = None
        elif settle is None:
            settle = (i + 1) * T
    return k, peak, settle, sat * T


def part2():
    print(f"Arm joint, 1 rad move, |torque| <= {UMAX} N*m (on top of gravity feedforward), 200 Hz")
    for kind, label in (("lqr", "LQR, output clipped"), ("mpc", f"MPC, horizon {N} steps")):
        k, peak, settle, sat = move(kind)
        if kind == "lqr":
            print(f"  LQR gains: K = [{k[0]:.2f}, {k[1]:.3f}]  (kp in N*m/rad, kd in N*m/(rad/s))")
        s = f"{settle:.3f} s" if settle else "never"
        print(f"  {label:22s} overshoot {math.degrees(peak - 1.0):5.2f} deg, within 1 deg from {s}, at the limit for {sat:.3f} s")


if __name__ == "__main__":
    part1()
    print()
    part2()
```

## One gain row, four states

<Term id="lqr">LQR</Term> asks for the input sequence that minimises a cost over the whole run:

<Formula label="LQR cost: state error plus control effort">J = Σ (xᵀ Q x + uᵀ R u)</Formula>

Q is a 4 × 4 matrix that penalises state error; R is a positive scalar that penalises force. Units matter: position enters in m², angle in rad², force squared in N². The gains come from iterating the discrete Riccati equation (A and B here are the zero-order-hold matrices) until P stops changing:

<Formula label="Discrete Riccati iteration and the gain it gives">P ← Q + Aᵀ P A − Aᵀ P B (R + Bᵀ P B)⁻¹ Bᵀ P A,   K = (R + Bᵀ P B)⁻¹ Bᵀ P A</Formula>

The control law is u = −K x. K has one entry per state, so the same row uses position, speed, angle and rate together. Month 3's cascade used two loops tuned one after the other: an inner loop on the pitch angle and an outer loop on wheel speed that moved the inner loop's setpoint. LQR replaces both with one gain row and lets Q and R decide the balance.

The positive force pushes the cart under the leaning pole." />

## Tuning Q and R

Three runs show the trade-off. All start 10° off upright and use the same 10 N force limit. Q = diag(1, 1, 10, 1), R = 1 is the baseline. Raising the position weight to 100 asks for the cart to return: the final position falls from 0.028 m to 0.000 m, but peak force rises from 3.28 N to 5.19 N. Lowering R to 0.01 instead makes every gain larger, and the peak force reaches 10.00 N, the limit.

1. Leave Q1 = 1.0, Q3 = 10 and R = 1.0 and read K = [−0.92, −1.75, −18.76, −3.03] and peak force = 3.28 N.
2. Set R = 0.01 and read K = [−6.86, −10.95, −59.07, −11.51] and peak force = 10.00 N (at the 10 N limit).
3. Set R = 1.0 and Q1 = 100, keep Q3 = 10, and read K = [−9.01, −6.54, −29.74, −4.91] and peak force = 5.19 N.
4. Set Q1 = 1.0 and R = 10 and read K = [−0.29, −0.78, −15.51, −2.37] and peak force = 2.71 N.
5. Conclusion: LQR trades state error against force; a smaller R lowers the cost of control effort so all gains grow until the force saturates (R = 0.01 reaches 10.00 N at the 10 N limit against 3.28 N at R = 1.0), and a larger Q1 tightens the position return (Q1 = 100 raises peak force to 5.19 N).

Note the sign of the position gain. The position gain is negative, like the angle gain. With u = −K x, a positive position error, meaning the cart is to the right of the target, commands a positive force and pushes it further right. That is deliberate: the controller first tips the pole left, then drives left to catch it. A cart-pole is non-minimum phase in position, so an immediate push toward the target would lean the pole the wrong way.

To use less force, raise R or lower the state weights. Raising the position weight in Q instead gives a tighter return and spends more force.

## MPC and the receding horizon

Part 2 moves the arm joint through 1 rad with a torque limit of 0.6 N·m on top of gravity feedforward, at 200 Hz, so T = 5 ms. LQR uses the same cost but its output is simply clipped at the limit. MPC predicts N = 40 steps ahead, 40 × 5 ms = 0.2 s, optimises all 40 future torques subject to `|u| ≤ 0.6 N·m`, applies only the first, then repeats. That is the receding horizon. The model solves it by projected gradient descent: 150 steps per control period, warm-started with the previous plan shifted by one.

<SimOutput source="model">

```text
Arm joint, 1 rad move, |torque| <= 0.6 N*m (on top of gravity feedforward), 200 Hz
  LQR gains: K = [15.93, 0.323]  (kp in N*m/rad, kd in N*m/(rad/s))
  LQR, output clipped    overshoot  2.24 deg, within 1 deg from 0.210 s, at the limit for 0.175 s
  MPC, horizon 40 steps  overshoot  0.86 deg, within 1 deg from 0.160 s, at the limit for 0.165 s
```

</SimOutput>

The LQR gains are K = [15.93, 0.323], much larger than lesson 1's PD gains 2.86 N·m/rad and 0.115 N·m/(rad/s), because Q = diag(400, 0.01) with R = 1 prices a 1 rad error far above 1 N·m of torque: a 1 rad error costs `400 × 1² = 400`, matched by `u² = 400` → `|u| = 20 N·m` (about 33× the 0.6 N·m limit and about 7× lesson 1's 2.86 N·m/rad scale), which is why the position gain lands near 16. Gains that large spend most of the move pinned at the limit, which is exactly where plain LQR stops holding: K is computed for an unclipped output, and once the command is clipped the effective loop gain is no longer the designed one. With clipping, LQR overshoots 2.24° and is within 1° from 0.210 s. MPC overshoots 0.86° and is within 1° from 0.160 s. It is at the limit for 0.165 s, LQR for 0.175 s. The improvement exists but is limited; the bigger difference is computation.

MPC costs far more computation per step: every 5 ms period it runs 150 gradient steps, each a forward pass and a backward pass over 40 steps, about 12,000 small state updates, while LQR is two multiplications and an addition. On a microcontroller the 5 ms deadline is fixed. If the MPC does not finish in time, you must shorten the horizon, lower the control rate, or move to a faster chip. A lower rate adds delay, and delay eats phase margin, as lesson 1 showed.

## Common mistakes

- <strong>Q and R in inconsistent units.</strong> Changing position from metres to centimetres multiplies that state by 100, so the same Q entry penalises 10,000 times more. Keep states in SI and re-tune after a unit change.
- <strong>Using the linear model far from upright.</strong> The 45.78 term is a linearisation about upright. At 53° the true dynamics are different; a gain that works at 10° is not a proof that far out.
- <strong>Ignoring actuator limits in the LQR design.</strong> An unclipped LQR assumes it can deliver any force. The R = 0.01 run reaches the 10 N limit; include saturation in the simulation, or design with MPC.
- <strong>Forgetting the sign conventions of the state.</strong> x = [position, speed, angle, rate] with angle measured from upright. Flip the angle sign and the controller pushes the pole over. Write the positive direction down before tuning.
- <strong>Believing MPC is always better.</strong> MPC needs a model and a solver every period. If the limit is not active and the linear model is good, LQR can match it with a fraction of the code and time.
