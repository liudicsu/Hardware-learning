## Why model the joint

The joint is the same one from Month 3: J = 0.004 kg·m², B = 0.05 N·m per rad/s, and gravity 0.4 N·m × cos(q). Gravity feedforward computes the gravity torque from the measured angle and adds it to the command; when the model is right, it cancels gravity, so the remaining dynamics are linear: torque u drives J q'' + B q'. Transfer functions and Bode plots describe linear plants, and keeping the test steps small is what keeps the real joint inside the range where the linear model holds.

<Formula label="Plant with gravity feedforward: angle per unit torque">G(s) = 1 / (J s² + B s) = 1 / (s (J s + B))</Formula>

With J = 0.004 kg·m² and B = 0.05 N·m per rad/s, the denominator is s(J s + B). One pole sits at s = 0, the free integrator that turns torque into speed. The other sits at s = −B/J = −12.5 1/s, a first-order lag with time constant J/B = 0.004 / 0.05 = 0.08 s. After a torque step, speed reaches 63 % of its final value in 0.08 s.

Month 3 expressed the gains in degrees: 0.05 N·m/deg and 0.002 N·m per deg/s. Multiply by 180/π to get SI: 0.05 × 180/π = 2.86 N·m/rad, and 0.002 × 180/π = 0.115 N·m/(rad/s). The model below uses those converted gains, so its results describe the loop you tuned by hand.

## Identify the model from data

Before trusting a margin, check that the model matches the motor. The simplest test is an open-loop torque step: hold a constant torque u with gravity feedforward on, let the joint accelerate from rest, and log speed. For this first-order speed response the final speed is u/B and the 63 % time is tau = J/B. With u = 0.2 N·m and B = 0.05 N·m per rad/s, the final speed should be 0.2 / 0.05 = 4 rad/s; the log stops at 0.5 s, about six time constants, when the speed is still 0.2 % short, so it reads 3.99 rad/s. The 63 % point lands at 0.080 s, so J = B × tau = 0.05 × 0.080 = 0.0040 kg·m².

```python
"""joint_freq.py: model the Month 3 arm joint, then read its loop in the frequency domain.

The joint is the one from pid_sim.py (J = 0.004 kg*m^2, B = 0.05 N*m per rad/s, gravity
0.4 N*m * cos(angle)), with gravity cancelled by a feedforward term so that what is left
is linear: torque -> J*q'' + B*q'. The controller runs at 200 Hz, holds its torque for one
period (zero-order hold) and, like most real firmware, applies the torque computed from a
reading one period later (one sample of delay). Units are SI: angles in rad, gains in
N*m per rad and N*m per rad/s (Month 3's 0.05 N*m per degree is 2.86 N*m per rad).
"""
import cmath
import math

J, B, GRAV, T = 0.004, 0.05, 0.4, 0.005
A = B / J                                    # 12.5 1/s, so the time constant J/B is 0.08 s
E = math.exp(-A * T)
# exact discretisation of J*q'' + B*q' = u with the torque held over each period
PHI = ((1.0, (1 - E) / A), (0.0, E))
GAM = ((T - (1 - E) / A) / (A * J), (1 - E) / (A * J))


def step(q, w, u):
    return (q + PHI[0][1] * w + GAM[0] * u, E * w + GAM[1] * u)


def identify():
    """Open-loop test: hold 0.2 N*m (plus gravity feedforward) and log the speed."""
    print("Open-loop step: 0.2 N*m from rest, speed logged at 200 Hz")
    q, w, log = 0.0, 0.0, []
    for k in range(101):
        log.append((k * T, w))
        q, w = step(q, w, 0.2)
    for t, s in log[::8][:8]:
        print(f"  t = {t:4.2f} s   speed {s:5.2f} rad/s")
    final = log[-1][1]
    t63 = next(t for t, s in log if s >= 0.632 * final)
    b = 0.2 / final
    print(f"  final speed {final:.2f} rad/s -> B = 0.2 / {final:.2f} = {b:.3f} N*m per rad/s")
    print(f"  63 % of it at t = {t63:.3f} s -> J = B x tau = {b * t63:.4f} kg*m^2")


def loop(kp, kd, w):
    """Loop gain L = C * P at angular frequency w (rad/s), with z = e^(jwT)."""
    z = cmath.exp(1j * w * T)
    det = (z - PHI[0][0]) * (z - PHI[1][1]) - PHI[0][1] * PHI[1][0]
    plant = ((z - PHI[1][1]) * GAM[0] + PHI[0][1] * GAM[1]) / det   # angle / torque
    pd = kp + kd * (1 - 1 / z) / T
    return pd * plant / z                                           # one sample of delay


def margins(kp, kd):
    """Gain and phase margins from a fine logarithmic sweep up to the Nyquist frequency."""
    ws = [10 ** (k / 2000) for k in range(-2000, int(2000 * math.log10(math.pi / T)))]
    wc = pm = wpc = gm = None
    last_ph, unwrap, prev = None, 0.0, None
    for w in ws:
        l = loop(kp, kd, w)
        ph = math.degrees(cmath.phase(l))
        if last_ph is not None and ph - last_ph > 180:
            unwrap -= 360                     # keep the phase continuous
        last_ph = ph
        ph += unwrap
        if prev is not None:
            if wc is None and abs(prev[1]) >= 1 > abs(l):
                wc, pm = w, 180 + ph
            if wpc is None and prev[2] > -180 >= ph:
                wpc, gm = w, -20 * math.log10(abs(l))
        prev = (w, l, ph)
    return wc, pm, wpc, gm


def bode(kp, kd):
    print(f"Loop gain, kp = {kp} N*m/rad, kd = {kd} N*m/(rad/s)")
    print("   w (rad/s)  |L| (dB)  phase (deg)")
    for w in (1, 3, 10, 30, 100, 300):
        l = loop(kp, kd, w)
        ph = math.degrees(cmath.phase(l))
        ph = ph - 360 if ph > 0 else ph
        print(f"  {w:9.0f}  {20 * math.log10(abs(l)):8.1f}  {ph:11.1f}")
    wc, pm, wpc, gm = margins(kp, kd)
    print(f"  gain crossover {wc:.1f} rad/s, phase margin {pm:.0f} deg")
    print(f"  phase crossover {wpc:.1f} rad/s, gain margin {gm:.1f} dB (x {10 ** (gm / 20):.1f})")


def closed(kp, kd, target=0.1, seconds=2.0):
    """Closed-loop step of 0.1 rad (about 6 degrees), small enough to stay linear."""
    q, w, u, prev = 0.0, 0.0, 0.0, 0.0
    peak, hist = 0.0, []
    for k in range(int(seconds / T)):
        rate = (q - prev) / T
        prev = q
        nxt = kp * (target - q) - kd * rate      # computed now, applied next period
        q, w = step(q, w, u)
        u = nxt
        peak = max(peak, q)
        hist.append(q - target)
    early, late = hist[100:200], hist[-100:]     # 0.5-1.0 s and the last 0.5 s
    size = lambda h: max(h) - min(h)
    ups = [k for k in range(len(hist) - 100, len(hist) - 1) if hist[k] < 0 <= hist[k + 1]]
    freq = 2 * math.pi * (len(ups) - 1) / ((ups[-1] - ups[0]) * T) if len(ups) > 2 else None
    return 100 * max(0.0, peak - target) / target, size(early), size(late), freq


def sweep():
    _, _, wpc, gm = margins(1.0, 0.0)
    print(f"P only, kp = 1.0: gain margin {gm:.1f} dB, so the loop should ring at {wpc:.1f} rad/s")
    print(f"and turn unstable near kp = 1.0 x {10 ** (gm / 20):.2f} = {10 ** (gm / 20):.2f}. Check it on 0.1 rad steps:")
    print("     kp     kd   PM (deg)  overshoot  swing 0.5-1 s  swing 1.5-2 s  ringing at")
    for kp, kd in ((0.5, 0), (1.0, 0), (2.0, 0), (2.86, 0), (6.5, 0), (7.0, 0), (2.86, 0.115)):
        _, pm, _, _ = margins(kp, kd)
        over, early, late, freq = closed(kp, kd)
        f = f"{freq:.1f} rad/s" if freq and late > 1e-4 else "-"
        o = f"{over:6.0f} %" if late < early else "  grows"
        print(f"  {kp:5.2f}  {kd:5.3f}  {pm:8.0f}   {o}   {1000 * early:8.2f} mrad  {1000 * late:9.2f} mrad  {f}")


if __name__ == "__main__":
    identify()
    print()
    bode(2.86, 0.115)
    print()
    sweep()
```

## Read the loop in the frequency domain

Write the controller as C and the plant as P; the loop gain is L = C × P. Magnitude is plotted in decibels, 20 log10 |L|, so 0 dB means |L| = 1. Phase is the lag from the command around the loop and back to the summing point. The gain crossover is the frequency where |L| = 1 (0 dB). The phase crossover is the frequency where the phase reaches −180°.

<Formula label="Gain margin: how much more gain the loop can take at the phase crossover before |L| reaches 1">GM = 1 / |L(jω_pc)|, in dB: GM_dB = −20 log10 |L(jω_pc)|</Formula>

<Formula label="Phase margin: how much more phase lag the loop can take at the gain crossover before reaching −180°">PM = 180° + ∠L(jω_c)</Formula>

With the Month 3 gains, kp = 2.86 N·m/rad and kd = 0.115 N·m/(rad/s), the model gives the table below. |L| crosses 0 dB at 34.6 rad/s (read between the 30 and 100 rad/s rows), where `∠L(34.6 rad/s) ≈ −124°`, so `PM = 180° + (−124°) = 56°`. The phase reaches −180° at 150.8 rad/s, where `|L(150.8 rad/s)| ≈ −14.2 dB`, so the <Term id="gain-margin">gain margin</Term> is 14.2 dB, a factor of `10^(14.2/20) = 5.1`. The 300 rad/s row is already at −263°, well past −180°; the margin is read at the first crossing.

These numbers already include two lags that a continuous C × P sketch leaves out. The controller holds its torque for one period (zero-order hold), and the firmware applies the torque computed from a reading one period late. At 200 Hz each sample is 5 ms. A delay of T seconds costs ω × T radians of phase, more at higher frequency: at the 34.6 rad/s crossover one sample costs 34.6 × 0.005 = 0.17 rad, about 10°, and the hold, which acts like half a sample, about 5° more. That is 15° of margin a delay-free Bode plot would report but the real loop does not have.

## From margins to step response

Margins are not decoration: they predict how the closed loop will move. With kd = 0, raising kp raises |L| at every frequency, so the gain crossover moves right into a region with more phase lag. PM falls, and overshoot rises.

At kp = 1.0 with P only, the gain margin is 16.6 dB, a gain ratio of 10^(16.6/20) = 6.8. Sustained oscillation needs `|L| = 1` with `∠L = −180°`. Scaling kp changes magnitude but not phase, so −180° can only be met at the phase crossover ω_pc = 40.2 rad/s (hence the ringing frequency), and the gain there must rise by that factor 6.8, giving `kp_crit = 1.0 × 6.8 = 6.8 ≈ 6.79`. The same margin therefore predicts that the loop should ring at 40.2 rad/s and turn unstable near kp = 6.79. The sweep agrees: as kp goes 0.5, 1, 2, 2.86, PM falls 53°, 37°, 22°, 15°, and overshoot rises 15 %, 33 %, 54 %, 66 %. At kp = 6.5, PM is 1°, overshoot is 98 %, and the 39.3 rad/s ringing decays slowly, with the swing falling only from 172.47 to 137.12 mrad between the two windows. At kp = 7.0, PM is −1°, the ringing grows from 236.89 to 285.66 mrad, and its frequency is 40.5 rad/s. Prediction and step response line up.

Derivative changes those numbers. Month 3's kd = 0.115 N·m/(rad/s), together with kp = 2.86, lifts PM from 15° to 56° and cuts overshoot from 66 % to 2 %. The PD term itself contributes phase `∠(kp + jω kd) = atan(ω · kd / kp) = atan(34.6 × 0.115 / 2.86) ≈ 54°` at the new crossover; as ω_c moves from ≈25 rad/s (P-only at the same kp) to 34.6 rad/s, the plant and sample-delay lag grow by about 11°, so the net rise is about 43° (54° − 11°); the measured PM lift is 15° → 56°. D adds that phase lead near the crossover, exactly where the loop needs it. That is the frequency-domain reason D calms the approach: it does not remove steady error, but it raises the phase margin.

## Persistency of excitation vs a fair step (sysid)

Lesson 1 already identified B and J from one open-loop torque step. That works for a first-order speed lag: PE is **not** the claim "two parameters ⇒ a step cannot identify them." Persistency of excitation means the **regressors over the identification horizon** are rich enough that `ΦᵀΦ` is well-conditioned (Ljung's input-signal chapter, pointed from the MIT OCW 6.435 syllabus; De Nicolao's 1997 tutorial contrasts equation-error and output-error). The toy reports the **finite-window** Gram condition number `cond(ΦᵀΦ)` as a practical diagnostic of richness on this horizon; **strict PE** is a stronger claim: there exist a fixed window length `N` and `α>0` such that for all sliding start indices `k`, `Σ_{i=k}^{k+N-1} φᵢφᵢᵀ ⪰ αI` (a **uniform** lower bound) — **not** “a positive-definite lower bound as the window grows” — and is **not** claimed here. For a richer structure the same step can leave `ΦᵀΦ` ill-conditioned — you learn that by **reporting** conditioning and parameter error, not by guaranteeing that a richer input always wins.

### Fair comparison

The toy locks three rules so the comparison is honest:

1. **Same duration** N = 200 samples.
2. **Same noise sequence** for every input arm inside a case.
3. **Matched input energy** `Σ u²` within `ENERGY_TOL = 0.01` (the richer input is scaled to the step's energy). Peak `|u|` is printed too — do not compare a tiny step to a huge PRBS.

### Estimator honesty

**Noise model (LOCKED):** an independent additive **measurement** noise. A noise-free state `z` follows the ARX recursion; the measured output is `y = z + v` with `v` independent of `(z, u)`. This is **not** the ARX *innovation* model `y_k = a y_{k-1} + b u_{k-1} + e_k` (where `e_k` is independent of the lagged regressors and OLS is consistent).

The fit is **equation-error OLS** (ARX-style): rows of `Φ` contain lagged **measured** `y`. Because those lagged outputs carry `v`, OLS is an **errors-in-variables (EIV) / equation-error** estimator — the printed `‖θ̂−θ‖` **includes that EE-OLS bias**. It is **not** claimed unbiased (finite-sample or asymptotic). An output-error (OE) or instrumental-variable (IV) fit would be a different estimator; this page does not implement one. Month 7's `sysid_fit` is a sibling pointer, not redone here.

```python
#!/usr/bin/env python3
"""sysid_pe_compare_toy.py: PE vs step — fair energy, report conditioning (stdlib).

Persistency of excitation (PE) is about the RICHNESS of the regressors over the
identification horizon (how well-conditioned ΦᵀΦ is), not a claim that "two
parameters ⇒ a step cannot identify them." A transient step often identifies a
first-order time constant τ; for a richer structure the same step can leave
ΦᵀΦ ill-conditioned. Numbers decide — this toy reports them and does not
guarantee that PE always wins.

Fair comparison LOCKED: same horizon N, the SAME measurement-noise sequence for
every input arm of a case, and input energy Σ u² matched within ENERGY_TOL
(the richer input is scaled to the step's energy). Peak |u| is also printed.

Noise model (LOCKED): independent additive measurement noise. A noise-free
state z follows the ARX recursion; the measured output is y = z + v with
v ~ N(0, σ²) independent of (z, u). Equation-error OLS then puts noisy lagged
y into Φ, so it is an errors-in-variables (EIV) estimator: the printed
‖θ̂−θ‖ includes that EE-OLS bias. This is NOT the ARX *innovation* model
y_k = a y_{k-1} + b u_{k-1} + e_k (where e_k is independent of the lagged
regressors and OLS is consistent). An output-error (OE) or instrumental-
variable (IV) fit would be a different estimator; not implemented here.

The finite-window Gram cond(ΦᵀΦ) is a practical diagnostic of regressor
richness on this horizon. Strict PE is a stronger statement: there exist a
fixed window length N and α>0 such that for all sliding start indices k,
Σ_{i=k}^{k+N-1} φᵢφᵢᵀ ⪰ αI (a uniform lower bound). The toy reports the
diagnostic, not a PE certificate.

Pointers (no copyrighted book text pasted): Ljung, System Identification, 2ed
(ISBN 0136566952) via the MIT OCW 6.435 syllabus; De Nicolao 1997 tutorial on
OE vs EE and PE. Existing lesson 5.1 step-τ identification and Month 7
sysid_fit are siblings, not redone here.
usage: python3 sysid_pe_compare_toy.py
"""
from __future__ import annotations

import math
import random

SEED = 51
N = 200                 # identification horizon (samples), shared
DT = 0.01               # s
ENERGY_TOL = 0.01       # |E_step - E_other| / E_step must be <= this
NOISE_STD = 0.02        # additive measurement noise v on y = z + v (same stream per case)

# Case A: first-order speed plant  τ z' + z = K u  (discrete ARX-1 on noise-free z).
# A single step is classically enough to read τ; PE is not required.
TAU_A = 0.08            # s  (matches the Month 3 / 5.1 joint time constant)
K_A = 1.0
A_TRUE_A = math.exp(-DT / TAU_A)
B_TRUE_A = K_A * (1.0 - A_TRUE_A)

# Case B: second-order ARX-2 with a slow and a fast mode. A step puts almost
# all energy at DC; a richer two-tone input improves the conditioning of ΦᵀΦ.
A1_TRUE_B = 1.70
A2_TRUE_B = -0.72
B_TRUE_B = 0.05


def prbs(rng: random.Random, n: int, amp: float) -> list[float]:
    """±amp pseudo-random binary sequence (clock every 4 samples)."""
    u, level = [], amp
    for k in range(n):
        if k % 4 == 0:
            level = amp if rng.random() < 0.5 else -amp
        u.append(level)
    return u


def two_tone(n: int, amp: float, f1: float = 1.5, f2: float = 7.0) -> list[float]:
    """Sum of two sines (Hz) — richer spectrum than a single step."""
    return [amp * (math.sin(2 * math.pi * f1 * k * DT)
                   + 0.7 * math.sin(2 * math.pi * f2 * k * DT)) for k in range(n)]


def scale_energy(u: list[float], target: float) -> list[float]:
    e = sum(v * v for v in u)
    if e <= 0.0:
        return list(u)
    s = math.sqrt(target / e)
    return [s * v for v in u]


def sim_meas_arx1(u: list[float], a: float, b: float, noise: list[float]) -> list[float]:
    """Noise-free ARX-1 state z; measured y = z + v (independent measurement noise)."""
    z = [0.0] * len(u)
    y = [0.0] * len(u)
    for k in range(1, len(u)):
        z[k] = a * z[k - 1] + b * u[k - 1]
        y[k] = z[k] + noise[k]
    return y


def sim_meas_arx2(
    u: list[float], a1: float, a2: float, b: float, noise: list[float]
) -> list[float]:
    """Noise-free ARX-2 state z; measured y = z + v (independent measurement noise)."""
    z = [0.0] * len(u)
    y = [0.0] * len(u)
    for k in range(2, len(u)):
        z[k] = a1 * z[k - 1] + a2 * z[k - 2] + b * u[k - 1]
        y[k] = z[k] + noise[k]
    return y


def ols(phi: list[list[float]], yy: list[float]) -> tuple[list[float], float]:
    """θ̂ = (ΦᵀΦ)⁻¹ Φᵀ y via Gaussian elimination; also return cond(ΦᵀΦ)."""
    p = len(phi[0])
    g = [[0.0] * p for _ in range(p)]
    rhs = [0.0] * p
    for row, yk in zip(phi, yy):
        for i in range(p):
            rhs[i] += row[i] * yk
            for j in range(p):
                g[i][j] += row[i] * row[j]
    # 2-norm condition via eigenvalue ratio of the Gram matrix (p small).
    cond = _cond(g)
    theta = _solve(g, rhs)
    return theta, cond


def _cond(g: list[list[float]]) -> float:
    # For p=2 use closed form; for p=3 use characteristic polynomial roots via
    # numpy-free power iteration on G and G^{-1} for rough 2-norm cond.
    p = len(g)
    if p == 2:
        tr = g[0][0] + g[1][1]
        det = g[0][0] * g[1][1] - g[0][1] * g[1][0]
        # eigenvalues of 2x2: roots of λ² - tr λ + det = 0
        disc = max(0.0, tr * tr - 4.0 * det)
        lam1 = 0.5 * (tr + math.sqrt(disc))
        lam2 = 0.5 * (tr - math.sqrt(disc))
        return abs(lam1 / lam2) if abs(lam2) > 1e-18 else float("inf")
    # Power iteration for λ_max(G) and λ_max(G^{-1}).
    def power(mat, iters=40):
        v = [1.0] * p
        for _ in range(iters):
            w = [sum(mat[i][j] * v[j] for j in range(p)) for i in range(p)]
            nrm = math.sqrt(sum(x * x for x in w)) or 1.0
            v = [x / nrm for x in w]
        w = [sum(mat[i][j] * v[j] for j in range(p)) for i in range(p)]
        return sum(v[i] * w[i] for i in range(p))
    lam_max = power(g)
    ginv = _invert(g)
    lam_min_inv = power(ginv)  # ≈ 1/λ_min
    lam_min = 1.0 / lam_min_inv if abs(lam_min_inv) > 1e-18 else 0.0
    return abs(lam_max / lam_min) if abs(lam_min) > 1e-18 else float("inf")


def _invert(g: list[list[float]]) -> list[list[float]]:
    p = len(g)
    a = [row[:] + [1.0 if i == j else 0.0 for j in range(p)] for i, row in enumerate(g)]
    for col in range(p):
        piv = max(range(col, p), key=lambda r: abs(a[r][col]))
        a[col], a[piv] = a[piv], a[col]
        div = a[col][col]
        for j in range(2 * p):
            a[col][j] /= div
        for r in range(p):
            if r == col:
                continue
            f = a[r][col]
            for j in range(2 * p):
                a[r][j] -= f * a[col][j]
    return [row[p:] for row in a]


def _solve(g: list[list[float]], rhs: list[float]) -> list[float]:
    p = len(g)
    a = [g[i][:] + [rhs[i]] for i in range(p)]
    for col in range(p):
        piv = max(range(col, p), key=lambda r: abs(a[r][col]))
        a[col], a[piv] = a[piv], a[col]
        div = a[col][col]
        for j in range(p + 1):
            a[col][j] /= div
        for r in range(p):
            if r == col:
                continue
            f = a[r][col]
            for j in range(p + 1):
                a[r][j] -= f * a[col][j]
    return [a[i][p] for i in range(p)]


def fit_arx1(u: list[float], y: list[float]) -> tuple[list[float], float, float]:
    phi, yy = [], []
    for k in range(1, len(u)):
        phi.append([y[k - 1], u[k - 1]])
```

## Smith predictor: taking a dead time out of the loop

The frequency-domain section above counts the phase that one 5 ms sample of delay costs: `ω × T` radians. This section takes the delay **much** longer, a dead time of several time constants' worth of phase, and shows one way to take it out of the loop and what that costs when the model is wrong. It is **not** the lead–lag compensator from Month 3, **not** the discrete LQR from the state-space lesson, and **not** a rework of PID anti-windup.

<Resource id="wiki-smith" />

**Source actually opened (HTML body read).** Wikipedia — Smith predictor: a predictive controller for systems with a significant feedback time delay (O. J. M. Smith, 1957). The plant is `G(z)` followed by a pure delay `z^−k`. Design `C` for the delay-free `G`, so that `H = C G / (1 + C G)` is satisfactory. Then ask for a controller `C̄` on the delayed plant that gives `H × z^−k`, and solve to get `C̄ = C / (1 + C G (1 − z^−k))`. It is implemented with a model `Ĝ`: an outer loop feeds the (outdated) output back, and an inner loop predicts the current, unobservable output of `G`. If `Ĝ z^−k` matches the plant perfectly, the outer and middle loops cancel; the article adds that a perfect match is impossible in reality. 以原文为准.

### Two loops and one model

Write the controller as one equation. The PI sees the measured error, corrected by what the model says is still in flight:

<Formula label="Smith predictor error">e = r − y − (ŷ − ŷ_delayed),   ŷ = Ĝ u,   ŷ_delayed = Ĝ z^−k̂ u</Formula>

With a true model, `ŷ_delayed` equals the noise-free plant output, so `e = r − ŷ`: the PI is closing the loop around the **undelayed** model, and the plant just plays that response `k` samples later. With `k = 0` the bracket is exactly zero and the Smith loop **is** the plain PI.

**Worked example: a first-order plant, a PI designed without the delay.**

```text
PI on the delay-free model:  C G = (τ / (K λ_c)) × (τ s + 1)/(τ s) × K/(τ s + 1) = 1 / (λ_c s),  λ_c = 0.15 s
crossover ω_c = 1 / λ_c = 6.67 rad/s; delay L = 0.20 s costs ω_c × L = 1.33 rad = 76.4°
A (ignore delay):  PM = 90° − 76.4° = 13.6°; unstable once L > λ_c × π/2 = 0.236 s (continuous estimate)
B (Smith, true model):  closed loop = e^(−L s) / (λ_c s + 1), the delay-free design shifted by L
short delay L = 0.04 s:  A keeps PM = 90° − 15.3° = 74.7°
```

The PI zero cancels the plant pole, so the delay-free loop is a pure integrator `1 / (λ_c s)`. A 0.2 s delay eats 76.4° of the 90° margin, and a PI that ignores it is left with 13.6°. The Smith predictor keeps the delay-free response and adds the delay at the end. A short 0.04 s delay leaves the plain PI with 74.7° of margin, so there is little left to fix.

**Integration step and its stability criterion.** The plant `τ dx/dt = −x + K u(t − L)` is stepped with explicit Euler at `H` inside each controller period `TS`. For `τ dx/dt = −x` explicit Euler multiplies `x` by `(1 − H/τ)` per step, so it is stable only when `H < 2τ`. The toy asserts `H < 2τ` on every run, and prints the bound (`2τ_min = 0.8233 s` against `H = 1 ms`). `H = 1 ms` is chosen for accuracy, ten sub-steps per 10 ms period, not for stability. The independent tests check that Euler on `τ dx/dt = −x` decays at 0.98× the limit and grows at 1.02×, and that halving `H` changes the matched Smith ISE by under 1 %. The closed loop's own stability is a separate question: that is the phase margin above, and A's 13.6° is why A rings.

### Fair setup

`smith_predictor_delay_toy.py` is **synthetic** and stdlib only. **Model assumptions:** an LTI first-order plant `K / (τ s + 1)` with a pure input delay `L = k × TS`. `K` is drawn in 0.8–1.2 and `τ` in 0.4–0.6 s. A discrete PI runs at `TS = 10 ms`, designed IMC-style on the delay-free nominal model (`Ti = τ`, `Kp = τ / (K λ_c)`, `λ_c = 0.15 s`). There is no actuator limit, so no windup. #!/usr/bin/env python3
```python
"""Smith predictor vs a PI that ignores the delay vs a Smith predictor with the wrong model.

Synthetic, stdlib only.  Not lead-lag (Month 3), not discrete LQR (Month 5
state-space lesson), not the PID anti-windup lesson.  A real delayed plant on
a bench: 本页未运行.  Smith-predictor statements are 以原文为准 (Wikipedia).

Plant: first-order lag with a pure input delay of L = k * TS seconds,
    tau * dx/dt = -x + K * u(t - L),      y = x + measurement noise,
integrated with explicit Euler at H inside each controller period TS.
Controller: one discrete PI designed on the delay-free model G = K / (tau s + 1)
(IMC-style: Ti = tau, Kp = tau / (K * LAMBDA_C), target closed loop 1 / (LAMBDA_C s + 1)).
    A_pi_ignore     that PI acting on the delayed plant directly
    B_smith         the same PI inside a Smith predictor with the true K, tau and k:
                    e = r - y - (y_model - y_model_delayed)   (C_bar = C / (1 + C G (1 - z^-k)))
    C_smith_wrong   the same Smith structure with a wrong model: delay k_hat and gain K_hat off
Common random numbers: per (regime, seed) the plant K and tau, the reference
step, the load disturbance, the noise sequence and the model errors for C are
drawn once and shared by all three arms.  Arms differ only in the controller.

Explicit Euler on tau * dx/dt = -x + ... is stable when H < 2 * tau; the toy
asserts H < 2 * tau on every run.
"""
import math
import random

SEEDS = (0, 1, 2, 3, 4)
TS = 0.01                 # s, controller period
SUB = 10                  # Euler sub-steps per controller period
H = TS / SUB              # s, plant integration step
LAMBDA_C = 0.15           # s, target delay-free closed-loop time constant
T_END = 8.0               # s
T_STEP, T_LOAD = 0.5, 4.0 # s: reference step, then an input load step
U_MAX = 1e6               # no actuator limit in practice; only stops float overflow
DIVERGED = 1e3            # ISE above this is reported as divergence
NUM_ZERO = 1e-9           # |m| and sd both below this: floating-point residue, not a gap

# name: (delay k in samples, delay-model error ratio range for C, gain-model error range for C)
REGIMES = {
    "zero_delay": (0, (0.3, 0.5), (-0.2, 0.2)),
    "long_delay": (20, (0.3, 0.5), (-0.2, 0.2)),
    "short_delay": (4, (0.3, 0.5), (-0.2, 0.2)),
    "wrong_delay_big": (20, (0.9, 1.1), (-0.05, 0.05)),
}
ARMS = ("A_pi_ignore", "B_smith", "C_smith_wrong")


def shared_draws(regime, seed):
    """Common random numbers: one plant, one reference, one disturbance, one noise sequence, one model error."""
    k, derr, gerr = REGIMES[regime]
    rng = random.Random(f"{regime}/{seed}")
    gain, tau = rng.uniform(0.8, 1.2), rng.uniform(0.4, 0.6)
    ref, load = rng.uniform(0.8, 1.2), rng.uniform(-0.4, -0.2)
    noise = [rng.gauss(0.0, 0.005) for _ in range(int(round(T_END / TS)) + 1)]
    d_ratio = rng.uniform(*derr) * rng.choice((-1.0, 1.0))
    g_ratio = rng.uniform(*gerr)
    return {"K": gain, "tau": tau, "k": k, "ref": ref, "load": load, "noise": noise,
            "k_hat_wrong": max(0, int(round(k * (1.0 + d_ratio)))), "K_hat_wrong": gain * (1.0 + g_ratio)}


def euler_first_order(x, u, gain, tau, h, steps):
    for _ in range(steps):
        x += h * (-x + gain * u) / tau
    return x


def run(regime, seed, arm):
    d = shared_draws(regime, seed)
    gain, tau, k = d["K"], d["tau"], d["k"]
    assert H < 2.0 * tau, (regime, seed, H, tau)
    kp, ti = tau / (gain * LAMBDA_C), tau          # PI designed on the delay-free nominal model
    if arm == "C_smith_wrong":
        k_hat, gain_hat = d["k_hat_wrong"], d["K_hat_wrong"]
    else:
        k_hat, gain_hat = k, gain
    n = int(round(T_END / TS))
    u_hist = [0.0] * (max(k, k_hat) + 1)            # u_hist[-1 - j] = u from j periods ago
    x = xm = 0.0
    ym_hist = [0.0] * (k_hat + 1)
    integ, ise, peak, settle = 0.0, 0.0, -math.inf, None
    diverged = False
    for i in range(n):
        t = i * TS
        r = d["ref"] if t >= T_STEP else 0.0
        y = x + d["noise"][i]
        e = r - y
        if arm != "A_pi_ignore":
            e -= ym_hist[-1] - ym_hist[-1 - k_hat]  # Smith: undelayed model output minus delayed model output
        integ += e * TS / ti
        u = max(-U_MAX, min(U_MAX, kp * (e + integ)))
        u_hist.append(u)
        load = d["load"] if t >= T_LOAD else 0.0
        x = euler_first_order(x, u_hist[-1 - k] + load, gain, tau, H, SUB)
        xm = euler_first_order(xm, u, gain_hat, tau, H, SUB)
        ym_hist.append(xm)
        err = r - x
        ise += err * err * TS
        if t >= T_STEP and t < T_LOAD:
            peak = max(peak, x)
            if abs(err) > 0.02 * d["ref"]:
                settle = t - T_STEP
        if not math.isfinite(x) or ise > DIVERGED:
            diverged = True
            break
    if diverged:
        return {"ise": math.inf, "over": math.inf, "settle": math.inf, "div": True}
    return {"ise": ise, "over": 100.0 * max(0.0, peak - d["ref"]) / d["ref"],
            "settle": (settle if settle is not None else 0.0) + TS, "div": False}


def mean_sd(xs):
    mu = sum(xs) / len(xs)
    return mu, math.sqrt(sum((x - mu) ** 2 for x in xs) / (len(xs) - 1))


def num(x):
    if x != 0.0 and abs(x) < 5e-4:
        return f"{x:.3e}"
    return f"{x:.4f}"

    n, opp, zero = len(diffs), sum(1 for d in diffs if d * m < 0), sum(1 for d in diffs if d == 0)
    if opp == 0 and zero == 0:
```

## Common mistakes

- **Degrees in a radian model.** Month 3's 0.05 N·m/deg is 2.86 N·m/rad. Using 0.05 in a model that works in radians makes the loop about 57 times too weak, so the margins mean nothing.
- **Forgetting the hold and the delay.** A continuous C × P Bode plot has no sampling. The real loop holds torque for 5 ms and applies it one sample late; both add phase lag (about 15° at this crossover), so leave them out and your predicted PM is too optimistic.
- **Reading margins from an unchecked model.** If the open-loop step misses the measured final speed or 63 % time, fix B and J first. Margins read from wrong parameters have no basis.
- **Ignoring saturation.** Linear analysis assumes the commanded torque is actually delivered. If the motor clips, the loop gain is no longer that L; keep test steps small, and sweep gains only where the command stays inside the limit.
- **Identifying with a different load.** Gravity feedforward cancels the gravity you modelled, not a new payload or a spring. Measure tau and B in the pose and load the joint will run with; a different load changes J and B and moves both margins.
- **Declaring "two parameters ⇒ step unidentifiable."** A first-order τ is routinely read from a step. PE is about regressor richness; report `cond(ΦᵀΦ)` and `‖θ̂−θ‖` instead of a blanket ban.
- **Comparing inputs with unequal energy.** A huge PRBS against a tiny step is not a PE lesson. Match `Σ u²` (or peak `|u|`) within a stated tolerance.
- **Calling equation-error OLS unbiased on noisy y.** With `y = z + v`, lagged measured y sits in `Φ` → EIV / EE-OLS bias; say so, or switch to OE / IV. Do not confuse this with an ARX innovation model (where OLS is consistent).
- **Treating finite-window `cond(ΦᵀΦ)` as a strict PE certificate.** The printed condition number is a horizon diagnostic; strict PE needs a fixed window length `N` and `α>0` such that for all sliding starts `k`, `Σ_{i=k}^{k+N-1} φᵢφᵢᵀ ⪰ αI` (uniform lower bound) — not “positive-definite as the window grows.”

## Computed torque: inverse dynamics in the loop

This lesson's gravity feedforward computes one term, the gravity torque `0.4 N·m × cos(q)`, and adds it to the command. **Inverse dynamics** computes the whole torque a prescribed motion needs, inertia and coupling included, and **computed torque** puts that model inside the feedback loop. This section compares PD + gravity compensation with computed torque on one shared two-joint arm, and keeps a regime where computed torque with the wrong payload loses. It extends the gravity feedforward above (that is the `ĝ` term alone, kept as arm A). It is **not** discrete LQR or MPC, **not** the Smith predictor, **not** 2-DOF setpoint weighting, and **not** a humanoid whole-body controller.

### The torque map, the control law and the step limit

<Formula label="Rigid two-joint arm (inverse dynamics: the torque for a given motion)">τ = M(q) q'' + C(q, q') + g(q)</Formula>

<Formula label="Computed torque, model in the loop (e = q_d − q)">τ = M̂(q) (q_d'' + KP e + KD e') + Ĉ + ĝ</Formula>

<Formula label="PD + gravity compensation (arm A; D0 = diagonal of M at the start pose)">τ = D0 (KP e + KD e') + ĝ(q)</Formula>

<Formula label="Error dynamics when the model is exact, no friction, no noise">e'' + KD e' + KP e = 0</Formula>

<Formula label="Stable step of semi-implicit Euler on those error dynamics: DT must stay below H*">H* = 2 (√(1 + Z²) − Z) / W,  W = √KP,  Z = KD / (2 W)</Formula>

**Worked example.** `KP = 400 1/s²` and `KD = 40 1/s` give `W = 20 rad/s` and `Z = 1`, so `H* = 2 × (√2 − 1) / 20 = 41.4214 ms`; the toy steps at `DT = 1 ms`, `0.0241 H*`. With point masses 1.5 kg at the elbow and 1.0 + 0.5 kg at the tip, links 0.30 m and 0.25 m, at the centre pose `q2 = 0.8 rad`: `M22 = 1.5 × 0.25² = 0.09375`, `M12 = 0.09375 + 1.5 × 0.30 × 0.25 × cos 0.8 = 0.1721` and `M11 = 3.0 × 0.30² + 0.09375 + 2 × 0.0784 = 0.5205 kg m²`.

**Correctness criterion for the model.** A test checks the mass matrix, Coriolis and gravity terms against these hand values, and checks that the matched arm with no friction and no noise tracks a 1 Hz trajectory with an error under 5 mrad. The friction `FC tanh(q' / 0.02)` with `FC = 0.3 N m` is in the plant but in **no** arm's model.

**Stable-step criterion.** Plant and controller are stepped together with semi-implicit Euler. With an exact model the error obeys the linear equation above, which is stable when `DT` stays below `H*`. The toy runs the matched arm from a 0.0707 rad error with a fixed target: at `0.98 H*` the error after 300 steps is 4.0202e-10 rad (decays); at `1.02 H*` it is 2.4418e+05 rad (grows). A and C have nonlinear error dynamics, so the toy checks them by running the whole table again at `DT / 2`: the largest relative change in rms error is 0.0143.

```python
#!/usr/bin/env python3
"""Computed torque (inverse dynamics in the loop) vs PD + gravity compensation on one shared 2R arm.

Synthetic, stdlib only.  Not this lesson's single-joint gravity feedforward (that is the g(q)
term alone, kept here as arm A); not discrete LQR / MPC, not the Smith predictor, not 2-DOF
setpoint weighting, not a humanoid whole-body controller.  Real arm or identification lab:
本页未运行.  Wikipedia "Inverse dynamics" statements (robot motor torques from a prescribed
motion and the inertial properties) are 以原文为准; the arm model and the control law below are
a textbook-style stand-in.

Plant: planar 2R arm moving in a vertical plane, point masses at the link ends (M1 at the elbow,
M2 + payload at the tip), link lengths L1, L2.  With c2 = cos q2, s2 = sin q2:
  M11 = (m1 + m2) L1^2 + m2 L2^2 + 2 m2 L1 L2 c2,  M12 = m2 L2^2 + m2 L1 L2 c2,  M22 = m2 L2^2
  C   = (-m2 L1 L2 s2 (2 q1' q2' + q2'^2),  m2 L1 L2 s2 q1'^2)
  g   = ((m1 + m2) G L1 cos q1 + m2 G L2 cos(q1 + q2),  m2 G L2 cos(q1 + q2))
  M q'' + C + g = tau - friction,  friction = FC tanh(q' / 0.02) per joint (in no arm's model).
Controllers (e = q_d - q measured, KP, KD per joint in 1/s^2 and 1/s):
  A_pdg     tau = D0 (KP e + KD e') + g_hat(q)          D0 = diag of M at the start pose,
                                                         correct payload (PD + gravity)
  B_ct      tau = M_hat(q) (q_d'' + KP e + KD e') + C_hat + g_hat   matched model (computed torque)
  C_ctwrong the same law with the payload left out of M_hat, C_hat, g_hat (wrong inertia)
Integration: semi-implicit Euler at step DT, the controller is evaluated every step.  Stable-step
criterion: with a matched model and no friction or noise, the error obeys e'' + KD e' + KP e = 0
integrated by this scheme, which is stable for DT < H_STAR = 2 (sqrt(1 + Z^2) - Z) / W with
W = sqrt(KP), Z = KD / (2 W).  Printed checks: matched arm from a 0.05 rad error at 0.98 x and
1.02 x H_STAR, and the whole table again at DT / 2.  A and C have nonlinear error dynamics; they
are covered by the half-step check only.
Measurement noise (q and q') is drawn per 1 ms sample and held, so DT / 2 sees the same noise.
Metrics per seed: rms tracking error (mrad, both joints), peak error (mrad), rms feedback torque
(N m, the part of tau that comes from e and e').
Common random numbers: per (regime, seed) the trajectory amplitude scale, both phases and the
noise sequence are drawn once and used by all three arms.
Regimes and expectations, written before the first run:
  fast_coupled       f 1.0 Hz, payload 0.5 kg   B consistent win over A on rms error
  slow_quasi_static  f 0.05 Hz, payload 0.5 kg  A and B near-tie (gravity dominates, both have it)
  payload_mismatch   f 0.25 Hz, payload 2.0 kg  C (computed torque, wrong inertia) loses to A
                                                 (PD + gravity with the right payload), consistent
  C loses to B in every regime.
The FC=0 sensitivity block and the centre-pose stiffness lines were added after
the first run; they are not pre-declared regimes.

import math
import random

SEEDS = (0, 1, 2, 3, 4)
L1, L2 = 0.30, 0.25        # m
M1, M2 = 1.5, 1.0          # kg, point masses at elbow and tip (tip mass without payload)
G = 9.81
FC = 0.3                   # N m, Coulomb-like friction, unmodelled
KP, KD = 400.0, 40.0       # 1/s^2, 1/s
DT = 1e-3                  # s
SAMPLE = 1e-3              # s, noise sample period
SIG_Q, SIG_QD = 2e-4, 0.01  # rad, rad/s
Q0 = (0.3, 0.8)            # rad, centre pose
AMP = (0.8, 1.0)           # rad
NUM_ZERO = 1e-9
ARMS = ("A_pdg", "B_ct", "C_ctwrong")
# name: (f Hz, duration s, real payload kg, payload in C's model kg); written before the first run
REGIMES = {
    "fast_coupled": (1.0, 4.0, 0.5, 0.0),
    "slow_quasi_static": (0.05, 6.0, 0.5, 0.0),
    "payload_mismatch": (0.25, 6.0, 2.0, 0.0),
}
STREAM = {"fast_coupled": 0, "slow_quasi_static": 1, "payload_mismatch": 2}


def h_star(kp=KP, kd=KD):
    w = math.sqrt(kp)
    z = kd / (2.0 * w)
    return 2.0 * (math.sqrt(1.0 + z * z) - z) / w


def dyn(q, qd, payload):
    m2 = M2 + payload
    c2, s2 = math.cos(q[1]), math.sin(q[1])
    m11 = (M1 + m2) * L1 * L1 + m2 * L2 * L2 + 2.0 * m2 * L1 * L2 * c2
    m12 = m2 * L2 * L2 + m2 * L1 * L2 * c2
    m22 = m2 * L2 * L2
    h = m2 * L1 * L2 * s2
    cv = (-h * (2.0 * qd[0] * qd[1] + qd[1] * qd[1]), h * qd[0] * qd[0])
    c12 = math.cos(q[0] + q[1])
    gv = ((M1 + m2) * G * L1 * math.cos(q[0]) + m2 * G * L2 * c12, m2 * G * L2 * c12)
    return (m11, m12, m22), cv, gv


def desired(t, f, scale, ph):
    w = 2.0 * math.pi * f
    q = [Q0[i] + scale * AMP[i] * math.sin(w * t + ph[i]) for i in (0, 1)]
    qd = [scale * AMP[i] * w * math.cos(w * t + ph[i]) for i in (0, 1)]
    qdd = [-scale * AMP[i] * w * w * math.sin(w * t + ph[i]) for i in (0, 1)]
    return q, qd, qdd


def shared_draws(regime, seed):
    rng = random.Random(1000 * STREAM[regime] + seed)
    scale = rng.uniform(0.8, 1.0)
    ph = (rng.uniform(0.0, 2.0 * math.pi), rng.uniform(0.0, 2.0 * math.pi))
    n = int(round(REGIMES[regime][1] / SAMPLE)) + 1
    noise = [(rng.gauss(0.0, SIG_Q), rng.gauss(0.0, SIG_Q), rng.gauss(0.0, SIG_QD), rng.gauss(0.0, SIG_QD)) for _ in range(n)]
    return scale, ph, noise


def control(arm, qm, qdm, qr, qdr, qddr, payload_real, payload_c, d0):
    e = (qr[0] - qm[0], qr[1] - qm[1])
    ed = (qdr[0] - qdm[0], qdr[1] - qdm[1])
    v = (KP * e[0] + KD * ed[0], KP * e[1] + KD * ed[1])
    if arm == "A_pdg":
        _, _, gh = dyn(qm, qdm, payload_real)
        fb = (d0[0] * v[0], d0[1] * v[1])
        return (fb[0] + gh[0], fb[1] + gh[1]), fb
    mh, ch, gh = dyn(qm, qdm, payload_real if arm == "B_ct" else payload_c)
    a = (qddr[0] + v[0], qddr[1] + v[1])
    tau = (mh[0] * a[0] + mh[1] * a[1] + ch[0] + gh[0], mh[1] * a[0] + mh[2] * a[1] + ch[1] + gh[1])
    fb = (mh[0] * v[0] + mh[1] * v[1], mh[1] * v[0] + mh[2] * v[1])
    return tau, fb


def step_plant(q, qd, tau, payload, dt, friction=True, fc=None):
    m, cv, gv = dyn(q, qd, payload)
    # plant friction is FC * math.tanh(qd / 0.02) per joint (unmodelled); fc overrides FC
    fval = 0.0 if not friction else (FC if fc is None else fc)
    f = (fval * math.tanh(qd[0] / 0.02), fval * math.tanh(qd[1] / 0.02)) if fval else (0.0, 0.0)
    r0 = tau[0] - cv[0] - gv[0] - f[0]
    r1 = tau[1] - cv[1] - gv[1] - f[1]
    det = m[0] * m[2] - m[1] * m[1]
    a0 = (m[2] * r0 - m[1] * r1) / det
    a1 = (-m[1] * r0 + m[0] * r1) / det
    qd = [qd[0] + dt * a0, qd[1] + dt * a1]
    q = [q[0] + dt * qd[0], q[1] + dt * qd[1]]
    return q, qd


def run_arm(arm, regime, draws, dt, fc=None):
    f, dur, payload, payload_c = REGIMES[regime]
    scale, ph, noise = draws
    q, qd, _ = desired(0.0, f, scale, ph)
    m0, _, _ = dyn(desired(0.0, f, scale, ph)[0], (0.0, 0.0), payload)
    d0 = (m0[0], m0[2])
    n = int(round(dur / dt))
    se = peak = sfb = 0.0
    for k in range(n):
        t = k * dt
        qr, qdr, qddr = desired(t, f, scale, ph)
        nz = noise[int(t / SAMPLE + 1e-9)]
        qm = (q[0] + nz[0], q[1] + nz[1])
        qdm = (qd[0] + nz[2], qd[1] + nz[3])
        tau, fb = control(arm, qm, qdm, qr, qdr, qddr, payload, payload_c, d0)
        e2 = (qr[0] - q[0]) ** 2 + (qr[1] - q[1]) ** 2
        se += e2
        peak = max(peak, math.sqrt(e2))
        sfb += fb[0] ** 2 + fb[1] ** 2
        q, qd = step_plant(q, qd, tau, payload, dt, fc=fc)
    return {"rms": 1000.0 * math.sqrt(se / n), "peak": 1000.0 * peak, "fb": math.sqrt(sfb / n)}


def matched_error_run(h, steps=300):
    """B_ct with a constant target, no friction, no noise, 0.05 rad start error; |e| at the end."""
    qr = list(Q0)
    q, qd = [Q0[0] - 0.05, Q0[1] - 0.05], [0.0, 0.0]
    for _ in range(steps):
        tau, _ = control("B_ct", q, qd, qr, (0.0, 0.0), (0.0, 0.0), 0.5, 0.5, None)
        q, qd = step_plant(q, qd, tau, 0.5, h, friction=False)
    return math.hypot(qr[0] - q[0], qr[1] - q[1])



def centre_pose_stiffness(payload=0.5):
    """M, (M^{-1})22 and joint-2 stiffness at Q0; used by the post-hoc FC=0 block."""
    m, _, _ = dyn(Q0, (0.0, 0.0), payload)
    det = m[0] * m[2] - m[1] * m[1]
    minv22 = m[0] / det
    inv_m22 = 1.0 / m[2]
    k_ct = KP / minv22
    k_pd = m[2] * KP
    e_ct = 1000.0 * FC / k_ct
    e_pd = 1000.0 * FC / k_pd
    return m, minv22, inv_m22, k_ct, k_pd, e_ct, e_pd


def run(dt):
    out = {}
    for regime in REGIMES:
        draws = [shared_draws(regime, s) for s in SEEDS]
        out[regime] = {arm: [run_arm(arm, regime, d, dt) for d in draws] for arm in ARMS}
    return out


def mean_sd(xs):
    mu = sum(xs) / len(xs)
    return mu, math.sqrt(sum((x - mu) ** 2 for x in xs) / (len(xs) - 1))


def num(x):
    if x != 0.0 and abs(x) < 5e-5:
        return f"{x:.3e}"
    return f"{x:.4f}"


def sign_note(diffs, m):
    n, opp, zero = len(diffs), sum(1 for d in diffs if d * m < 0), sum(1 for d in diffs if d == 0)
    if opp == 0 and zero == 0:
        return f"same sign on all {n} seeds"
    if opp == 0:
        return f"no seed has the opposite sign, {zero} of {n} equal"
    note = f"{opp} of {n} seeds {'has' if opp == 1 else 'have'} the opposite sign"
    return note + (f", {zero} of {n} equal" if zero else "")


def verdict(xa, xb):
    diffs = [a - b for a, b in zip(xa, xb)]
    if all(d == 0.0 for d in diffs):
        return "0.0000+-0.0000: tie: identical on every seed"
    m, s = mean_sd(diffs)
    if abs(m) < NUM_ZERO and s < NUM_ZERO:
        return f"{num(m)}+-{num(s)}: numerically zero (floating-point residue), effectively a tie"
    if abs(m) <= s:
        label = "near-tie / small gap, within seed noise (|m| <= sd)"
    elif abs(m) < 0.2 * min(abs(mean_sd(xa)[0]), abs(mean_sd(xb)[0])):
        label = "small but consistent gap, not a tie (|m| > sd)"
    else:
        label = "clear gap, not a tie (|m| > sd)"
    return f"{num(m)}+-{num(s)}: {label}; {sign_note(diffs, m)}"
```

### Read the regimes

How the labels are used on this page, in this order: **tie: identical on every seed** only when the paired per-seed difference is exactly zero on every seed; **numerically zero (floating-point residue), effectively a tie** when `|paired mean|` and its sd are both below 1e-9 (no sign count is printed on such a line); **near-tie / small gap, within seed noise** when `|paired mean| ≤ sd`; otherwise a **consistent** gap (`|paired mean| > sd`), called **small** if `|m|` is under 20 % of the smaller arm mean and **clear** otherwise; the 20 % rule only chooses between those two words. Every consistent line carries a same-sign count over the 5 seeds, and any seed with the opposite sign is reported; a sign count alone never makes a gap consistent. Gaps are computed from unrounded values. Paired differences are B−A, C−B and C−A. `rms` is the rms tracking error in mrad, `fb` the rms feedback torque in N m.

- **fast_coupled:**
  - **Computed torque wins with a clear gap:** B−A rms −100.9081±33.6992 mrad, same sign on all 5 seeds. At 1 Hz the inertia and coupling torques are large, and PD + gravity has to produce them from error; B computes them, so its feedback torque drops too (B−A fb −13.9555±3.3677 N m, clear, 5/5).
