## Why model the joint

The joint is the same one from Month 3: J = 0.004 kg·m², B = 0.05 N·m per rad/s, and gravity 0.4 N·m × cos(q). Gravity feedforward computes the gravity torque from the measured angle and adds it to the command; when the model is right, it cancels gravity, so the remaining dynamics are linear: torque u drives J q'' + B q'. Transfer functions and Bode plots describe linear plants, and keeping the test steps small is what keeps the real joint inside the range where the linear model holds.

<Formula label="Plant with gravity feedforward: angle per unit torque">G(s) = 1 / (J s² + B s) = 1 / (s (J s + B))</Formula>

With J = 0.004 kg·m² and B = 0.05 N·m per rad/s, the denominator is s(J s + B). One pole sits at s = 0, the free integrator that turns torque into speed. The other sits at s = −B/J = −12.5 1/s, a first-order lag with time constant J/B = 0.004 / 0.05 = 0.08 s. After a torque step, speed reaches 63 % of its final value in 0.08 s.

Month 3 expressed the gains in degrees: 0.05 N·m/deg and 0.002 N·m per deg/s. Multiply by 180/π to get SI: 0.05 × 180/π = 2.86 N·m/rad, and 0.002 × 180/π = 0.115 N·m/(rad/s). The model below uses those converted gains, so its results describe the loop you tuned by hand.

## Identify the model from data

Before trusting a margin, check that the model matches the motor. The simplest test is an open-loop torque step: hold a constant torque u with gravity feedforward on, let the joint accelerate from rest, and log speed. For this first-order speed response the final speed is u/B and the 63 % time is tau = J/B. With u = 0.2 N·m and B = 0.05 N·m per rad/s, the final speed should be 0.2 / 0.05 = 4 rad/s; the log stops at 0.5 s, about six time constants, when the speed is still 0.2 % short, so it reads 3.99 rad/s. The 63 % point lands at 0.080 s, so J = B × tau = 0.05 × 0.080 = 0.0040 kg·m².

```python
"""joint_freq.py: model the Month 3 arm joint, then read its loop in the frequency domain.

The joint is the one from pid_sim.py (J = 0.004 kg*m^2, B = 0.05 N*m per rad/s, gravity
0.4 N*m * cos(angle)), with gravity cancelled by a feedforward term so that what is left
is linear: torque -> J*q'' + B*q'. The controller runs at 200 Hz, holds its torque for one
period (zero-order hold) and, like most real firmware, applies the torque computed from a
reading one period later (one sample of delay). Units are SI: angles in rad, gains in
N*m per rad and N*m per rad/s (Month 3's 0.05 N*m per degree is 2.86 N*m per rad).
"""
import cmath
import math

J, B, GRAV, T = 0.004, 0.05, 0.4, 0.005
A = B / J                                    # 12.5 1/s, so the time constant J/B is 0.08 s
E = math.exp(-A * T)
# exact discretisation of J*q'' + B*q' = u with the torque held over each period
PHI = ((1.0, (1 - E) / A), (0.0, E))
GAM = ((T - (1 - E) / A) / (A * J), (1 - E) / (A * J))


def step(q, w, u):
    return (q + PHI[0][1] * w + GAM[0] * u, E * w + GAM[1] * u)


def identify():
    """Open-loop test: hold 0.2 N*m (plus gravity feedforward) and log the speed."""
    print("Open-loop step: 0.2 N*m from rest, speed logged at 200 Hz")
    q, w, log = 0.0, 0.0, []
    for k in range(101):
        log.append((k * T, w))
        q, w = step(q, w, 0.2)
    for t, s in log[::8][:8]:
        print(f"  t = {t:4.2f} s   speed {s:5.2f} rad/s")
    final = log[-1][1]
    t63 = next(t for t, s in log if s >= 0.632 * final)
    b = 0.2 / final
    print(f"  final speed {final:.2f} rad/s -> B = 0.2 / {final:.2f} = {b:.3f} N*m per rad/s")
    print(f"  63 % of it at t = {t63:.3f} s -> J = B x tau = {b * t63:.4f} kg*m^2")


def loop(kp, kd, w):
    """Loop gain L = C * P at angular frequency w (rad/s), with z = e^(jwT)."""
    z = cmath.exp(1j * w * T)
    det = (z - PHI[0][0]) * (z - PHI[1][1]) - PHI[0][1] * PHI[1][0]
    plant = ((z - PHI[1][1]) * GAM[0] + PHI[0][1] * GAM[1]) / det   # angle / torque
    pd = kp + kd * (1 - 1 / z) / T
    return pd * plant / z                                           # one sample of delay


def margins(kp, kd):
    """Gain and phase margins from a fine logarithmic sweep up to the Nyquist frequency."""
    ws = [10 ** (k / 2000) for k in range(-2000, int(2000 * math.log10(math.pi / T)))]
    wc = pm = wpc = gm = None
    last_ph, unwrap, prev = None, 0.0, None
    for w in ws:
        l = loop(kp, kd, w)
        ph = math.degrees(cmath.phase(l))
        if last_ph is not None and ph - last_ph > 180:
            unwrap -= 360                     # keep the phase continuous
        last_ph = ph
        ph += unwrap
        if prev is not None:
            if wc is None and abs(prev[1]) >= 1 > abs(l):
                wc, pm = w, 180 + ph
            if wpc is None and prev[2] > -180 >= ph:
                wpc, gm = w, -20 * math.log10(abs(l))
        prev = (w, l, ph)
    return wc, pm, wpc, gm


def bode(kp, kd):
    print(f"Loop gain, kp = {kp} N*m/rad, kd = {kd} N*m/(rad/s)")
    print("   w (rad/s)  |L| (dB)  phase (deg)")
    for w in (1, 3, 10, 30, 100, 300):
        l = loop(kp, kd, w)
        ph = math.degrees(cmath.phase(l))
        ph = ph - 360 if ph > 0 else ph
        print(f"  {w:9.0f}  {20 * math.log10(abs(l)):8.1f}  {ph:11.1f}")
    wc, pm, wpc, gm = margins(kp, kd)
    print(f"  gain crossover {wc:.1f} rad/s, phase margin {pm:.0f} deg")
    print(f"  phase crossover {wpc:.1f} rad/s, gain margin {gm:.1f} dB (x {10 ** (gm / 20):.1f})")


def closed(kp, kd, target=0.1, seconds=2.0):
    """Closed-loop step of 0.1 rad (about 6 degrees), small enough to stay linear."""
    q, w, u, prev = 0.0, 0.0, 0.0, 0.0
    peak, hist = 0.0, []
    for k in range(int(seconds / T)):
        rate = (q - prev) / T
        prev = q
        nxt = kp * (target - q) - kd * rate      # computed now, applied next period
        q, w = step(q, w, u)
        u = nxt
        peak = max(peak, q)
        hist.append(q - target)
    early, late = hist[100:200], hist[-100:]     # 0.5-1.0 s and the last 0.5 s
    size = lambda h: max(h) - min(h)
    ups = [k for k in range(len(hist) - 100, len(hist) - 1) if hist[k] < 0 <= hist[k + 1]]
    freq = 2 * math.pi * (len(ups) - 1) / ((ups[-1] - ups[0]) * T) if len(ups) > 2 else None
    return 100 * max(0.0, peak - target) / target, size(early), size(late), freq


def sweep():
    _, _, wpc, gm = margins(1.0, 0.0)
    print(f"P only, kp = 1.0: gain margin {gm:.1f} dB, so the loop should ring at {wpc:.1f} rad/s")
    print(f"and turn unstable near kp = 1.0 x {10 ** (gm / 20):.2f} = {10 ** (gm / 20):.2f}. Check it on 0.1 rad steps:")
    print("     kp     kd   PM (deg)  overshoot  swing 0.5-1 s  swing 1.5-2 s  ringing at")
    for kp, kd in ((0.5, 0), (1.0, 0), (2.0, 0), (2.86, 0), (6.5, 0), (7.0, 0), (2.86, 0.115)):
        _, pm, _, _ = margins(kp, kd)
        over, early, late, freq = closed(kp, kd)
        f = f"{freq:.1f} rad/s" if freq and late > 1e-4 else "-"
        o = f"{over:6.0f} %" if late < early else "  grows"
        print(f"  {kp:5.2f}  {kd:5.3f}  {pm:8.0f}   {o}   {1000 * early:8.2f} mrad  {1000 * late:9.2f} mrad  {f}")


if __name__ == "__main__":
    identify()
    print()
    bode(2.86, 0.115)
    print()
    sweep()
```

## Read the loop in the frequency domain

Write the controller as C and the plant as P; the loop gain is L = C × P. Magnitude is plotted in decibels, 20 log10 |L|, so 0 dB means |L| = 1. Phase is the lag from the command around the loop and back to the summing point. The gain crossover is the frequency where |L| = 1 (0 dB). The phase crossover is the frequency where the phase reaches −180°.

<Formula label="Gain margin: how much more gain the loop can take at the phase crossover before |L| reaches 1">GM = 1 / |L(jω_pc)|, in dB: GM_dB = −20 log10 |L(jω_pc)|</Formula>

<Formula label="Phase margin: how much more phase lag the loop can take at the gain crossover before reaching −180°">PM = 180° + ∠L(jω_c)</Formula>

With the Month 3 gains, kp = 2.86 N·m/rad and kd = 0.115 N·m/(rad/s), the model gives the table below. |L| crosses 0 dB at 34.6 rad/s (read between the 30 and 100 rad/s rows), where `∠L(34.6 rad/s) ≈ −124°`, so `PM = 180° + (−124°) = 56°`. The phase reaches −180° at 150.8 rad/s, where `|L(150.8 rad/s)| ≈ −14.2 dB`, so the <Term id="gain-margin">gain margin</Term> is 14.2 dB, a factor of `10^(14.2/20) = 5.1`. The 300 rad/s row is already at −263°, well past −180°; the margin is read at the first crossing.

These numbers already include two lags that a continuous C × P sketch leaves out. The controller holds its torque for one period (zero-order hold), and the firmware applies the torque computed from a reading one period late. At 200 Hz each sample is 5 ms. A delay of T seconds costs ω × T radians of phase, more at higher frequency: at the 34.6 rad/s crossover one sample costs 34.6 × 0.005 = 0.17 rad, about 10°, and the hold, which acts like half a sample, about 5° more. That is 15° of margin a delay-free Bode plot would report but the real loop does not have.

## From margins to step response

Margins are not decoration: they predict how the closed loop will move. With kd = 0, raising kp raises |L| at every frequency, so the gain crossover moves right into a region with more phase lag. PM falls, and overshoot rises.

At kp = 1.0 with P only, the gain margin is 16.6 dB, a gain ratio of 10^(16.6/20) = 6.8. Sustained oscillation needs `|L| = 1` with `∠L = −180°`. Scaling kp changes magnitude but not phase, so −180° can only be met at the phase crossover ω_pc = 40.2 rad/s (hence the ringing frequency), and the gain there must rise by that factor 6.8, giving `kp_crit = 1.0 × 6.8 = 6.8 ≈ 6.79`. The same margin therefore predicts that the loop should ring at 40.2 rad/s and turn unstable near kp = 6.79. The sweep agrees: as kp goes 0.5, 1, 2, 2.86, PM falls 53°, 37°, 22°, 15°, and overshoot rises 15 %, 33 %, 54 %, 66 %. At kp = 6.5, PM is 1°, overshoot is 98 %, and the 39.3 rad/s ringing decays slowly, with the swing falling only from 172.47 to 137.12 mrad between the two windows. At kp = 7.0, PM is −1°, the ringing grows from 236.89 to 285.66 mrad, and its frequency is 40.5 rad/s. Prediction and step response line up.

Derivative changes those numbers. Month 3's kd = 0.115 N·m/(rad/s), together with kp = 2.86, lifts PM from 15° to 56° and cuts overshoot from 66 % to 2 %. The PD term itself contributes phase `∠(kp + jω kd) = atan(ω · kd / kp) = atan(34.6 × 0.115 / 2.86) ≈ 54°` at the new crossover; as ω_c moves from ≈25 rad/s (P-only at the same kp) to 34.6 rad/s, the plant and sample-delay lag grow by about 11°, so the net rise is about 43° (54° − 11°); the measured PM lift is 15° → 56°. D adds that phase lead near the crossover, exactly where the loop needs it. That is the frequency-domain reason D calms the approach: it does not remove steady error, but it raises the phase margin.

## Persistency of excitation vs a fair step (sysid)

Lesson 1 already identified B and J from one open-loop torque step. That works for a first-order speed lag: PE is **not** the claim "two parameters ⇒ a step cannot identify them." Persistency of excitation means the **regressors over the identification horizon** are rich enough that `ΦᵀΦ` is well-conditioned (Ljung's input-signal chapter, pointed from the MIT OCW 6.435 syllabus; De Nicolao's 1997 tutorial contrasts equation-error and output-error). For a richer structure the same step can leave `ΦᵀΦ` ill-conditioned — you learn that by **reporting** conditioning and parameter error, not by guaranteeing that a richer input always wins.

### Fair comparison

The toy locks three rules so the comparison is honest:

1. **Same duration** N = 200 samples.
2. **Same noise sequence** for every input arm inside a case.
3. **Matched input energy** `Σ u²` within `ENERGY_TOL = 0.01` (the richer input is scaled to the step's energy). Peak `|u|` is printed too — do not compare a tiny step to a huge PRBS.

### Estimator honesty

The fit is **equation-error OLS** (ARX-style): rows of `Φ` contain lagged outputs. When those outputs are noisy, OLS is an errors-in-variables / equation-error estimator and is **not** claimed unbiased. An output-error (OE) or instrumental-variable (IV) fit would be a different estimator; this page does not implement one. Month 7's `sysid_fit` is a sibling pointer, not redone here.

```python
#!/usr/bin/env python3
"""sysid_pe_compare_toy.py: PE vs step — fair energy, report conditioning (stdlib).

Persistency of excitation (PE) is about the RICHNESS of the regressors over the
identification horizon (how well-conditioned ΦᵀΦ is), not a claim that "two
parameters ⇒ a step cannot identify them." A transient step often identifies a
first-order time constant τ; for a richer structure the same step can leave
ΦᵀΦ ill-conditioned. Numbers decide — this toy reports them and does not
guarantee that PE always wins.

Fair comparison LOCKED: same horizon N, the SAME measurement-noise sequence for
every input arm of a case, and input energy Σ u² matched within ENERGY_TOL
(the richer input is scaled to the step's energy). Peak |u| is also printed.

Estimator class: equation-error OLS (ARX-style). Rows of Φ contain lagged
outputs, which are noisy, so OLS is an errors-in-variables / equation-error
estimator and is NOT claimed unbiased. An output-error (OE) or instrumental-
variable (IV) fit would be a different estimator; not implemented here.

Pointers (no copyrighted book text pasted): Ljung, System Identification, 2ed
(ISBN 0136566952) via the MIT OCW 6.435 syllabus; De Nicolao 1997 tutorial on
OE vs EE and PE. Existing lesson 5.1 step-τ identification and Month 7
sysid_fit are siblings, not redone here.
usage: python3 sysid_pe_compare_toy.py
"""
from __future__ import annotations

import math
import random

SEED = 51
N = 200                 # identification horizon (samples), shared
DT = 0.01               # s
ENERGY_TOL = 0.01       # |E_step - E_other| / E_step must be <= this
NOISE_STD = 0.02        # additive measurement noise on y (same stream per case)

# Case A: first-order speed plant  τ y' + y = K u  (discrete ARX-1).
# A single step is classically enough to read τ; PE is not required.
TAU_A = 0.08            # s  (matches the Month 3 / 5.1 joint time constant)
K_A = 1.0
A_TRUE_A = math.exp(-DT / TAU_A)
B_TRUE_A = K_A * (1.0 - A_TRUE_A)

# Case B: second-order ARX-2 with a slow and a fast mode. A step puts almost
# all energy at DC; a richer two-tone input improves the conditioning of ΦᵀΦ.
A1_TRUE_B = 1.70
A2_TRUE_B = -0.72
B_TRUE_B = 0.05


def prbs(rng: random.Random, n: int, amp: float) -> list[float]:
    """±amp pseudo-random binary sequence (clock every 4 samples)."""
    u, level = [], amp
    for k in range(n):
        if k % 4 == 0:
            level = amp if rng.random() < 0.5 else -amp
        u.append(level)
    return u


def two_tone(n: int, amp: float, f1: float = 1.5, f2: float = 7.0) -> list[float]:
    """Sum of two sines (Hz) — richer spectrum than a single step."""
    return [amp * (math.sin(2 * math.pi * f1 * k * DT)
                   + 0.7 * math.sin(2 * math.pi * f2 * k * DT)) for k in range(n)]


def scale_energy(u: list[float], target: float) -> list[float]:
    e = sum(v * v for v in u)
    if e <= 0.0:
        return list(u)
    s = math.sqrt(target / e)
    return [s * v for v in u]


def sim_arx1(u: list[float], a: float, b: float, noise: list[float]) -> list[float]:
    y = [0.0] * len(u)
    for k in range(1, len(u)):
        y[k] = a * y[k - 1] + b * u[k - 1] + noise[k]
    return y


def sim_arx2(u: list[float], a1: float, a2: float, b: float, noise: list[float]) -> list[float]:
    y = [0.0] * len(u)
    for k in range(2, len(u)):
        y[k] = a1 * y[k - 1] + a2 * y[k - 2] + b * u[k - 1] + noise[k]
    return y


def ols(phi: list[list[float]], yy: list[float]) -> tuple[list[float], float]:
    """θ̂ = (ΦᵀΦ)⁻¹ Φᵀ y via Gaussian elimination; also return cond(ΦᵀΦ)."""
    p = len(phi[0])
    g = [[0.0] * p for _ in range(p)]
    rhs = [0.0] * p
    for row, yk in zip(phi, yy):
        for i in range(p):
            rhs[i] += row[i] * yk
            for j in range(p):
                g[i][j] += row[i] * row[j]
    # 2-norm condition via eigenvalue ratio of the Gram matrix (p small).
    cond = _cond(g)
    theta = _solve(g, rhs)
    return theta, cond


def _cond(g: list[list[float]]) -> float:
    # For p=2 use closed form; for p=3 use characteristic polynomial roots via
    # numpy-free power iteration on G and G^{-1} for rough 2-norm cond.
    p = len(g)
    if p == 2:
        tr = g[0][0] + g[1][1]
        det = g[0][0] * g[1][1] - g[0][1] * g[1][0]
        # eigenvalues of 2x2: roots of λ² - tr λ + det = 0
        disc = max(0.0, tr * tr - 4.0 * det)
        lam1 = 0.5 * (tr + math.sqrt(disc))
        lam2 = 0.5 * (tr - math.sqrt(disc))
        return abs(lam1 / lam2) if abs(lam2) > 1e-18 else float("inf")
    # Power iteration for λ_max(G) and λ_max(G^{-1}).
    def power(mat, iters=40):
        v = [1.0] * p
        for _ in range(iters):
            w = [sum(mat[i][j] * v[j] for j in range(p)) for i in range(p)]
            nrm = math.sqrt(sum(x * x for x in w)) or 1.0
            v = [x / nrm for x in w]
        w = [sum(mat[i][j] * v[j] for j in range(p)) for i in range(p)]
        return sum(v[i] * w[i] for i in range(p))
    lam_max = power(g)
    ginv = _invert(g)
    lam_min_inv = power(ginv)  # ≈ 1/λ_min
    lam_min = 1.0 / lam_min_inv if abs(lam_min_inv) > 1e-18 else 0.0
    return abs(lam_max / lam_min) if abs(lam_min) > 1e-18 else float("inf")


def _invert(g: list[list[float]]) -> list[list[float]]:
    p = len(g)
    a = [row[:] + [1.0 if i == j else 0.0 for j in range(p)] for i, row in enumerate(g)]
    for col in range(p):
        piv = max(range(col, p), key=lambda r: abs(a[r][col]))
        a[col], a[piv] = a[piv], a[col]
        div = a[col][col]
        for j in range(2 * p):
            a[col][j] /= div
        for r in range(p):
            if r == col:
                continue
            f = a[r][col]
            for j in range(2 * p):
                a[r][j] -= f * a[col][j]
    return [row[p:] for row in a]


def _solve(g: list[list[float]], rhs: list[float]) -> list[float]:
    p = len(g)
    a = [g[i][:] + [rhs[i]] for i in range(p)]
    for col in range(p):
        piv = max(range(col, p), key=lambda r: abs(a[r][col]))
        a[col], a[piv] = a[piv], a[col]
        div = a[col][col]
        for j in range(p + 1):
            a[col][j] /= div
        for r in range(p):
            if r == col:
                continue
            f = a[r][col]
            for j in range(p + 1):
                a[r][j] -= f * a[col][j]
    return [a[i][p] for i in range(p)]


def fit_arx1(u: list[float], y: list[float]) -> tuple[list[float], float, float]:
    phi, yy = [], []
    for k in range(1, len(u)):
        phi.append([y[k - 1], u[k - 1]])
        yy.append(y[k])
    theta, cond = ols(phi, yy)
    true = [A_TRUE_A, B_TRUE_A]
    err = math.sqrt(sum((theta[i] - true[i]) ** 2 for i in range(2)))
    return theta, cond, err


def fit_arx2(u: list[float], y: list[float]) -> tuple[list[float], float, float]:
    phi, yy = [], []
```

## Common mistakes

- **Degrees in a radian model.** Month 3's 0.05 N·m/deg is 2.86 N·m/rad. Using 0.05 in a model that works in radians makes the loop about 57 times too weak, so the margins mean nothing.
- **Forgetting the hold and the delay.** A continuous C × P Bode plot has no sampling. The real loop holds torque for 5 ms and applies it one sample late; both add phase lag (about 15° at this crossover), so leave them out and your predicted PM is too optimistic.
- **Reading margins from an unchecked model.** If the open-loop step misses the measured final speed or 63 % time, fix B and J first. Margins read from wrong parameters have no basis.
- **Ignoring saturation.** Linear analysis assumes the commanded torque is actually delivered. If the motor clips, the loop gain is no longer that L; keep test steps small, and sweep gains only where the command stays inside the limit.
- **Identifying with a different load.** Gravity feedforward cancels the gravity you modelled, not a new payload or a spring. Measure tau and B in the pose and load the joint will run with; a different load changes J and B and moves both margins.
- **Declaring "two parameters ⇒ step unidentifiable."** A first-order τ is routinely read from a step. PE is about regressor richness; report `cond(ΦᵀΦ)` and `‖θ̂−θ‖` instead of a blanket ban.
- **Comparing inputs with unequal energy.** A huge PRBS against a tiny step is not a PE lesson. Match `Σ u²` (or peak `|u|`) within a stated tolerance.
- **Calling equation-error OLS unbiased on noisy y.** If lagged y sits in `Φ`, treat bias risk explicitly or switch to OE / IV and say so.
